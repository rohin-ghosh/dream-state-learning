# Paper 1 immediate end-to-end gate after the scope audit

**Status:** nonauthoritative design advisory.  This does not alter the frozen
Paper-1 goalposts, authorize implementation/model/GPU work, supersede the
ratified v2e package, or claim a result.

## Decision

Preserve the frozen Paper-1 controller and claim.  Do not make the newly
proposed learned LOOP adapter the immediate experiment; it remains Paper 2 or
stretch exactly as `research_notes/35_goalposts_paper1.md` says.  Do not finish
the full PCFL V3/lite benchmark first.  The highest-value next model experiment
is a small end-to-end recurrence canary on the shortcut-repaired v03r world:

```text
public life, final goal hidden
  -> prompted target-blind recurrent microdreams
  -> provisional/self-checked local memories M0
  -> non-answer operational probe
  -> prompted THINK0 identifies one missing typed relation
  -> bounded return-dream over target-blind selected public/memory views
  -> self-checked connected memories M1
  -> freeze/compile the identical supported corpus
  -> {bounded structured text | fresh per-life MEMORY LoRA}
  -> reveal final goal
  -> prompted adaptive THINK1 retrieves and composes local atoms
  -> final paired v03r answer/action
```

This closes the exact frozen Paper-1 arrows with the smallest existing world
that blocks the v0.2 target-signature shortcut.  It uses no learned LOOP
policy, no rank pyramid, no model-visible hidden truth, and no exact verifier in
the cognitive loop.

## Why not execute the already-ratified v2e package as the next GPU result?

V2e isolates whether a trusted THINK0 coordinate can allocate later public
views that change provisional local-connection proposals.  That diagnostic is
scientifically coherent, but its contract forbids the final goal, final
thinker, answer, LoRA, and any behavior claim.  It schedules 514 shared DREAM
calls plus up to 288 return-DREAM and 102 exploratory calls.  The current
implementation also lacks its phase-A/phase-B producer bodies, CLI, remote job,
artifact verifier, and transition test.  Completing and running it may help
debug the selection interface, but it cannot by itself satisfy any remaining
Paper-1 success criterion.

The end-to-end canary should borrow v2e's tested world, selector, alias,
recurrent-memory, and provider-boundary code rather than inherit its entire
artifact/governance surface.  If a query-guided return-dream cannot improve M1
and the final paired outcome in text, stop before LoRA.  That is a more direct
falsifier than hundreds of proposal-only calls.

## Frozen mechanisms

### DREAM

- Same prompted resolver machinery used by THINK, invoked without the final
  goal over one current public event plus a bounded local memory neighborhood.
- Writes one local operation per call: pass, create/reinforce/supersede concept
  or edge, or request follow-up evidence.
- Every new relation cites the exact public/memory handles used.  Depth is
  computed from cited memory parents; it is never self-declared.
- Model self-check is blind to final truth and answer.  It may compare a
  proposal only with visible public events and previously committed memories,
  predict what another visible/later public record should show, and label the
  proposal `SUPPORTED`, `CONTRADICTED`, or `UNRESOLVED`.
- False self-approved rows remain in the frozen corpus and are scored offline;
  the hidden evaluator never filters, repairs, or steers cognition.

### THINK

- THINK0 sees only the non-answer operational probe and M0.  It repeatedly
  retrieves/follows local atoms, updates a bounded workspace, and may emit one
  `REQUEST_DREAM(source, relation, target)` coordinate or defer.
- THINK1 sees the final public goal only after M1 freezes.  It uses the same
  operation grammar and a fresh context/KV state to retrieve and compose atoms.
- Every final answer cites returned memory; mask/twin substitution is an
  offline path-use diagnostic, not an in-loop verifier.

### SLEEP/WRITE

- For Paper 1, sleep is an inspectable deterministic compiler plus LoRA SFT,
  not a learned policy.  It deduplicates canonical semantic identities,
  preserves contradiction/provenance status, and emits the registered
  bidirectional/paraphrase/incident-edge views.
- M-TEXT and M-LORA receive exactly the same eligible semantic rows and views.
  LoRA receives the measured exposure recipe; it does not receive final goals,
  target answers, hidden proof, or THINK traces.
- MEMORY LoRA resets per life and composes with a clean unmounted reasoner.

## Minimal arms and stages

### Stage 0: existing CPU integrity

Keep v03r twin construction, final-goal embargo, edge-removal checks, local
window failure, renderer/skin split, exact paired oracle, deterministic replay,
life reset, and provider-call isolation.  Add only tests needed for final
THINK1, text/LoRA corpus equality, and offline path-use masking.

### Stage 1: one aligned DEV twin pair, text only

Run exactly three return allocations after a common target-blind prefix:

1. `NO_RETURN`: M0 is frozen directly;
2. `OWN_RETURN`: THINK0's sole valid missing-relation coordinate selects the
   bounded return views;
3. `DISTRACTOR_RETURN`: the frozen matched distractor coordinate selects the
   same number of views.

For each, retain `NO_GATE`, `SELF_CHECK`, and `SELF_CHECK_DRIFT` as writer
conditions only if they share the same call budget and common prefix.  A
lighter first canary may compare SELF_CHECK versus SELF_CHECK_DRIFT after the
existing no-gate/v5 negative is carried as historical evidence.

Compile M1 into structured text and run fresh THINK1 on both collision twins.
Advance only if OWN_RETURN:

- increases exact own-relation closure over both NO_RETURN and DISTRACTOR;
- contains at least one correct depth-2 row whose cited parent is an earlier
  memory, not only public events;
- improves paired final success over both controls;
- has no target/answer/proof/scorer descendant in any dream or memory byte;
- loses the final gain when the decisive returned atoms are masked or replaced
  by matched twin atoms; and
- does not obtain its gain solely from offline normalization.

The canary is an existence/mechanism check, not a statistical claim.

### Stage 2: same-corpus MEMORY-LoRA transport

Only after Stage 1 passes, train a fresh per-life Qwen2.5-7B MEMORY LoRA on the
exact OWN_RETURN self-checked corpus and the already registered write views.
Use DEV only to choose between the two predeclared installation capacities,
preferably ranks 8 and 32; rank is capacity, not timescale.

Compare:

- clean/no memory;
- raw public-life RAG with adaptive retrieval;
- structured M1 text;
- direct-QA/action-outcome LoRA;
- dreamed M1 LoRA;
- wrong-life or twin-swapped dreamed LoRA; and
- an oracle-atom text ceiling.

Advance if fixed varied-cue read fidelity is at least 0.90, paired final value
is no worse than text by more than 0.10, wrong-life/twin swap removes the gain,
and THINK1 actually uses retrieved atoms.  A text win plus LoRA transport
failure is an honest negative and removes parametric-memory language.

### Stage 3: frozen Paper-1 replication and prompt ablation

Only after Stages 1--2 freeze, run the predeclared three seeds and three skins,
with collision twins always scored as one pair.  Compare minimal, generic
cognitive-loop, generic-pattern-repertoire, and game-informed prompts under
matched budgets.  Report all malformed/deferred/missing cells.  This stage is
where the frozen Paper-1 criteria are evaluated; the one-pair canary never
promotes a claim.

| Observed result | Maximum interpretation |
|---|---|
| OWN_RETURN does not improve M1 closure | Goal-conditioned recurrence did not help connection growth under this interface. |
| Closure improves but final paired result does not | Memory construction improved; actionable reconstruction did not. |
| Text works and LoRA read fidelity fails | Dream/think mechanism works in explicit memory; parametric transport fails. |

| Text and LoRA work only with game-informed prompt | Engineered ceiling, not autonomous generic dreaming. |

| Wrong-life/twin-swapped memory retains gain | Experiential attribution is invalid. |

## Relationship to the LOOP relay proposal

The `chg_20260902_one_cycle_flywheel_relay_v1` proposal should be relabeled a
Paper-2/stretch successor, not a replacement Paper-1 path.  Its operation
traces can be trained only after the prompted organism above generates lawful
examples.  The rank pyramid remains after a single LOOP adapter transfers.
This ordering preserves the owner's explicit no-goalpost-change handoff:

```text
Paper 1: fixed prompted policy, learned life memory
  -> Paper 2: shared learned LOOP policy over many completed lives
  -> later: rank/data/update-timescale cascade and base promotion
```
