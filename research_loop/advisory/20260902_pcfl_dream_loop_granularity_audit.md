# PCFL-Compose Dream-loop granularity audit

**Date:** 2026-09-02  
**Status:** read-only scientific advisory. This file is not architecture
consensus, human ratification, implementation/model/GPU authorization, or a
scientific result.

## Disposition

Use **B, the typed recurrent resolver, as the primary generic Dream-1/Dream-2
condition**. Keep **A, one full-context call per phase, as a mandatory paired
control**.

This reverses the one-call primary specified in
`20260902_pcfl_sparse_construct_text_spec.md`; it is a material architecture,
budget, and claim change and must enter a new hash-bound deliberation rather
than being patched into that advisory as an implementation detail.

This is a construct choice, not a prediction that recurrence will win. The
existing small-lifetime evidence actually makes the one-shot arm a strong
competitor. If A matches B, the result may still support prospective generic
abstraction and self-revision, but it does **not** support a recurrent-Dream
claim; the simpler batch compiler should then be the paper description. If B
fails while A succeeds, the shared recurrent organism has failed on this
assay. If B succeeds only by receiving factor-specific operations, solution
packets, more candidate capacity, or an external correctness decision, the
comparison is invalid.

The reason to make B primary is architectural: Rohin's current thesis says
Think and Dream are two invocation contexts of one resolver, with Sleep only
compiling model-authored content. A single monolithic call can test generic
batch synthesis, but not local retrieval choice, state revision, provenance-
conditioned connection, or a controller that can continue when the lifetime
itself no longer fits one prompt. The primary arm should instantiate the
claimed organism; the simpler arm should test whether that machinery was
necessary.

## What the current evidence says

| Evidence already in the repository | Consequence for this choice |
|---|---|
| v5 was 53 independent task-family-scaffolded generations, not recurrent use of prior nodes. Parent recall plateaued `0/12 -> 3/12 -> 3/12 -> 3/12`; its retained parent corpus was `0/12` true. | More one-shot proposals did not create cumulative structure. Do not use v5 as evidence that A or B works; use it as evidence that proposal sampling is not recurrence. |
| v5's downstream trace emitted multiple operations in one completion and was malformed on 29/30 items. | One typed operation per call and failure-preserving parsing are warranted interface controls, not cosmetic engineering. |
| Unstructured recurrent Semantic-World dreaming stayed depth 1 and recovered 0/12 parents at both 7B and 32B. | Recurrence alone is not intelligence. B must externalize a legible local state; merely looping a long prompt is not the proposed treatment. |
| Requiring prior-memory citations changed recurrent depth from 1 to 5 over 32 cycles, but still recovered 0/12 true parent sets. | Explicit provenance is necessary for measurable depth, not sufficient for correctness. Do not equate a deeper trace with a correct dream. |
| The exhaustive atomic branch/revisit controller reached 23/24 exact parents on untouched worlds; the monolithic versions failed. | Local proof state and revisit can unlock model capability, but the 57-subset controller was a ceiling. PCFL B must remain family-neutral and may not enumerate the factor closure. |
| At 23 episodes, batch dreaming beat streaming (`D2 .50` versus `.25` in the best streaming rows). | A is a serious control, and B is not expected to dominate while the complete relevant evidence fits context. Streaming/recurrent value begins at the long-life boundary, not by assertion. |
| In the substrate x protocol 2x2, context+recognition and LoRA+recognition both scored `.50`, versus direct context `.083` and direct LoRA `.167`. | The resolution protocol is a major part of the intelligence. Any B gain belongs to the complete prompted resolver, not to LoRA. Text must pass before LoRA, and the same reader/resolver must be used across substrates. |

These results favor B as the faithful system treatment and A as a powerful
falsifier. They do not establish that B will be more accurate or efficient.

## Construct comparison

### A: one full-context Dream-1 and Dream-2 call

**Strengths.** It is cheap, easy to audit, gives the model all 13 tree events
without retrieval failure, and cleanly tests whether a generic frozen model
can propose before evidence and self-revise after raw evidence. It minimizes
prompt/harness intelligence and matches the earlier empirical result that
batch processing is preferable while the relevant life fits one window.

**Limits.** It tests a batch research/summary call, not the one-system
Think/Dream architecture. It cannot identify query selection, incremental
state repair, traversal, or connection-through-use. A literal whole-life
version ceases to exist beyond context; a selected local batch can continue,
but then the unmeasured selector owns the scaling story.

**Maximum claim if positive.** A frozen generic full-context compiler made a
prospective model from a bounded public batch and self-revised it from later
raw outcomes. It cannot support recurrent dreaming, local-memory traversal,
or beyond-context Dream operation.

### B: typed recurrent Dream resolver

**Strengths.** It implements the same computational contract as Think:
bounded state, one selected local read, one typed cognitive mutation, explicit
provenance, and a terminal decision. It exposes where failure occurs and is
compatible with a lifetime larger than context because raw episodes need not
co-reside. Dream-2 becomes actual state revision from public experience rather
than a second summary prompt.

**Limits.** It supplies more prompt structure, more forward passes, an
external workspace, and a retrieval API. Those are amortized controller
intelligence. A success is therefore about a **frozen prompted recurrent
reference organism**, never a learned or emergent dream policy. A B-versus-A
gain is a protocol result at disclosed extra call/input-token cost, not a
pure-compute-matched theorem about recurrence.

**Maximum claim if positive.** Under a preregistered family-neutral operation
grammar, a frozen recurrent resolver selected local public evidence, built a
cited predictive state, and revised its own durable model from later raw
outcomes. A post-context claim additionally requires the registered lifetime
checkpoints and constant-bounded local access; this single 13+2 module alone
does not establish it.

### Prompt amortization and cost

B is more heavily amortized than A. The operation ontology, rolling workspace,
reader, provenance rules, and scheduler all supply a way to think. That is
permitted by the Paper-1 goalposts only when the prompt gives process guidance
rather than the PCFL solution. Preserve the three prompt rungs already required
by the model-owned protocol: neutral reflection/compression, primary generic
operations, and a separately labeled class-informed formula ceiling. If only
the class-informed rung succeeds, the system fitted a supplied family. If the
generic rung beats neutral, report that the result depends on process
scaffolding; do not call the behavior spontaneous.

The exact planning call envelope is also materially different:

| Treatment | Calls per life | Calls for sampled root + antipode | Calls for a 16-life diagnostic orbit |
|---|---:|---:|---:|
| A | 2 | 4 | 32 |
| B hard maximum | 48 | 96 | 768 |

Early stopping can make B cheaper, but assigned failures and unused budget must
remain visible. Repository timing anchors (44 short thinker calls in about
three minutes; 53 longer dream calls in about 29.5 minutes) suggest the B
envelope is operationally feasible on a small DEV panel, not cheap at powered
scale. Those timings are from another world and are not PCFL measurements. Do
not materialize the complete 16-life orbit merely to compare A and B unless its
diagnostic value justifies roughly 24 times as many Dream calls; sampled roots
plus predeclared antipodes are the cost-feasible scientific unit.

## Exact minimal proposed protocol

These bytes still require the full `AGENTS.md` deliberation and human
ratification before implementation.

### Shared kernel and firewall

1. Pin Qwen2.5-32B-Instruct revision
   `5ede1c97bbab6ce5cda5812749b4c0bdf79b18dd` for both A and B. Use the
   same tokenizer, provider configuration, public rendering, presentation
   order, presealed non-adaptive seed schedule, candidate order, DSL,
   candidate/record limits, and parser in factorized and independent-table
   lives.
2. Use `temperature=0.2`, `top_p=0.95`, one presealed seed per assigned life.
   Do not retry a scientific call with a new seed. Infrastructure replay, if
   allowed at all, must use identical bytes/seed and retain the first failure.
3. The shared family-neutral operation set is:

   ```text
   READ(handle)
   NOTICE(claim, premises)
   CONNECT(claim, premises)
   PREDICT(candidate_id, records, action_predictions, premises)
   REVISE(node_or_candidate_id, replacement, premises)
   COMMIT(candidate_ids_or_final_decision)
   ABSTAIN(reason, premises)
   PASS(reason)
   ```

   The grammar may explain these process verbs. It may not say `factor`,
   `S_6`, `row`, `column`, `anchor`, `orientation`, `tree path`, the two
   equations, target roles, or a completion recipe. A class-informed version
   is a separately labeled ceiling.
   The resolver state machine, parser, budget accounting, `READ`, workspace
   update, provenance, malformed-output, and halt transitions must be the same
   implementation used by THINK. Mode may change only the initial objective,
   eligible input store, and terminal permissions: DREAM can `PREDICT/COMMIT`
   memory but cannot `USE`; THINK can `USE/LOCK` but cannot durably rewrite the
   frozen memory. Shared operations must have byte-identical semantics.
4. One B response contains exactly one operation. A malformed response is
   logged, consumes one operation, mutates no semantic state, and receives at
   most the fixed string `INVALID_SYNTAX`; no parser repair or expanded retry
   is allowed.
5. The episodic reader returns one immutable raw public event or `NOT_FOUND`.
   Its catalog exposes only public handle, action label, and chronology. It
   performs exact handle/label lookup, no semantic ranking, path completion,
   reciprocal expansion, candidate enumeration, or target-aware prefetch.
6. The live prompt contains the fixed instruction, public operation/catalog
   metadata, a canonical current workspace, the latest reader response, and
   remaining budget—not the growing full transcript. Keep at most three raw
   event payloads live simultaneously. The complete trace remains in the
   audit artifact, not silently in model context.
7. `NOTICE` cites at least one eligible public or prior workspace ID.
   `CONNECT` cites at least two distinct premises. `REVISE` cites the
   superseded node/candidate and the new evidence. All committed records have
   an acyclic provenance path to public events. Citations establish origin,
   not truth.
8. Dream-1 may emit at most `K=2` candidates. Each candidate contains both
   prospective revision-chord predictions and at most `R=13` standalone
   semantic records. Each record is at most 256 UTF-8 bytes; one candidate
   package is at most 4,096 UTF-8 bytes. False well-formed content is never
   silently deleted.
9. The sleeper receives only the final model-selected AST and performs the
   representational-only operations already specified. Hidden truth and the
   public comparator remain sterile offline scorers. SELF, NO-GATE, and
   PERFECT-PUBLIC-GATE fork only after the common model trace freezes.

### B Dream-1: prospective local construction

Use a hard cap of **32 resolver operations**:

- at most 13 `READ` operations over the source tree; repeats and `NOT_FOUND`
  consume the same budget;
- at most 13 total `NOTICE + CONNECT + REVISE` operations;
- at most two `PREDICT` operations, one per candidate, each predicting both
  announced revision chords;
- exactly one terminal `COMMIT` or `ABSTAIN`; and
- at most three remaining `PASS`/malformed slots.

The live workspace holds at most 16 model-authored nodes and 4,096 tokenizer
tokens. Ordinary cognitive operations may emit at most 256 tokens, `READ` at
most 64, each `PREDICT` at most 2,048, and terminal commit at most 256, under a
hard cumulative Dream-1 generation cap of **8,192 tokens**. Early commit is
allowed. Running out of budget without a valid terminal operation is a failed
Dream-1 assignment, not an abstention invented by the harness.

### B Dream-2: raw-evidence self-revision

Start a fresh model context with only the fixed kernel, catalogs, and handles
for the frozen Dream-1 packages and two new raw validation events. Use a hard
cap of **16 resolver operations**:

- at most eight total reads: two candidate-package reads, two validation-event
  reads, and up to four source-event rereads;
- at most five total `NOTICE + CONNECT + REVISE` operations;
- at most one `PREDICT` of both disjoint audit chords for the final program;
- exactly one terminal `COMMIT(RETAIN|REVISE)` or `ABSTAIN`; and
- one remaining `PASS`/malformed slot.

The final active program count is zero or one. Dream-2 may not create a third
candidate unrelated to Dream-1; a revision must cite its parent candidate and
raw validation evidence. Use a 16-node/4,096-token live workspace and a hard
cumulative **4,096 generated-token** cap. A wrong retention, corrupt revision,
false abstention, or timeout remains in the assigned denominator.

### A one-shot control

Run exactly one fresh full-context call for Dream-1 and one for Dream-2.
Dream-1 receives all 13 raw tree events; Dream-2 receives those events, the
unaltered Dream-1 packages, and both raw validation events. It uses the same
generic instruction, DSL semantics, `K=2`, `R=13`, record/package byte caps,
presentation seed, and terminal rules. Its response may serialize up to 32
typed Dream-1 trace operations or 16 Dream-2 operations before the same
terminal object, but the harness performs no intermediate state transition.

Give A the same cumulative generated-token entitlements: 8,192 for Dream-1
and 4,096 for Dream-2. Report input tokens, generated tokens, model calls,
latency, and estimated FLOPs separately; B necessarily has more recurrent
forward passes and repeated state input. Therefore a B advantage licenses
only “the recurrent execution protocol helped at this disclosed resource
point.” A causal efficiency claim would require a separately preregistered
call/FLOP frontier, not this pair alone.

## Required comparisons and estimands

Run A and B on byte-matched open and untouched factorized lives and on the
matched independent-table control. For each, report before target release:

- Dream-1 candidate-pool recall and exact prospective chord prediction;
- Dream-2 retention, correction, corruption, false-retain, false-abstain, and
  disjoint audit-chord prediction;
- committed record truth/coverage, bytes, provenance depth, operations,
  calls, tokens, latency, and failures; and
- downstream text-memory D1/D4 executed action, causal memory cuts, and
  target-only/atom/raw-RAG/A-MEM controls.

Add the paired diagnostic

```text
Delta_dream_loop = Y(B, SELF text) - Y(A, SELF text)
```

at identical public information, candidate/record capacity, and generated-
token entitlement. Treat model-call/input-token differences as part of the
reported treatment, not as matched away. Also compare prospective prediction
and final-law correctness; action alone cannot establish Dream ownership.

## Stop and interpretation rules

1. **Invalid construct:** stop if the B reader supplies more than one raw
   event, a derived path/compound, semantic ranking, target-aware retrieval,
   or if the rolling prompt accumulates the whole raw life. B then collapses
   into hidden A or a solver-assisted treatment.
2. **Invalid ownership:** stop if any comparator/scorer verdict, hidden factor,
   exact completion, target descendant, or parser repair reaches Dream state,
   Sleep, memory, or Think.
3. **No generic Dream:** if generic B fails but the class-informed ceiling
   succeeds, report known-family fitting only and do not promote B to LoRA.
4. **No recurrent-Dream claim:** if A matches or exceeds B within the
   preregistered practical margin (recommended DEV margin `0.05`) on both
   prospective correctness and downstream D4, retain the simpler A result and
   state that recurrence was unnecessary here.
5. **Recurrent-organism failure:** if A succeeds and B fails because of local
   read, workspace, halt, or revision errors, do not describe A as evidence
   for the one-system resolver. Preserve the organ-localized negative.
6. **Specificity failure:** if either generic treatment produces above-chance
   target action or non-abstaining global-law confidence in the independent-
   table control, invalidate the abstraction interpretation.
7. **Depth without correctness:** cited depth, node count, or operation count
   cannot promote B. Require prospective predictions, final audit predictions,
   and executed target action.
8. **No post-context claim:** do not claim scalable or beyond-context Dream
   from the 13+2 module. At `1.5L`, `3L`, and `6L`, the recurrent live state
   and per-sleep read/operation caps must remain fixed while unique public
   factor entropy grows. If target-time or sleep-time access becomes a linear
   hidden scan of accumulated life bytes, the crossover/scaling claim fails.
9. **No LoRA promotion:** follow the existing Stage-1 text gate. B must create
   nonzero prospective true-schema coverage, self-revision must not increase
   false retained content, authentic text memory must beat its twin/cuts, and
   the independent family must remain null before a separately ratified LoRA
   stage is scientifically interpretable.
10. **No learned-loop language:** success supports a frozen prompted recurrent
    reference controller only. The LOOP adapter, learned scheduler, on-policy
    evidence acquisition, and full continual flywheel remain absent.

## Bottom line

B is the right primary **because it is the proposed organism**, not because
looping is known to outperform one-shot thought. A is mandatory and may win.
That outcome would simplify the paper rather than invalidate the prospective
abstraction result. The scientifically useful result is the paired boundary:
whether local recurrent state is necessary once both treatments receive the
same public evidence and semantic capacity, and exactly what additional calls
it costs.
