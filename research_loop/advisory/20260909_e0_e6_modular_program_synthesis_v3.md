## E0 -- writer obligation, not yet an adopted experiment

The current long-life path cannot pass E0: it calls the legacy bare-text
compiler/trainer, and rejecting an adapter head does not quarantine the
associated corpus from later cumulative rebuilding.

E0 contains two evidence types that must not be conflated.

### Deterministic transaction and provenance fixtures

These must prove exact source/model/tokenizer/compiler/trainer/mask/rank/dose/
seed/corpus identities; immutable birth; candidate-only staging; separate
adapter-head and evidence-corpus promotion; rejection quarantine; atomic
commit and rollback; previous-child preservation; and source-to-launch-to-
artifact receipts. They also prove that only exact public-state -> native child
continuation -> dispatched typed action -> public outcome evidence is eligible,
and that parent prose, tool results, raw ledgers, unsupported derivatives, and
rejected candidate-only rows cannot silently carry loss or return later.

### Stochastic carrier and behavior evidence

Across independently generated writer roots, with root-level failure-inclusive
reducers, the candidate writer must pass:

- assigned-semantic absorption and retention;
- free-routing quality and typed-forced proposal/provenance quality;
- native thought/action syntax, DREAM restoration, generic anchors, and
  relevant competence noninferiority versus the previous child;
- adapter-off, wrong-life/root, and action--outcome binding-shuffle contrasts;
- exact mount/off, candidate-only base, rejection, and rollback behavior.

Calls, prompts, samples, rows, and repeated fits within a writer root never
increase `n`. No confirmation root count, margins, failure values, uncertainty
method, or power receipt is adopted here; those are unresolved and must be
derived before a positive E0 carrier claim. Until then E0 is an open blocker,
not a “small panel” ready to execute.

## E1 -- exact open estimand and contamination boundary

The older one-parent v1--v4 candidate defines a useful causal surface:

```text
P childhood = matched practice + process parent + child application +
              public admission + childhood write
U childhood = matched practice + child self-review + public admission +
              dose-matched childhood write, with no parent

P0/U0 = deployment personal LoRA writes disabled
P1/U1 = deployment personal LoRA writes enabled
```

Within each independent root, `P0/P1` share exact parented entry bytes and
`U0/U1` share exact unparented entry bytes. Parent and nursery are deleted
before deployment. The primary root-level interaction is

```text
D = [gain_AUC(P1)-gain_AUC(P0)]
  - [gain_AUC(U1)-gain_AUC(U0)].
```

`D` distinguishes parenting's effect on later write-enabled learning from a
mere entry-competence shift. Parent-absent entry-adjusted trajectory, absolute
learning, forward transfer, old-skill retention, information gained per
generated token, typed proposal/routing preservation, and complete failure-
inclusive resource/row-yield mediators remain noncompensatory secondary
obligations. One independently raised root is one row; lessons, tasks, calls,
fits, probes, and classroom branches are repeated measures.

That older surface is **not adopted here** because the user-ratified
Adaptive Parent Development v5 proposal supersedes v4's scientific intent,
and the direct Fable--Codex design exchange on adaptive teaching, scaled
THINK, continuity, and perspective is still pending. Its exact source and
proposal-only receipt are bound below.

Any E1 successor must reconcile the factorial above with these contamination
rules:

1. During development, the strongest fixed-weight parent may improve its
   teaching through bounded context/files/playbook and short- plus delayed-
   horizon evidence.
2. Before confirmation, either freeze the complete parent state/policy or
   prospectively freeze the complete adaptive algorithm and its allowed view.
   Every independent confirmation root begins from the same lawful initial
   parent state; no outcome crosses roots.
3. A canonical developmental child may continue across parenting subjects
   while THINK/DREAM/SLEEP/writer/capacity/eligibility/promotion semantics stay
   fixed.
4. A mechanism change creates an immutable sibling at the last common clean
   snapshot.
5. Any deployment-gym or final-benchmark descendant is disposable. Its
   weights, context, DREAM, SLEEP rows, memories, actions, outcomes, parent
   observations, and summaries never flow back into the clean developmental
   child or a later parenting comparison.
6. Final confirmation restarts prospectively from frozen clean births/stages;
   development exams and final identities are disjoint.

No E1 maximum claim, final factor roster, failure value, margin, uncertainty
rule, power rule, or sample size is released until the pending joint design is
resolved and independently reviewed.
