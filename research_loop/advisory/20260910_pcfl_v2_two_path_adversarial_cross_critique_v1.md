# PCFL v2 two-path adversarial cross-critique

Date: 2026-09-10

Status: **advisory cross-critique and ratification candidate only**. This file
authorizes no implementation, materialization, root generation, test or
scientific execution, model/provider/tokenizer call, GPU use, lineage action,
claim, or release. The controlling v1 consensus remains `human_required` and
`implementation_forbidden`.

## Ruling

**Select path A as the architecture direction, with two corrections: do not
call FeltCraft V7 a PCFL Stage 0, and do not leave M0 abstract.** Keep the exact
frozen V7 manifest unchanged as an external symbolic reference; require a new
hash-bound reuse edge before importing any function or output; and recast the
useful, non-overlapping parts of path B as candidate requirements for the thin
PCFL-specific M0.

**Do not materialize or implement `PCFL_STAGE0_V2` as a separate 64-root
platform or paper milestone.** Its deterministic no-selection materializer may
later be proposed as preparation tooling, with independently checked outputs
frozen before M-TEXT, but only after a new exact scope decision. The fixed
64-root universe, synthetic scripts, root reducer, and acceptance profile are
not presently ratified semantics.

The fastest valid route to paper-relevant evidence is therefore:

```text
V7 (unchanged external reference)
  -> exact, M-TEXT-bound reuse/mapping decision
  -> thin M0 containing only missing PCFL semantics used by M-TEXT
  -> narrow supplied-memory M-TEXT causal-use ceiling
  -> separate DREAM-authorship extension
  -> G + E0 + M-LORA and later P/L/C/O packages
```

This selects A over B-as-a-product. It does not select indefinite deferral:
the next deliberation must bind M0 and the M-TEXT interface together.

## Why the apparent choice is partly false

Path A does not eliminate new PCFL code. Its four M0 responsibilities—deck
semantics, actor visibility and phase state, support admission and carrier
compilation, interventions and receipts—are most of the legitimate content of
path B. Conversely, path B is not an alternative symbolic foundation: it is a
large candidate M0 specification that reimplements some V7 mathematics and
adds many PCFL-specific rules.

The real choice is whether to build and celebrate a standalone CPU overlay
before its semantics are bound to the model experiment, or to implement only
the subset that the first M-TEXT assay actually consumes. Only the latter has
a short causal path to a paper result.

## Adversarial audit of path A

### What A gets right

- V7 should not be rebuilt merely to obtain another alignment, projection,
  twin, cost, or bridge-deletion implementation.
- V7 passage is software evidence only. A correctly preserves its forbidden
  benchmark, rendered-world, model, DREAM/SLEEP, LoRA, and scientific scope.
- M, E0, M-LORA, L, P, C, O, and confirmation have different estimands and
  cannot be unlocked by a CPU receipt.
- The D0 cross-audit identifies real PCFL-specific risks that V7 cannot solve:
  visible prefixes, join/reset chronology, query agendas, provenance,
  renderer/tokenizer cuts, and root construction.

### Gaps and overstatements

1. **“The ruler is built” is too strong.** V7 is approved only in its narrow
   symbolic scope; its external scope audit failed and successor promotion is
   forbidden. It is evidence about its own functions, not evidence that those
   functions are sufficient or correctly mapped to PCFL.
2. **Renaming V7 `Stage 0-SK` risks authority laundering.** Existing human
   approval authenticates the frozen V7 subject and limits. It does not approve
   a PCFL dependency edge. Until that edge is independently reviewed and
   ratified, V7 should remain an external reference, not a PCFL stage.
3. **“Thin M0” understates the work.** A deck, phase machine, reader boundary,
   support DAG, carrier compiler, interventions, and reducer are a substantial
   instrument. Thin must mean “no duplicated V7 primitives and no later-stage
   organs,” not “small.”
4. **The staging graph omits a stated prerequisite.** Its G section requires G
   before any claim-bearing model or M run, while the diagram permits
   `M0 -> M-TEXT` without G. A paper-bearing M-TEXT execution needs the scoped
   G/session/no-return boundary; a nonclaim engineering rehearsal does not.
5. **The nine D0 findings are evidence, not circular authority.** The source
   D0 bundle is unratified and its rework plan is superseded. A successor must
   disposition each finding as retained, replaced, or inapplicable. It must not
   import old tokenizer, energy, 64-pair, or world choices merely because the
   failed bundle mentioned them.
6. **A's strongest M-TEXT branch is not the fastest first claim.** Requiring
   authentic child/DREAM link authorship in the first text ceiling bundles
   discovery with use. The v1 consensus explicitly permits narrowing first to
   supplied linked-memory use. That narrower causal-use result is still
   paper-relevant and leaves authorship as a separate falsifiable extension.

## Adversarial audit of path B

### Legitimate additions not supplied by V7

Path B usefully sketches paired-prefix equality, one actor-visible view and
command boundary, explicit joins and resets, repeat/replay behavior, a public
taint rule, provenance-root deduplication, support-after-proposal chronology,
carrier-specific interventions, separate uncertainty fields, and adverse
root reduction. These are credible M0 requirements if the M-TEXT design uses
them. They are not generic replacements for V7.

### Scientific gaps

1. **It is a self-conformance instrument, not a mechanism experiment.** The
   scripted actor is constructed to satisfy the declared scorer, and the
   reducer checks the declared expected profile. Passage proves consistency of
   code with stipulated semantics, not that a model can use connected memory.
2. **The “AUTH” advantage can be imposed by the scoring interface.** A trace
   receives constructive credit only when it cites declared atom/link IDs.
   Such `deps` can be decorative. Actual causal use requires model-behavior
   interventions—memory masking, twin substitution, recurrence removal, and
   honest bypass baselines—not a script's self-reported dependency edges.
3. **Reference DREAM does not establish DREAM authorship.** Exhaustively
   enumerating every composable pair and later validating it is deterministic
   closure. Path B acknowledges this in prose, but `DREAM_REF` and `AUTH`
   naming invite a stronger interpretation than the assay supports.
4. **The 64 roots add little semantic diversity.** They are 32 alias/order
   nuisances crossed with one hidden bit; the old graph and path structure are
   invariant. This is useful for leakage tests but does not establish
   generalization, accumulation, planning breadth, or developmental scale.
5. **Character-level balance is not model-level balance.** With no tokenizer,
   renderer, prompt, or model, equal string counts and fixed byte padding do
   not control token counts, token priors, position effects, or model-visible
   salience. Those choices can force a redesign at M-TEXT.
6. **The task is solvable by ordinary graph search over atoms.** Path B can
   verify that a link-aware script obeys an interface, but it does not show
   connected organization adds utility over raw context, RAG, native graph,
   or organized-memory bypasses. Those are precisely the paper-relevant
   M-TEXT comparisons it defers.
7. **The unit universe silently changes.** Path B has 64 roots, hence 32 twin
   pairs, while the D0 source/rework material referred to a 64-pair CPU deck.
   Because B is a new benchmark this is not intrinsically illegal, but neither
   32 pairs nor 64 roots is scientifically justified. The count must follow
   the M-TEXT estimand and precision rule; syntactic nuisance copies must not
   later be treated as independent scientific units.

### Incompleteness and incorrect exactness assertions

The title and prose call the semantics exact, but the file correctly admits
that it is not an exact-byte packet. More than bytes remain open:

- `public-action-id`, public handles/object IDs, root-ID derivation, the full
  phase enum, and public aliasing for all command types are not closed;
- `MemoryReturn` is assigned a fixed byte bound but is not defined as a
  standalone record; `TransitionRow` has `pad` but no bound; and complete
  canonical rules for nested `FiniteView`, `GoalsComplete`, and `ProbeSlot`
  objects are not supplied;
- transformed atom semantic IDs, dependent link IDs, citations, and trace
  rewrites after `TWIN_REDIRECT` are not fully specified;
- the complete root-receipt schema, carrier-by-cut cell universe, and expected
  bit vector that the reducer claims to check are absent;
- contradiction matching, revocation timing, support identities, failure
  precedence, and several command/budget transitions need executable tables;
  and
- the canonical roots, views, goldens, transition table, and independent
  checker identities are intentionally missing.

These are not clerical omissions: several can change visible bytes, legal
behavior, and acceptance. Path B therefore cannot yet authorize either a core
implementation or generated roots under the governing consensus.

### Redundant work

The finite relation algebra, path enumeration, involutive twins, exact path
costs, and bridge deletion substantially overlap V7. Rebuilding them in a new
package creates two reference truths and a future equivalence problem. The
64-root golden matrix and synthetic positive/sham scripts also become
throwaway work if M-TEXT later chooses different rendered objects, token cuts,
baselines, or units. Only PCFL-specific state, visibility, support, carrier,
and intervention logic should survive into M0.

### Circular authority risks

- A materializer plus checker derived from the same prose can prove mutual
  consistency while preserving a semantic mistake. Independent checking must
  include an independently derived oracle or exhaustive mathematical
  invariants, not merely a second parser of the same generated manifest.
- `DREAM_REF` declares which pairs are authentic, the renderer admits them,
  the scripted trace cites them, and the reducer expects their success. That
  closed circle is valid software testing but supplies no independent
  scientific ground truth for useful memory.
- Neither the superseded D0 draft nor V7's approval can ratify B's new world.
  Hash continuity authenticates bytes; it does not confer benchmark validity.

## Exact staged decision recommended for human ratification

Ratify only the following direction now:

> Preserve the full Dream--LoRA--Think program. Keep the exact frozen FeltCraft
> V7 files unchanged and outside the PCFL stage graph until a separately
> reviewed, hash-bound reuse edge maps each consumed primitive and proves
> oracle isolation. Reject `PCFL_STAGE0_V2` as a standalone 64-root platform.
> Treat its paired-prefix, capability, phase/join/reset, provenance/support,
> carrier-intervention, uncertainty, failure, and reducer clauses only as
> candidate inputs to a thin M0 that is co-designed with the first M-TEXT
> assay. Authorize no code or execution from this decision.

The next exact packet should then do, in order:

1. **Bind the first claim before its instrument.** Select `M-TEXT-SUPPLIED`:
   one frozen model uses independently supplied, publicly supported connected
   text memory under a common reader. The claim is causal use of supplied
   memory, not DREAM discovery, learning, LoRA storage, or continued life.
2. **Freeze one M0/M-TEXT interface.** Bind the actual root universe and unit
   rule, renderer/tokenizer/chat bytes, actor view, commands, phase/join/reset,
   support rule, carrier transformations, budgets, parser, baselines,
   endpoints, failure values, and claim reducer. Do not inherit “64 roots” or
   “64 pairs” without an explicit precision/design justification.
3. **Bind V7 reuse narrowly.** Provide a primitive-by-primitive compatibility
   table and golden mapping. Anything not exactly isomorphic is implemented in
   M0; nothing is silently generalized from V7.
4. **Materialize without selection.** Under a separately ratified preparation
   scope, a deterministic exhaustive materializer may produce candidate deck
   bytes. It may not search seeds, rank candidates, replace failures, or inspect
   model results. Independently derive/check the invariants, freeze all bytes
   and hashes, and obtain human ratification before claim-bearing M-TEXT use.
5. **Implement only the consumed M0 surface.** No standalone Stage-0 root
   report is a paper result. Its receipt certifies software and visibility
   preconditions only.
6. **Gate and execute M-TEXT separately.** Bind the scoped G/session boundary
   and Q decision DAG, then test recurrence-disabled, no-memory, raw-context,
   RAG/native-graph, organized-memory, bridge-cut, and twin/binding controls
   with noncompensatory recall, transfer, composition, planning/action,
   revision, information, and retention endpoints.
7. **Only after that result**, deliberate a target-independent child/DREAM
   proposal assay. E0 and M-LORA remain independent later gates; P, L, C, and
   O remain distinct claims.

This route spends the next implementation effort on semantics that reach an
actual model comparison. It preserves the full organism by sequencing its
claims, not by building every organ into the CPU prelude.

## Claim ceiling

A green M0 receipt may say only that the frozen software implements the
ratified finite instrument and visibility/intervention contracts. A green
`M-TEXT-SUPPLIED` result may support bounded causal use of supplied connected
text memory under its registered roots, baselines, model, and resources. It
does not establish DREAM authorship, experiential learning, parametric memory,
clean-lineage learning, accumulation, lifetime improvement, compression, or
the on-policy flywheel.
