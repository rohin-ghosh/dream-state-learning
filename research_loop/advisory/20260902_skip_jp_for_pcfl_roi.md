# Paper-ROI audit: skip J/P as the PCFL predecessor

## Recommendation

**Skip the J/P Bubblewrap D0 and later four-pair G1 as a prerequisite to
PCFL-Stream.** Reuse their assurance patterns, but direct the next proposed
gate to a PCFL-specific CPU construct gate plus a tiny direct compiled-text
semantic-use canary.

The decisive limitation is explicit in the J/P consensus: minimal D0 and the
four-pair G1 are debugging and spending-decision instruments, not a benchmark,
a learning result, a population estimate, or paper evidence. A green D0 does
not change a PCFL claim-relevant uncertainty. A green G1 only says that a
chosen model can use supplied, gold, finite J/P semantics in a small DEV assay.

## Uncertainty removed by each route

| Paper-critical uncertainty | J/P D0 | Four-pair J/P G1 | PCFL CPU gate + direct-text canary |
|---|---:|---:|---:|
| No hidden shortcut / valid causal construct | toy-only | toy-only | PCFL-specific |
| Target-blind compiler turns life into useful memory | no | no | canary directly tests text treatment |
| Model uses semantic memory for action | no | yes, but curated J/P only | yes, on the actual PCFL interface |
| Old retention / new acquisition / cross-era composition | no | no | construct gate; later scale required |
| Same-corpus text versus LoRA transport | no | no | text stage isolates whether LoRA is worth funding |
| Post-native growth / baseline plateau / capacity frontier | no | no | no, but it is the direct prerequisite |
| Paper-grade splits, causal cuts, resources, statistics | no | no | begins the actual required design work |

J/P therefore removes one peripheral uncertainty--whether a model can use a
deliberately constructed semantic API--while leaving the five central PCFL
requirements untouched: target-blind compilation, lifetime growth,
retention/composition, substrate attribution, and strong baseline/resource
comparisons. The G1 result is nontransferable by its own contract: it has four
pairs, nested observations, no confidence interval or paper claim, and a green
result can only request a successor decision.

## Calendar and opportunity cost

The known cost is already disproportionate to the expected information value.
The ratification request limits the backend to one implementation attempt under
a **ten-working-day / two-calendar-week** outer bound, before a separately
ratified G1. D0 direct compute is negligible and CPU-only (the scientific
worker is bounded below ten seconds warm-cache and 256 MiB), but calendar cost
is dominated by roughly 2.1k statements plus Bubblewrap staging, two-stage
freeze, full TCB binding, dual monitors, and conformance evidence. G1's
model/engineering cost is not bounded, and PCFL would still require its own
material design and authorization afterward.

Thus the route consumes a known minimum two-week detour and introduces multiple
sequential authority and engineering gates without creating paper-eligible
evidence. The PCFL gate also has nontrivial cost and requires a new scope, but
unlike J/P it resolves the construct and semantic-use risks that determine
whether the eventual paper experiment is worth funding.

## Minimal PCFL transition

1. Resolve the PCFL proposal's blocking design gaps into a ratifiable
   construct-only scope: sealed total target allocation, descendant-level
   visibility/reset contract, depth/headroom and decisive-cut certificates,
   exact public sufficient-statistic controller, fixed source policy, and
   failure denominators.
2. Conduct a small, disjoint calibration-only **direct compiled-text** canary
   on PCFL--not LoRA, not scaling, and not confirmation. It must use a
   target-blind frozen corpus, bounded resolver/action budget, a genuine
   decisive memory cut, authentic/twin substitution, and retained assigned
   failures.
3. Stop if the typed controller fails construct validity or compiled text lacks
   directional causal action value. Revise or abandon PCFL before adapter/GPU
   expense.
4. If text passes, seek a fresh same-corpus LoRA transport-sentinel decision;
   do not automatically proceed to a full-scale confirmation experiment.

## Reuse, do not implement as a predecessor

Reuse from J/P:

- Total, rejection-free target generation and exhaustive target-byte twin
  equality.
- Target-only/headroom oracle analysis, typed deterministic controllers at
  value one, and decisive causal cuts.
- Presealed manifests, retained failures, pair-as-replication logic, and
  strict no-automatic-promotion rules.
- The directional criterion that a wrong twin must redirect the decisive plan
  or lose value.

Do not reuse Bubblewrap containment as a PCFL prerequisite. Its consensus
limits its receipt to `BWRAP_CPU_INTERFACE_ISOLATION`, expressly excludes
model-facing and interactive PCFL isolation, and treats it as neither benchmark
nor paper evidence.

## Non-authority note

This advisory is a paper-ROI recommendation only. It authorizes no
implementation, model/provider call, GPU work, network action, experiment,
scientific claim, or promotion. PCFL-Stream remains proposed/awaiting
consensus, and a PCFL construct gate or text canary requires its own exact
human-ratified scope.
