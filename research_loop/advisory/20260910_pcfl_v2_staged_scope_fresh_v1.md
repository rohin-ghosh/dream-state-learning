# PCFL v2 staged scope: reuse the approved symbolic kernel, preserve the full organism

Date: 2026-09-10

Status: **fresh architecture interpretation and ratification candidate only**.
This file is not human ratification. It authorizes no implementation,
benchmark or root generation, model or tokenizer call, adapter/checkpoint or
writer work, GPU use, parenting, evaluation, scientific execution, claim, or
release. Under `AGENTS.md`, models cannot infer authorization from this
recommendation or from agreement.

## Human explanation

The project already built the ruler. Do not spend time building another
ruler before measuring the thing the paper is about.

`feltcraft_symbolic_kernel_v7` already supplies a narrow, deterministic CPU
symbolic reference for overlapping alignment, projection, twin, cost, and
bridge-deletion mathematics. It is not a PCFL benchmark or a learning result,
and its approval expressly forbids promotion into a rendered/model stage.
The failed D0 cross-audit shows that the missing work is PCFL-specific: freeze
the actual deck, visibility chronology, support rules, renderer/tokenizer
cuts, reader/compiler behavior, and claim reducers. A second generic symbolic
or governance kernel would not fill those gaps.

So the smallest honest Stage 0 is the one that already exists. The decision
now should be: retain V7 unchanged as the only CPU symbolic reference, create
no replacement K0/D0 core, and require one later exact PCFL mechanism packet
for the first new implementation.

The full Dream--LoRA--Think ambition remains intact. Staging delays claims; it
does not shrink the scientific question.

## Executive ruling

1. **Do not implement a new generic PCFL contract kernel.** Canonical object
   envelopes, generic phase engines, general provenance frameworks, and new
   governance wrappers would be redundant infrastructure unless a specific
   PCFL package demonstrates that V7 plus existing repository machinery
   cannot enforce a required invariant.
2. **Designate the frozen, already implemented and human-approved
   `feltcraft_symbolic_kernel_v7` subject as Stage 0-SK.** Its authorization
   and scientific limits remain exactly unchanged.
3. **Do not claim that V7 is PCFL.** It covers only overlapping symbolic
   primitives. Its current external scope audit has `passed: false`, and its
   human ratification forbids benchmark, rendered-world, model, DREAM/SLEEP,
   source-life, LoRA, paper-result, and scientific-claim promotion.
4. **Make the first new code a thin, PCFL-specific M0 package, not a platform.**
   M0 remains blocked until its exact finite deck and the D0/v1 semantic
   blockers are frozen in a new hash-bound deliberation.
5. **Keep all model, writer, LoRA, lifetime, codec, parenting, on-policy, and
   confirmation work in later independent packages.** No green CPU receipt
   unlocks a successor.

This is the narrow reconciliation of the v1 consensus with efficient staging:
the combined v1 system is not implementable, but the already approved CPU
symbolic asset should be reused instead of recreated.

### Why V7 cannot yet be imported into a PCFL result

The V7 human approval is real but narrow. The later scope-audit receipt has
`passed: false`: timestamp ordering failed, the requested fresh independent
human semantic source review was not obtained, independence/freshness were
not attested, and no post-review human governance adjudication accepted the
audit. More importantly, V7's own ratified forbidden scope excludes benchmark
and successor promotion.

Therefore V7 eliminates redundant symbolic implementation, but it does not
grandfather scientific eligibility. The future M0 proposal must bind the
exact V7 hashes, state which functions/outputs it consumes, show that no
oracle/golden expectation reaches a candidate, obtain any required scope
extension, and undergo the ordinary independent-review gate. Reuse is a new
edge in the PCFL graph, not an inference from filesystem proximity.

## Retained Dream--LoRA--Think thesis

The target paper still asks whether one clean, parent-deleted agent can turn
its own grounded action--outcome history into useful parametric personal
knowledge. The full architecture remains:

- THINK recurrently retrieves, composes, plans, acts, observes, and revises;
- DREAM manages finite context and proposes target-independent local
  connections from eligible public child experience;
- later independent public evidence, not synthetic restatement, determines
  which proposals become supported;
- SLEEP validates and compiles only supported action--outcome continuations;
- a transactional cumulative life-local LoRA transports, but does not invent,
  those semantics;
- M tests connection, changed-goal traversal, informative expansion, and
  delayed old-plus-new use in fixed-child roots;
- L tests retained improvement across independently raised paired lineages
  against a certified evolving `ACTIVE_TEXT_FIXED` comparator;
- P separately tests whether target-blind parenting changes later learning
  rather than entry competence;
- O separately tests the stronger on-policy action--evidence--consolidation--
  action flywheel that bounded M plus exogenous L cannot identify; and
- C separately tests semantic rate--distortion without calling LoRA physical
  compression below a complete measured byte crossover.

Preserving the ambition means retaining these falsifiable packages and
reporting their failures. It does not mean forcing every organ into Stage 0
or preserving a positive headline after a failed gate.

## M0: the first new implementation package, deliberately not authorized now

M0 is a thin PCFL-specific layer over approved/re-ratified V7 primitives. It
must not reimplement the alignment enumerator, symbolic projections, twin
involution, cost algebra, or bridge-deletion checker unless a later cross-
audit demonstrates a concrete incompatibility and a human ratifies the fork.

M0 has exactly four responsibilities:

1. bind and verify the actual finite PCFL deck and its relation/world
   semantics;
2. implement the PCFL public event, phase, reset/join, reader, and visibility
   contract;
3. implement target-independent proposal/support admission and explicit-text
   carrier compilation; and
4. emit structural root certificates and a non-scientific root-level
   conformance report.

It contains no model, tokenizer invocation, LoRA, writer, child, parent,
lineage, GPU, scientific estimator, or confirmation run. Any tokenizer-
derived constant needed by M0 must be frozen as an input by a separately
authorized preparation packet; M0 may verify it but may not choose it.

### Exact D0 cross-audit blockers before M0 implementation

The 2026-09-01 D0 cross-audit remains controlling negative evidence. All nine
blocking areas must be disposed before M0 code is ratifiable:

1. freeze renderer bytes, tokenizer identity/revision/hashes, BOS/EOS policy,
   complete-event cut vectors, and S-bind bins, or ratify a scientifically
   equivalent tokenizer-free replacement through a new material change;
2. materialize before implementation the exact 64 CPU pairs, accepted
   candidate counters/world ranks, targets, rejection histories, token cuts,
   and reachability certificates, so implementation verifies rather than
   selects the deck;
3. bind the exact runtime/native hashes and either supply the <=65 W resource
   certificate or remove the energy qualifier prospectively;
4. resolve the contradiction between D0 DEV access and the authority contract;
5. bind relation-specific fit, prediction, contradiction, alias, revision,
   cycle, diamond, and evidence-root-dedup support admission with goldens;
6. bind Bayes conditioning on the complete deck construction history, not
   only one visible target slot, including the 103,680-world golden;
7. either expose a target-independent ontology slot for the derived-transform
   anchor or deliberate the new derivation and its causal credit;
8. replace invalid/placeholder canonical goldens with protocol-valid bytes or
   mark them as expected-reject fixtures; and
9. bind the exact 1,000-transition fixture, initial state, actions, pair,
   warm-up, timing boundary, and expected digest.

The same packet must also dispose of the cross-audit consistency repairs:
legal inventory/preparation trajectories, candidate-ID exposure, distinct
memory-only versus matched-state twin certificates, frozen RNG derivation,
nonduplicated deterministic arms, exact resource ledger IDs and counts,
estimator goldens where applicable, comparator surfaces, and claim order.

No PCFL deck or frozen bytes are created by this advisory.

## Later packages

### M-TEXT — explicit-text mechanism ceiling

After M0, M-TEXT must bind exact prompts, chat template, tokenizer, parser,
reader and query agendas, one fixed child, model/provider session boundary,
recurrence-disabled and honest no-memory/raw-context/RAG/native-graph/
organized-memory bypass baselines, and separate noncompensatory endpoints for
recall, transfer, composition, planning, action value/regret, revision,
information selection, realized information, and retention.

The retained ambition selects the stronger DREAM-authorship branch: authentic
links originate as target-independent child/DREAM proposals before later
independent public support; deterministic SLEEP may validate and render, but
not invent, their semantics. Supplied authentic links may be a diagnostic but
cannot inherit the DREAM or connected-experience claim.

M-TEXT is a solvability and engineering ceiling. It is not a LoRA or learning
result.

### G — clean source and terminal descendants

Before any claim-bearing model, writer, M, P, L, C, O, or confirmation run, G
must bind exact `CleanSourceReceipt` and `ExperimentPlan` schemas, the admitted
source and quarantine denials, maximal readable sets, OS/VM/mount/process/file-
descriptor/network/session/provider/cache/RNG/log/timing boundaries, root-
local store ownership, no upstream promotion capability, no-return policy,
partial-result release policy, and residual human/administrator trust.

An upstream-terminal L descendant may retain its own registered local state
across cuts; “terminal” means no return to source/parent, not local amnesia.

### E0 — native writer truth and safety

E0 remains independent and noncompensatory. Its exact later package must bind
native prompt/response rows, response-only mask, cumulative rebuild,
adapter/corpus transaction, previous-child and raw-base comparisons,
wrong-life/binding and adapter-off controls, absorption, free extraction,
forced proposal, action-interface behavior, retention, imprecision/harm,
rollback, failures, margins, units, uncertainty, and independent review.

The contradicted legacy writer cannot be grandfathered into passage. Neither
M0 nor M-TEXT can substitute for E0.

### M-LORA — grounded same-semantics transport

M-LORA requires passing, separately ratified M-TEXT and E0 packages plus G.
It must bind adapter-off, wrong-root/life, binding swap, no-write/sham-write,
read-mask, unaided-LoRA-read, common-reader, recurrence, capacity, and work
factors using the same admitted semantic rows. It may support bounded root-
specific transport only. Same semantics is not fixed bytes or fixed compute;
a fixed-budget efficiency claim requires a separate charged sweep.

### P — target-blind parenting factorial

P binds independently raised `P0`, `P1`, `U0`, and `U1` lineages, identical
certified active text and opportunities, parent deletion, entry score, the
entry-adjusted parenting-by-write interaction, acquisition, delayed retention
and transfer, harm, resources, practical margins, and no descendant-to-parent
return. Entry improvement alone is installed competence, not learning-to-
learn.

### L — exogenous increasing-lifetime use

L binds the certified `ACTIVE_TEXT_FIXED` service, independent paired F/B
lineages, byte-identical exogenous opportunity tapes, isolated local journals,
resource envelopes, prospective plateau equivalence, at least three late
cuts, positive learner slope, positive paired slope advantage, retention,
terminal practical margin, lineages, covariance/uncertainty, multiplicity,
failures, missingness, and stopping. It supports longitudinal use, not the
on-policy flywheel.

PCFL-13/M0 is a finite mechanism deck, not L evidence: its 13 relations fit in
roughly 16.7 bits and can saturate early. Continued-learning language requires
PCFL-Stream-like genuinely growing, nonrepeated information and independent
lineages.

### C — semantic-code rate--distortion

C binds disjoint roots and loads; expanded, normalized-connected, and schema-
residual codecs; deterministic denotation; standalone and amortized schema,
decoder, index, and prompt costs; generator denial or charging; complete live
bytes/work; fidelity, decoder-created false relations, model false memories,
and common-reader utility as separate endpoints; and root-level uncertainty.
Absent a complete charged crossover, C is textual semantic coding, not
physical LoRA compression.

### O — on-policy action--experience flywheel

O exists because bounded M plus exogenous L cannot prove the central feedback
loop. It must show that current memory changes a registered action, the action
changes acquired public evidence, grounded DREAM/SLEEP changes later memory,
and later memory improves a subsequent action. It needs action-policy,
acquisition, no-update, sham-update, counterfactual-opportunity, retention,
harm, resource, and repeated-cycle controls, with independent lineages for
population language.

### Q — sealed confirmation

Every claim-bearing package receives its own Q package. Q binds the complete
unit universe/order, DEV/reserve/confirmation identities, result mask,
release principal and point, exclusions, retries, failure values, stopping,
estimator, margins, uncertainty, multiplicity, missingness, mandatory negative
reporting, claim withdrawal, and allowed post-result decision DAG. Runtime,
output size, missing files, logs, scheduling, and partial receipts are results.

Confirmation cannot change the source, parent, mechanism, writer, benchmark,
baseline, roots/lineages, thresholds, or analysis. Strict human blinding is
claimed only if an independent administrative principal enforces it.

already captures the reusable finite symbolic geometry, while the D0
cross-audit identifies the experiment-specific missing information. The next
useful packet is the repaired M0 freeze, and the next paper-design effort is
