## Verdict

**REVISE FOUR NARROW EXACTNESS EDGES, THEN ADVANCE.**

The addendum repairs the substantive objective and scope failures in the prior
cross-critique. Topology is exact; claim-facing text units now require
`SUPPORTED` status; traversal requires a link-only returned target; compression

Four remaining byte-level defects prevent a full PASS:

1. `ERA_EXPANSION` does not define support/link onset when a provisional record
   becomes supported later or linked endpoints become supported after link

2. The link overlay simultaneously keeps seed documents unchanged and changes
   diagnostic rendering, without defining the actor-visible link bytes, query

3. The shadow outcome/score “semantic bundle” lacks an exact field schema and
   donor-to-recipient mapping, so independent implementations can change

4. The cited power script uses the wrong feasible support for `D`: it clips to
   `[-10/3,10/3]`, while cached identical P and U entry evaluations make the
   exact bound `[-5/3,5/3]`.

None requires a topology or headline redesign. The addendum should be repaired
and rehashed before becoming a v2 deliberation source.

## 1. Topology and claim boundary — PASS

The addendum preserves the user's fixed topology without semantic loopholes:

- one P life contains one reset, frozen, target-blind parent policy and one
  child;
- the U child is an isolated factorial counterfactual, not a peer;
- no parent state survives or accumulates across children;
- service stores, roots, and child state do not cross;
- independent roots draw task/life realizations for one fixed policy pair and
  do not create a population-learning mechanism; and
- R0 deployment parity is accurately distinguished from total-compute,
  childhood-history, equal-content, or carrier parity.

The separate carrier arms and expansion controls are sterile causal clones or
isolated source lives. They do not add a parent, classroom, cohort, peer
exchange, or shared learning store. The addendum wisely uses within-root
twin/binding controls rather than an ambiguous live wrong-child memory edge.

Its LoRA wording is also correct. Even the future carrier panel may claim only
that a parametric carrier trained on authentic connected experiential code
preserved/exposed information that a frozen resolver behaviorally used. It may
not infer a readable graph topology, explicit outcome representation, or
private path inside the adapter.

## 2. Experiential object totality — one remaining onset ambiguity

The repaired hierarchy is scientifically clean:

```text
OWN_OBSERVATION
  -> nonsuperseded EVIDENCE_UNIT
  -> status==SUPPORTED SUPPORTED_UNIT
  -> supported-endpoint AUTHENTIC_LINK
  -> target returned only by one-hop TRAVERSED_LINK(q)
```

This prevents provisional or contradicted records from being counted as
supported knowledge and prevents a target independently retrieved by BM25/BGE
from being credited to a link. `LATER_RETURNED` is availability, not private
use, and the addendum correctly reserves utility for the intervention.

`ERA_EXPANSION(t)` is not yet total. A record may be added as `PROVISIONAL` in
era 1 and become `SUPPORTED` by `REVISE` in era 2. Its “first valid commit” is
era 1, but its first claim-eligible support is era 2. Likewise, a link may be
committed while one endpoint is provisional and become `AUTHENTIC_LINK` only
after a later endpoint revision. Independent reducers can count different
eras.

Bind:

```text
support_onset(key) = earliest immutable commit ordinal after which the sole
                     live record for key first satisfies SUPPORTED_UNIT

authentic_link_onset(source,target) = earliest immutable ordinal after which
                     the directed link exists and both current endpoints
                     satisfy SUPPORTED_UNIT
```

Count a semantic key/link in exactly the era containing its onset. A later
supersession, contradiction, or endpoint loss remains in the lifecycle table
and determines whether the unit is live at cut `t`; it does not move the onset
backward or create a second “new” unit unless a separately named recovery
quantity is defined. This repair keeps expansion descriptive and does not turn
automatic curation into child-directed expansion.

## 3. Link diagnostic — close the actor-byte and interactive-query boundary

The addendum correctly moves corruption after authentic ranking, keeps the
valid store/index immutable, uses a noncommitting adjacency overlay, avoids
probe-score/hidden-solution selection, assigns zero to infeasible probes, and
defines the root statistic `K_link`.

One inconsistency remains. A canonical active-text seed document contains
`linked_memory_ids`. If seed documents are actor-visible and unchanged, they
still advertise the authentic links while the overlay returns different
targets. If diagnostic rendering rewrites those IDs to the deranged targets,
the seed documents are not unchanged. Both implementations satisfy the prose
but present materially different evidence to the actor.

The minimal exact choice is:

1. compute each diagnostic continuation's query from that diagnostic branch's
   own current public objective, metric, last two actions, and latest outcome;
2. rank that query against the immutable authentic index and freeze its fused
   pre-expansion seed identities/ranks;
3. create actor-visible diagnostic copies of seed records whose **only**
   changed field is `linked_memory_ids`, following the overlay;
4. expand from those displayed diagnostic links; keep all target records
   otherwise byte-identical to the authentic store; and
5. account these copies as diagnostic render bytes, never records, index
   replacements, or valid-store commits.

This makes seed identity/rank invariant while making the actor-visible carrier
coherent. It also avoids freezing the intact arm's later query after the two
interactive trajectories diverge. Using the intact arm's call-2-to-call-8
queries in the diagnostic branch would no longer be the registered ordinary
retrieval policy.

The derangement itself also needs these exact bytes:

- lexicographic edge-order key and cycle direction;
- whether the cycle is over edge instances or unique target IDs;
- self-link, duplicate-link, already-linked, missing/superseded-target, and
  multi-edge-source rejection rules;
- the pinned tokenizer and inclusive boundaries for “64-token” length buckets;
- an exact requirement that final packed document cardinality, order class,
  and target-length bucket match, or an explicit failure-to-zero disposition;
  and
- whether all eligible links are overlaid or a prospectively fixed subset.

No root/probe is excluded. `K_link` must remain the mean over all eight probes,
with an infeasible/zero-engagement probe contributing zero as written. The
Holm family plus point-estimate margin then supplies a valid bounded secondary
claim; it does not prove adaptive child-chosen traversal.

## 4. Outcome-binding diagnostic — nearly closed, enumerate the shadow tuple

The addendum repairs the important causal and provenance defects:

- the authentic ledger, event IDs, ordinals, hashes, `REVISION` references,
  and conditioning bytes remain immutable;
- only a shadow admission reducer sees corrupted semantics;
- authentic childhood rows, response targets, slot/rehearsal law, anchors,
  optimizer, clean base, and terminal P1 store remain fixed;
- strata of size one and roots with no changed slot remain in the estimand at
  zero; and
- `K_binding` is explicitly a fixed-history terminal-compilation contrast, not
  an on-policy lifetime, mediation result, or internal outcome representation.

The phrase “complete public outcome+score semantic bundle” is not an exact
object in either source. The shadow must enumerate the donor tuple used by the
admission law—for example the exact outcome class, validity/dispatch state,
score-before integer, score-after integer, derived score delta, and any public
non-inferiority/surprise fields—and state which recipient action-block IDs and
chronology remain fixed. `public_text`, source hashes, event IDs, program IDs,
and raw result bytes must either be explicitly excluded or given a deterministic
shadow projection. The reducer must not independently reinterpret them.

Also name the lexicographic stratum ordering key and one exact cycle rotation.
“Target bytes remain unchanged” should mean that every selected target is an
unmodified authentic response suffix; it cannot mean that the authentic and
shadow **selected target sets** are byte-identical, since changed admission is
the intervention.

These are serialization repairs, not a request for another arm.

## 5. Statistical contract — headline passes; power-support constant must change

The exact `V`, cut order, cached fork entries, gain-AUC, `D`, `W_P`, absolute
P1 improvement, deployment-gain comparison, terminal R0 comparison, fixed
five-rung sequence, ITT failure handling, and fixed `N=32` resolve the earlier
statistics/manuscript conflicts. The sixth local-plateau claim is properly
placed after the five superiority rungs and constructed as an intersection-
union test; bare saturation is forbidden.

The claimed simulation ranges reproduce exactly when the checked script is
run with 300,000 repetitions and seed 20260907:

```text
SD=.10 design alternative: .8695--.9072 joint pass probability
mean=0, SD=.10:          .0014--.0059 joint pass probability
SD=.125 sensitivity:     .7972 minimum
```

However, the script declares:

```text

```

That support is too wide. Because P1/P0 share one cached P entry and U1/U0
share one cached U entry,

```text
W_P = [2(V_P1,16-V_P0,16) + 2(V_P1,32-V_P0,32)
       + (V_P1,48-V_P0,48)] / 6 in [-5/6,5/6]

W_U in [-5/6,5/6]
D = W_P-W_U in [-5/3,5/3].
```

Using the corrected clip changes none of the displayed four-decimal summary
ranges under the current seed, but the source, stdout, and claimed feasible
range must still be correct before hashing. Repair the constants, rerun, and
bind the new source/stdout hashes. This is an exactness blocker, not a power-
adequacy reversal.

The two secondary diagnostics are explicitly precision-gated and form a Holm
family. The later exact statistics manifest should state the one-sided nulls,
Holm ordering/tie rule, p-value calculation, and the conjunction of adjusted
rejection with observed mean at least `.05`; that is a downstream byte freeze,
not another conceptual defect.

## 7. Headline versus carrier versus expansion relay — PASS

The addendum now makes the three scientific objects non-substitutable:

1. **Headline:** one fixed parent policy changes the benefit of later personal
   writes; writes help P1; P1 improves over finite life; the full package gains
   more and ends higher than one certified active-memory R0; R0 may show only a
   registered local plateau.
2. **C/D diagnostics:** the explicit textual layer forms/returns supported
   links, link corruption affects terminal action, and correct outcome binding
   affects a fixed-history terminal writer. These do not establish compression,
   LoRA topology, or online mediation.
3. **Future carrier:** a separate controlled experiment may establish
   parametric transport and behavioral use of own authentic connected code
   under compact/expanded/atoms/derangement/bridge/text/adapter controls. It
   still cannot reveal an internal graph.
4. **Future expansion relay:** prior memory changes an information-seeking
   action, its public outcome is later admitted, and a still-later fresh goal
   benefits under causal shams/cuts/write-off. A terminal fixed carrier cannot
   substitute for this loop.

The carrier and relay require separate workflows, power, resources, and human
ratification and cannot rescue a failed headline. Each source remains an
isolated one-child life. This is the correct, topology-preserving disposition
of the standing Dream--LoRA--Think objective.
