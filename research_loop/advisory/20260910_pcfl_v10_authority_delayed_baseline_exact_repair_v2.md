## 2. External per-member provenance; no self-hashing

### 2.1 Placement law

No candidate source member contains or embeds its own `source_sha256`, its own
`SourceProvenanceRowV1`, or a hash of a container that contains that member.
There is exactly one provenance row for each of the 23
`manifest_member=true` source bytes. The row occurs only as the
`provenance` value in that member's external entry in `MANIFEST_PATH`:

```text
  entries:[{
    logical_path:repo_relative_path,
    role:SourcePlanRow.role,
    media_type:"application/json"|"text/markdown"|"text/x-python",
    nbytes:u64,
    sha256:hex64,

  }, ...]

```

`entries` equals every and only the 23 true-member plan rows in identical
bytewise path order. `entries[i].logical_path`, role, and media type equal its
plan row; `nbytes` is at most that row's maximum; `sha256` rehashes the member;
and `provenance.logical_path` and `provenance.source_sha256` equal the enclosing
entry's path and hash. The manifest has no entry or provenance row for itself,
contains no field for its own hash, and is not a manifest member. Its external
SHA-256 is computed only after all entries close.

The construction order is exact and acyclic:

```text

  -> member nbytes and SHA-256
  -> external SourceProvenanceRowV1[C10]
  -> external manifest entry
  -> closed MANIFEST_PATH bytes
  -> external manifest SHA-256
```

that is itself a true manifest member, a row for `MANIFEST_PATH`, a duplicate or
missing row, or a manifest hash embedded in the manifest rejects before byte
review.

## 4. Delayed baseline resource equality and causal accounting

V1's delayed public-event basis, allowlisted pointers, first-visible origins,
and dynamic descendants remain exact. The phrase “unchanged resource charges”
is replaced by the following narrower law.

### 4.1 Fields that remain twin-equal

For fixed `k`, condition, phase, mode, and authorized schedule, both h twins
retain identical:

- registered slot count, maximum input allowance, registered generation
  allowance, read opportunities, world-action opportunities, and terminal
  opportunities;
- static row/document/atom/link counts, schemas, orders, stable handles,
  padding lengths, stored byte counts, stored tokenizer counts, and planned
  build/query operation counts;
- common preprocessing entitlement and standalone/physical allocation law; and
- before the first entitled model-visible origin, all deterministic emitted
  request/return bytes and token counts, call-status counters, read/query/result
  counters, action/terminal counters, and installed artifact byte counts for
  forced-equal histories.

Content digests at the V1 allowlisted h-specific leaves may differ and are not
required equal. Measured CPU nanoseconds, latency, wall span, GPU active time,
and peak memory are independently metered and hidden; their numerical equality
is not a semantic invariant. Before the first origin they may not alter any
request, return, ordering, padding, cache/session key, error, action, or other
actor/model-visible byte.

### 4.2 Static and common charging

RAW/native static content is stored once in its arm's static representation and
is charged again in `input_static_context_tokens` for every emitted request
that contains it. RAG charges its document storage, index construction, cache
warmup, query, candidate/postings work, returned document bytes/tokens, and the
reader-return tokens in every causally subsequent emitted model request.
Common-reader work charges each invocation and complete found/null/blocked
envelope.

Common preprocessing is recorded once physically in `__COMMON__` and included
in every arm's standalone accounting. Standalone CAS storage is the full
reachable digest closure for that arm; suite-physical storage is the digest
union counted once. No fractional allocation, observed-performance allocation,
or allocation to a different arm is allowed.

### 4.3 Allowed post-origin resource descendants

After an allowed RAW/native static span or entitled RAG `d20`/`d22` document
event first becomes model-visible, the response, parsed command, public
transition/outcome, later legal query/read, terminal, and request suffix may
causally diverge under V1 section 3. Consequently these actual—not registered—
quantities may differ across twins when and only when their complete causal
parent chain reaches that allowed origin:

```text
slots_request_emitted
slots_not_reached
offered_generation_allowance
reader/query/return counters
calls_attempted/completed/failed
input-token segments and generated tokens
world-action and terminal counters
CPU, latency, wall, GPU, and peak-memory meters
request/response/tool/trace/receipt/log/temporary artifact bytes
```

Every such value remains charged to its originating root, condition, phase,
arm, and physical device. Every subsequent request containing static context or
a reader return carries those input-token charges. No actual counter, time, or
artifact may be erased, reallocated to the delayed content itself, amortized to
another arm, or used as actor/model feedback. The registered opportunity and
static laws in sections 4.1–4.2 remain equal even after origin.

A post-origin difference without the allowed causal parent, an unmetered
descendant, hidden retry/background call, static-token omission, RAG-work
omission, common-work reallocation, or CAS allocation drift is `INVALID`, not a
behavioral zero.
