# One-parent/one-child objective-coverage audit v1

Date: 2026-09-07

Status: **independent read-only scientific-scope audit**. This artifact changes
no bound plan, contract, manuscript, workflow, model, tokenizer, benchmark,
adapter, or run state. It authorizes no implementation, generation, fit, GPU,

## Audited objective and sources

The standing objective asks whether a Dream--LoRA--Think agent can:

1. turn its own action--outcome experience into connected/compressed
   experiential knowledge;
2. traverse and expand that knowledge under goals;
3. improve later actions across increasing lifetimes; and
4. outperform strong agent-memory baselines where those baselines saturate.

This audit treats the user's later topology ruling as fixed: exactly one reset,
state-isolated parent and one child per parented life, with no classroom,
cohort, peer, population, multi-parent, cross-child-memory, or shared-learning
mechanism. Independent roots are statistical replications, not interacting
children.

## Verdict

**PARTIAL COVERAGE: KEEP THE HEADLINE, BUT DO NOT EQUATE IT WITH THE FULL
STANDING OBJECTIVE.**

The current candidate is scientifically coherent for the narrower headline:
one process-only parent teaches one child, disappears, and the registered
factorial tests whether parenting increases the later benefit of the child's
own deployment-time parametric writes. It cleanly supports a finite
parent-absent learning-curve experiment against one prospectively certified
active-text mechanism.

It does **not** presently operationalize connected/compressed parametric
knowledge or agent-directed traversal/expansion. It also does not require the
full system to have greater absolute terminal value than the public strong
memory reference at that reference's own plateau. The plan's `C_public` is a
difference in deployment gain from each system's entry, not an absolute
outperformance estimand. These are scientific-object gaps, not missing prose.

Accordingly:

- the one-parent/one-child headline may advance as a bounded parenting and
  per-life-write experiment;
- the current bytes cannot release the full connected/compressed/traversal or
  “outperforms a saturated strong memory baseline” wording; and
- the smallest resource-preserving repair is to add exact zero-call endpoint
  definitions and replace, rather than accompany, the optional descriptive
  LEAFE-style terminal comparator with two compact terminal diagnostics.

## Topology audit

The topology is not the problem.

- Each P life has one frozen-policy parent and one child.
- Parent state, advice, nursery state, and caches are deleted before
  deployment.
- The U branch is a sealed causal counterfactual and never exchanges state
  with P.
- `P0/P1/U0/U1/R0` are isolated services; their stores do not communicate.
- Repeated roots are independent replications of one-to-one lives, not a
  classroom or population-learning mechanism.

For manuscript clarity, “the same parent” should mean the same stateless,
reset frozen parent policy instantiated independently in every P root. It must
not mean one stateful parent serially learning across children. This is a
wording clarification, not a new arm or mechanism.

## Exact scientific gaps

### 1. The LoRA writer is outcome-gated behavioral self-distillation, not an explicit knowledge compiler

The plan calls the selected target an exact pre-outcome child continuation.
Public outcomes decide eligibility, but the durable LoRA target is not a
closed proposition, evidence relation, link, or compressed code. The only
explicit connected semantic object is produced by `ACTIVE_TEXT_FIXED`, which
is common to `R0/U0/U1/P0/P1` and is not the SLEEP writer.

Therefore a positive `P1-P0` supports:

> enabling repeated outcome-gated writes of the child's own native
> continuations added bounded closed-loop value on top of active text.

It does not by itself support:

> the LoRA contains connected/compressed experiential knowledge.

Adapter-off shows that parameters matter. It cannot identify what relational
structure those parameters contain. A same-corpus carrier test can compare
interfaces, but it also cannot reveal a human-interpretable graph in weights.

### 2. Connection, compression, traversal, and expansion are four different assays

The current plan partially collapses them into the existence of a linked
playbook and a one-hop retriever. That is insufficient:

- **connection** requires authentic binding to beat a marginal-matched false
  binding on later action;
- **compression** requires an exact denotation, an expanded equivalent, full
  code accounting, and a predeclared rate/non-loss rule;
- **traversal** requires a relevant link target to be made available before
  the scored action and a causal loss when authentic traversal is corrupted;
- **expansion** requires prospectively new supported units over lifetime and
  later use of those units, not merely more updater output.

These must be reported separately. Success on one must not release the
others.

### 3. The lifetime curve does not yet require literal improvement by `P1`

`C_active=gAUC(P1)-gAUC(P0)>0` is an incremental write benefit. It can pass if
`P0` deteriorates while `P1` stays flat. `D>0` can pass even if both write-on
cells worsen, provided the parenting contrast is less bad. Those are valid
relative causal effects, but they do not satisfy “improves later actions
across increasing lifetimes.”

The ordinary learning claim additionally needs an absolute `P1` change gate
on the already collected probe values. Continued improvement needs a late-era
gate; a positive average curve alone is not continued improvement.

### 4. The public contrast is gain superiority, not value superiority

The plan defines
`C_public=gAUC(P1)-gAUC(R0)`. Because both curves are entry-normalized, P1 may
pass `C_public` while remaining below R0 at every cut. The claim ladder
correctly calls this “greater deployment gain,” but readiness and the standing
objective use “beats/outperforms.” Those phrases require an absolute terminal
or absolute value-AUC contrast.

The existing plateau test names `P0+ACTIVE_TEXT_FIXED`, not public `R0`. `P0`
is the right parent-matched memory-only comparator for the causal LoRA
increment; `R0` is the right public full-system comparator. A result may name
only the comparator whose own strength, local plateau, and absolute
outperformance gates all pass.

### 5. Several manuscript endpoints are labels without plan-level reducers

`main.tex` promises early learning slope, forward transfer, backward
retention, forgetting, proposal quality, and routing assays. The plan has
enough raw checkpoints for a fixed-panel transfer curve, but it does not bind
the reducers, failure values, margins, or multiplicity for those named
quantities. The same eight sealed programs at every cut measure change on a
fixed held-out panel; they are not automatically both a forward-transfer and
an old-task backward-retention panel.

The manuscript is otherwise commendably narrower than the standing objective:
it does not currently claim connected/compressed knowledge or goal-directed
traversal. The mismatch is that the paper omits those objective components,
not that its present result placeholders already overclaim them.

## Smallest decisive additions within the declared resource scale

### A. Add zero-generation endpoint and ontology definitions

These additions use values, stores, ledgers, and receipts already produced by
the five services.

1. **Absolute learning.** Define per root

   ```text
   L_terminal,r = V_P1,r(48) - V_P1,r(0)
   S_early,r     = [V_P1,r(16) - V_P1,r(0)] / 16
   S_late,r      = [V_P1,r(48) - V_P1,r(32)] / 16
   ```

   “Improves later actions” requires a positive two-sided 95% root-level
   interval and the frozen practical margin for `L_terminal`, in addition to
   the existing causal contrast and no-routing/proposal erasure. “Continues
   improving late in life” additionally requires a positive one-sided 95%
   lower bound for `S_late`. Do not require monotonicity at every noisy cut.

2. **Absolute baseline outperformance.** For each comparator intended for a
   claim, predeclare

   ```text
   T_B,r = V_P1,r(48) - V_B,r(48),  B in {P0,R0}.
   ```

   An outperformance sentence requires a positive multiplicity-controlled
   root-level interval and point estimate at least `0.05` for `T_B`. Preserve
   `C_active` and `C_public`; `T_B` answers a different question and does not
   replace the registered hierarchy.

3. **Comparator-specific local plateau.** Apply the existing two-increment
   equivalence rule separately and prospectively to each named `B`, using the
   same probes and search-headroom reference. Release “P1 outperformed B at a
   registered local plateau” only when B's own plateau passes, `T_B` passes,
   P1's late increment is positive, and the P1-minus-B late-increment contrast
   passes. Never select P0 or R0 after seeing which one passes. Keep the
   qualifiers “local,” “conditional,” “48-program,” and “registered
   read/update budget.”

4. **Experiential ontology.** On live scientific artifacts define:

   - an `OWN_OBSERVATION` as one same-service action/outcome block created by a
     dispatched non-probe child action;
   - a `SUPPORTED_UNIT` as one nonsuperseded live record supported under the
     exact contract by own observations that all precede the scored query;
   - an `AUTHENTIC_LINK` as one directed link between live units whose endpoint
     evidence and link commit precede the query;
   - a `TRAVERSED_LINK` as an authentic seed-to-target link for which both
     complete documents were actually returned before the scored action; and
   - `EXPANSION(t)` as the root-level counts of distinct supported semantic
     keys, cross-program units, authentic links, and later-used units at each
     registered cut.

   Counts are failure-inclusive diagnostics. No minimum-yield root may be
   excluded or replaced. A positive count is not itself a behavioral claim.

5. **Compression denominator.** Deterministically construct and hash an
   `EXPANDED_EQUIVALENT` for every live compact record set: all observation-
   level proposition/guidance instances needed to reproduce the same current
   typed denotation, status, scope, links, and provenance. Verify exact
   reducer equality. Count UTF-8 bytes and pinned-child tokens for the compact
   and expanded carriers after charging schemas, dictionaries, IDs,
   provenance, link tables, indices, renderer, and any expansion machinery.
   The raw append-only ledger is reported separately and may not disappear
   from complete-system storage accounting.

   Freeze the rate margin before live records exist. A scientifically useful
   candidate is a compact code no greater than one half of the expanded-
   equivalent tokens and no greater than 35% of the eligible raw-ledger tokens,
   with a root-level upper confidence bound below each threshold. A passing
   size ratio supports only “shorter actor-facing semantic code” unless
   functional non-loss is also demonstrated. Fixed LoRA allocation,
   raw-ledger fraction, or a 256-token record cap alone is not a compression
   result.

6. **Manuscript reducer closure.** Either bind exact forward/retention/
   forgetting/proposal reducers and margins, or rename the repeated eight-
   program result as a fixed held-out transfer panel and delete unsupported
   backward-retention language. Define routing failure as the registered
   missing-action value, never as missing data.

### B. Replace the optional LEAFE-style terminal comparator with two diagnostics

Do not run both packages under the present resource claim. Reallocation keeps
the optional ceiling at one extra fit/root and stays below its generated-token
allowance.

Both diagnostics must be specified before scientific identities are opened,
but may execute only after the headline root count and primary artifacts are
immutable. They cannot affect root count, root eligibility, `D`, `C_active`,
or `C_public`. They are claim-eligible only if their predeclared interval and
practical-margin rules achieve adequate precision on the already locked root
count; no extra root may rescue them.

1. **`P1_LINK_DERANGED_READ` (no fit).** Clone the frozen terminal P1
   checkpoint and read-only terminal active-text store before probes. Keep the
   fused seed ranks, live record inventory, every non-link record field,
   document/token cap, link count, in/out degree, endpoint memory type, scope
   level, status, retrieval cadence, and per-query returned one-hop document
   count/token-length bucket fixed while applying a presealed no-fixed-point
   link derangement. Recompute canonical bytes, hashes, and index receipts in
   the diagnostic clone only; the corrupted clone does not pass through or
   mutate the valid live-store commit path. The map is fixed before probe
   outputs and never returns to life. Replay the same eight terminal probes
   under common RNG and the same failure values. If no exact matched
   derangement exists, retain the root with the predeclared diagnostic failure
   value rather than selecting another link or root.

   Credit functional connection/goal-conditioned one-hop traversal only if
   intact P1 beats this marginal-matched derangement by the frozen practical
   margin and a root-level interval, the intact receipt shows the authentic
   target was returned before action, and routing/proposal quality is not
   worse. Roots with no usable authentic link remain in the estimate at their
   observed/failure outcome. This result belongs to the explicit active-text
   layer, not to an inferred graph inside LoRA.

2. **`P1_FIXED_HISTORY_ACTION_OUTCOME_DERANGED_WRITE` (one clean-base terminal
   fit).** Before any probe, take the already sealed authentic P1 deployment
   source history and deterministically permute each complete public
   outcome+score bundle across different action blocks within root, era, and
   normalized action family, with no fixed points. This preserves the exact
   outcome/score multiset in every stratum but does not condition the
   permutation on the original validity or score-effect bin, which would make
   the corruption inert. Re-run the unchanged absolute writer law, slot order,
   rehearsal filling, four-exposure loss, childhood rows, anchors, optimizer,
   and transactional gates as one clean-base terminal rebuild, then replay the
   same eight terminal probes. If an exact derangement is impossible, the root
   is retained with the predeclared diagnostic failure value.

   Intact P1 superiority supports that correct personal action--outcome
   binding matters to terminal compilation on the fixed authentic P1 history.
   Because the history was generated by the intact online system, this is a
   fixed-history writer diagnostic, not a second on-policy lifetime and not an
   estimate of the entire online mediated effect. It does not establish
   connectedness or compression.

The two added terminal replays cost at most:

```text
2 diagnostic services * 8 probes * 8 calls/probe = 128 calls/root
2 * 8 * 1,024 = 16,384 generated output tokens/root
1 clean-base terminal fit/root
```

The currently optional `LEAFE_STYLE_FINAL` allowance is 160 calls, 45,056
generated output tokens, and one fit/root. Replacing it with these diagnostics
therefore reduces optional calls and output tokens and leaves the fit ceiling
unchanged. The deterministic ontology/compression reducers add no model call,
tokenizer call, adapter fit, or GPU work. Token lengths remain gated later by
the already required separately authorized tokenizer receipt; this advisory
does not perform them.

## Maximum claim after the minimal additions

If the headline causal gates and the added absolute gates pass, the paper may
say:

> In independent one-parent/one-child lives, a reset frozen process-only
> parent improved the benefit of the parent-absent child's later personal
> writes; the resulting system improved over its own finite deployment and
> exceeded a prospectively certified active-text reference at that reference's
> registered local plateau.

If the live typed-store rate audit and link-derangement assay also pass, it may
add, separately:

> The complete agent converted its own public action--outcome stream into a
> shorter connected actor-facing textual code, and authentic goal-conditioned
> one-hop bindings improved terminal action relative to a matched
> derangement.

It still may **not** say that the LoRA itself contains a connected graph, that
the child adaptively traversed a graph, that the full retained life was
compressed, that automatic curation was child-directed expansion, or that it
beat multiple named memory methods.

## What cannot be repaired cheaply

If the intended claim is specifically **connected/compressed knowledge inside
the per-life LoRA**, the smallest valid experiment remains a separate sealed
carrier panel with, at minimum, compact linked, denotationally equivalent
expanded linked, atoms-only, marginal/degree-preserving binding derangement,
and leave-one-necessary-bridge-out carriers, plus same-corpus text and
adapter-off diagnostics under one frozen resolver and byte-identical decision
supervision. That panel requires additional fits, a controlled compositional
instrument, its own power calculation, and full code accounting. It cannot be
inferred from CompilerGym behavior or squeezed into the current resource
manifest by relabeling existing diagnostics.

Likewise, “strong agent-memory baselines” in the plural requires prospectively
implemented additional methods. The current plan supports one bespoke,
strong-certified functional active-text comparator. Singular wording is the
resource-honest choice.

## Disposition

**REVISE THE OBJECTIVE MAP BEFORE EXACT RATIFICATION; DO NOT CHANGE THE
ONE-PARENT/ONE-CHILD HEADLINE.** The necessary change is small in runtime but
material in scientific contract: bind the absolute learning/outperformance
reducers, define the live experiential ontology and complete compression
denominator, specify the two replacement terminal diagnostics, and align the
paper's transfer/retention and singular-baseline language. Because those
changes alter endpoints, diagnostics, resource allocation, and released
claims, they require the architecture-deliberation and exact human-ratification
path in `AGENTS.md` before implementation.

Without those additions, the honest paper is the narrower parenting-by-write
paper. That paper can still be valuable; it simply does not complete the full
standing connected/compressed/traversal/saturation objective.
