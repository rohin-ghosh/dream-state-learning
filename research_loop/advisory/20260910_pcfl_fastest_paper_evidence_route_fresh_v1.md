# PCFL fastest paper-evidence route: fresh skeptical strategy v1

Date: 2026-09-10

Status: **fresh source-only experiment-strategy advisory**. This file is not
an architecture decision or human ratification. It authorizes no
implementation, fixture/root/data generation, CPU scientific execution,
model/tokenizer/provider call, adapter/writer/training operation, GPU use,
claim, promotion, release, or manuscript result. Every material successor is
subject to the complete deliberation, exact-byte ratification,
implementation/review, and scientific/GPU gates in `AGENTS.md`.

## Decision

The fastest valid immediate package is a **manifest-first, thin PCFL M0
fixture/kernel overlay**. Do not build another generic CPU contract core, and
do not jump directly to M-TEXT or E0 execution.

Use the exact finite choices already proposed in
`20260910_pcfl_v2_minimal_exact_semantics_fresh_v1.md` as the candidate PCFL
fixture specification, but implement only PCFL-specific deck, state/view,
visibility, intervention, provenance, scorer, and reducer behavior. Reuse or
cross-check the overlapping FeltCraft V7 mathematics only through a newly
ratified, hash-bound reuse edge. V7's present approval forbids successor
promotion and its scope audit did not pass, so filesystem availability is not
authority to import it.

This is the shortest route to the first paper-facing question:

```text
exact M0 manifest -> thin CPU M0 conformance -> M-TEXT DEV engineering gate
                                           \-> E0 exact writer gate (independent)

M-TEXT pass + E0 pass + clean guard -> M-LORA same-semantics relay
                                    -> bounded M result
                                    -> L only after baseline certification
```

M0 is specification/software work, not paper evidence. M-TEXT and E0 are the
first paper-facing empirical gates. They are independent prerequisites and
must not borrow passage from one another.

## Why the alternatives lose time or validity

| candidate next package | disposition | reason |
|---|---|---|
| New generic CPU core | **Reject** | FeltCraft V7 already supplies the reusable algebra/twin/bridge reference. Another envelope/provenance platform spends the deadline without answering a PCFL-specific uncertainty. |
| Thin M0 fixture/kernel overlay | **Choose now** | It closes the exact deck, visibility, intervention, shortcut, and reducer uncertainties that make every model result otherwise uninterpretable. It is bounded and CPU-only. |
| M-TEXT immediately | **Not yet** | Without frozen M0 bytes, a failure could be world, renderer, visibility, reader, or model; a success could use a shortcut. Run it immediately after M0 conformance. |
| E0 writer as the sole next route | **Prepare in parallel; do not substitute** | E0 is noncompensatory and urgent, but a passing generic writer does not show that PCFL is solvable or connected. It cannot remove the M0/M-TEXT critical path. |
| L, parenting, scaled THINK, C, or CompilerGym | **Defer** | They have longer paths, missing prerequisites, weaker headline value per day, or consumed/development-only identities. None can rescue an unproved PCFL relay or writer. |

## Immediate package: `M0-THIN`

The next deliberation should ratify exact bytes, not authorize an open-ended
implementation. It should contain:

1. The complete materialized 64-root fixture manifest, canonical bytes,
   digests, expected-reject fixtures, transition table, carrier variants,
   phase views, resets, join, uncertainty posteriors, and root outcome vectors.
2. The paired-world visible-prefix law, public-taint rule, actor capability
   boundary, explicit command/query agendas, repeat/retry state, and exact
   `GOALS_COMPLETE` projection.
3. Chronological provenance, root deduplication, synthetic non-evidence,
   aliases, diamonds, cycles, contradiction/revocation, and descendant-denial
   semantics.
4. Separate path, answer, shortcut, information-choice, realized-information,
   acquisition, delayed-old-plus-new, retention, and failure fields. A bundled
   relay bit is insufficient.
5. Exact atoms/null/authentic/deranged/bridge/twin/sham/reachout/old-cut/new-cut
   transforms and tests proving each changes only its named target.
6. A root reducer that fixes `N` at environment roots and retains every
   adverse terminal without retry, replacement, or conditional omission.
7. The exact V7 reuse edge: approved file hashes/functions, direction of data
   flow, oracle/golden denial from actor-visible state, and the required scope
   extension or independent human disposition of the failed audit.
8. Two independent materializer/checker identities. Implementation may verify
   the frozen deck; it may not search, rank, select, or repair roots.

`M0-THIN` must contain no model, tokenizer, chat template, provider, child,
LoRA, writer, parent, baseline, scientific estimator, GPU, clean-source
security claim, journal/CAS, L, or C machinery. Those are distinct packages.
Its successful receipt means only that the PCFL instrument is structurally
identified.

The minimal-semantics advisory is useful because it already removes much of
the old D0 choice surface: fixed finite symbols and roots, explicit actor
views and commands, a fixed chronology, balanced uncertainty, conservative
public-evidence DREAM, exact interventions, and an exhaustive reducer. The
efficient move is to cross-critique and materialize those choices, not reopen
a generator search or revive the unratifiable D0 bundle.

## First paper-facing gate: M-TEXT

After M0 passes its independent implementation review, M-TEXT should be the
first model-facing DEV gate. It is cheaper and more diagnostic than training a
LoRA on a relay that may not be behaviorally solvable.

M-TEXT must freeze model/provider/session identity, tokenizer/chat bytes,
rendered prompts, parser, reader/query agendas, context and generated-token
envelopes, DEV/reserve identities, and failure values before the first model
call. Its minimum comparison is:

- explicit authentic connected text;
- same atoms without asserted links;
- truthful null and deranged links;
- bridge cut, twin redirect, reachout off, uncertainty sham, and old/new cut;
- recurrence disabled; and
- honest raw-context, ordinary RAG, native graph, and organized-memory bypass
  ceilings under declared resource factors.

Recall, composition, goal-path switching, planning, action value, revision,
experiment choice, realized information, acquisition, delayed old-plus-new
use, and retention are noncompensatory endpoints. The deterministic CPU
scripts prove instrument solvability, not model solvability. Model traces must
show prospective constructive dependence rather than post-hoc answer
reconstruction.

Use a very small DEV smoke subset first for parser/headroom/obvious-shortcut
falsification. Expand only if those pass. Any model feedback consumes those
root identities and renderer/prompt version. M-TEXT remains an engineering
ceiling until a separate sealed confirmation package exists.

If M-TEXT fails with adequate headroom, stop PCFL LoRA dispatch and repair only
on declared DEV identities. E0 may still proceed as an independent writer
program, but M-LORA is not interpretable until explicit text works.

## E0 timing

Draft and deliberate the exact E0 package in parallel with M0 because E0 is
the other critical-path prerequisite. Do not wait for M-TEXT to begin its
specification, CPU mask/provenance/transaction tests, or independent review.

If only one scarce model/GPU queue is available after M0, run the bounded
M-TEXT smoke first: it uses inference rather than adapter training and most
quickly detects an unsolvable or shortcut-ridden relay. With parallel capacity,
M-TEXT DEV and the separately ratified E0 assay may run concurrently because
their units, artifacts, and decisions are independent.

E0 must name one writer version. Legacy R2/RP/R3/R4 lives cannot certify it.
The exact response-only mask, immutable-birth cumulative rebuild, committed-
corpus rule, candidate adapter/corpus transaction, previous-child and raw-base
comparisons, wrong-life/binding and adapter-off controls, absorption, free
extraction, forced proposal, action-interface behavior, retention, rollback,
harm/imprecision margins, and rejected-derivative quarantine must all be
bound prospectively on disjoint panels.

A passing E0 without M-TEXT supports only a writer result. A passing M-TEXT
without E0 supports an explicit-text mechanism ceiling or transport-boundary
story. Only both passing, plus the clean-source/terminal-descendant guard,
authorize consideration of M-LORA.

## Clean guard and confirmation boundary

The clean guard `G` is not folded into M0. Its exact authority substrate,
source receipt, readable-set boundary, root-local stores, provider/session
limits, no-upstream-promotion capability, partial-result release policy, and
residual human/administrator trust must be ratified before claim-bearing
writer/model execution. A DEV M-TEXT smoke may use explicitly consumed
development roots under a narrowed local boundary; it cannot become
confirmation evidence afterward.

CPU enumeration of every root does not itself consume model confirmation
identities, but any model output, human inspection, threshold change, prompt
change, scheduling decision, or favorable-root selection does. Reserve and
confirmation identities and the permitted post-result decision DAG must be
fixed before partial model results are visible.

## Information-per-resource sequence

1. **M0 exact manifest and adversarial review:** no GPU; eliminates semantic,
   visibility, join, uncertainty, and reducer ambiguity.
2. **Thin M0 implementation/conformance:** no model/GPU; failure is cheap and
   localizes to the instrument.
3. **M-TEXT smoke on consumed DEV roots:** lowest-cost model falsifier of
   headroom, parser, recurrence, and shortcut behavior.
4. **Full M-TEXT DEV gate:** only after smoke passage; establishes the explicit
   text ceiling and chooses no confirmation result.
5. **E0:** specified in parallel, executed independently; if GPU is scarce,
   dispatch after the M-TEXT smoke, not after a full paper-scale M-TEXT sweep.
6. **M-LORA DEV:** only after M-TEXT, E0, and G; same admitted semantics with
   adapter-off/wrong-life/binding/no-write/read-mask/common-reader controls.
7. **Sealed bounded M confirmation:** the fastest plausible main-paper causal
   result.
8. **L:** only after the writer and active-text baseline are certified and a
   one-lineage end-to-end canary closes the cost/variance envelope.

Parenting `P` can remain a separate developmental factorial, but it should not
delay M. `C` is ancillary text-interface coding unless a charged crossover is
real. `O` preserves the full on-policy flywheel target but follows bounded M;
M plus exogenous L cannot substitute for it. Scaled THINK remains a mechanism
sibling and should stay out unless it independently clears its gates before
the scientific child is frozen.

## Stop, pivot, and paper consequences

- M0 failure: no model spend; repair only the frozen DEV specification.
- M-TEXT headroom/solvability failure: no PCFL LoRA inference; normally no
  connected-memory paper until repaired on DEV plus a new reserve.
- M-TEXT pass, E0 fail: explicit-text ceiling plus writer safety/transport
  failure; remove positive personal-LoRA language.
- E0 pass, M-TEXT fail: native personal-write result only; no connected relay.
- M-TEXT and E0 pass, M-LORA fail: transport-boundary paper.
- Bounded M passes: viable mechanism-relay paper even if L misses the
  deadline; report fixed-child/environment-root scope.
- L passes every noncompensatory plateau, slope, retention, and terminal gate:
  add the lifetime claim. No result-selected plateau or inherited M/P sample
  size is allowed.

This sequence preserves the full end goal while making the deadline robust:
the first publishable target is bounded M, not the most expensive lifetime
claim. L, P, O, and C remain explicit later falsifiers rather than being
silently deleted or prematurely bundled.

## Final recommendation

Ratify and materialize `M0-THIN` next. It should be a PCFL fixture/verifier
overlay over an explicitly approved V7 reference edge, not a replacement
symbolic platform. In parallel, prepare E0's exact independent package. After
M0 conformance, spend the first model budget on a tiny M-TEXT DEV smoke, then
run M-TEXT and E0 as independent gates. Do not spend on M-LORA, L, parenting,
scaled THINK, or a new CPU platform until their actual prerequisites pass.

That route maximizes information per day and GPU-hour because each expensive
failure has already been separated from cheaper benchmark, visibility,
solvability, writer, and contamination failures. It retains the complete
Dream--LoRA--Think goal through explicit downstream packages rather than
pretending the first CPU layer proves the organism.
