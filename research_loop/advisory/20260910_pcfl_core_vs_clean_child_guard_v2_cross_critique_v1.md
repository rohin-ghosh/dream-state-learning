## Verdict

Clean-child v2 has the right enforcement insight—accepted outputs inherit the
whole capability-limited readable set, not a worker-declared input list—but it
is substantially overbuilt for the PCFL M/L/C paper. It specifies an adaptive
classroom, canonical parent, developmental-exam declassifier, universal
state-slot authority, remote-parent broker, CompilerGym final service, and
cross-experiment partition ledger. M/L/C instead use one fixed parent-deleted
source child and isolated experimental descendants; no M/L/C output needs a
transition back into that source.

The smallest paper boundary is therefore:

```text
authenticated frozen CleanSourceReceipt
        -> preflight(exact plan, purpose, split)
        -> role-separated OS launch
             trusted controller sees private root/seed/intervention
             actor/compiler sees only its finite public view
        -> isolated M, L-F, L-B, or C descendant root
        -> terminal receipt + reducer/report
        X no clean-source promotion API
```

Keep a stronger blinded confirmation batch as a thin shell when confirmation
claims require it. Do not make that shell part of the pure PCFL kernel or claim
that ordinary hashes provide human blinding.

## Contamination channels both notes must close more explicitly

### 1. Private grant leakage into the actor

Mount isolation is insufficient if a granted blob contains both public and
private fields. The actor must not see root certificate, generator seed, split,
oracle state, future goal, intervention name, sibling outcome, correct answer,
or target annotation. The controller constructs `visible_view` and passes only
its canonical public bytes. Environment variables, argv, filenames, working
directory, log headers, exception text, and timing must not reveal private grant
fields.

### 2. Shared state across roots and arms

Separate directories do not exclude a shared model server, provider session,
KV/prompt cache, compiler cache, RNG service, temp directory, shared memory,
open file descriptor, process, device cache, telemetry sink, or mutable package
cache. Each M root and C root, and the L `F` and `B` branches, needs a separate
process/session, RNG stream, scratch store, logs, corpus/memory head, and cache
namespace. Read-only code/model blobs may be shared only by exact hash. A remote
provider session must be fresh per registered unit; if provider-side isolation
cannot be established, the claim states that limitation.

### 3. TEST_ONLY and certificate-counterexample laundering

Synthetic fixtures, malformed roots, rejected generator versions, failed
certificates, intervention-development examples, and reducer adversaries must
carry a terminal `TEST_ONLY` or rejected receipt. No path copy, reserialization,
or successful later parse can admit them to DEV/CONFIRMATION. A systematic
certificate counterexample makes the generator version `NO_GO`; silently
discarding only that root is selection feedback.

### 4. Partial confirmation feedback

Per-root results, failures, output size, runtime, retries, filenames, telemetry,
and a unit being scheduled can change later units or analysis. A confirmation
plan must bind the complete unit set, order/randomization law, exclusions,
failure values, retry predicates, stopping rule, reducers, and release point
before the first result is visible. Until release, logs/results go to a store
unreadable by the investigator/controller that could change the plan. If strict
human blinding is claimed, this store and scheduler require a separate
administrative principal; otherwise the result is tamper-evident preregistration,
not enforced blinding.

### 5. Source intake and semantic laundering

Hashing an approved checkpoint proves only its bytes. The `CleanSourceReceipt`
must bind authenticated upstream ancestry, exact base/model/tokenizer,
mechanism, writer/compiler, committed corpus, exposure set, and promotion
state. Missing upstream authority rejects. A human can still retype remembered
CompilerGym information into a new blob; machine enforcement cannot prove
semantic independence. Prospective freeze, restricted intake authority, and
honest claim language are required.

### 6. Runtime and side-channel inputs

The maximal readable set must also cover or deny ambient randomness, clock,
locale, package/config discovery, DNS, network, signals, `/proc`-like process
views, shared quotas, cloud dashboards, and mutable environment images. For
science mode, the controller supplies registered randomness and a fixed
environment; undeclared ambient inputs make the unit receipt invalid. Shared
resource timing cannot be called eliminated unless the execution substrate
actually isolates it.

### 7. Cross-unit output reachability

A descendant output may reach only its registered reducer/report sink. It is
not a source for a sibling root, L opposite arm, later confirmation unit,
carrier compiler, source preflight, or clean birth. DEV results may select a
later DEV/confirmation **experiment plan** only through an explicit freeze on a
disjoint reserve split; they never promote the child. Confirmation results are
released only after the batch is terminal and cannot revise that batch.

### 8. Opportunity and representation leakage

L's opportunity tape must be outcome-independent and frozen before either arm;
neither arm may infer the other's state through scheduling or shared storage.
C's codecs must receive the identical canonical semantic ledger, not a
codec-specific rendering containing labels or future goals. M's cloned goals
must not write into each other or the acquisition trunk. These are scientific
visibility constraints enforced by the kernel/controller, not by the lineage
receipt alone.

## Smallest exact paper guard

### A. `CleanSourceReceipt`

One immutable, authenticated receipt supplied by the upstream birth process
binds:

- source/lineage ID and exact frozen snapshot hash;
- parent receipt/hash and promotion state;
- base/model/tokenizer, mechanism, writer/compiler, committed corpus, and any
  state that can affect inference;
- canonical exposure tuples `(domain, split, purpose)`, trust zone, and source
  receipts; and
- the authority that admitted it.

`preflight` accepts only the exact receipt authorized by the paper plan.
Unknown/unhashed/path-only/`DONE`-only sources reject. `R2_B_seed3`/seed-303 and
derivatives reject for a clean CompilerGym downstream purpose. Paths, symlinks,
hardlinks, filenames, and copied bytes cannot substitute for the receipt.

### B. `ExperimentPlan`

One canonical plan binds `M|L|C`, `DEV|CONFIRMATION`, the clean source receipt,
sealed generator/config/split, exact unit universe and nesting, phase machine,
visibility projections, intervention/tape/codec specs, source/code/environment/
command hashes, failure/retry/stopping rules, reducers, and allowed output sink.
Unset fields reject; there are no science-mode defaults.

For confirmation, the plan additionally binds a one-time split/claim-consumption
ID and result-release condition. E0 and parenting remain separate plans.

### C. Role-separated launch and terminal receipt

A small experiment supervisor owns the source/plan store under OS permissions
unavailable to workers. It validates `preflight` before directory creation or
external access, opens the exact source read-only, creates a new empty unit
root, and launches:

- a trusted deterministic controller with private certificate/seed/phase data;
- an actor/model endpoint with only canonical `visible_view` bytes;
- a carrier compiler with only the rows/semantics allowed by its phase; and
- a reducer with only the complete registered terminal receipt set.

The supervisor conservatively binds each output to every object exposed to
that role. It records exact pre/post source hashes, plan, role views, command,
environment, randomness, root-local artifacts, failures, and output hashes.
The source has no writable mount and no promotion endpoint. A direct helper
without the supervisor can produce bytes but not a valid science receipt.

### D. Root-local transaction only

M and L may update state inside their disposable roots. Each root has one
controller-owned head journal; under an exclusive lock, a commit verifies the
expected previous hash and atomically advances all future-readable local slots
(checkpoint/adapter, corpus, writer/compiler receipt, memory/state, and root
manifest). Rejection advances none. L `F` and `B` use different journals. No
root journal is accepted as a `CleanSourceReceipt`.

This local lock/CAS and crash test replaces v2's experiment-wide authority
database. An append-only OS-owned receipt log is adequate on one host; add
cryptographic signatures only when receipts cross an administrative or machine
boundary.

## What to delete from v2 for this paper

Delete from the M/L/C implementation scope:

- adaptive classroom reducer and canonical parent-notebook state;
- developmental exams and the declassifier principal;
- general remote-parent/author broker policy;
- the four-operation eligibility matrix and global partition-consumption
  service;
- mutable clean-head slots and clean SLEEP promotion;
- a universal blob registry, Ed25519 envelope, and second canonical encoder;
- CompilerGym 2x2 final-cell, pedagogy-core, and root-local parent machinery;
- all-decision receipts and general human-information-flow claims; and
- the claim that the paper guard authenticates semantic target blindness.

Retain:

- exact upstream source receipt and current CompilerGym quarantine;
- fail-closed purpose/split/source preflight before exposure or writes;
- authority-derived maximal readable sets;
- OS read-only source and isolated root/arm capabilities;
- role-specific public/private visibility, especially seed/intervention hiding;
- exact root-local transactional commit/rejection and no “latest” scanning;
- trainer-consumed provenance/masks for PCFL `TransitionRow`s;
- source pre/post hashes and terminal receipts; and
- a frozen, optionally separately blinded confirmation plan with no descendant
  return to the source.

## Exact remaining material choices

Before paper-guard implementation, ratify only:

1. the `CleanSourceReceipt` schema, upstream authority, accepted source hash,
   exposure policy, and explicit `R2_B_seed3` denial;
2. the single kernel canonical encoding and PCFL object schemas;
3. the `ExperimentPlan` schemas for M/L/C, including purpose/split and complete
   unit/schedule/reducer semantics;
4. the controller/actor/compiler/reducer view projections and exact OS/process/
   session/cache/RNG isolation substrate;
5. root-local journal slots, lock/CAS, atomicity, and crash recovery;
6. the `TransitionRow` provenance and tokenizer-derived mask contract;
7. whether confirmation is merely preregistered or strictly human-blinded, and
   if blinded, the separate scheduler/result/release principal and abort/retry
   protocol; and
8. the exact CPU negatives for source forgery/aliasing, private-field leakage,
   TEST_ONLY laundering, branch/root cross-talk, rejected-state reuse,
   concurrent local promotion, partial-result adaptation, and source mutation.

Everything about adaptive parenting, developmental-exam return, or a final
CompilerGym 2x2 remains in its own later packet. This preserves the user's
contamination rule while keeping the PCFL paper core small: frozen clean source
in, isolated terminal descendants out, and no edge back.
