# One-parent/one-child integrated strong-baseline final audit v1

Date: 2026-09-06

Status: **fresh independent read-only audit of the current edited candidate**.
This artifact changes no candidate bytes and authorizes no external
deliberation, implementation, model/tokenizer call, task generation, LoRA
operation, benchmark, or GPU use.

## Verdict

**REVISE THREE NARROW CONTRACT EDGES, THEN ADVANCE.** The one-parent/one-child
topology, active-memory causal interpretation, fixed-sequence contrasts,
conditional local-plateau rule, slot geometry, and stated call/output/fitting
arithmetic are coherent. The current bytes are not yet an exact strong-baseline
contract because the active-text updater can pass without a semantic-faithful
write certificate, several updater/retrieval bytes are still implicit, and the
optional powered LEAFE schedule is temporally impossible as written.

## What passes

1. **Architecture fidelity — PASS.** The treatment is exactly one frozen
   parent teaching one parented child through a closed childhood channel,
   followed by deletion and parent-absent deployment. `P0/P1/U0/U1/R0` are
   isolated counterfactual services/replications, not a classroom, cohort,
   ensemble, shared store, or cross-child learning mechanism.
2. **Public reference semantics — PASS.** The plan consistently defines `R0`
   as a fit-free raw actor whose complete system is a
   **frozen-parameter active-memory reference**, never a raw or never-learning
   complete system. The paper and readiness note preserve that qualification.
3. **Causal language and power — PASS.** `D` is the parenting-by-write
   interaction; `C_active=P1-P0` is explicitly a closed-loop total effect that
   includes the post-treatment active-store mediator; `C_public=P1-R0` is a
   full-package contrast that isolates no component. The fixed sequence
   `D -> C_active -> C_public`, root-level unit, SESOI, intervals, pilot
   exclusion, blinded variance rule, and lower-rung preservation are mutually
   consistent.
4. **Local saturation — PASS.** The rule names
   `P0+ACTIVE_TEXT_FIXED`, the CompilerGym distribution, 48 programs, and the
   read/update envelope; pairs the same probes across cuts; uses two separate
   95% equivalence intervals (at least 90% simultaneous coverage by the union
   bound); requires hidden search headroom plus positive P1 last-era growth and
   a positive last-era difference-in-differences; forbids rescue roots; and
   suppresses the word if any condition or precision check fails. It is a
   prospective local-plateau rule, not a nonsignificant-slope story.
5. **Main resource arithmetic — PASS.** Recalculation gives exactly:

   ```text
   per root: 5,291 calls; 972,544 output tokens; 12 fits
   N=20 route (26 roots): 137,566 calls; 25,286,144 output; 330 fits incl. canary
   N=32 route (38 roots): 201,058 calls; 36,956,672 output; 474 fits incl. canary
   active reads: 2,949,120 wake + 1,310,720 probe = 4,259,840 input tokens/root
   updater caps: 240*(8,192+4,096) = 2,949,120 input tokens/root
   combined named active-memory input: 7,208,960 tokens/root
   maximum new/revised record embeddings: 240*4 = 960/root
   ```

   The optional comparator's stated additions also recalculate exactly:

   ```text
   160 calls; 45,056 output tokens; 48 rollback dispatches; 1 fit/root
   N=20 optional route: 141,726 calls; 26,457,600 output; 356 fits incl. canary
   N=32 optional route: 207,138 calls; 38,668,800 output; 512 fits incl. canary
   ```

6. **LEAFE comparison meaning and slot geometry — PASS.** It is called a
   bounded `LEAFE_STYLE_FINAL` complete-system comparison, not an exact LEAFE
   reproduction or schedule-only causal estimate. Its 24 childhood slots,
   48 branch slots, three rehearsal-filled DREAM slots, 20 anchors, four
   exposures, and clean-base rank-8 rebuild reproduce the 320-position
   terminal geometry honestly.
7. **Scope JSON — PASS WITH THE CONTRACT REPAIRS BELOW REQUIRED.** It forbids
   classroom/shared learning, parent-after-deletion, hidden/probe/future edges,
   unsupported targets, semantic overclaiming, and premature execution. Its
   authorization effect remains proposal/CPU-only after later ratification.

## Exact blockers

### 1. `ACTIVE_TEXT_FIXED` is not yet byte-reproducible

The plan closes visibility and token partitions, and gives a record shape, but
does not bind:

- the closed field-level JSON schema for `REFLECT`;
- the field-level payload and legal transition table for each
  `ADD | REVISE | LINK | SUPERSEDE | NOOP` delta;
- exact prompt/render bytes and the serialization inserted into the actor;
- the query/render rule for updater-side prior retrievals; or
- the exact dense-query prefix bytes ("the published prefix" is an external
  description, not a byte string).

The reported 4,400 query-embedding ceiling is arithmetically plausible only as
4,160 actor/probe queries plus exactly one `REFLECT` query after each of 240
program-services. The candidate never states that cadence or that `CURATE`
uses zero additional query embeddings. Bind this mapping, document inclusion
and truncation under the BGE tokenizer, and hash the exact schemas,
prompts/renders, query bytes, transition table, and actor insertion template
before the development strength certificate.

### 2. The strength gate does not certify semantic-faithful writes

The actual updater is tested for citation existence, typed operation/status
F1, reusable-record recall, retrieval/use, and end-to-end value. However, the
candidate removed the counter-audit's evidence-entailment precision check and
now says free prose is never semantically graded. A structurally correct
updater can therefore cite real events while inventing the
`claim_or_observation` or `action_guidance`, yet still satisfy the structural
write cells and potentially pass an aggregate 24-program value gate.

Restore a prospective semantic-faithfulness certificate, e.g. at least `.95`
precision on 100 sealed typed propositions/action-guidance fields whose truth
is mechanically derivable from public fixture events. If open prose remains,
score a separately frozen offline entailment rubric only after outputs seal;
that scorer must never admit live rows or feed the updater. Also separate
updater-development fixtures from a once-only sealed strength-certificate set,
so a failed score cannot be repaired and re-scored on the same cases.

Until this passes, `ACTIVE_TEXT_FIXED` may run as a comparator but cannot be
called a validated **strong** memory baseline.

### 3. The powered optional comparator schedule and input budget conflict

Section 13 says `LEAFE_STYLE_FINAL` runs only after `D` and `C_active` are
immutable, while also saying a powered `C_batch` has its SD included in the
blinded N=12 root-count rule. Once `D`/`C_active` are immutable and unblinded,
the N=12 decision has already happened. Both requirements cannot hold.

Choose one prospectively:

- keep the comparator staged after the headline and make `C_batch`
  descriptive/exploratory; or
- declare powered `C_batch` before unblinding, run its first 12 root cells in
  time for the blinded variance decision, and include it in the fixed
  hierarchy; or
- fix its confirmation size at 32 independently of the adaptive N rule.

The optional resource envelope also lacks hard input-token partitions for its
256-output-token diagnosis and 512-output-token recovery calls over historical
state. Add those two input ceilings, deterministic complete-event packing and
overflow behavior, and any associated retrieval/embedding work. The call,
output-token, dispatch, fit, and 320-position arithmetic itself is correct.

## Nonblocking wording cleanup

The manuscript's phrase “frozen-parameter active-memory ordinary agent” and
the readiness note's “strong ordinary reference” are understandable, but
`frozen-parameter active-memory reference` is safer everywhere. The complete
`R0` system adapts text, so “ordinary” should never appear without that
qualification.

## Disposition

No topology, root-count ceiling, public two-agent figure, or new longitudinal
service needs to change. Repair the exact updater/retrieval contract, restore
semantic write faithfulness, and choose a coherent LEAFE power/timing path
with bounded inputs. Then rehash and re-source-bind the proposal before any
external deliberation approval is requested. This audit is not an execution
gate.
