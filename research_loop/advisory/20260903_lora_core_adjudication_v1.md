# LoRA-core adjudication for Paper 1

**Date:** 2026-09-03  
**Role:** fresh independent scientific adjudication  
**Status:** advisory only; not architecture ratification, implementation
authority, GPU authority, preregistration, or a scientific result

## Executive ruling

Two propositions have been conflated:

1. **What is the smallest scientifically credible Paper 1?** A locked,
   text-only RTCW confirmation can be a credible benchmark-and-causal-memory
   paper. LoRA is not required for that paper.
2. **What evidence confirms the stated Dream--LoRA--Think thesis?** LoRA is
   required. Text-only evidence cannot establish that admitted experiential
   structure was transported into weights or read back from weights. Calling a
   text-only result confirmation of Dream--LoRA--Think would change the thesis
   while retaining its name.

The recommended resolution is therefore **text-primary, LoRA-gated**, not
LoRA-co-primary and not silently text-only:

- The load-bearing Paper-1 efficacy experiment should remain `E-TEXT` against
  native A-Mem-like and faithful Auto-Dreamer-style systems on sealed
  post-context action.
- A same-semantics LoRA transport study should be specified before
  confirmation, run only if its disjoint technical gate passes, and remain a
  secondary mechanistic claim.
- If the LoRA gate is omitted or fails, publishable text results should survive,
  but the title, abstract, contribution list, and conclusion must drop
  Dream--LoRA--Think, parametric world model, experience-to-weights, and
  weights-based persistence language.
- If the project insists that **Paper 1 itself** confirm the named
  Dream--LoRA--Think target, then a passing LoRA transport arm must appear in
  the locked confirmation. It still should not become the primary efficacy
  comparison.

This is stricter than saying “LoRA is optional.” LoRA is optional for the
smallest credible publication; it is not optional for the weights clause of
the user's target.

## What each study can actually establish

The causal story should be factored into propositions rather than treated as
one organism-level effect:

| Proposition | Minimum evidence | Text-only status |
|---|---|---|
| `P1` Experience contains learnable action-relevant structure | Public-life and gold/program ceilings; target-identical twins | Testable |
| `P2` DREAM proposes useful structure before its validating outcome | Sealed proposal pool, pre-outcome precision/coverage and contradiction accounting | Testable |
| `P3` Later ordinary outcomes improve admission, not merely selection after seeing the answer | Same proposal pool: raw proposal vs blind self-check vs chronological admission | Testable |
| `P4` Connected admitted semantics plus recurrent THINK improve sealed post-context action | `E-TEXT` vs native strong text systems, plus binding/twin/cut interventions | Testable and sufficient for the smallest paper |
| `P5` The same semantics retain action value after transport into per-life LoRA weights | Frozen corpus `M`, matched text/LoRA resolver, candidate-only control, adapter swaps | Not testable without LoRA |
| `P6` Capability continues to develop as lifetime and required depth grow | Prespecified cut/lifetime response surface with a positive last-interval effect | Not established by a one-boundary text paper, with or without LoRA |
| `P7` Memory improves the next evidence-acquisition cycle | Separate randomized authentic/null/shuffle/twin memory trial | Not established by fixed-deck confirmation |

Thus the hostile review is correct about the minimum publication but too broad
if read as saying that text-only evidence proves the canonical project target.
It proves `P1`--`P4`. The recognition-assisted LoRA study can add `P5`.
Neither one proves the older “continuing to improve where existing systems
saturate” sentence; note 50 correctly removes that claim pending a separately
powered study. Neither proves the continual intelligence flywheel without the
randomized next-cycle experiment `P7`.

## Primary-prior adjudication

The six papers make LoRA less novel as an ingredient, but they do not make the
same-corpus substrate intervention scientifically useless.

- [TMEM](https://arxiv.org/html/2606.04536) already converts accumulated
  history into QA supervision, performs cumulative within-rollout LoRA updates,
  and outcome-trains the extraction policy. It reports stronger results than
  summary and A-Mem-style retrieval baselines and shows that QA supervision is
  substantially better than raw next-token supervision. Therefore “experience
  can be written to LoRA and change later behavior” and “write format matters”
  are occupied.
- [Auto-Dreamer](https://arxiv.org/html/2605.20616) already performs bounded,
  provenance-linked multi-source region rewriting and trains its consolidator
  from downstream utility with counterfactual masking. Its untrained rewrite
  pipeline accounts for most of the reported bank reduction, while GRPO adds
  heterogeneous task utility and can discard useful local detail. Therefore
  offline dreaming, cross-session abstraction, compact replacement, and
  downstream-trained consolidation are occupied.
- [PEAM](https://arxiv.org/html/2605.27762) already internalizes successful and
  failure--correction trajectories into isolated MoE-LoRA skill modules and
  evaluates long-horizon Minecraft action, retention, and efficiency.
  Parametric competence, selective consolidation, and weights-as-agency claims
  are occupied. A PEAM-like arm is needed only if this paper claims procedural
  policy or agency in weights; it should make no such claim.
- [A-Mem](https://arxiv.org/html/2502.12110) already creates enriched atomic
  notes, LLM-judged links, evolving prior descriptions, and linked retrieval,
  with its largest reported advantages on multi-hop and temporal QA. Connected
  evolving external memory is occupied, so an atoms-only retriever is not an
  adequate baseline.
- [EVAF](https://arxiv.org/html/2606.26806) explicitly keeps retrieval intact
  while unloading working context, separates factual access from durable
  goal-conditioned behavioral influence, and factorizes LoRA event selection
  from actuation strength. Its own results show strong model-dependent
  actuation and contamination tradeoffs. Post-unload parametric influence and
  selective writes are occupied, and raw/write-everything LoRA is insufficient
  as the only parametric control.
- [Parametric Memory Law](https://arxiv.org/html/2605.30260) maps LoRA rank and
  sequence length to loss reduction, studies exact reconstruction failures,
  and introduces hard-token-weighted MemFT; it also includes a small seen versus
  unseen linear-rule study. Rank/capacity curves and exact-memory optimization
  are occupied and should not be added to the core unless they explain action
  utility beyond memorization.

The remaining LoRA question is narrow and orthogonal to those headline claims:

> Holding the target-blind, prospectively admitted semantic set fixed, does an
> isolated per-life adapter preserve enough identity-specific one-hop access
> for a clean recurrent resolver to recover action value, and does that value
> disappear under adapter-identity interventions?

That is a useful decomposition of semantic induction from substrate transport.
It is not a claim that LoRA discovers, verifies, reasons, outperforms text, or
uniquely changes policy.

## Scientific information, novelty, risk, and compute

| Dimension | Text-only locked confirmation | Adding LoRA to the primary core | Recommended gated LoRA extension |
|---|---|---|---|
| Scientific information | Identifies proposal, chronological admission, authentic semantic content, access/traversal, and action utility | Adds transport information but entangles the strongest result with adapter optimization and reader fidelity | Adds the transport result only after induction and traversal work, so failure is localizable |
| Novelty | Strongest remaining lane: RTCW as an intervention instrument plus the prospective-admission pathway; system novelty remains low | “LoRA memory” itself has little novelty after TMEM, EVAF, PEAM, and the Memory Law | Same-corpus transport and adapter-identity interventions are a modest but clean mechanistic addition |
| Reviewer risk | High benchmark-co-design risk and direct A-Mem/Auto-Dreamer overlap; mitigated by native baselines, independently locked pack, action-primary scoring, and interventions | Adds baseline explosion, hyperparameter researcher degrees of freedom, candidate-roster leakage, pseudo-replication across adapter seeds, contamination/drift, and a likely “bolted-on LoRA” critique | Keeps the primary paper legible; a failed LoRA gate cannot invalidate the text result, and a passing arm answers the thesis-alignment objection |
| Compute | Mostly model inference and environment execution, though native region rewriting and linked-memory construction remain expensive | Per-life training multiplies over adapter types, roots, sides, and technical seeds; outcome-training a faithful TMEM writer is an additional outer-loop burden | Pay calibration first; train once per life and adapter arm, reuse across nested targets/cuts, and spend confirmation compute only after a frozen technical pass |
| Match to the user's target | Establishes constructive experiential **external** memory and THINK; does not establish experience-to-weights | Can establish the narrow weights-transport clause if clean, but not continued development or a flywheel | Preserves the possibility of the named target without making weak LoRA results carry the paper |

At 48 pair roots, two world sides already imply 96 life-specific memory
instances. Authentic, raw-event, direct-QA/TMEM-like, and selective
EVAF-like adapters imply at least 384 adapter trainings per technical seed;
a separately trained binding-shuffled adapter raises that to 480. Twin and
wrong-life reads can often reuse the opposite or existing adapters and should
not trigger retraining. These counts exclude writer training, calibration,
and failed hyperparameter settings. Exact GPU-hours must be measured before
authorization, but the multiplicative structure alone is enough to reject a
casual “add LoRA everywhere” design.

## Recommended evidence ladder

### L0 — freeze two paper contracts before model-facing development

Register two nested contracts:

- **Text contract:** tests `P1`--`P4`; this is the primary paper and survives
  if every LoRA arm is removed.
- **Weight-transport contract:** tests only `P5`; it is activated only after a
  disjoint technical gate and is required before using Dream--LoRA--Think or
  experience-to-weights framing.

Freeze the decision rule now: a failed or omitted weight contract causes a
scope/name change, not a post-hoc softening of what “LoRA” supposedly means.

### L1 — G1 controller construct gate

Use the already bounded D0 gold-action test only to show that supplied
knowledge can alter the recurrent action interface and that authentic, sham,
cut, and twin records behave differently. It supplies no learning, population,
text-memory, or LoRA evidence. Failure stops both tracks.

### L2 — RTCW validity and leakage gate

Before paper-bearing calls, require:

- independent pair roots and target-byte-identical twins;
- one separately authored, output-blind locked transition-mechanism pack;
- generator-aware program induction, exact witnessed graph, and
  target-independent gold-text ceilings;
- no-life/adaptive-search bounds, nonce/renderer/target-permutation audits,
  and intervention-sensitive action targets;
- a measured post-context boundary where decisive source events are absent;
- target, proposal, writer, retrieval, traversal, and cost budgets sealed
  independently of outcomes.

Graph recovery is diagnostic. Sealed environment action under unseen
interventions is the primary construct.

### L3 — G2 text development, not a paper result

On the disjoint small development set, establish that:

1. a target-blind fixed proposal pool has nontrivial pre-outcome precision and
   coverage without contradiction-by-enumeration;
2. later-public-outcome admission improves the precision--coverage--action
   frontier over raw proposals and blind self-check on that identical pool;
3. authentic admitted content beats binding-shuffled, twin, cut, and sham
   content;
4. full recurrent `E-TEXT` retains a practically prespecified portion of the
   gold-over-none action gain; and
5. native RAG, native A-Mem-like linking/evolution, and faithful
   Auto-Dreamer-style region rewriting are usable and not interface-handicapped.

If this stage fails, do not train LoRA: weight transport cannot rescue failed
semantic induction.

### L4 — disjoint LoRA technical gate

Use a disjoint locked calibration set, suggested by note 50 as six pair roots.
For each life, freeze one admitted semantic set `M` before target selection.
Derive text and adapter corpora only from `M`, with canonical row identity and
provenance unchanged.

The gate must include:

- `E-TEXT`;
- recognition-assisted `E-LORA-R`;
- candidate-only clean base with the identical target-independent roster;
- a generative `E-LORA-G` sentinel, diagnostic only;
- wrong-life, whole-twin, and binding-shuffled adapter reads;
- adapter unmounting before multi-hop composition;
- exact/reverse/paraphrase/partial-cue row fidelity, `NOT_FOUND`, false-match,
  contamination, old-retention, wall-time, memory, and training-cost audits;
- actuation-strength calibration separated from selection, following the EVAF
  lesson.

Pass criteria must be frozen after this disjoint calibration and before
confirmation. At minimum they need (a) a practical canonical-row fidelity
floor, (b) directionally correct authentic-over-candidate-only and
authentic-over-each-identity-swap checks, (c) bounded contamination and
old-memory loss, and (d) a practical action-retention floor relative to
`E-TEXT`. With only six calibration roots, these are technical go/no-go checks,
not population inference. The numerical floors should come from the disjoint
calibration and power audit; inventing them now without a variance estimate
would be false precision. Statistical significance alone is not a
practical-retention criterion.

If L4 fails, remove all LoRA arms from confirmation and rename the paper scope.
Do not tune on confirmatory roots.

### L5 — one locked 48-root text-primary confirmation

Use at least 48 fresh pair roots, 16 per non-isomorphic fixed pack. Use one
prespecified post-context boundary for the minimum paper; do not attach the
`4x -> 8x` development or saturation claim to this experiment.

The single primary endpoint is pair-root-level environment-action performance
on sealed, binding-sensitive, multi-step interventions. The primary claim is
conjunctive:

```text
E-TEXT > native A-Mem-like memory
AND
E-TEXT > faithful Auto-Dreamer-style consolidation
```

Both contrasts must pass their predeclared practical and uncertainty bounds,
and no transition pack may be rescued by pooling. Full-history/adaptive
truncation, none, witnessed atoms, iterative raw RAG, hierarchical reflection,
program induction, exact graph, and gold text remain interpretation controls
or ceilings. Resource-quality frontiers accompany the fixed-budget result.

Within the same roots, the fixed-pool sequence—atoms, raw proposals, blind
self-check, admitted rows, full traversal—and authentic/binding/twin/cut/sham
read interventions provide controlled-effect attribution. They are not a
natural-mediation analysis.

If L4 passed, build every text and LoRA substrate before target selection and
include the frozen LoRA panel in these same roots as a **secondary family**.
Average adapter seeds within root before inference. Do not count targets,
sides, cuts, or seeds as independent observations.

If `E-TEXT` does not clear both primary comparators, there is no positive
system-efficacy claim. Preserve the benchmark and controlled phase diagram
only if the independently locked instrument remains valuable. A positive LoRA
transport result cannot rescue a failed text induction/action pathway.

### L6 — secondary confirmatory LoRA transport family

The minimum claim-bearing LoRA roster is:

- authentic `E-LORA-R`;
- candidate-only clean base;
- raw-event LoRA;
- outcome-trained direct-QA/TMEM-like LoRA using the same public lifetime;
- matched selective event-to-LoRA/EVAF-like control with write count and
  actuation calibrated separately;
- wrong-life, binding-shuffled, and whole-twin adapter swaps;
- `E-TEXT` from the identical `M`.

The LoRA claim requires a conjunction: authentic `E-LORA-R` must clear the
predeclared practical action gain over candidate-only, beat every identity
swap, clear row-fidelity/contamination/retention gates, and retain the
predeclared practical portion of `E-TEXT` action value. A generative LoRA read
may be reported as a failure-boundary sentinel. Noninferiority or superiority
to text is not required unless separately powered; neither should be implied.

Do not add PEAM unless claiming skill/policy/agency in weights. Do not add a
rank sweep or MemFT family unless making a capacity-law claim. The recommended
paper should make neither claim.

### L7 — later claims, outside the minimum paper

- A prespecified `2x--8x` response surface with a positive `4x -> 8x` lower
  bound is needed for finite continued-development language.
- A separately powered equivalence/crossover design is needed to say a named
  baseline saturated while this system continued improving.
- New roots and randomized authentic/null/shuffle/twin memory before an actual
  evidence-gathering phase are needed for a one-cycle flywheel claim.
- Repeated open-ended self-improvement and a learned DREAM/THINK controller
  remain later papers.

## Claim and title structure

### If only the text contract passes

Use a title and abstract centered on **prospectively grounded connected
experiential memory** or **causal evaluation of agent memory**. A defensible
conditional result sentence is:

> On preregistered RTCW generators, after source events left the controller's
> context, target-blind proposals admitted only by later ordinary public
> outcomes produced connected text memory whose recurrent use improved sealed
> interventional action relative to native linked-memory and offline-
> consolidation baselines; binding and twin swaps reduced that gain.

Do not use Dream--LoRA--Think, parametric world model, experience-to-weights,
weights-based persistence, self-learning, continued improvement, saturation,
compression, or flywheel language. The result is not a failed version of the
weights paper; it is a narrower external-memory and evaluation paper.

### If both text and LoRA contracts pass

Keep the text result primary and add:

> The identical admitted semantics retained practically significant action
> value when transported into isolated per-life LoRA weights through a
> recognition-assisted one-hop read channel; candidate-only and adapter-
> identity interventions did not reproduce the effect.

The strongest combined sentence is:

> In RTCW, a frozen controller converted its public action--outcome history
> into target-blind, prospectively supported connected semantics, used those
> semantics recurrently for held-out post-context action, and preserved part
> of their action value when the same semantic set was transported through an
> isolated per-life LoRA read channel.

Even then, say **transported** or **preserved**, not “learned reasoning in
weights.” The explicit ledger remains epistemic authority; THINK performs
composition externally. The combined result supports the narrow
Dream--LoRA--Think information path, not the old claims of baseline saturation,
autonomous continual improvement, or a causal flywheel.

## Final decision

Proceed with the text-only RTCW study as the primary, smallest paper-worthy
confirmation. Pre-register LoRA as a disjointly gated secondary transport
extension. This gives the highest information per unit compute and the lowest
avoidable reviewer risk while preserving a clean route to the user's named
target.

But enforce the semantic consequence: **without a passing LoRA extension, the
paper does not confirm Dream--LoRA--Think.** It confirms
experience--prospective-admission--connected-text--THINK. If preserving the
named thesis in Paper 1 is non-negotiable, LoRA must pass L4 and appear as the
secondary L6 family in the locked confirmation; otherwise the scientifically
correct action is to narrow and rename the paper, not to promote text memory
into evidence about weights.
