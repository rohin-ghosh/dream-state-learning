## Verdict

**PASS for proposal-byte and semantic closure.** The v8 blocker is closed.
Every accepted `REFLECT` now has a total deterministic disposition before
`CURATE`: required-input overflow, finalized-transition unrepresentability,
exact prescribed-output unrepresentability, or a representable second call.
The finalized-transition preflight uses the exact production commit path and
therefore closes the 16-to-17 evidence/link and 256-to-257 final-record
boundaries across every applicable operation. The certificate applies the
same no-call accounting to model-produced valid-but-unrepresentable

This PASS is not a strong-baseline result and does not authorize spending a

## v8 transition-feasibility blocker

**CLOSED.** After `REFLECT` semantic acceptance, the governing order is:

1. Construct the complete required `CURATE` input union and record
   `INPUT_OVERFLOW` if any fixed partition cannot contain every required
   block, receipt, and the accepted reflection.
2. Deterministically construct the complete prescribed canonical `CURATE`
   object from the accepted model-produced reflection and immutable pre-call
   store.
3. Apply its entire prescribed delta list to a temporary store through the
   exact commit path. This assigns new IDs and supersession provenance,
   unions retained and new evidence, inserts links, sorts arrays, recomputes
   derived values/statuses/hashes, and checks every cardinality, record-size,
   collision, provenance, transition, and one-live-key invariant.
4. If that unique final state cannot commit, record
   `TRANSITION_UNREPRESENTABLE`, skip `CURATE`, preserve the accepted
   `REFLECT`, and leave the store unchanged.
5. Only for a feasible transition, measure the exact canonical prescribed
   assistant-response suffix under the pinned official chat template plus
   exactly one EOS. More than 384 tokens records
   `OUTPUT_UNREPRESENTABLE`; 384 is inclusive.
6. Call `CURATE` only after all three pre-call gates pass.

The headline plan, supporting contract, and 25-line model-visible prompt
schema state the same finalized-transition/no-call law. No prescribed delta,
old citation, link, provenance edge, record field, or byte may be removed or
shortened to evade a gate.

### Boundary attack by operation

- **`ADD`: PASS.** The temporary commit assigns the deterministic memory ID,
  derives all fields, sorts arrays, and checks the complete final stored
  record. A null-ID proposed record that becomes 257 tokens after assignment
  is rejected before the second call.
- **`REVISE`: PASS.** The preflight preserves and unions all old and new
  evidence, resolves retained observations, recomputes aggregate fields and
  status, and then checks both 16-entry evidence-array caps and the 256-token
  final record. A 16-to-17 support or counterevidence union has the named
  no-call disposition.
- **`LINK`: PASS.** The preflight inserts the directed target into the source,
  sorts the final link array, and checks the changed source record. A 17th
  link or a link insertion that changes a 256-token record to 257 is rejected
  before the compact ID/hash-only `LINK` response can be requested.
- **`SUPERSEDE`: PASS.** The temporary transition assigns the replacement ID
  and exact `supersedes_memory_id`, changes the old immutable record to
  `SUPERSEDED`, recomputes the replacement, and checks the entire final store.
  A 257-token replacement or any provenance/live-key violation is a pre-call
  failure.

The required deterministic fixture set explicitly covers 16-to-17 support
IDs, 16-to-17 counterevidence IDs, 16-to-17 links, and the 256-to-257 final
stored-record boundary for every applicable `ADD`, `REVISE`, `LINK`, and
`SUPERSEDE` path. These are prospective implementation obligations; no
fixture, tokenizer, or model was executed in this audit.

## Output representability and valid-`REFLECT` overflow scoring

**PASS.** The earlier v7 output-size repair remains exact. The preflight
measures the complete prescribed top-level object, all ordered deltas,
complete embedded records, IDs, hashes, and sole `NOOP` where applicable.
It measures the assistant-response suffix plus one pinned EOS, accepts 384,
rejects 385, and requires one- through four-delta boundary fixtures. The new
transition preflight correctly precedes this measurement, so an infeasible
store state is not mislabeled as merely an output-length problem.

Certificate execution is total for an accepted model-produced `REFLECT`:

- `INPUT_OVERFLOW`, `TRANSITION_UNREPRESENTABLE`, and
  `OUTPUT_UNREPRESENTABLE` all skip `CURATE`, seal the unchanged isolated
  store, and retain the reflection as a scored audit event;
- the emitted reflection is scored normally;
- the fixture's presealed gold `CURATE_CLASS` receives exactly one false
  negative;
- no `CURATE` false positive is added because no second-call prediction was
  attempted; and
- the case is never excluded.

Before certificate sealing, the generator constructs the exact gold second-
call input and prescribed canonical response, then executes the complete gold
transition on a temporary store through the same production commit path. It
rejects the case unless every fixed input partition fits, every final
cardinality/record-length/transition invariant passes, and the gold response
plus EOS fits the 384-token cap. Thus deliberately failing 17-entry and
257-token model-free boundary fixtures cannot enter the once-only gold set as
supposedly executable units.

## Certificate gold firewall

**PASS.** Every case has an isolated presealed store. Only the accepted
canonical model-produced `REFLECT`, its displayed public evidence, and the
immutable case store drive required-input construction, prescribed-operation
selection, feasibility preflight, exact-output construction, and commit. A
contract-valid gold-different path commits before scoring. The commit
validator has no gold access; gold opens only after raw responses and the
post-commit or unchanged store are sealed. Stores, IDs, records, indices, and
ordering effects never cross certificate cases. Gold can neither select,
veto, repair, nor redirect a live transition.

## Operation closure retained from v7

**PASS.** The operation selector remains single-valued: no live same-key
record gives `ADD`; same-signature new complete observation identity gives
`REVISE`; a contradicted same-key record plus a different newly provisional
or supported signature gives `SUPERSEDE`; the eligible no-new-evidence process
case gives the lexicographically first directed `LINK`; all other cases give
no prescribed delta and therefore the sole `NOOP`. First-seen ordinary
`ADD_CONTRADICTED`, repeated semantic keys, mutation collisions, link-source
collisions, and in-call ID/hash dependencies reject before `CURATE`.

Exact citation sets, complete observation identities, record receipts,
current hashes, immutable pre-call selection, full-store same-key surfacing,
block-first/record-second input ordering, store version locking, and the
one-live-semantic-key invariant remain closed.
