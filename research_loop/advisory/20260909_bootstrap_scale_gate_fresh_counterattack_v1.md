# Bootstrap scale-gate fresh counterattack v1

Date: 2026-09-09

Status: **fresh source-only adversarial advisory**. This review attacks one
scale rule; it does not choose or modify an architecture, bootstrap corpus,
control corpus, curriculum, statistic, writer, parent, lineage, model,
tokenizer, benchmark, adapter, or compute budget. It performs no
model/tokenizer/benchmark/data/adapter/GPU/network work. Scaled-THINK topology
remains unselected pending the requested Fable response and later
adjudication.

## Verdict

The sentence

> when writer provenance, mounting, absorption, or row likelihood works but
> downstream transfer is absent, the default scale authorization is zero

is correct **when its premise means writer evidence only**. It is too strict
if “downstream transfer is absent” also collapses a different state: a
prospectively measured, causal, delayed, post-bootstrap storage/extraction or
public process change has appeared, but the registered task-transfer endpoint
has not yet emerged at the first developmental horizon.

Those states have different evidential value. A writer-only result says that
the intervention entered parameters. A binding-sensitive, context-reset,
write-carried change from newly acquired personal experience says that at
least part of the proposed developmental recurrence is operating. Neither is
task transfer, but the latter can make one bounded test of delayed emergence
more informative than another shallow root or an immediate stop.

The counterattack does **not** license open-ended patience. Replace the
unqualified zero rule with this conditional rule:

```text
writer only / ritual only / practical null / harm -> zero lifetime scale
transfer estimate merely imprecise                  -> roots, same horizon
causal proximal development but no early transfer   -> one prebound runway
positive registered transfer                        -> new-root confirmation
```

There is no second runway. If transfer has not passed by its fixed end, the
tested delayed-emergence hypothesis stops. This is a diagnostic continuation,
not a learnability claim or a promotion of the child.

## 1. What the original gate gets right—and what it assumes

The original advisory correctly blocks a common invalid inference:

```text
lower loss / likely rows / valid mount / fluent reflection
  != behavioral extraction
  != task transfer
  != learning-to-learn
```

It also correctly separates more independent roots from longer lives. Roots
estimate reproducibility and root-level uncertainty at a fixed horizon;
additional ages from one lineage do not create independent `n`.

Its overly strong reading enters when an early-horizon practical-null rule is
treated as a lifetime-futility rule. Rohin's hypothesis is explicitly a
recurrence over action--observation--consolidation cycles. On that hypothesis,
complex state-conditioned regulation could require multiple distinct
experiences and commits before a final-family task score moves. An early
transfer interval whose upper bound is below `delta_T` establishes practical
futility **at that horizon**. It does not establish futility at every longer
horizon unless the experiment has also shown that the proposed intermediate
developmental chain is absent.

Conversely, invoking “development takes time” after seeing a null is not
evidence. A longer life is interpretable only if its maximum horizon, total
GPU envelope, checkpoints, proximal gates, transfer endpoints, and stop rule
were fixed before the early outcome was read.

The earlier allowance for one horizon extension still demands that the latest
two transfer cuts move favorably. That requirement partly assumes the answer:
it licenses delayed emergence only when downstream emergence has already
started. A sharper developmental gate should instead demand stable evidence
for the preregistered causal **intermediate** chain. It need not demand an
early trend in the endpoint whose possible delay is being tested.

## 2. Five outcome classes, decided in order

Predeclare one root-level transfer contrast `T`, its practically meaningful
effect `delta_T`, protected endpoints and harm margins `h_j`, and a small
family of public proximal contrasts. The classification is aggregate by
randomized arm; it must not select individually promising children.

The ordered classes are:

| class | minimum evidential pattern | disposition |
|---|---|---|
| **D — harm** | any protected endpoint crosses its bound, including reduced action, increased ritual/indecision, retention damage, or calibration regression | stop and quarantine the candidate; no mean benefit or writer success rescues it |
| **B — ritual/style only** | the change is confined to syntax, verbosity, self-description, lexical rehearsal, template repetition, row probability, admission yield, or parent-pleasing language, without binding-sensitive public use | zero developmental scale; diagnose or redesign outside the scientific lineage |
| **A — mechanism-bearing proximal change, no task transfer** | the early transfer interval excludes `delta_T` at `H0`, but the post-bootstrap personal-write chain passes the causal proximal ticket below | permit exactly one prebound developmental runway |
| **C — noise/imprecision** | the transfer or proximal intervals still contain materially different decisions, roots/cuts disagree, or the data cannot distinguish A from ritual/null without more sampling | add independent roots only at the same horizon, up to the fixed root cap; do not lengthen lives |
| **E — practical null** | no harm, no ritual-only positive, no causal proximal ticket, and the fixed-horizon intervals exclude the registered meaningful proximal and transfer effects | stop; more lifetime, roots, rank, dose, or thought are unauthorized repairs |

The ordering matters. Harm dominates everything. A ritual cannot be promoted
to class A because it is stable. An imprecise transfer or apparent proximal
effect remains class C, not A. A precise early transfer null can nevertheless
be class A if the causal proximal ticket passes; at the final runway horizon,
the same transfer null ends the test.

### The causal proximal ticket

Training loss, mount success, target probability, exact row recall, and
increased writer admission are never enough. Class A requires all of the
following:

1. **New personal cause.** The evidence was acquired after bootstrap through
   a public child action and outcome; it is not bootstrap, parent, answer-key,
   DREAM, exam, or descendant content.
2. **Valid carrier.** The exact writer and lineage gates pass, and rejected
   candidate-derived corpus cannot re-enter a later cumulative build.
3. **Write-carried persistence.** A preregistered `NEW_COMMIT` versus
   `NO_NEW_COMMIT` disposable-descendant contrast shows delayed recovery or
   use after the parent and waking context disappear. Adapter cut/swap or a
   bound wrong-life control removes the relevant effect.
4. **Extraction or public-process consequence.** On fresh, non-answer-bearing
   cues, the child either uses the stored relation with correct binding or
   shows a state-conditioned public operation change that affects a
   registered intermediate action: discriminating evidence sought, plan
   selected or revised, intention triggered, erroneous belief corrected, or
   unproductive recursion stopped. Mere reflective wording fails this item.
5. **Selectivity and cost.** The effect is absent on irrelevant/wrong-binding
   states and is evaluated at matched action opportunities and generated-token
   budget. More hesitation or a ritual sprayed across states fails.
6. **Temporal stability and safety.** The direction survives the two fixed
   proximal cuts or the registered delayed-retention cut, while all protected
   endpoints pass.

Thus the minimum ticket is delayed write-carried storage **plus** either novel
cue extraction or an action-facing public process consequence. It supports
only “the registered proximal developmental chain operated.” It does not
support transfer, metacognitive disposition, private mechanism, or general
learning-to-learn.

## 3. Exact sequential scale recommendation

### Before any outcome

Bind exact immutable values for:

- the early developmental horizon `H0` and one final horizon `H1`, expressed
  in action--outcome--DREAM--SLEEP opportunities rather than wall-clock time;
- `H1`'s absolute GPU ceiling and the total arm-by-root ceiling;
- the starting independent-root count `R0` and maximum root count `Rmax`;
- one planned early analysis and one final analysis, with a fixed
  group-sequential uncertainty procedure;
- `delta_T`, proximal minimum effects, harm margins, state classes, immediate
  and delayed cuts, fresh-family identities, and all missing-data rules; and
- the exact arm-continuation rule below.

`H1` may be materially longer than `H0` if that is the scientific meaning of
“mixing,” but it may be specified only once and may not be enlarged after
observing `H0`. The complete maximum spend is visible before the first root.
The project sources supply no honest universal episode count, so inventing one
in this advisory would be false precision.

### Step 0 — close E0 and lineage first

Do not spend a developmental ticket while the long-lifetime path still calls
the legacy writer or allows rejected candidate corpus into later builds. Bind
the native response-only writer, separate adapter-head from evidence
promotion, compare every commit to the preceding child, seal mechanism
identity, and pass provenance, off/swap/wrong-life, routing, typed-action,
transaction, retention, and harm gates.

Writer passage alone still authorizes zero scientific lifetime scale.

### Step 1 — cheap bootstrap and control falsification

Before adaptive development, measure entry effects and the public
action-value/generated-token frontier. Reject task inheritance, binding leaks,
generic adapter damage, ritualized reflection, and uncontrolled dose. This
stage identifies installed policy only. It does not earn the developmental
runway.

### Step 2 — run the fixed `H0` root packet

Randomize independent immutable roots to the prospectively bound bootstrap
and parenting packages. Use common task-opportunity blocks where valid, equal
opportunity envelopes, root-local parent state, and the same writer and
mechanism. Collect personal-evidence, commit, extraction, process, transfer,
cost, and harm readouts from the same packet. Disposable commit descendants
are paired probes; they are not new roots and their outcomes never flow back.

At the one planned `H0` analysis, apply D, B, A, C, then E:

- **D, B, or E:** stop.
- **C:** add roots at `H0` only until the registered interval half-width or
  `Rmax` is reached. Reclassify once. If still C at `Rmax`, report
  inconclusive and stop.
- **A:** continue every still-safe randomized canonical root in every primary
  arm to `H1`. Do not continue only roots with favorable trajectories. Do not
  change rank, dose, replay, cadence, THINK, parent law, tasks, or endpoint.
- **Transfer gate passed:** freeze this as calibration evidence and move to a
  separately powered confirmation on new roots; do not use a longer horizon
  as a reward for success.

No favorable early transfer trend is required for class A. The required
signal is the causal proximal ticket. That is the narrow correction to the
earlier scale rule.

### Step 3 — one developmental runway, then a hard stop

At the fixed `H1` endpoint:

- harm stops and quarantines;
- passed transfer can justify a fixed-N, new-root confirmation at the same
  `H1` mechanism and horizon;
- a still-imprecise transfer result may receive only the preregistered
  same-`H1` root top-up within `Rmax`, never another age extension; and
- persistent proximal change without passed transfer is reported as such and
  stops. It does not purchase `H2`.

Every age, interim state, control choice, and calibration root is consumed
selection evidence. Confirmation starts from new birth roots and cannot reuse
the selected adults. E6 remains closed until the separate strong active-text
plateau, later-checkpoint, root-level slope, terminal-value, and uncertainty
conditions pass.

## 4. Independent roots and longer within-root development answer different questions

| resource | scientific question | forbidden interpretation |
|---|---|---|
| additional roots at fixed `H0` | is the observed contrast reproducible, and is its interval precise enough to classify? | episodes, ages, branches, or descendants cannot substitute for roots |
| continuing all randomized roots from `H0` to `H1` | does the same child mechanism require more cycles before the endpoint emerges? | the later ages are not new `n`, and favorable children cannot be selected |
| new roots run to fixed `H1` | does the selected lifetime effect reproduce across births? | these cannot be appended to the calibration growth curve as if prespecified confirmation |
| disposable `NEW_COMMIT/NO_NEW_COMMIT` descendants | did the latest personal write carry a delayed effect? | neither descendant is a population root or a continuing canonical child |

Root replication is the remedy for sampling uncertainty. Within-root time is
the intervention for a latency hypothesis. Spending one as though it answers
the other either wastes GPU or changes the question.

## 5. Information per GPU

The highest-value ordering is:

1. source, provenance, contamination, and sham-accounting audits;
2. representative E0 writer and interface falsifiers;
3. short no-learning entry/ritual assays;
4. the fixed `H0` causal packet with paired commit probes;
5. same-horizon root replication only when classification is imprecise;
6. the single `H1` runway only for class A; and
7. new-root confirmation only after registered transfer passes.

Use readouts already produced by the same action/outcome cycles, shared
evaluation states where leakage rules permit, paired within-root descendants,
and root-blocked randomization. Do not buy more tokens, rank, epochs, replay,
task families, or parent turns to repair a null; each changes the treatment
and creates a mechanism sibling. Stop harm immediately. Stop class C at the
root cap and class A at `H1`. This concentrates GPU on resolving the next live
causal uncertainty rather than maximizing experience volume.

## 6. The `META/SHAM x parent` factorial is not semantically clean by construction

A sham cannot simultaneously preserve the candidate's full semantics and
remove the candidate semantic relation. If `META` says, in effect, “compare a
prediction with a later outcome and revise the governing belief,” then a
control containing that same operative cross-state relation is contaminated;
one without it is semantically different. Matching topics, prose style,
source class, or token count does not solve this logical problem.

“Dose matched” must also be decomposed:

- Ex ante exposure can match unique grounded identities, derivative views,
  rendered response tokens, preservation mix, rank/capacity, optimizer slots,
  epochs, and task opportunities.
- It cannot guarantee matched semantic information, target difficulty,
  gradient signal, behavioral salience, later admission yield, or realized
  parent messages.
- Duplicating weak sham rows to equal tokens changes repetition dose; making
  the sham equally useful may install another real policy. Either can be a
  valid active control, but neither is “the same semantics minus
  metacognition.”

The factorial is nevertheless feasible as a randomized **package** test if
its claim is narrowed. The `META x parent` interaction asks whether the exact
adaptive-parent package has a different effect after `META` than after the
named active control. Because the parent adapts to child behavior, realized
feedback is a post-treatment mediator and will generally differ by bootstrap.
The estimand is not an equal-message-dose correction effect and not a pure
semantic atom.

### Recommended control strategy

Do not certify one corpus as a perfectly semantic-matched `SHAM`. Use three
roles:

1. **`FORM_SHAM`:** matches dialect, self-reference/style, source class,
   rendered exposure, and training mechanics while carrying no intended
   cross-state control relation. It diagnoses format and ritual effects.
2. **`ACTIVE_NONMETA`:** carries an equally explicit, coherent, grounded,
   cross-state but non-metacognitive public policy, with the same ex ante dose
   accounting. It controls for receiving useful structured content, while
   admitting that its semantics differ.
3. **`NONE`:** an adapter-free/raw-birth anchor for generic adaptation damage
   and entry calibration, not the primary causal control.

Use the cheap writer/entry assay to falsify all three roles. For the expensive
parenting factorial, prospectively designate `META` versus
`ACTIVE_NONMETA` as the primary two-level bootstrap contrast; retain
`FORM_SHAM` and `NONE` as bounded diagnostic anchors rather than crossing
every control through the long lifetime. The active control and its selection
rule must be fixed before outcome inspection. If no credible active control
can be constructed without task leakage or covert metacognitive content, the
2x2 may still be a developmental package feasibility study, but it cannot
identify a metacognition-specific bootstrap effect.

Report every result conditional on the named control. A positive interaction
supports “this `META` package increased benefit from this exact adaptive
parent relative to this active control.” It does not show that a perfectly
matched semantic sham was beaten, because such a sham is not available.

## 7. Exact recommendation

Amend the scale language to:

> Writer passage alone authorizes zero developmental scale. If task transfer
> has not passed at the first fixed horizon, one and only one prospectively
> bounded within-root developmental runway may proceed when delayed,
> binding-sensitive, post-bootstrap personal-write evidence passes the causal
> proximal ticket and all ritual and harm gates. Imprecision is resolved only
> by independent roots at the same horizon. Practical null without that
> ticket, ritual/style-only change, or harm authorizes no extension. Failure
> to pass transfer at the final fixed horizon ends the candidate; no further
> lifetime is licensed.

Treat `META/ACTIVE_NONMETA x parent absent/present` as a package factorial,
not a pure semantic subtraction. Use `FORM_SHAM` and `NONE` as bounded
diagnostic anchors. Prebind `H0`, `H1`, `R0`, `Rmax`, GPU ceiling, uncertainty
looks, effect/harm margins, and control roles before reading outcomes. Do not
select scaled-THINK topology pending Fable.
