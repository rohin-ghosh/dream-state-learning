# PCFL-Active-Stream V3 repair map (nonauthoritative)

Status: advisory design note only.  This is not a change proposal, intake,
ratification, scope authorization, implementation instruction, test result, or
scientific evidence.  It deliberately does not adjudicate the V2 deliberation.
It recommends a minimal, coherent V3 successor that preserves the paper's
text-first target: a deterministic finite synthetic construct plus a complete,
failure-inclusive eight-root DEV stress test.  It does not authorize or propose
LoRA, rank-pyramid work, training, Stage C, Stage D, or a scientific/GPU call.

## Recommended V3 disposition

Prepare a new exact-byte V3 proposal rather than patching V2 in place.  Retain
the scientific object, the eight independent twin-pair roots, target-blind
unmount/reconsolidation design, all failure inclusion, the current empty claim
set, `DEFERRED_NEW_PREREGISTRATION` for Stage C, and
`NOT_REQUESTED_STAGE_D` for text-stage D.  Replace only the internally
inconsistent operational machinery below.  Every V3 gate remains prospective
until an authorized implementation, CPU certification, independent review, and
later distinct scientific-call authority occur.

The recommended V3 decisions are:

| Issue | V3 choice |
|---|---|
| AS-EXT and row count | Preserve six full-surface arms and select exactly one AS-EXT configuration at A2 by an immutable non-performance rule before B0.  Do not run two AS-EXT configurations over B3. |
| Field closure | Use machine-readable schemas, a closed component registry, a 27-class by component permission matrix, noncircular field IDs, and trace-indexed equality. |
| Fork isolation | Use a named local broker/TCB and isolated worker processes; destruction means logical revocation plus worker teardown and bounded non-reachability, not unverifiable physical erasure. |
| Paired randomness | Use a pinned local deterministic sampler and logged counter-based common random numbers; provider seed equality is not accepted as exact CRN. |
| Terminal semantics | Separate procedure sealing, independent review, and deterministic terminal classification; make the machine total and acyclic. |
| Result limits | Make `RENDERER_BOUNDARY` an orthogonal limitation tag; retain favorable/null as result classes and remove all active noninferiority language. |
| Namespace | Introduce a complete V3 claim/test namespace and V3-only maps; do not machine-alias active V1/V2 names. |
| Ratified work | Let a V3 ratification authorize only a narrowly listed A0--A2 implementation and CPU-fixture phase.  B0, scientific model/provider calls, GPU, B1--B3, and all claims remain separately gated. |

## 1. AS-EXT: preserve the fixed roster

Choose the **single-pre-B0-AS-EXT** design.  At A2, freeze both candidate
specifications for provenance but select one `AS_EXT_PRIMARY` by a
non-performance, non-result property such as a predeclared lexicographic
ordering of canonical configuration digests.  The other candidate is not a B3
arm, does not receive B3 target evaluations, and cannot enter a post-B3
selector.  If comparison to the second candidate is desired later, it needs a
separate design and an explicit row/resource budget.

This choice is preferable to silently treating two condition-specific
outcomes/failures as one row, and it avoids an outcome-conditioned comparator.
The pre-B0 classifier must use `AS_EXT_PRIMARY`, never a post-B3 designation.
`POST_B3_DEV_DISPOSITION` may choose a display ordering only; it has no input
to a descriptive sign, terminal class, completion, Pareto decision, or any B3
path.

Bind the arithmetic in the V3 statistics, resource, test, release, and paper
contracts as follows:

```text
ordinary full-surface rows = 64 targets/side x 2 sides x 6 arms = 768
P1 sentinels                = 92
P2 lagged-snapshot rows     = 36
P3 first-acquisition rows   = 12
---------------------------------------------------------------
B3 target-evaluation rows/root                               = 908
eight roots                                                   = 7,264
```

The six binding-only diagnostic actions remain nested actions, not target
evaluation rows.  By contrast, a second AS-EXT full-surface arm is 64 targets
per side times two sides, or **128 additional target-evaluation rows/root**:
it would require an explicitly revised 1,036/root and 8,288-total protocol.
V3 should not claim both designs simultaneously.

## 2. Closed executable component and field system

Replace the V2 eight-stage matrix with one closed, hash-bound component
registry.  The registry is the authority for every executable reader, writer,
service, IPC boundary, audit endpoint, and post-B3 process.  V3 should use the
following exact component IDs (no implicit helper, cache, logger, exception
handler, provider adapter, or filesystem boundary is permitted):

```text
C01 GENERATOR
C02 OPPORTUNITY_TARGET_ALLOCATOR_CERTIFIER
C03 WORLD_ENVIRONMENT_EXECUTOR
C04 RENDERER
C05 SCHEDULER
C06 ORDINARY_ARM_INSTALLER
C07 ORDINARY_WAKE_ACTOR
C08 PUBLIC_WITNESS_EXTRACTOR
C09 DREAM1_COMPILER
C10 DREAM2_COMPILER
C11 SLEEPER_AND_SELF_STORE
C12 SELF_READER
C13 FORK_CONTENT_BLIND_RANDOMIZER
C14 FORK_INSTALL_BROKER_TCB
C15 FIXED_SHAPE_SEMANTIC_INSTALLER
C16 DIAGNOSTIC_READER_ACTOR
C17 METADATA_ONLY_RESETTER
C18 DELTA_COMPILER
C19 EVALUATION_INSTALLER
C20 STERILE_EVALUATION_ACTOR
C21 SCORER
C22 RESOURCE_AUDITOR
C23 TERMINAL_AUDITOR
C24 POST_B3_REPORTER
```

The component registry must bind a process identity, direct inputs/outputs,
writer/reader permissions, persistence boundary, log/cache/error channels,
allowed IPC edges, runtime image digest, and destruction/teardown obligation
for each ID.  Any process or boundary not listed is a hard closure failure.
The broker is deliberately named rather than hidden in a route abstraction;
it is a minimal trusted computing base, not a cognitive component.

Bind a `27 x 24` machine-readable permission matrix, one row for every V2
information class and one column for every component above.  Each cell is
`FORBIDDEN`, `DIRECT`, or `DERIVED(transform_id)`.  `DERIVED` is valid only
when `transform_id` names a closed deterministic transform with declared input
field IDs, output field ID, shape, reader set, and destruction rule.  It is
not permission to aggregate arbitrary inputs.  The row for
`COMPOUND_RESTRICTED` is computed from its named source-class set by
intersection; it cannot grant a broader reader than any source class.

The V3 matrix must, at minimum, enforce these non-negotiable entries:

- `HIDDEN_TRUTH_AND_TARGET_ALLOCATION`: direct only to C01, C02, C03, and C21;
  forbidden to every cognitive, fork, evaluation, resource, and post-B3
  component.
- `ARM_AND_CAPACITY_ASSIGNMENT`: direct only to C02, C06, C15, C19, and C23;
  never a policy, target, score, or compiler input.
- `EXPLORATION_ASSIGNMENT_METADATA`: direct only to C13 and C23; C17 may have
  only a fixed-shape derived reset key.  It is forbidden to C01--C12 and
  C18--C22.
- `EXPLORATION_CAPABILITY_AND_HANDLE_METADATA`: direct only while live to
  C13--C17.  It is forbidden to C23; C23 receives only a distinct sealed
  `DESTRUCTION_AND_ABSENCE_RECEIPT` after revocation.
- `EXPLORATION_MEMORY_CONTENT`: direct only to C15 and C16 before the single
  probe; forbidden after reset and forbidden to C18--C24.
- `BRANCH_PUBLIC_EVENT`: direct only to C03, C08, C18, and C21; C18 receives
  only the post-unmount lawful branch event.
- `BRANCH_DELTA`: direct only to C19 and C20; no life writeback is permitted.
- `A2_PREMODEL_CONFIGURATION`: each component may read only its component-
  indexed frozen slice, not the complete class.  C24 receives only declared
  hash/aggregate derivatives.
- `POST_B3_DEV_DISPOSITION`, `PRIOR_RESULTS`, and `RESOURCE_AUDIT`: direct
  only to C24 after all B3 seals; all B3 components are forbidden.  C24 may
  receive only sealed aggregate/hash transforms, never live clocks, handles,
  A2 bytes, routes, or failure internals.
- `TIMING_AND_RESOURCE_TELEMETRY`: direct only to C22 and C23.  It is never a
  cognitive, retry, target, routing, or resource-abort input.

All other positive cells should be written explicitly rather than inferred
from a prose role name.  The V3 validator should prove both matrix dimensions,
exact component-ID equality with the registry, exact class equality with the
ontology, and the absence of undeclared IPC/log/cache fields.

### Field identity and equality

Use only canonical machine-readable schemas as the definition universe.
Markdown is explanatory and cannot create a `field_uid`.  Let
`schema_set_digest` be the SHA-256 of the canonical sorted schema files and
their canonicalization specification; it expressly excludes generated IDs,
the field registry, and the ontology manifest.  Then define:

```text
field_uid = SHA256(schema_set_digest || canonical_schema_path || wire_tag || field_version)
```

This is noncircular and reproducible.  The registry records each `field_uid`
once, plus its class, taint-source set, writers/readers, transforms, wire
digest, planned finite instance-domain generator, shape/status alternatives,
persistence, revocation point, and receipt class.

Equality is per trace, not a global union of mutually exclusive outcomes:

```text
U_plan(trace_id) = finite planned slots, including every status/failure slot
E_emit(trace_id) = emitted slot IDs, exactly once each
require E_emit(trace_id) = U_plan(trace_id) for every registered trace
```

Success, denied, malformed, timeout, reset, crash, unavailable, and abort are
values of fixed registered slots, not late-created alternative fields.  A
supervisor owns the corresponding crash/abort slots on every trace.  Separately
bind a finite fixture suite `F`; require all planned trace IDs to appear once
and require the union of emitted `(trace_id, slot_id, status)` to cover every
prospectively required alternative in the suite coverage table.  A missing
alternative fixture, duplicate slot, unknown field, or field emitted on a
wrong trace fails closed.

## 3. Honest fork isolation, revocation, and paired randomness

V3 should not promise that ordinary Python objects are nonreifiable or that an
application can physically erase every allocator, OS, or provider copy.  Use
the following bounded and auditable contract instead.

1. C13, C14, C15, C16, C17, and C18 are isolated local processes with distinct
   credentials, no shared heap, no shared writable filesystem, no debug
   endpoint, and an allow-listed IPC graph.  C14 is the explicitly trusted
   broker/TCB; its sole role is opaque route delivery and one-use installation.
2. An install capability is a broker-owned, single-use channel with a fresh
   opaque handle for each trace and mutation trial.  The handle authorizes a
   fixed-shape write to one sealed clone slot, exposes no destination discovery
   or semantic read, and becomes invalid after its one attempt.  Mutation
   equality compares canonical public transcripts, fixed shapes, route counts,
   schedules, and sealed nonsemantic receipts; it never requires literal token
   reuse across trials.
3. `destroyed` means: broker revocation, closure of the allow-listed IPC edge,
   termination of workers holding live treatment/handle state, deletion of the
   declared ephemeral store, and a bounded non-reachability check over the
   registered runtime/process/log/cache domain.  It does not assert physical
   erasure beyond the named TCB.  Remote providers are forbidden on this fork
   path unless a separately frozen provider retention/cache contract extends
   the TCB and is independently accepted.
4. The terminal auditor receives sealed assignment records and absence
   receipts only, never a live capability, route, semantic treatment, timing
   stream, or reset workspace.

For P1, choose actual common random numbers rather than a weaker seed claim:
use one pinned local deterministic sampler, a fixed tokenizer/model/runtime
image, a counter-based uniform stream keyed by the frozen pre-fork seed and
indexed by `(request_id, token_position, draw_index)`, and a fixed maximum
consumption schedule.  Log the canonical request, stream commitment, sampler
version, and output.  AUTH/TWIN/NULL pairs use the same stream indices; cuts
and shams reuse their assigned stream and never resample.  Assignment, branch,
label, lane, route, handle, and installation descendants are excluded from the
seed derivation.  If local deterministic sampling cannot be delivered, V3 must
state the weaker `paired canonical seed/request equality` invariant and must
not call it exact paired randomness or CRN.

## 4. Result signs, attribution, shortcut, and resources

### Conformance is not a favorable result

Make every A0--A2 and B3 conformance test pass on complete, correctly scored
observations of either direction.  In particular, split the current T04-like
obligation into:

- `COMPILER_CONTROL_CONFORMANCE`: identity/lifecycle/cursor/shape,
  target-blindness, intervention execution, accounting, and complete
  failure-inclusive scoring; and
- `COMPILER_CONTROL_DESCRIPTIVE_SIGN`: the predeclared directional vector
  consumed only by terminal classification.

The same separation applies to any B3 direction currently phrased as a gate.
B1/B2 construct stopping rules remain validity gates only where they concern
construct validity rather than an empirical favorable direction.  A complete
valid B3 surface lacking a favorable sign is
`PROCEDURALLY_COMPLETE_NULL`, not a failed conformance test.

### Finite operational shortcut/path audits

Define `solves_excluded_route` and the single-return audit over a finite,
presealed domain: held-out renderer/root IDs, exact controller build, typed
action grammar, action cap, seeds, predictor family/hyperparameters, feature
set, resource budget, and deterministic threshold.  Instrument reference IDs
and a typed provenance/dataflow predicate for path use.  Define
`MODEL_OWNED_PATH_USE` per item and the root reducer explicitly as a
prospectively frozen comparison of authentic, `MISBOUND_MEMORY`, and
`RAW_EVIDENCE_POLICY` values.  The conclusion is only that no excluded route
was found in that named audit domain; it is never a proof that no pretrained
semantic or policy-prior route exists.  A detected hard route remains
`STOP_TEXT_ORGAN_INVALID`.

### Retention terminology

Keep the finite arithmetic but rename the third P3 component everywhere to
`FINITE_RETENTION_TOLERANCE_0P05`:

```text
P3_w = min(A_w - tau_w,
           L_w - tau_w,
           L_w - A_w + 0.05)
```

The final component means only that the sealed same-root 6L value did not fall
more than 0.05 below the sealed acquisition value.  It is a deterministic
finite descriptive sign, not noninferiority, equivalence, an interval, or a
population statement.  A V3 semantic lint must reject `noninferiority`,
`non-inferiority`, `NI`, `confirmation`, `power`, `powered`, `plateau`, and
`LoRA execution` from active graph nodes, tests, evidence paths, status names,
claims, figures, filenames, and result text.

### Pareto missingness and comparability

Freeze a resource-coordinate schema before B0 with units, direction,
precision/rounding, measurement boundary, shared-cost allocation,
amortization denominator, and a pairwise applicability mask for each
configuration pair.  A coordinate may be excluded only when it is declared
inapplicable for both members of the pair before execution.  If it is
applicable and `NOT_MEASURED` for either member, the pair is incomparable and
neither can be called Pareto-dominant.  Missing mandatory data is
`RESOURCE_INCOMPLETE`; it is never zero.  No scalar efficiency score, later
weighting, or post-B3 AS-EXT selection is allowed.

## 5. Fresh V3 namespace and terminal machine

Create new V3-only `claim_namespace_map.json` and
`claim_test_applicability.json`, both hash-bound to the V3 change.  Use
`PCFL_V3_C0` through `PCFL_V3_C5` for the future/deferred conceptual claim
records, with `current_claim_ids = []`; use `PCFL_V3_T01` through
`PCFL_V3_T21` for all V3 acceptance tests.  Historical V1/V2 IDs may appear
only in a nonnormative predecessor crosswalk and cannot satisfy a V3 join.

Use this total acyclic machine, evaluated in the written order:

```text
PROPOSAL_ONLY
  -> NOT_RUN                         (no scientific dispatch)
  -> A0_A2_IMPLEMENTATION_REQUESTABLE (after V3 ratification only; nonautomatic)

A0_A2_IMPLEMENTATION_REQUESTABLE
  -> A0_A2_IN_PROGRESS               (only within ratified CPU scope)
  -> NOT_RUN                         (scope absent, declined, or incomplete before dispatch)

A0_A2_IN_PROGRESS
  -> A2_SEALED                        (all scoped CPU fixtures and review pass)
  -> NOT_RUN                         (no scientific dispatch; no inference from fixture failure)

A2_SEALED
  -> B0_IN_PROGRESS                   (only under separate exact scientific-call authority)

B0_IN_PROGRESS | B1_IN_PROGRESS | B2_IN_PROGRESS | B3_IN_PROGRESS
  -> STOP_TEXT_ORGAN_INVALID:INCOMPLETE_AFTER_DISPATCH (abort, missing assigned work, or unreviewed change)
  -> STOP_TEXT_ORGAN_INVALID          (registered construct/shortcut/validity failure)
  -> next named phase                 (only after the prior phase's required seal)

B3_SEALED
  -> REJECT                           (independent provenance/reproduction/completeness/claim-lint rejection)
  -> STOP_TEXT_ORGAN_INVALID          (registered validity failure found on the sealed package)
  -> PROCEDURE_SEAL                   (all mechanical validity conditions pass)

PROCEDURE_SEAL
  -> INDEPENDENT_REVIEW

INDEPENDENT_REVIEW
  -> REJECT                           (review rejects reproducibility, provenance, completeness, or lint)
  -> TERMINAL_CLASSIFICATION           (review accepts the seal)

TERMINAL_CLASSIFICATION
  -> FAVORABLE_DESCRIPTIVE             (all frozen descriptive signs)
  -> PROCEDURALLY_COMPLETE_NULL        (otherwise)

FAVORABLE_DESCRIPTIVE | PROCEDURALLY_COMPLETE_NULL
  -> MAY_REQUEST_FRESH_ASSOCIATIVE_LORA_DELIBERATION

NOT_RUN | REJECT | STOP_TEXT_ORGAN_INVALID
  -> INELIGIBLE_FOR_ASSOCIATIVE_LORA_REQUEST
```

`PROCEDURE_SEAL` contains no reviewer acceptance of a label; the reviewer
checks it, then a deterministic classifier applies the frozen signs.  Thus no
terminal state is circular.  `RENDERER_BOUNDARY` is an orthogonal
`limitations[]` tag permitted on either valid complete terminal class when the
presealed renderer rule allows it and no hard shortcut occurred.  It narrows
all language to the named frozen renderer and requires separate panels; it
does not force a favorable complete surface into a null.  A hard shortcut is
never a tag and always stops the affected construct.  `NATIVE_BASELINE_DOMINANCE`
may likewise be a separately reported finite limitation on the affected
comparisons, without being promoted to an efficiency or general-superiority
claim.

`MAY_REQUEST_FRESH_ASSOCIATIVE_LORA_DELIBERATION` remains merely permission to
ask for a fresh architecture deliberation.  It does not create a LoRA
artifact, training scope, rank-pyramid work, model call, GPU allocation, or
scientific claim.

## 6. Requested V3 ratification scope

The V3 human decision should authorize a useful but bounded next step after
the repaired bytes have completed the durable deliberation.  The recommended
post-ratification scope is:

```text
implementation:
  create only the V3 generator/schema/registry/component-matrix/serializer,
  local broker/process harness, deterministic sampler test double, fixture
  ledgers, semantic-lint, state-machine validator, and CPU conformance tests
  required by PCFL_V3_T01--T21 through A2
execution:
  run only deterministic local CPU fixture/certification tests against
  synthetic fixtures and test doubles; record no B0--B3 result
review:
  obtain independent A2 implementation/reproduction review of the sealed
  implementation and CPU artifacts
```

The authorization must be limited to named V3 implementation/test locations
and the exact SHA-bound V3 bytes, must preserve all existing repository work,
and must stop at `A2_SEALED`.  It expressly forbids scientific model/provider
or network calls, GPU work, real experimental inference, B0--B3 execution,
training, adapters, LoRA, rank-pyramid work, Stage C, Stage D, publication,
claims, root reuse, new rows, and changing frozen scientific bytes.  A later
scientific dispatch needs a new exact human decision over the sealed A2 hash,
the independent review, exact model/backend/sampler, root/stage/resource
scope, and any GPU authorization.  Favorable CPU certification is conformance
only, not scientific evidence.

## Residual risks to carry into V3 deliberation

- A finite renderer/semantic audit can find specified shortcut families but
  cannot prove absence of all pretrained priors; paper language must retain
  that boundary.
- Local exact CRN and process isolation constrain backend choice.  Relaxing
  either must weaken the corresponding claim/invariant explicitly rather than
  preserve its current words.
- The selected single AS-EXT protects the fixed roster but does not establish
  that the unselected candidate would behave similarly; it must remain absent,
  not implicitly equal.
- Logical revocation is only as strong as the named broker, OS isolation, and
  retention boundary.  The TCB and its threat assumptions need independent
  review before any scientific dispatch.
- A completed favorable description, a complete null, native dominance, or a
  renderer limitation all remain finite DEV observations.  None supplies a
  population, efficacy, formal-mediation, online-learning, or successor claim.
