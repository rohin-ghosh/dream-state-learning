## 1. Requested final checks

### 1.1 Fixed deployment slots and cumulative replay — PASS

The repaired writer prospectively allocates:

- childhood: one `THINK_TO_ACT` and one `DREAM_STATE` slot for each of 12
  opportunities = 24 target slots;
- deployment wake: one `THINK_TO_ACT` slot for each of 48 programs;
- deployment DREAM: one `DREAM_STATE` slot for each of three eras; and
- 20 fixed anchor positions in every fit.

All accepted childhood slots remain in every later clean-base rebuild;
deployment slots accumulate through the current cut. Empty scientific slots
are deterministically replaced from a presealed task-disjoint rehearsal pool.
Every scientific/rehearsal target receives four exposures. This is a complete
bounded replay policy, not a hidden curator.

The position formulas are correct:

```text
childhood j=1: 4*(8*1)+20 =  52
childhood j=2: 4*(8*2)+20 =  84
childhood j=3: 4*(8*3)+20 = 116

deployment k=1: 4*(24+16+1)+20 = 184
deployment k=2: 4*(24+32+2)+20 = 252
deployment k=3: 4*(24+48+3)+20 = 320
```

At the exact suffix and sequence maxima:

```text
320 positions * 256 labeled tokens = 81,920 labeled tokens
320 positions * 2,048 attended tokens = 655,360 attended tokens
```

Those bounds include empty-slot rehearsal replacements because the replacement
occupies the same slot/exposure schedule. The terminal calibration now uses the
same 320-position geometry and has explicit fit/lifecycle gates. This raises
the older resource advisory's 128-position cap, but does so openly and makes
measured runtime a promotion gate; it is no longer an arithmetic contradiction.

One implementation assertion should be made explicit in the final bytes:
every anchor and rehearsal suffix, including EOS, is also capped at 256 tokens.
The present global “complete target” wording strongly implies this, but the
hard 81,920 proof should not depend on implication.

### 1.2 Rehearsal padding and slot-normalized loss — PASS

The v2 missing-padding defect is closed. The reservoir is presealed before
root generation, large enough for every empty slot through the terminal
schedule, bucketed by native target type/length, and mapped by immutable
cycle/cut/type/ordinal rather than treatment yield. P and U therefore have the
same positions, slot weights, optimizer opportunities, and anchor positions.
Padding remains labeled as padding.

Loss is averaged within each response suffix and then across slots, so a
longer child response does not get more causal weight merely by containing
more tokens. Actual label-token differences remain a resource receipt, not a
dose claim. This is the correct resolution of target-length matching without
allowing one branch to inspect the other's targets.

For implementation, bind the exact reduction formula over the four repeated
positions and the 20 anchor positions so “across slots” has one executable
meaning. That is a testable encoding detail, not a remaining architecture
blocker.

### 1.3 CompilerGym support law — PASS WITH ONE MECHANICAL REPAIR

Section 11 now defines the missing deployment admission rule:

- earliest complete native response per program;
- numeric prediction before a schema-valid dispatched action;
- either first positive incumbent improvement, or expectation violation plus
  belief/action revision followed by a nonnegative recovery;
- outcome excluded from the supervised suffix;
- a separately frozen non-inferiority guard for deployment DREAM; and
- identical would-be slot computation in all cells.

This is a prospective, public-outcome law. It cannot select by later probes,
arm label, score magnitude, or downstream behavior.

Residual blocker: “explicit belief/action revision” is semantic unless the
live interface exposes a typed field or frozen mechanically parsed relation.
A free-text LLM judge would become hidden SLEEP intelligence; a regex would
reward dialect rather than revision. Before source initialization, bind a
mechanical predicate such as a native pre-outcome revision object citing the
violated prediction/event and declaring the changed scoped assumption/action,
or reduce the gate to an action/event relation computable from typed records.
The content may remain child-generated; only admission must be mechanical.

### 1.6 Environment-specific DREAM guard — PASS, terminal timing edge

Section 8 explicitly dispatches to Codebreaker/RuleShift guards in childhood
and the separate Section 11 CompilerGym guard in deployment. A successor is
not trained merely because it is syntactically valid: restoration and an

Residual blocker: one DREAM opportunity is scheduled per 16-program era, and
the third era ends at program 48. If the terminal scheduled opportunity occurs

reserved final continuation inside programs 16, 32, and 48 (or before the
last program of each era), with an early request replacing that call. The
reserved continuation must already be inside the 12-call/2,048-token wake
allocation. This changes no resource total and makes all three DREAM slots

> output, or cross-life data to feed the child, DREAM, compiler, trainer, or

masked parent scaffold in childhood training, and public-world outcome/
admission bit. It also conflicts with Section 7's statement that the sealed

Repair the scope by naming allowed and forbidden edges precisely:

- allow the frozen parent only through the closed childhood correction channel;

  content, future outcomes, probe information, reporter output, and cross-life
  data from entering child/DREAM/training/later life.

This is a scope-byte blocker because the current requested implementation and
forbidden scope cannot both be obeyed literally.
