# PCFL-Compose growing-life design and lifetime-validity audit

**Date:** 2026-09-02  
**Status:** read-only scientific/design advisory. This is not architecture
consensus, human ratification, implementation authority, a model/GPU run, or
scientific evidence.

## Executive ruling

The current `r=9,c=5` construction is a valid **one-cycle semantic gate**, but
it is not a lifetime experiment. It contains 13 factor-bearing tree events and
two public revision events (plus two later audit events). No tokenizer-exact
calculation can turn those 15 events into a `3 L_native` life without padding,
repetition, or inflated rendering. Its present `3L` label and conditional
`0.75/1.5/6L` fill are therefore unsupported.

The smallest coherent lifetime extension is a **chain of symmetric
D4-complete factor blocks**. Each block attaches 13 fresh factor vertices and
13 fresh tree edges to one suffix carried forward from the preceding block.
The whole life remains one tree before local validation chords. The
composition orientation is shared life-wide; a permanent global hub is not.
This gives:

- genuinely increasing independent per-life information rather than filler;
- bounded local write episodes that fit one context;
- exact old, new, and cross-era target cohorts;
- a local `2^4` target-orbit theorem for every D4 item;
- constant-size compiled reads when memories share a life-wide gauge; and
- a raw episodic sufficient frontier that grows with cross-era graph distance.

That last contrast is the honest scaling mechanism. A global double-star would
make raw target-time induction constant-depth forever and should not be used
for a lifetime/saturation claim.

This lifetime construction should **not** be folded into the current minimal
text ratification. First run the one-cycle semantic gate with no `L_native`
label. Only if generic prospective Dream-1, raw-outcome Dream-2 self-revision,
and target action use work there should a new material change ratify the
recurrent growing-life protocol. The current change should delete or disable
S1C rather than pretending the minimal module occupies four lifetime bins.

## 1. What a lifetime point must mean

Let `L_native` be the pinned resolver's tokenizer-exact usable raw-history
budget after subtracting the exact frozen system/task prompt, current public
state and goal, THINK workspace and operation history, reader response reserve,
and output reserve. It is a property of an exact invocation contract, not the
model card's maximum sequence length.

A checkpoint at multiplier `alpha` must be a prefix of one chronological life
whose public eligible action/outcome rendering contains approximately
`alpha * L_native` tokens. The realized token count, not a nominal episode
number, is reported. Successive checkpoints are nested prefixes. Every interval
adds new independently sampled factor-bearing tree edges. Repeated prose,
paraphrases, dream views, validation chords, targets, and distractors do not
qualify as the information that advances a checkpoint.

The four proposed bins remain useful:

```text
alpha in {0.75, 1.5, 3, 6}.
```

`0.75L` is the within-window control. `1.5L`, `3L`, and `6L` are finite
post-context points. Each is reported with its exact realized source tokens,
total public-event tokens, unique tree-edge count, unique factor entropy or
description length, semantic records, and all other stores.

## 2. Minimal chained block

### 2.1 Nodes

Begin the life with one suffix connector `q_0`. At block `b >= 1`, introduce
exactly these 13 fresh vertices:

```text
one stem hub:                 p_b
four paired stem choices:    (u_b,l, v_b,l), l=1..4
four decisive suffixes:      j_b,l, l=1..4
```

After the block, define the connector carried into the next block as

```text
q_b := j_b,4.
```

Thus the fourth decisive suffix is a real factor used by the current block and
later becomes the public bridge endpoint. It is not a dummy connector.

### 2.2 Factor-bearing source tree

Execute these 13 fresh source edges before any local validation:

```text
(p_b, q_b-1)                                      [1 bridge edge]
(p_b, j_b,l)                         l=1..4       [4 suffix edges]
(u_b,l, q_b-1), (v_b,l, q_b-1)       l=1..4       [8 paired-stem edges]
```

The first block is exactly the current `r=9,c=5` double-star after renaming
`p_1=u0` and `q_0=j0`. Every later block attaches 13 new vertices by 13 edges
to one old vertex. Therefore, after `B` blocks,

```text
|V_B| = 1 + 13B
|E_tree,B| = 13B
```

and the pre-validation graph is one connected acyclic tree. This is minimal
within the declared chained-double-star family: four independently swappable
D4 stages require eight choice stems and four suffix factors; one new hub is
needed to support those suffixes and align the block to the prior component.
Reusing the previous suffix removes the otherwise redundant fourteenth new
vertex. A smaller universal optimum is not claimed.

The local unexecuted target pair at stage `l` remains

```text
(u_b,l, j_b,l) versus (v_b,l, j_b,l).
```

Each candidate has a three-edge source path

```text
u_or_v_b,l -- q_b-1 -- p_b -- j_b,l,
```

but neither candidate compound is ever executed in eligible experience.

### 2.3 What is shared across life

Share exactly:

1. one life-wide orientation bit `h` (`BA` versus `AB`);
2. one connected gauge class induced by the tree; and
3. the physical connector node between adjacent blocks.

Do **not** share a permanent high-degree stem/suffix hub. With a global hub,
every old/new compound has a three-edge raw proof at every life length. Raw RAG
could then solve any target from a constant number of exact label lookups, so
there would be no graph-distance mechanism for a post-context crossover.

The exact program may privately choose `q_0=e` as a deterministic gauge. The
headline model is not told that anchor or a completion equation. For cross-era
composition to be meaningful, the model's records must nevertheless remain in
one compatible coordinate system, or must carry explicit model-authored
alignment records. Independent block-local gauges cannot support the current
13-item compiled reader and are a construct failure, not a thinker failure.

## 3. Repeated Dream--validation--Dream--sleep chronology

Each complete block is one bounded wake/sleep cycle. It is processed before
the next block arrives, so no cognitive call ever loads the complete past.

```text
W_b   execute 13 new tree actions with fresh handles
D1_b  model reads W_b plus bounded prior SELF-memory reads; commits candidates
A_b   execute the preannounced symmetric revision-chord pair as raw actions
D2_b  fresh model call reads exact D1_b bytes plus raw A_b; owns
      RETAIN/REVISE/ABSTAIN and commits the next semantic delta
S_b   truth-blind sleeper parses, provenance-checks, deduplicates, indexes,
      and realizes the model-owned delta; it carries M_b-1 forward unchanged
B_b   execute the disjoint symmetric audit-chord pair after M_b freezes
E_b   on a clone, run any checkpoint targets; all target outcomes are sterile
```

Use local chord roles analogous to the minimal module:

```text
A_b = {(u_b,1,j_b,2), (v_b,1,j_b,2)}
B_b = {(u_b,2,j_b,3), (v_b,2,j_b,3)}.
```

The paired chords preserve the `u/v` label-swap equivariance. `A_b` is public
validation for the current self-revision. `B_b` is scored only after `M_b`
freezes. At the start of block `b+1`, its raw, unlabeled before/after outcomes
may enter the ordinary public episodic stream; no offline correctness bit,
score, factor solution, or repair ever enters cognition. This delayed release
lets later cycles learn from prior predictive errors without turning a checker
into the write policy.

The exact comparator is offline only. `SELF` later reads only earlier `SELF`
records. Perfect-public-gate, class-informed, exact-program, and oracle-schema
branches remain physically separate and cannot seed later SELF cycles.

### 3.1 Bounded access to old semantic memory

`D1_b` and `D2_b` may use the same atomic, logged reader available to THINK,
but future target identities and goals do not exist in that process. Queries
may be derived only from:

- the current block's public source/chord bytes;
- public entity or time identifiers already in those bytes;
- exact prior model-authored record bytes and public provenance; and
- the model's current bounded workspace.

The minimum useful prior read set is a model-owned record for the carried
connector/gauge alignment plus the life-wide composition-law record. The model
must request those records; a hidden solver may not inject the right factors.
The reader returns no truth status beyond the model's own stored uncertainty.
`NOT_FOUND`, wrong retrieval, gauge drift, false retention, and abstention stay
in the denominator.

The sleeper never re-summarizes the entire history. It writes a delta and an
append-only supersession ledger. Text memory can retain old records externally;
a later LoRA realization may stream the cumulative target-blind training
corpus without placing it in one forward-pass context. Mixing older records
into LoRA replay is permitted and required for retention, but it must be
reported as training data and is not evidence that the Dream call remembered
them unaided.

This design measures recurrent semantic learning with external durable state.
It does not establish a wholly parametric recurrent organism unless a later
condition uses the prior adapter itself for subsequent Dream reads and passes
the same isolation tests.

## 4. Old, new, and cross-era targets

All targets, target fibers, starts, goals, menus, cuts, and evaluation times are
presealed. No target outcome enters any later block or target.

At checkpoint `k` ending at block `B_k`:

- **New D1/D4:** choose four stage pairs and suffixes introduced strictly in
  `(B_k-1, B_k]`, preferably from the latest completed block. The lagged
  `M_k-1` snapshot has never seen those factor-bearing source edges.
- **Old D1/D4:** choose earliest-block factors whose last eligible public
  occurrence is mechanically certified to be more than `L_native` raw tokens
  behind the target invocation. Avoid using a carried connector whose later
  bridge uses would make its evidence young, or account for its actual last
  occurrence.
- **Cross-era D4:** use two old-paired-stem/new-suffix stages and two
  new-paired-stem/old-suffix stages. All four stem pairs are distinct, every
  compound is absent from experience, and all endpoints are supported in the
  one tree. Register old-only, new-only, both, law, and byte-matched sham cuts.

The old cohort is meaningful only at post-context checkpoints. If no eligible
factor's last evidence is older than `L_native`, report `NOT_ELIGIBLE`; do not
relax the definition. New target factors must be genuinely absent from the
lagged snapshot. Cross-era value must fall under the registered old/new cuts,
not merely change prose.

For blocks `a < b`, a raw path from a stem in block `a` to a nonconnector
suffix in block `b` has length

```text
d_raw(a -> b) = 2(b-a) + 3.
```

In the reverse direction it is approximately `2(b-a)+1`, with the exact value
certified from the tree. A four-stage cross-era target's sufficient raw edge
set is the union of its eight candidate paths, not their sum. For the canonical
two-era construction that union is at most

```text
R_raw_cross(a,b) = 2(b-a) + 13
```

tree-edge records, plus the declared orientation evidence. The certifier must
compute the exact union for every target. Compiled globally aligned memory
still needs eight stem factors, four suffix factors, and one law record: 13
atomic items independent of `b-a`.

This is a resource-frontier hypothesis, not guaranteed accuracy superiority.

## 5. The `2^4` target orbit over a growing life

Give every block pair `(u_b,l,v_b,l)` an independent hidden label-swap bit.
Generate both paired source edges and every paired chord symmetrically, with
fresh-handle/event-slot bijections under the swap. The public target menu order,
start, goal, budgets, error behavior, and every non-source target byte are
independent of the hidden bit.

For any registered D4 target, select four distinct paired-stem roles. Its
private target fiber is the 16 whole-life worlds obtained by varying exactly
those four bits while holding all other life randomness and pair bits fixed.
The source stream is equivariant, the fixed target packet is byte-identical,
and the correct four-action sequence changes in all 16 ways. Thus, conditional
on the other life variables and the uniform four-bit prior,

```text
target-only D4 full-trajectory value = 1/16
target-only D4 first-action value     = 1/2
target-only D1 value                  = 1/2.
```

A `B`-block life contains `4B` latent pair-label bits. It is neither necessary
nor computationally sensible to enumerate the global `2^(4B)` cube. CPU
certification must exhaust the local 16-member fiber for every registered
target and separately prove the generator's product/equivariance construction.
Fibers, members, checkpoints, targets, and calls remain nested within the
world-life root and never become replication units.

Do not reuse a target's outcome as evidence about a shared pair bit. Evaluation
processes are isolated clones. If operational evaluation cannot guarantee that,
use disjoint pair roles across evaluated cohorts.

## 6. Token and entropy feasibility

Let:

```text
tau_s = mean tokenizer-exact tokens in one canonical tree event
tau_v = mean tokenizer-exact tokens in one canonical validation/audit event
C     = measured L_native
```

After `B` complete blocks the eligible raw chronology contains approximately

```text
N_tree(B)   = 13B
N_chord(B)  = 4B
T_raw(B)    = sum(tree event tokens) + sum(chord event tokens)
            ~= B(13 tau_s + 4 tau_v).
```

The actual generator must sum exact token IDs, not use the approximation. Pick
the `alpha` checkpoint as the nearest predeclared complete-block prefix to
`alpha*C`, with `0.75C` required to remain below the native limit and all later
points required to exceed their stated threshold. Report the realized ratio.
If complete-block granularity misses a bin by more than the preregistered
tolerance, change the event/world design before model work; never pad text.

For a fixed orientation, independent uniformly sampled tree transformations
are in bijection with gauge-fixed node factors. Before construct conditioning,
the free factor information is

```text
H_free(B) = 13B log2(720) + H(h)
          ~= 123.394B + H(h) bits.
```

Validation and audit chords are deterministic in the factorized family and add
no independent factor entropy. They still count as real public experience and
tokens. If the generator rejects/resamples worlds to guarantee
noncommutation, unique trajectories, or chord disagreement, the formula above
is only a proposal-description length, not the accepted distribution's Shannon
entropy. The final construct must either:

1. use a fixed, disclosed, guaranteed-noncommuting seed scaffold and sample all
   later tree transformations freely, reporting the scaffold's lost degrees of
   freedom; or
2. derive and certify the exact conditional entropy/min-entropy of its accepted
   generator.

Silently reporting `(r+c-1)log2(720)+1` after rejection sampling is invalid.

### 6.1 Illustrative scale only

The exact prompt/tokenizer has not yet been run. For feasibility, if
`C ~= 27,000` and canonical public events average 80--160 tokens, then a
17-event block is roughly 1,360--2,720 tokens. The approximate complete-block
counts are:

| checkpoint | blocks | tree factors/edges | free-factor bits | Dream calls |
|---|---:|---:|---:|---:|
| `0.75L` | 8--15 | 104--195 | 987--1,851 | 16--30 |
| `1.5L` | 15--30 | 195--390 | 1,851--3,702 | 30--60 |
| `3L` | 30--60 | 390--780 | 3,702--7,404 | 60--120 |
| `6L` | 60--120 | 780--1,560 | 7,404--14,808 | 120--240 |

These are planning ranges, not protocol constants. At the measured historical
32B rate of about 53 calls per 29.5 minutes, 240 sequential Dream calls are
about 2.2 GPU-hours per realized life before retries and evaluation. A primary
plus antipode over open and untouched roots is therefore on the order of
4.5--9 GPU-hours for recurrent Dream generation, depending on actual block
count/call length. Checkpoints must reuse one incremental life; rerunning the
prefix independently four times would be waste.

At the measured old saturation recipe of roughly 24 touches per atomic fact, a
final 780--1,560-factor corpus implies roughly 19k--37k QA lines before
multiview expansion. That is below the prior 94k-line LoRA anchor but not yet a
PCFL timing measurement. Four checkpoint adapters per side remain a later
separately ratified transport experiment.

## 7. Legitimate baseline scaling

### 7.1 Native context

The native-context arm receives the complete raw chronology while it fits. At
post-context points it receives a frozen, target-independent most-recent
`L_native` token suffix. No summary, cache, earlier KV state, or checkpoint
memory survives unless a separately named rolling-summary agent baseline owns
that state.

### 7.2 Raw RAG / observed-event graph

Raw RAG stores every immutable public event. A strong implementation may build
a mechanical adjacency index from literal public stem/suffix labels; this does
not solve the group composition. It is evaluated at both:

1. an equal-serialized-token/fixed-resource point matched to compiled memory;
2. a fixed target-time budget curve; and
3. the **construct-sufficient frontier**, the exact union of necessary raw tree
   paths plus orientation evidence certified for that target.

The old fixed ceiling of 25 unique events is valid only for the one-block
module. It is reader starvation for far cross-era targets and must not be
called a baseline failure. On the chained life, the sufficient frontier grows
as `Theta(|b-a|)` while the compiled local factor interface stays at 13 items.
If raw RAG matches accuracy at its sufficient frontier but costs linearly more
reads/tokens, the supported conclusion is amortized target-time efficiency,
not accuracy superiority.

### 7.3 Native A-MEM or linked memory

A faithful native A-MEM condition receives the same chronological public
events and its own predeclared streaming write/link/update budget. It may use
its native target-time retrieval policy and is measured at an equal-token point
and its strongest predeclared native frontier. It must not receive SELF's
factor records, hidden graph paths, target roles, or offline truth. If no
official/vendored faithful implementation is available, record `NOT_RUN`.

Because linked memory may itself create cross-block shortcuts, its actual
target-time cost/accuracy curve is the relevant comparator. Forcing it through
the 13-factor reader or a 25-event cap would manufacture a win.

### 7.4 Compiled text

Compiled text contains only the model-owned SELF deltas plus unchanged older
SELF records. Retrieval is atomic and target-time local. The 13-item D4 cap is
legitimate only after CPU/model artifacts show that all requested records use
one compatible life-wide gauge and that changing any declared item can change
the action. If records are block-local, compiled text needs alignment-chain
reads and its cap must grow just like raw memory.

The exact streaming factor program remains the upper ceiling: it stores one
potential per vertex plus `h`, updates in `O(13)` per block, and solves a target
from local factors. The observed-table arm stores raw edges but performs no
completion. A simple rolling-summary/compiler baseline should be considered at
the lifetime stage so the claimed value is not merely periodic summarization.

### 7.5 Independent-table specificity sentinel

Use the same chained labels, event slots, token envelope, local fibers, and
target rendering. Sample unexecuted compounds independently. Be precise about
the word *entropy-matched*: the prevalidation tree has the same independent
uniform edge marginals and entropy, but factorized validation chords are
determined whereas independent-table chords contain fresh conditional entropy.
That conditional predictability difference is the treatment. The two families
can be token-, interface-, schedule-, and marginal-matched; they are not
joint-Shannon-entropy matched after validation unless a new null construction
proves it. Keep the independent family a specificity sentinel rather than a
full lifetime comparator until this wording is repaired.

## 8. Fatal checks before any lifetime run

1. **False checkpoint labels:** 15 events may not be called `3L_native`.
2. **Gauge drift:** block-local factors without a model-owned alignment path
   make cross-era D4 impossible under the 13-item interface.
3. **Global-hub shortcut:** a permanent hub erases raw-depth growth and leaves
   only database-size interference.
4. **Orbit overclaim:** primary+antipode is a causal intervention, not an
   empirical 16-way estimate; the `1/16` theorem needs every target's certified
   local 16-member fiber and a uniform product prior.
5. **RAG starvation:** a lifetime-wide 25-event cap is invalid on chain-spanning
   targets.
6. **Hidden verifier:** only raw public validation events may reach Dream-2;
   offline exact matching never selects SELF memory.
7. **Target leakage through later dreams:** future target IDs/goals/cuts and all
   evaluation outcomes are absent from the streaming reader, indexes, prompts,
   caches, filenames, and errors.
8. **Entropy fiction:** rejection-conditioned generators may not retain the
   free-factor entropy formula without proof.
9. **Target-construction failures:** every D1/D4 goal needs uniqueness,
   no-shorter-path, no-wrong-prefix-recovery, wrong-law sensitivity, and
   factor-cut certificates in every local orbit member. A total or explicitly
   failure-inclusive generator is still missing.
10. **Repeated-call cost:** 60--120 blocks at `6L` means 120--240 large-model
    Dream calls per life. The experiment is feasible as a DEV sentinel, but a
    16--20-root confirmation plus multiple semantic arms is not a two-week
    entitlement without a measured batched/incremental canary.
11. **Text retention triviality:** append-only text cannot by itself establish
    learned parametric retention. Separate access scaling, semantic correctness,
    target action, and later LoRA retention claims.
12. **Full-organism overclaim:** if later Dream cycles consult compiled text
    while LoRA is used only at final target time, the result is recurrent
    external-state learning plus LoRA transport, not a wholly parametric
    continual learner.

## 9. Staging recommendation

### Current exact ratification: minimal semantic gate only

Keep one `r=9,c=5` module and its full CPU 16-state target-orbit certificate.
Call it the **one-cycle/native-scale semantic DEV gate**, not `3L`. Test:

```text
raw tree -> prospective Dream-1 -> raw A -> model-owned Dream-2
-> truth-blind text sleep -> bounded action
```

Delete/disable the present S1C lifetime fill. Do not add LoRA, a chained life,
or a growth/plateau claim to this change. Its only decision is whether the
generic model can produce and self-revise a causally useful factor account at
all, with the independent-table specificity sentinel and strong text/program
baselines.

### Later material change, conditional on semantic success

Ratify the chained block generator, recurrent prior-memory reader, exact token
cuts, per-block cycles, local target fibers, old/new/cross cohorts, scaled raw
frontiers, entropy accounting, and incremental snapshot semantics together.
Start with CPU certification, then one text-only open life through `1.5L` and
`3L`. Run `6L` only if the recurrent compiler remains semantically valid and
the measured call/token envelope is acceptable. LoRA snapshots require another
bound promotion after text succeeds.

### Cheapest post-context falsifier

Before a four-checkpoint roster, materialize one open factorized root only
through the first complete block prefix above `1.5L_native`; CPU-certify every
registered local orbit but run only the sampled primary life. Preserve the
`0.75L` snapshot from that same prefix. Use one D4 item in each eligible
`new/old/cross` cell and run, in order:

1. exact streaming program plus raw-path sufficient-frontier reader;
2. oracle-schema/class-informed recurrent text, which must maintain one gauge
   and score all three D4 cells; and only then
3. generic SELF recurrent text, with every block's prospective A prediction,
   self-owned revision, delayed B audit, and final action retained.

Stop before antipodes, intervention panels, `3L`, LoRA, or another root if the
exact program is below 1.00, the class-informed/oracle arm cannot preserve the
global gauge, the old item is not actually older than `L_native`, the cross-era
raw sufficient certificate is wrong, or generic memory fails to contain a
causally usable old/new alignment. This is a plumbing/mechanism falsifier, not
evidence for growth or a baseline win.

The planning table implies roughly 30--60 large-model Dream calls per life to
reach `1.5L`, historically about 0.3--0.6 occupied GPU-hours, plus target
resolution and startup. Budget **under two GPU-hours** after CPU artifacts are
green; exceeding that without a diagnosed infrastructure cause stops the
pilot. This is the cheapest honest test that is actually post-context. A
two- or three-block demo is cheaper but cannot answer the lifetime question.

The eventual narrow lifetime question is defensible:

> Does recurrent model-owned factor compilation preserve old action knowledge,
> acquire genuinely new factors, and support cross-era actions at a bounded
> local read frontier as raw episodic path reconstruction grows with life?

That is materially stronger and more precise than assigning four lifetime
labels to one 15-event puzzle.
