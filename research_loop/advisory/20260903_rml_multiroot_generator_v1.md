# RML multi-root world-life generator v1

**Date:** 2026-09-03
**Status:** design advisory only. This file does not ratify architecture bytes,
authorize implementation, release a model/GPU run, or support a scientific
claim. Any implementation must enter the architecture-deliberation path in
`AGENTS.md`, receive exact human ratification, pass independent review, and
obtain a separate GPU gate.

## Executive decision

Build the first paper-bearing RML generator as a **Randomized Typed Causal
Workshop (RTCW)**: a finite, discrete, action-first maintenance world whose
public surface is readable but whose consequential bindings, local programs,
causal topology, schema law, exception placement, and paired counterfactual
side are freshly sampled for every independent root.

One private `pair_root` produces exactly one coupled H/twin pair of world-lives.
The two sides share the complete public target bytes and nuisance allocation,
but a registered hidden involution changes at least two decisive action
bindings. Their ordinary source outcomes differ in the way required to learn
the side. Targets, cuts, target sides, model calls, DREAM samples, and adapter
seeds are nested observations. The **counterfactual pair root is the sole
independent unit**.

RTCW is preferable to a larger affine/table world because it can reuse one
finite transition and certificate engine for all of the required constructs:

```text
ordinary source action -> public state change/outcome
                     -> prospective target-blind schema commitment
                     -> later ordinary support/contradiction
                     -> sealed memory snapshot
                     -> fresh R/N/O/J/P/X target action
                     -> optional randomized on-policy collection
                     -> one reconsolidation -> presealed later action
```

The minimal post-G1 build should be **RTCW-MR1**, not an extension of D0's
fixture namespace: one fluid/thermal pack, two independently generated DEV pair
roots, one honest `2 L_native` cut, two J and two P targets per side, fixed
common source lives, gold/witnessed/program references, and the complete CPU
certificate bundle. It contains no LoRA and no powered on-policy experiment.
It is the smallest generator that can make the planned G2 learned-text test
scientifically different from the current nested single-fixture G1.

## 1. What must change from RML-D0

`rml_d0` should remain an immutable regression micro-fixture. Its checked-in
report is internally green for `CPU_STAGE_A_INSTRUMENT_CONFORMANCE`, with 996
events, 285 cumulative mappings, exact nine-action plans, target-byte twins, J
deletion witnesses, a P atoms-only value of 1/4, and zero model/GPU/network
calls. Those are useful unit-test vectors.

They are not independent lives:

- every target golden is nested inside one deterministic four-code fixture;
- `make_target` recreates one literal target-handle tape, so target diversity is
  algebraic enumeration under repeated public nuisance bytes rather than new
  roots;
- the four conditioner functions and four valve modes form a tiny truth-table
  problem that a generator-aware program can solve by a short exact lookup;
- most source modules render a nearly complete table, making the source look
  like a disguised database rather than a life of selective interventions;
- D0's output strings and handles have never been tested as a model-facing
  renderer, and a literal fixed tape cannot establish absence of handle,
  renderer, or pretrained semantic priors;
- the target environment allows informative public effects, but D0 does not
  compute the best adaptive within-target no-memory policy on the selected
  target slice;
- D0's numerical bit algebra is easy to certify but hard to interpret as a
  reusable causal model without exposing the underlying codebook.

RTCW therefore reuses D0's good engineering ideas—closed actions, pure finite
transitions, canonical bytes, public outcome-only evidence, exhaustive planning,
twin substitutions, run/skip hashes, and compact certificates—while replacing
the fixture generator, program family, public names, source schedule, targets,
root split, and selection measure.

No D0 target, tape, descriptor roster, target digest, or source schedule may be
promoted into RTCW confirmation. D0 remains a regression dependency only.

## 2. Candidate generators

### Candidate A — randomized algebraic relay lattice

Each module applies a sampled affine or permutation map to a small categorical
state vector. Eras add relays; J composes an early map with a new relay; P
withholds one map entry predicted by a root-level affine law. Twins conjugate
the maps by a hidden derangement.

Advantages:

- lowest implementation cost;
- exact Bayes, planning, twin, and P certificates reduce to enumeration or
  linear algebra;
- natural continuation of D0 code and its two-bit state representation;
- source decks and post-context scaling are easy to generate.

Fatal scientific weakness:

- this is still a truth-table/program-induction assay with maintenance nouns;
- a generator-aware baseline can infer the entire useful law from a few rows,
  so DREAM may add only a verbose encoding of an exact small program;
- increasing the vector width makes it less human-readable before it becomes a
  qualitatively richer action world;
- local mappings remain separable enough that J can regress to retrieving two
  independent table cells rather than tracking one state-bearing causal path.

Candidate A is suitable as a CPU mutation family and explicit program baseline,
not as the paper-bearing generator.

### Candidate B — randomized typed causal workshop (RTCW)

Each life is a finite typed workshop containing single-use materials, converters,
routers, regulators, sensors, routes, and a terminal system. Modules execute
short sampled causal programs over public qualitative state. Eras add new
modules and new edges into the same persistent workshop. The program grammar
contains state transformation, compatibility, routing, guarded effects, and a
small number of scoped exceptions. A root-level schema relates neutral public
signatures to local program parameters, but multiple full programs remain
consistent with the source history.

Advantages:

- J is a real state-flow join: an early transformation creates the input that a
  recent guarded module needs;
- P requires a prospective schema without reducing the whole world to one tiny
  affine codebook;
- the same world supports irreversible evaluation, safe source experiments,
  and an on-policy evidence-acquisition block;
- programs stay finite and shallow enough for exhaustive/solver-backed CPU
  certificates and human-readable causal notes;
- graph, program, RAG, reflection, compiled text, and LoRA can all receive fair
  native interfaces over the same action/outcome chronology.

Cost:

- approximately 1.5--2 times the generator/certificate engineering of a direct
  D0 generalization;
- planning certificates require symbolic dominance and belief-state pruning,
  not only a four-value lookup;
- pack-specific transition motifs must be implemented rather than merely
  reskinned.

### Candidate C — continuous noisy maintenance simulator

Use continuous fluid, circuit, and growth equations with sensor noise and a
learned or numerical simulator.

Advantages:

- more naturalistic trajectories and richer active diagnosis;
- less likely to look like a table benchmark.

Disadvantages:

- exact target necessity, Bayes no-life, target-byte twins, and replay become
  approximate;
- numerical tolerance and stochastic outcomes confound memory with simulator
  noise;
- exact legal-history and adaptive-reacquisition certificates become expensive
  or impossible;
- substantially more engineering and evaluation calls are needed before the
  first branch-changing G2 result.

Candidate C is inappropriate for Paper 1's causal-instrument role.

### Selection

Select **Candidate B, RTCW**. Candidate A is cheaper but spends the GPU budget
answering a low-information question—whether an LLM can restate a compact
program already recoverable by a tiny exact solver. Candidate C has greater
surface realism but loses the exact causal and leakage guarantees that make a
bespoke synthetic world scientifically useful. RTCW gives the highest expected
information per engineering and GPU hour because one generated life supplies
J, P, retention, scaling, causal memory swaps, and later on-policy collection
without requiring a second environment or a stochastic oracle.

An explicit generator-aware RTCW program inducer remains a mandatory primary
baseline and is allowed to win. “Avoid exact-program triviality” means the
benchmark must not collapse to one small known lookup; it does **not** mean
crippling or omitting the exact structural competitor.

## 3. Terminology and independent objects

Use `root` carefully:

- **pair root:** one private random draw that generates a coupled H/twin pair;
  this is the independent unit;
- **world-life side:** H or twin under that pair root, with its own ordinary
  public outcomes and per-life memory;
- **public evidence root:** one immutable source action/outcome event that can
  support a semantic record;
- **target item:** one sterile evaluation clone nested in a side, cut, and
  stratum;
- **pack:** a non-isomorphic mechanics family, not a language skin;
- **skin:** a renderer lexicon/template allocation independent of hidden truth.

The generator must never count evidence roots, targets, target sides, cuts, or
adapter seeds as independent world replications.

## 4. Selected latent generative process

### 4.1 Pair-root randomness

For pair root `r`, draw independent, domain-separated private tapes:

```text
K_structure(r)   causal topology and module types
K_law(r)         local program ASTs and root schema
K_exception(r)   scoped exception placement
K_source(r)      source opportunity set and action order
K_target(r)      target skeletons and inventory permutations
K_skin(r)        neutral public signatures and renderer templates
K_handle(r)      pronounceable nonce handles
K_assignment(r)  evaluation/on-policy randomization
K_statistics(r)  bootstrap/randomization auxiliaries
```

No tape consumes a split label, target stratum, target ordinal, proposal result,
side, hidden answer, acceptance receipt, or model outcome as handle material.
Handles are drawn sequentially from the independent handle tape only after the
corresponding public object roster is sealed. A one-handle substitution must
change exactly one public handle and nothing else.

The private tapes are generated from 256-bit non-enumerable roots. Before a
locked run, publish only commitments to the root/tape manifests. Reveal the
seeds after the result seals for replay. Public handles must not be reversible
hashes of a root, counter, target slot, hidden law, or side.

### 4.2 Typed finite state

The common kernel has four object roles:

1. **materials/tokens** carry two or three qualitative public attributes;
2. **transformers** change one attribute under a setting or attachment;
3. **routers/guards** accept or reject a token according to a local
   compatibility predicate and may direct it to a new site;
4. **terminal regulators** require a state, route, and setting before `RUN` and
   `COMMIT` can succeed.

The hidden state is a finite tuple:

```text
(site, time_left, inventory, consumed, token_attributes,
 installed_edges, module_settings, latch_states, observations,
 run_state, terminal, failure_kind)
```

The model sees only the public projection and ordinary action results. Hidden
program nodes, compatibility tables, required settings, counterfactual side,
exception flags, proof state, and target certificates never appear in the
public state.

The generic action family is:

```text
OBSERVE(object_or_site)
MEASURE(object, public_test)
MOVE(route_or_site)
ACQUIRE(object)
ATTACH(object, target_or_port)
CONFIGURE(object, public_setting)
APPLY(tool_or_material, target)
RUN(object_or_process)
COMMIT(goal)
STOP
```

Every action consumes declared time or material. Illegal syntax or an unknown
handle ends the evaluation item with zero and no partial mutation. A legal
failed action returns only an ordinary visible consequence; it never names the
hidden rule, correct component, missing prerequisite, twin side, or score.

### 4.3 Local program grammar

Every module's hidden transition is a canonical AST of depth at most three over
a closed finite DSL:

```text
SET(attribute, value)
PERMUTE(attribute, local_permutation)
ROUTE(port_if_predicate, alternate_port)
GUARD(predicate, child)
SEQUENCE(child_1, child_2)
EXCEPT(public_signature_predicate, alternate_child)
```

Leaves use only finite equality predicates over token state, module setting,
attachment, and route state. The public signature is visible, but its mapping
to the AST parameter is root-specific. The grammar is intentionally small
enough to render as causal statements and large enough that the full root
program cannot be identified by reading one near-complete table.

Required generation constraints at every scored cut:

- the source witnesses no more than 30% of any module's reachable
  state/action table;
- at least 128 complete root programs remain consistent with public source
  history, while their posterior predictive action value for legal-history
  targets is at least .85;
- the relevant schema has at least 20 bits of pre-source description entropy
  under the registered prior;
- no target-visible signature leaves fewer than four equiprobable decisive
  action completions before source history;
- test roots contain canonical AST motifs absent as complete motifs from TRAIN
  and DEV, although their primitives are shared;
- the explicit program baseline receives the entire public grammar and prior,
  never the instantiated hidden AST.

The `128` and `20-bit` values are proposed design constants, not ratified
bytes. They should be changed only before root generation and only if blinded
CPU feasibility shows they are unnecessarily expensive or insufficient.

### 4.4 Root schema

A root contains two higher-order laws, one transformation law and one
guard/routing law. Each maps a neutral three-field public signature to one
local AST parameter through a sampled shallow decision program. Example at the
public semantic level:

> For modules with a `mira` band and a split notch, setting `CALM` preserves
> the carrier attribute; with a ring notch it exchanges the two carrier
> categories.

`mira`, the notch vocabulary, and the setting names are nonce public symbols.
The relation is learnable from events within the life; it has no stable
cross-root meaning. The true program may contain one predeclared scoped
exception, which is used by X but is excluded from a P target unless the P
schema explicitly includes that scope.

The schema must compress multiple module-local observations, but the
certificate does not require exact root-program recovery. It requires that a
prospectively committed prediction be action-identifying on the later P cell.

### 4.5 Persistent causal topology and eras

Each life has four or more eras. Era 0 introduces three independent local
modules and the first half of a future state path. Every later era adds:

- at least one new transformer family;
- at least one new router/guard or terminal relation;
- at least one edge that consumes an output reachable only through an earlier
  module;
- at least one target-independent prospective prediction for the next cohort;
- at least one optional diagnostic opportunity useful in the later on-policy
  extension;
- fresh public evidence roots and new local mappings.

The topology is a typed DAG for ordinary material flow with finite side state
for latches and settings. It is not a collection of independent namespaces.
Every post-native interval must increase the minimum sufficient public causal
description, not merely event count or rendered tokens.

### 4.6 Counterfactual twin involution

After drawing the common public skeleton, create H and twin by a registered
involution `tau_r` that:

- deranges selected transformer outputs;
- deranges selected guard or terminal settings;
- preserves object roster, sites, routes, opportunity schedule, target
  inventory, action budget, renderer template, handles, byte lengths, and all
  pre-action target-visible bytes;
- changes at least two decisive action bindings and the first irreversible
  decision on each J/P target;
- gives each side a unique legal plan under its own public history;
- makes the H-valid and twin-valid decisive component/setting tuples disjoint;
- keeps action-only and binding-erased source marginals equal at every cut.

The paired source uses the same public action schedule. Ordinary effects may
differ and are supposed to identify the side. A target-only or source-action-
string observer cannot identify the side; a legal-history observer can. The
binding-erased audit replaces instance/family handles by their public types and
signature classes while retaining actions, public state values, outcomes, and
rendered substitutions; its within-era multisets must match exactly across
sides at every cut. Chronological handle--outcome bindings remain available as
the intended life evidence.

Whole authentic/twin memory substitution behind unchanged target bytes must
make a successful resolver follow the twin-valid decisive branch, which then
fails or loses value in the authentic environment. Merely lowering confidence
is insufficient evidence of binding use.

### 4.7 Total construction, not result-conditioned first acceptance

RTCW should be a rejection-free constructor over a prevalidated library of
typed motifs:

1. draw a motif with guaranteed H/twin solution orbits;
2. draw hidden label and signature permutations uniformly;
3. draw a public skeleton and nuisance allocation independently;
4. instantiate source modules and target modules from disjoint instance pools;
5. prove the registered structural predicates;
6. emit the root or fail the entire generator build as a software error.

Do not generate thousands of targets and take the first one whose no-memory
value or model score is attractive. There is no per-target acceptance loop and
no result-dependent target replacement. If a future implementation cannot be
made total, every rejection and its conditioning factor must enter the exact
Bayes measure; this is a fallback, not the recommended design.

## 5. Non-isomorphic packs

The complete paper generator has three mechanics packs that share public API
discipline and certificate interfaces but not one transition graph with noun
substitution.

### Fluid/thermal

Materials carry flow and inhibitor attributes. Conditioners transform them;
couplers route them; regulators and relief settings guard stable operation.
The central causal motif is a transformed token flowing through a guarded
pipeline.

### Power/control

Cells, buses, relays, sensors, and grounding links form a directed circuit.
Actions install edges, choose polarity/configuration, and arm protection. The
central motif is path connectivity plus guarded relay activation; state is not
a coolant token and plan equivalence is graph-connectivity based.

### Material/biological

Reagents, substrates, cultures/coatings, containment, and incubation steps form
an order-sensitive production/consumption net. The central motif is resource
production under timing and containment guards. Applying steps in the wrong
order consumes material or activates a scoped exception.

Each pack must have its own transition and plan invariants. Shared abstract DSL
primitives are allowed, but graph isomorphism after relabeling pack nouns is a
pack-validity failure. A CPU certificate should compare canonical transition
motif hashes and reject isomorphic pack cores.

RTCW-MR1 implements only fluid/thermal. The other two packs are required before
confirmation or any cross-pack phase-diagram language.

## 6. Public renderer and anti-prior design

### 6.1 Readable but non-predictive names

The renderer deliberately preserves pretrained competence for ordinary
affordances—technicians move, acquire, attach, measure, configure, apply, run,
and commit—but removes pretrained knowledge of the consequential binding.

Use pronounceable nonce handles such as `narel`, `sovin`, and `tumaq`, drawn
without replacement from a large audited phonotactic pool. Do not expose long
hex strings as the only way a human must refer to an object. A separate opaque
internal ID may exist scorer-side; it is never model-visible.

Visible law-bearing signatures use short neutral tokens (`band mira`, `notch
ring`, `mark su`) whose mapping is independently permuted by root. Avoid words
such as `heater`, `alkaline`, `high-voltage`, `sterile`, red/green, or hot/cold
when those meanings predict the hidden effect. Object roles such as cartridge,
relay, or reagent remain meaningful only as action affordances.

### 6.2 Canonical public records

Every reset and event has one closed canonical JSON record and one deterministic
English rendering. The model sees the English rendering plus a compact action
menu; the scorer hashes the JSON. The English text is a pure function of public
JSON and a sealed template ID. It cannot inspect hidden truth.

Illustrative event:

```text
At the Lattice bench, technician applies cartridge narel to vessel sovin.
The vessel gauge now reads flow: dense; inhibitor: quiet.
```

Illustrative memory atom:

```text
When conditioner family narel was applied to quiet, thin carrier at a safe
bench, the carrier became quiet, dense. Support: events ev-suma, ev-taren.
```

Neither record contains a plan, a target handle, “correct,” a hidden code,
schema acceptance, a target stratum, twin side, or evaluator label.

### 6.3 Renderer split and audits

Template bundles, surface lexicons, nonce pools, list orderings, and syntactic
paraphrases are split by whole root. TEST templates are not used to tune the
model prompt or baseline. The same latent root rendered under two independently
balanced skins is an audit only, not an extra independent life.

Required anti-prior cells are exact generator-aware target-only/state-only and
finite learned probes for identifier-only, renderer-only, template-only,
signature-only, action-frequency, chronology, source-action-string, byte
length, list position, handle morphology, and target-selection history.

No finite audit proves absence of every pretrained semantic prior. Before a
paper run, the frozen no-memory resolver must also remain at or below `.35` on
unseen roots and unseen renderer bundles. A hard unseen renderer or handle
probe above `.35` stops the affected pack; it is not a covariate to regress
away.

## 7. Source/action chronology

One life uses a literal append-only seal order. “Source” means ordinary
environment actions and their visible consequences, not a rendered truth
table.

```text
T0  seal pair-root commitments, structure, source opportunity roster,
    action order, nuisance tapes, and suffix intent

T1  instantiate era-e public modules and safe reset benches

T2  execute a fixed target-blind source bundle; within the bundle, later
    actions cannot depend on outcomes; append ordinary public events

T3  DREAM/replay may propose local relations or a target-independent schema;
    proposal count and output budget were fixed at T0/T1

T4  seal next-era module signatures and committed predictions; no P target
    descriptor, target handle, or evaluation allocation exists

T5  execute the presealed next-era confirming source bundle; append ordinary
    action outcomes

T6  deterministic comparator appends MATCH/CONTRADICTION/UNTESTED against only
    the committed prediction and eligible public outcome

T7  deterministic SLEEP freezes witnessed/supported/provisional/contradicted
    semantic snapshot and baseline inputs

T8  construct and seal fresh evaluation targets from K_target; create a
    read-only evaluation clone

T9  run or skip sterile evaluation; destroy clone; prove source state, future
    tapes, suffix intent, and later evidence hashes are unchanged

T10 continue to the next era
```

Source coverage is a balanced incomplete intervention design, not exhaustive
enumeration. Each bundle contains single-action observations, short two- or
three-action causal trials, negative outcomes, and at least two cross-era
bridge episodes. It never contains a target goal, a target initial state, a
complete evaluation plan, `COMMIT`, or the same terminal sequence as a target.

Action schedules are outcome-blind in the common-deck experiment. The on-policy
experiment deliberately relaxes that one field only after randomized memory
assignment; it does not retroactively turn the common deck into a flywheel.

## 8. Prospective schema lifecycle

P is valid only if the following chronology is literal:

1. after era `e`, the writer sees eligible public events and neutral signatures
   for a target-independent next cohort;
2. it commits one scoped schema and a finite set of module/action predictions;
3. commitment bytes freeze before the next cohort's outcomes;
4. ordinary source actions test at least three predictions on at least two
   modules with provenance-distinct roots;
5. a deterministic comparator appends statuses without proposing or editing;
6. exactly one action-identifying edge for the later P target remains
   unwitnessed locally;
7. the P target and all its handles are created only after status append;
8. witnessed atoms admit at least four equally weighted legal completions with
   optimal action value at most `.35`; the prospectively supported schema
   raises the legal-history/program value to at least `.85`.

Repeated wording, multiple compiler views, duplicated events, or two outcomes
from one reset do not create independent support. Contradicted and untested
proposals remain in the audit ledger and are excluded from positive training.
An offline truth check may score the committed hypothesis after sealing; it may
not guide DREAM, search, admission, target selection, or retrieval.

The writer contrast required at G2 is witnessed-only compilation versus raw
DREAM proposals versus blind self-check versus chronological prediction/outcome
admission. P cannot be credited to DREAM if deterministic program induction or
witnessed atoms explain the same action.

## 9. Target construction

### 9.1 General contract

Targets use fresh instance, goal, route, and site handles drawn from target-only
tapes. They may reuse learned family/signature relations, never a source
instance or source state-goal pair. Target generation occurs after source and
proposal/status bytes freeze and before any model call for that target.

Every target has:

- 6--12 legal environment actions on a shortest successful plan;
- 3--5 consequential causal decisions after excluding logistics;
- at least one irreversible or consumptive decision before success;
- no source state-goal, full plan, terminal suffix, individual memory row, or
  legal set of bounded reader returns that directly closes the plan;
- exact H/twin target-public byte equality and distinct valid decisive plans;
- a fresh process, context, workspace, cache, reader, and target clone;
- one fixed cap with malformed, illegal, timeout, defer, or over-cap scoring
  zero and no retry or replacement.

Target public bytes state a maintenance goal such as stabilizing a named field
loop, not the hidden desired intermediate values. Legal actions and current
public state remain visible after every step.

### 9.2 Strata

`R` — one witnessed relation on fresh instances. Diagnostic only.

`N` — a relation introduced since the prior cut, not a verbatim source episode.

`O` — an era-0 relation whose last direct supporting root is outside the honest
native context projection.

`J` — a connected old-to-new target. An early transformer produces a state or
token that a recent guard/route consumes, and a recent regulator relation is
also needed. The decisive path must contain provenance-distinct old and recent
roots. Removing any registered early transition, state-flow bridge, or recent
guard makes every legal plan fail or exceed the cap. Early-only and
recent-only memories each remain at or below `.35`.

`P` — prospective sparse transfer. Exactly one decisive local edge was never
witnessed; a target-independent schema committed before confirming outcomes
predicts it. Witnessed atoms/graph remain at or below `.35`, while the
prospective schema/program reference reaches at least `.85`.

`X` — a scoped exception target. A public information action distinguishes a
default rule from an exception, a failed provisional path requires
backtracking, and a later analogous target was sealed before the exception
outcome. X is required for full confirmation, not RTCW-MR1.

J is invalid if it is two independent goals concatenated, if logistics supply
most of the claimed depth, or if any one record names the old/recent solution
pair. P is invalid if the “schema” is a late target-conditioned completion or
if source coverage already identifies the held-out edge.

### 9.3 Rejection-free target orbit constructor

For each stratum, sample a latent solution orbit uniformly, instantiate a
guaranteed-solvable motif, add matched distractors, and then independently
permute public slots and handles. Apply `tau_r` to obtain the twin hidden
semantics while copying the full public target object.

The constructor balances every decisive component and setting across public
slot, surface signature, list position, renderer template, cut, and side.
There is no target proposal counter visible to any predictor. Exact target-only
Bayes integrates over the latent solution orbit and must remain at or below
`.35`.

## 10. Preventing within-target reacquisition

Evaluation must allow ordinary feedback without making lifetime memory
optional. RTCW separates **safe evidence collection** from **irreversible field
execution**.

Source and on-policy collection provide resettable benches where diagnostic
actions are useful. Evaluation targets instead have single-use materials,
non-resettable latches, and a cap equal to the shortest plan plus at most one
nondecisive slack action. A diagnostic that distinguishes all remaining hidden
completions either:

- consumes a component needed by the unique plan;
- irreversibly changes the field state;
- costs more actions than the registered slack; or
- yields an observation shared by at least four remaining completions.

This is not asserted from one scripted no-memory policy. For every selected
target, an exact belief-state dynamic program enumerates all adaptive public
policies, including OBSERVE/MEASURE/APPLY outcomes, under the full model action
cap. Its optimal generator-aware no-life value must be at most `.35`. A
legal-history controller over the same public outcome interface must reach at
least `.85`.

The CPU certificate also computes the minimum expected and worst-case action
cost of identifying the decisive hidden class and then succeeding. Both must
exceed the evaluation budget. If an adaptive agent can probe and recover inside
the target, the target is rejected as an instrument bug; lowering the agent's
read budget does not repair it.

## 11. Sealed visibility and process separation

| Actor | May see | Must never see |
|---|---|---|
| pair generator | private tapes, hidden programs, full skeleton | model outputs or scores during construction |
| source executor | hidden transition function, sealed public action schedule | future targets, memories, model scores |
| public renderer | public reset/action/state/result plus template ID | hidden law, solution, side label, certificate |
| DREAM/writer | eligible public ledger, prior semantic snapshot, sealed target-independent next-cohort signatures | target deck/handles, hidden truth, comparator future, program solver, scores |
| comparator | one committed prediction and eligible later public outcomes | hidden truth, target, alternate proposals, model score |
| SLEEP/compiler | semantic rows, statuses, public provenance, fixed view schedule | target deck, target result, hidden program, scorer |
| memory builder | one sealed target-blind semantic snapshot | target/state, solution, cross-life corpus |
| reader service | one query and one sealed memory backend | target/state, assignment rationale, unopened rows, hidden candidates, scores |
| THINK/actor | public target/state, own public outcomes, permitted reader returns, append-only scratch | source truth, certificates, side, condition name, other targets, prior traces |
| exact oracle/certificate | sealed public artifacts plus private truth in an offline process | any write path into cognition, memory, source, target, or suffix |
| scorer | private target truth and sealed trace after termination | source/memory mutation, retry, replacement, future RNG |

Build-time and serve-time visibility are separate manifests. Gold snapshot
construction may use a registered semantic reference plus public source, but
the serving reader receives only sealed rows. Cut-mask construction sees only
the frozen cited row handles and a precomputed semantic-equivalence closure,
never correctness or score.

All public and cognitive records use closed schemas and canonical bytes.
Taint closure covers filenames, directory order, timing classes, exception
text, cache keys, candidate cardinality, reader latency, process environment,
provider state, retry paths, and error messages. Canary tests inject a private
answer into each forbidden input family and require that it cannot affect any
model-visible byte.

Evaluation runs in a clean process with no generator/oracle imports. Adapter,
KV cache, prompt state, indexes, scratch, file descriptors, RNG, temp paths,
and environment objects reset for every target. Run-versus-skip equality covers
source state, public ledger, proposal/status chain, tape cursors, target suffix
intent, and all future-event hashes.

## 12. Whole-root TRAIN/DEV/TEST split

### 12.1 Split unit

Split `pair_root` before generating any public or private descendant. H/twin
sides, skins, targets, cuts, and adapter seeds from one root never cross a
split. Canonical topology hashes, complete AST motif hashes, exception motifs,
and renderer bundles are also disjoint where declared.

Recommended registry:

- **TRAIN:** 24 pair roots per pack, available only for fitting a future shared
  LOOP policy, learned retriever/baseline, or writer-selection model. A frozen
  prompted Paper-1 resolver need not consume them.
- **DEV:** at most 4 pair roots per pack for implementation, prompt, budget,
  baseline, and threshold debugging.
- **LOCKED CAL:** 6 fresh pair roots across packs, descriptive variance and
  feasibility only; never recycled into confirmation.
- **TEST:** at least 8 fresh pair roots per pack (24 independent pairs total)
  for a three-pack confirmation.

The final TEST count should be increased, never reduced, if blinded CAL
variance/power simulation requires it. Target or seed counts cannot substitute
for pair roots.

### 12.2 Program and renderer generalization

Primitive DSL operations may appear in every split. Complete two- and
three-node AST motifs, topology motifs, exception scopes, renderer templates,
and nonce lexicon partitions are allocated before root creation. TEST includes:

- unseen complete AST compositions made from known primitives;
- unseen topology motifs within the same difficulty band;
- unseen renderer templates and nonce pool;
- the same registered action schema and semantic state vocabulary.

This tests compositional generalization without making TEST a new ontology.
Any shared policy or baseline trained on TRAIN is frozen before DEV selection
and completely frozen before TEST unsealing.

### 12.3 Randomness ceremony

Use separate entropy draws for split membership and each root's private tapes.
Bind commitments, counts, and generation software before opening TEST roots.
The model never sees root seeds, split labels, pair IDs, generation counters,
or manifest paths. Publish seeds and full rejection-free replay material only
after final traces seal.

## 13. Lifetime and difficulty axes

### 13.1 Honest native-context axis

Compute `L_native` from the exact frozen model, tokenizer, chat template,
system prompt, target state, workspace allowance, reader return, operation
history, and output reserve. Marketing context length is not the denominator.

Build source life from whole causal cohorts and select checkpoints nearest:

```text
0.5 L_native, 2 L_native, 4 L_native, 8 L_native
```

The last three must be strictly post-native under the actual unpadded rendered
chronology. Each interval adds approximately matched numbers of:

- new modules and unique public evidence roots;
- identifiable local causal relations;
- one old/new state-flow bridge;
- one prospective prediction/support cycle;
- one held-out target opportunity per primary stratum.

Report raw public tokens, minimal sufficient causal bytes, unique supported
relations, connected components, schema description bytes, and source action
cost. Padding, duplicate views, paraphrases, or repeated evidence cannot move a
checkpoint.

### 13.2 Orthogonal difficulty axes

Vary and report these independently rather than collapsing them into “longer”:

| Axis | Proposed levels | What changes |
|---|---|---|
| lifetime load | .5x, 2x, 4x, 8x | genuine cohorts and causal roots |
| causal decision depth | 2, 3, 4, 5 | required memory-bearing dependencies, excluding logistics |
| path width | 2, 4, 8 alternatives | distractor branches and backtracking |
| local ambiguity | 4, 8, 16 completions | target-only and atoms-only entropy |
| schema complexity | AST depth 1, 2, 3 | prospective law description |
| age gap | 1, 2, 3+ intervals | distance since last old support |
| exception density | 0, 1 scoped, 2 scoped | revision burden |
| evidence cost | cheap, medium, binding | on-policy intervention opportunity cost |
| memory capacity | fixed and small grid | text bytes, index bytes, LoRA rank/bytes |

Use a sparse balanced design: not every Cartesian cell is required, but age,
depth, and load must not be perfectly confounded. Every scored root contains
both low and high target difficulty nested under the same life.

Claims about depth stop at the maximum certified level. Claims about
compression require retained growth sublinear to the exact minimal sufficient
statistic while action is noninferior; a smaller text file alone is not
compression. Claims about saturation require three post-native points and
simultaneous equivalence bounds for each named baseline.

## 14. Exact CPU certificate suite

Every emitted pair root carries a replayable, scorer-only certificate bundle.
No model/GPU call occurs until all selected roots pass. At minimum:

### C0 — total generation and replay

- byte-identical regeneration from sealed private tapes;
- no per-target rejection, replacement, or result-conditioned filtering;
- complete tape consumption and namespace independence;
- stable hashes for hidden truth, public source, target deck, and suffix intent.

### C1 — finite transition correctness

- closed action parse and exact round trip;
- pure no-partial-mutation transition semantics;
- exhaustive state invariants and terminal behavior;
- pack-specific motif non-isomorphism;
- quotient proof that omitted hidden fields are behaviorally irrelevant.

### C2 — target solvability and value

- exhaustive BFS/A*/dynamic-program replay of every legal target policy under
  the action cap;
- legal-history/gold action value at least `.85` in R/N/O/J/P/X;
- minimum successful length 6--12 and registered causal decision depth;
- unique decisive component/setting orbit even when multiple logistics orders
  tie;
- all malformed, illegal, cap, defer, and terminal transitions score exactly.

### C3 — adaptive no-life/reacquisition bound

- exact belief-state Bellman solver over all target-visible states, actions,
  and outcomes under the registered generative measure;
- target-only, state-only, and full adaptive no-life value at most `.35`;
- minimum information-then-success cost exceeds budget;
- selected-slice certificate, not an average over easier unselected targets.

### C4 — target-byte twins

- exact equality of complete pre-action target JSON and English bytes;
- copied nuisance handles/template/timing/action roster;
- distinct/disjoint decisive plans and different first irreversible choice;
- authentic public history identifies the side;
- action-only and binding-erased source marginals equal cutwise;
- authentic/twin memory substitution has a precomputed action-redirection
  expectation.

### C5 — J necessity

- delete the cited early transition, old output state, state-flow bridge, recent
  guard, and recent terminal relation separately;
- each deletion makes all legal plans fail or exceed budget;
- early-only and recent-only information each has value at most `.35`;
- roots are provenance-distinct and no single reset supplies both sides;
- every redundant semantically equivalent route is included in the cut.

### C6 — P chronology and atoms-only ceiling

- commitment predates confirming outcomes, status append, target descriptor,
  target public bytes, and evaluation clone;
- exactly one decisive local edge is unwitnessed;
- at least four equally weighted witnessed-atom completions remain;
- atoms/witnessed graph value at most `.35` and supported schema/program value
  at least `.85`;
- later-schema and hidden-program conditions are separately labeled ceilings.

### C7 — no direct closure

- no source state-goal, source terminal suffix, complete plan, or target
  instance is reused;
- no individual memory row, reader return, legal set of bounded returns, index
  metadata, or compiler view names a complete target solution;
- nonadaptive precommitted reads remain at or below `.35` while a generic
  recurrent gold reader can reach at least `.85` with valid dependency traces.

### C8 — selection, handle, and renderer symmetry

- exact target-only posterior under the complete root/target measure;
- all decisive actions balanced over slots, signatures, handles, template,
  cut, pack, and side;
- one-tape-item metamorphic changes exactly one nuisance field;
- identifier/renderer/signature/frequency/source-action feature manifests
  contain no hidden-derived field;
- injection tests catch an answer placed in every allowed projection.

### C9 — lifetime growth

- actual tokenizer counts for the frozen model;
- three strictly post-native cuts;
- monotone unique evidence roots, supported local relations, minimum sufficient
  causal bytes, old/new joins, and prospective cycles;
- no duplicate/paraphrase/status view counted as new evidence.

### C10 — isolation and noninterference

- clean process and forbidden-import manifest for cognition;
- cross-life canaries over events, handles, caches, adapters, indexes, files,
  processes, descriptors, and provider state;
- evaluation run/skip equality over every future source/tape/suffix hash;
- scorer and certificates have no return channel into source, memory, or model.

### C11 — resource bound

- exact or conservative counts for states, transitions, belief states, program
  hypotheses/solver nodes, target items, disk, RAM, workers, and wall time;
- certificate replay under a frozen CPU ceiling;
- failure closes the root/panel rather than weakening the target filter.

The exact generator/Bayes/program code should be independently implemented or
checked against literal vectors outside the subject package. Subject-package
self-consistency is not an independent oracle.

## 15. Baseline-facing design

RTCW must make strong nonparametric approaches easy to implement, not force
every system through the proposed one-atom interface.

All arms receive byte-identical common source events in the fixed-deck study.
Required references include no memory, honest native context/truncation, raw
episodic RAG, hierarchical reflection, native linked/A-MEM-like memory, exact
witnessed event graph, generator-aware Bayesian/program induction, procedural
skill memory where meaningful, raw-event/direct-QA LoRA, compiled text, and the
identical compiled corpus in LoRA.

Report a common bounded one-atom reader factorial for mechanism attribution and
each baseline's uncrippled native planner/retriever for the system comparison.
Recognition candidates, graph traversals, whole-life scans, prompt tokens,
index bytes, adapter bytes, training FLOPs, action calls, and latency are all
charged and reported separately. The program baseline freezes its source-
conditioned posterior/program store before a target is rendered; it may use the
public target to plan, but may not use target acceptance or outcomes to refit
the world program.

If explicit graph/program memory is more accurate, smaller, or cheaper, that is
a scientifically informative RTCW result. It falsifies a proposed-system moat;
it does not invalidate the generator.

## 16. Randomized on-policy evidence-acquisition extension

The common-deck generator includes the extension points from day one but does
not claim the flywheel.

At each post-native boundary:

1. preseal a target-independent public diagnostic-opportunity roster, the
   source clone state, collection budget, and a later J/P/X target deck;
2. clone the same canonical state four ways;
3. randomize authentic, null, within-life binding-shuffled, or intact twin
   memory before any collection action;
4. give each collector the same broad readiness objective, public opportunity
   menu, action/query/token/wall-clock cap, and frozen resolver;
5. allow adaptive ordinary OBSERVE/MEASURE/APPLY/RUN actions on safe benches;
6. append only actually chosen public outcomes to that clone's life;
7. run exactly one frozen reconsolidation;
8. evaluate the presealed later target in a fresh sterile process;
9. cross each collected trace through compiled text, raw RAG, native graph, and
   direct-QA representations offline.

The collector never sees the later target or its allocation. Opportunities are
balanced so authentic memory can guide tests that disambiguate unresolved
parts of the persistent workshop rather than simply revisit a known target
component. Charge opportunity cost: collecting one fact prevents collecting
another.

The flywheel requires all four preregistered intention-to-treat links:

1. assigned memory changes information-seeking action;
2. chosen actions improve information gain or target-relevant causal coverage
   per action;
3. one later supported snapshot is better;
4. the presealed later action value improves.

A changed action with no information gain, better memory with no later action,
or better later action without assignment dependence fails the flywheel. A
one-root sentinel may check wiring after G2, but no effect size or learning
claim may be drawn from it.

## 17. RTCW-MR1: minimal version after G1

Build MR1 only if the current supplied-gold G1 establishes that the frozen
resolver can use bounded recurrent memory for J/P and the no-memory/open/atoms
controls remain low.

### Scope

- one fluid/thermal RTCW pack;
- two independent DEV pair roots, four world-life sides total;
- enough whole cohorts to reach one honest `2 L_native` cut;
- at least one era-0 module, one recent module, two cross-era bridge episodes,
  and one prospectively committed/supported schema per side;
- two fresh J and two fresh P target items per side, nested and failure-inclusive;
- public action/outcome common deck only;
- deterministic witnessed atoms, gold connected/schema snapshot, exact graph,
  and generator-aware program reference;
- writer inputs and chronology needed for witnessed-only/raw-proposal/
  chronological-admission learned-text comparisons;
- whole-memory twin assignment, post-compiler binding shuffle, and cited
  semantic-equivalence cut support;
- one sealed on-policy opportunity/target sentinel manifest, but no powered
  collection study;
- no LoRA fit, adapter, outer policy training, scaling curve, or confirmation
  claim.

### MR1 pre-model go/no-go

Both pair roots must pass every applicable C0--C11 certificate. In addition:

- legal-history/gold J and P value `>= .85` on both sides of both pairs;
- adaptive no-life, target-only, renderer-only, and atoms-only P value `<= .35`;
- target-visible twin bytes exactly equal and memory swaps predict different
  decisive actions;
- no direct/set-level closure and no within-target reacquisition;
- the learned-text writer has no access to targets, certificates, hidden
  programs, or later comparator outcomes;
- a short blinded human pilot with gold local notes reaches at least `.75`
  action success and can correctly explain the cited causal path on at least
  `.70` of targets; median completion must fit the registered human time cap.

The human pilot is a usability check, not a baseline in the model estimand. A
benchmark that only its generator author can decode has failed the renderer
design.

### What MR1 permits

MR1 can license the two-pair text-first G2 mechanism pilot described in the
September 3 synthesis. A positive learned-text result can support only a DEV
claim that target-blind, chronologically admitted text changed action in two
independent generated pairs under a common deck. It is not population evidence,
post-native growth, LoRA transport, or a flywheel.

The generator itself costs zero GPU. The planned G2 use retains the current
rough 4--12 GPU-hour branch estimate because writer outputs are cached per life
and targets reuse sealed snapshots. RTCW should not increase target-call count
relative to the already planned one-cut G2 roster; its extra cost is CPU
generation/certification and implementation review.

## 18. Human interpretability contract

Interpretability is a validity condition, not presentation polish.

- all visible state changes use two or three qualitative attributes, never raw
  hidden bit vectors;
- public handles are short pronounceable nonces and every action menu repeats
  type plus handle;
- a memory atom is one grammatical causal statement with public provenance;
- a target requires at most five memory-bearing decisions and twelve physical
  actions;
- the UI distinguishes current state, inventory, legal actions, memory return,
  and recent outcome;
- a one-page ontology card explains action affordances but no root-specific
  law;
- trained annotators who did not build the generator must reproduce target
  traces from gold notes under the registered time cap;
- explanation agreement is scored against dependency edges, not prose style.

Do not solve interpretability by adding semantic hints that predict the hidden
law. If human success requires labels such as “heater cartridge” or
“compatible relay,” the renderer has leaked the task. If nonce density makes
humans fail despite gold notes, shorten the local roster or improve display,
not the hidden action prior.

## 19. Unresolved choices requiring ratification or blinded calibration

### U1 — exact program grammar and entropy constants

The depth-three AST, `>=128` compatible programs, and `>=20` prior bits are the
recommended starting point. CPU feasibility must establish that exact Bayes,
program, and target certificates fit the local resource ceiling. Ratify the
literal grammar and prior before root generation.

### U2 — MR1 target count

Two J and two P targets per side provide failure-mode coverage without implying
replication. If the 2L source makes that target roster expensive, reduce nested
targets only before opening roots; do not reduce the two independent pair
roots.

### U3 — human time cap and population

Ratify whether the interpretability pilot uses technically trained generalists
or domain experts and set a time cap before data. Recommendation: technically
trained non-authors, a brief action-API tutorial, and a 12-minute median cap per
target.

### U4 — exact `L_native`

This remains undefined until model/tokenizer/template/workspace/output reserves
freeze. Generate modular cohorts now, but select checkpoint boundaries only
after the exact envelope is measured.

### U5 — exception/X complexity

X is unnecessary for MR1 but required for full confirmation. Decide whether
one scoped exception per later era is sufficient before adding the second pack.
Do not let X delay the J/P text gate.

### U6 — TEST root count

Eight pairs per pack is the present lower bound from the RML plan, not a power
calculation. Use locked CAL variance and a blinded conservative simulation to
ratify the final count.

### U7 — program baseline implementation

Choose between exact version-space/BDD inference and a canonical SAT/SMT
enumerator. The baseline must consume public evidence and the registered prior,
not hidden ASTs. Its native compute may exceed the proposed reader's; report
that cost rather than crippling it.

### U8 — on-policy collection objective

Ratify a broad maintenance-readiness objective that does not disclose the
later target yet creates real opportunity cost. The objective and opportunity
roster must be frozen before any assignment outcome is observed.

### U9 — public structured record exposure

Recommendation: the model sees deterministic prose plus a legal action menu,
while canonical JSON remains audit/scorer-facing. A diagnostic may expose JSON,
but mixing prose and JSON in the primary condition risks doubling information
and should be a ratified choice.

## 20. Falsifiers and interpretation map

### Generator/instrument falsifiers

Stop RTCW model work if any of the following occurs:

- any selected root or target lacks a replayable exact certificate;
- target generation uses result-conditioned rejection or replacement;
- target-only, full adaptive no-life, identifier, renderer, signature, source
  action, or within-target reacquisition value exceeds `.35` on a required
  root/pack;
- legal-history/gold value is below `.85` in a primary stratum;
- H/twin public target bytes differ or their decisive plans do not;
- authentic source history does not identify the twin, or source action-only
  bytes do;
- a J target survives the complete early/recent/bridge cut, or early-only or
  recent-only information solves it;
- P has more than one unwitnessed decisive edge, atoms exceed `.35`, a schema is
  committed late, or support comes from repeated/equivalent roots;
- a source state-goal, complete plan, terminal suffix, row, bounded return set,
  index, or error channel closes the target;
- exact root-program posterior collapses to a tiny lookup after the first era,
  or a target renderer identifies the exact program without life evidence;
- evaluation changes later source/tape/suffix hashes or any cross-life state
  survives reset;
- non-author humans cannot use gold local notes under the registered usability
  criterion;
- the three full packs are transition-graph isomorphs after label removal.

### Proposed-system falsifiers that do not invalidate RTCW

- recurrent gold works but learned chronological text does not: DREAM/compiler
  path fails; retain the benchmark;
- witnessed graph or generator-aware program induction wins: no learned-memory
  moat; report the strong baseline result;
- compiled text works and same-corpus LoRA loses: external compilation/use only,
  no weights clause;
- LoRA needs whole-life candidate scans or linearly growing rank: no scalable
  parametric-access/compression clause;
- value is flat from `2x` to `8x`, old retention falls, or one pack drives the
  pool: no continuing development or general phase diagram;
- baseline plateau equivalence is not established: no saturation/crossover
  language;
- whole-memory binding/twin swaps do not redirect action: no causal memory-use
  claim even if raw accuracy is high;
- randomized memory changes collection behavior but not information, later
  memory, and sealed action in sequence: no flywheel clause.

### Positive-result ceiling

Even a complete RTCW pass shows a bounded effect in a synthetic, designer-
specified causal workshop with a frozen action API and controller. It does not
show a learned general scientist, open-ended continual learning, natural-world
validity, first parametric memory, first dreaming agent, or general
intelligence.

## 21. Recommended sequence

1. Finish and adjudicate the existing D0-based supplied-gold G1. Do not build
   MR1 to rescue a failed recurrent controller.
2. If G1 passes, open a new architecture intake for RTCW-MR1 exact bytes and
   CPU-only implementation scope.
3. Implement MR1 as a new package; retain D0 unchanged as regression vectors.
4. Freeze two DEV pair roots and pass independent C0--C11 review plus the human
   readability gate.
5. Run the text-first fixed-deck G2 on MR1; no LoRA unless the learned text,
   writer/admission contrast, and cut/twin interventions pass.
6. Add same-corpus transport only after G2.
7. Add 4x/8x cohorts and the two non-isomorphic packs only after the one-cut
   mechanism is real.
8. Power and run randomized on-policy evidence acquisition only after fixed-
   deck confirmation.

This sequence preserves the project's thesis while ensuring that the first new
generator answers a genuinely new question: not whether one deterministic
fixture is internally consistent, but whether a target-blind memory system can
learn and use causal structure across independent, sealed, readable action
lives whose targets cannot be solved from priors, handles, a tiny exact
program, or fresh target-side experimentation.
