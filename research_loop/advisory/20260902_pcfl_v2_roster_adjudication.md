## Decision

The stronger paper-directed DEV is a **predeclared staged roster with a
3,414-call successful path**, not the full 8,228-call repaired roster.

Keep one-shot Think **structured-only** in v2. Run a small one-shot Think
diagnostic on the same presealed OPERATOR_AST cells used for the representation
diagnostic; do not add an opaque one-shot Think arm. State explicitly that v2
does not identify whether recurrent target-time Think is necessary, superior,
compute-efficient, or exposure-efficient for OPAQUE_NOTE_SELF.

This decision does not demote recurrent Think from the tested organism. The
primary assay still tests a bounded recurrent resolver reading a frozen,
model-selected opaque corpus and taking physical actions. It withholds only a
component-necessity comparison that the present opaque interface cannot make
fairly.

## Why opaque one-shot Think is not an identified comparison

In the primary lane, recurrent Think chooses lexical queries after seeing the
target and prior reader returns. Its realized memory exposure is therefore an
adaptive trajectory. A single model invocation cannot be given "the same
eligible information" without changing the treatment:

- giving it the whole opaque corpus grants bytes the recurrent resolver may
  never retrieve;
- giving it a transcript produced by the recurrent arm leaks a
  result-contingent query trajectory;
- precomputing target-aware top-k retrieval replaces model-owned adaptive
  reading with a different external resolver; and
- giving only catalogs or target-blind fixed notes deprives it of bytes the
  recurrent arm can acquire.

Equal token or output caps do not repair these exposure differences. The arm
would conflate recurrence, query adaptivity, reader access, and corpus
presentation. It could be reported as a new interface comparison, but not as a
clean ablation of recurrent Think.

By contrast, OPERATOR_AST has a closed, typed representation whose eligible
packet can be frozen before either resolver runs. A structured one-shot Think
diagnostic can therefore receive the same target and same eligible structured
memory bytes as its iterative comparator. It remains only
"eligible-information and output-capacity matched; interaction, input
trajectory, call count, latency, and FLOPs intentionally unmatched and
reported." It cannot support an efficiency claim or explain opaque notes.

Most importantly, opaque one-shot Think is unnecessary for the primary causal
estimand. That estimand is identified by seed-coupled, within-target contrasts
among authentic, EMPTY/OBSERVED, crossed-antipode, and footprint-matched sham
corpora while the recurrent resolver and all non-memory inputs are held fixed.
Those contrasts test whether the frozen life corpus changes later executed
action. A one-shot arm asks a different question: which resolver interface can
use that corpus.

If a later paper requires a recurrence claim for opaque memory, it needs a
separate, prospectively specified reader-interface study. It must freeze a
nonadaptive batch exposure policy before outputs, equalize exposed corpus bytes
and target information, and treat batch versus adaptive access as the named
factor. It must not be retrofitted into this causal DEV.

## Why the staged roster is stronger for paper direction

The full repaired roster is stronger only for exhaustive debugging and
within-root attribution. It is not stronger evidence for a paper result:

- its 8,228 scientific-call ceiling comprises 968 Dream, 6,724 recurrent
  Think, 24 structured one-shot Think, and up to 512 conditional native-A-MEM
  calls; without A-MEM it is still 7,716 calls;
- nearly all additional cells remain nested inside the same one open factor,
  one untouched factor, and one independent root;
- ceilings, prompt variants, gates, structural cuts, and retrieval baselines
  do not create independent experimental units;
- no roster confined to the 15-event minimal life answers context crossing,
  lifetime retention, cross-era transfer, or LoRA transport; and
- full simultaneous execution spends heavily on failure explanations that
  are irrelevant if an earlier causal organ has already failed.

The staged roster preserves every contrast required to decide whether the
minimal organism is alive, whether the effect is life-corpus specific, whether
it survives an untouched root, whether it appears under the independent
negative, and whether a structured representation changes the result. It then
stops. Calls saved here buy new independent roots and genuine post-context
experiments later; those add paper information, whereas another nested DEV cut
usually does not.

Sequential execution is valid only because the routing logic is part of the
frozen experiment. It is not permission to inspect results and choose a
favorable subset.

## Recommended mandatory stages and cells

All roots, sides, targets, goal twins, z/antipode assignments, invocation
seeds, coupling groups, gates, reducers, and possible terminal rows must be
hash-bound before the first model call.

Retain the repaired v2 CPU/contract suite in full:

1. certify all 64 factor and 64 independent roots and every private state;
2. verify target uniqueness, no recovery, goal twins, and the factor `1/16`
   theorem plus the conditional-independent null;
3. run zero-model-call EXACT_PROGRAM/EXACT_ABSTAIN and oracle-schema parser,
   reader, and action fixtures;
4. validate prompt/schema/reducer hashes, totality, reset, namespace, taint,
   failure, and authority rules;
5. validate the canonical RNG/coupling map, typed pre-READ event catalog,
   private-field mutation registry, and failure-inclusive analysis reducer;
6. enforce the opaque surface/provenance-only audit and structured-only
   semantic packet audit; and
7. materialize every possible Stage 1/2 and diagnostic assignment with a
   terminal status vocabulary including `NOT_TRIGGERED`.

Use the jointly satisfiable repaired CPU envelope: at most 10.5 CPU-minutes per
root and 24 aggregate CPU-hours. Any failure ends `NOT_RUN` and
`HUMAN_REQUIRED`; partial certification cannot select another root.

## Optional cells and frozen routing

The full decision tree must name the following panels before Stage 1, but they
are not on the successful causal path:

- missing exact opaque A candidate: factor AST, then CLASS_INFORMED only if the
  registered AST gate fails;
- exact A candidate but failed branch revision: PERFECT_PUBLIC_GATE,
  NO_REVISION, and NO_GATE_HASH1 on the frozen pool;
- exact B commitments but failed action: AST, oracle, and RAW_RAG_FULL on the
  same preselected targets; no opaque one-shot Think;
- noisy candidate selection: PERFECT_PUBLIC_GATE, NO_GATE_ALL, NO_GATE_HASH1,
  and NO_REVISION on presealed factor/independent sides;
- successful generic opaque with a predeclared scaffolding question:
  NEUTRAL_OPAQUE on one untouched factor and one independent side;
- successful AST with a predeclared structured-mechanism question:
  ORIENTATION_DELETED and frozen order/binding/sham AST cuts; and
- a proposed RAG or A-MEM comparison: run the faithful comparator on the later
  powered confirmation roster, not merely to decorate this DEV. Unavailable
  native A-MEM is root-wide `NOT_RUN` and permits no comparison.

Each trigger may route only from immutable receipts. It cannot change a prompt,
root, target, seed, threshold, parser, budget, or primary status. Triggered,
failed, untriggered, inapplicable, and unavailable cells all remain in the
ledger. No successful diagnostic reopens a failed primary stage.

## Claim and paper boundary

A successful staged v2 contributes a validated construct, a causal mechanism
trace on the named DEV roots, a matched-independent specificity alarm, a
structured representation diagnostic, failure localization, and empirical
cost measurements for designing the next study. This is more paper-directed
than the full roster because it answers the go/no-go question at lower cost and
reserves resources for independent units and post-context lives.

It does not contribute a population estimate, interval, p-value, baseline
ranking, recurrence benefit, opaque one-shot comparison, context-overflow
result, lifetime curve, LoRA result, or paper efficacy claim. The maximum
description must separate prospective Dream commitments, raw-A-caused Dream-2
revision, and frozen-corpus-caused later action.

After a successful v2, the next paper-relevant work remains separately
ratified: new-root minimal-cycle confirmation with root-blocked inference; a
chained-block text lifetime falsifier first beyond `1.5 L_native` and then at
`3 L_native`/`6 L_native`; and only after text survives, an identical-corpus
per-life LoRA transport canary followed by a powered new-root transport panel.
The v2 result authorizes none of them.

## Final disposition

Adopt the repaired contracts from the interpretation repair map and the staged
resource logic from the value audit. Use structured-only one-shot Think because
its eligible representation can be frozen fairly; withhold opaque recurrence
claims rather than adding a confounded arm. Use the 3,414-call staged successful
path because it preserves the causal organism, negative identifiability
control, representation diagnostic, and failure attribution while spending
less than half of the 8,228-call full repaired ceiling on the same three DEV
roots.

This is an advisory judgment only. A new exact v2, fresh independent
interpretations, human ratification, and a separate execution lock remain
required.
