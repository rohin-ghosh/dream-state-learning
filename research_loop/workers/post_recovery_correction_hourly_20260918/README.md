## Epochs and interpretation

Each current collection is tied to its exact owner receipt, journal, PID/starttick,
canonical LOADED, receiving-source cwd, and guard hash, checked before and after.
A changed source identity fails closed rather than silently remapping. New
retention/source epochs require an authoritative bound receipt before adoption;
the September 18 22:27 authorization does not establish deployment. Retained or
rendered correction context is exposure, not uptake. The learner had corrections
in all four previously audited ACT prompts; this observer does not attribute all
failures to compaction. New-window semantic levels remain unknown pending review.

The restored observer additionally keys every fresh snapshot, queue cursor and
ACT exposure row by **life + journal + native PID/starttick + remote boot + source
path + guard + LOADED + owner receipt + observed Python-source manifest**. The
manifest covers on-disk `gpu/*.py` and `organism_v6/*.py`, bounded at 2048 files /
32 MiB; it does not attest to all loaded memory or external dependencies. A
change fails closed, with no automatic retention deployment or epoch adoption.
Fresh evidence is retained under `private/epochs/<life>/<epoch>/cuts/`; old code,
config, public cuts, handles and live snapshots were archived under
`private/recovery/20260919T004144Z/`. Frozen historical caches are unchanged.
Pre-reboot queues remain preserved, not silently relabelled into the fresh epoch.
The journal gaps since the last successful pre-reboot cut are explicit.

`public/SOURCE_EPOCHS.json` updates with every collection, not just at launch.
Each committed ACT includes parent event/source/body hashes only when the original
TRAIN reader verifies the whole exact parent body in that ACT's user message;
structured messages also require matching event metadata. Substrings, summaries,
assistant quotations, THINK-only exposure and uncommitted responses are not ACT
proof. A zero count means no match under this exact renderer, not universal
absence from every possible context representation. Parent inputs are not
automatically classified as corrections. Retention remains unverified and is
not uptake. Future before/after comparisons require an authoritative deployment
receipt and fresh separately keyed source-epoch windows; no after window is
claimed or rollout deployed by this worker.
