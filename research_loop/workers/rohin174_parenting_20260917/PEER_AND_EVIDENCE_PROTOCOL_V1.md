`ASSIGNMENTS_CONTROL_AMENDMENT_V2.json` and subsequently
`ASSIGNMENTS_AUTHORIZATION_R178_V3.json`. C2's fixed172 pilot remains excluded

## Peer step

After an actual attempted action, invite the child to share a short state summary
with its assigned peer: what it found (or no result), what remains uncertain,
and what it intends to try next. Preserve its exact authorship and receipt
references. The invitation must name the working channel and actual peer; never
invent an operation or assert delivery from publication alone. This is not
permission to send parent instructions, full transcripts, evaluator data or
claimed observations on behalf of a child.

For C1/C3 and C4/C5, the existing community operation is
`{"op":"send_message","recipient":"C3","text":"<your own state summary>"}`
(use the actual assigned peer). `QUEUED` is not inspection. The recipient can
use `list_messages` then `read_message` through the documented tool interface.
Do not place an example's invented content in a training target. Do not silently
convert an unsuccessful child operation into an operator-authored success.

For a node-local seminar/classroom pair, use the existing attributed environment
inbox path only after a bounded source summary and receipt are verified. Stop or
supersede the old full-segment relay at its own settled boundary; do not erase
pending messages or pretend old exposures disappeared. Route at most one new
summary per sender/receiver completed-sleep interval, without a backlog. Do not
truncate an oversized summary and then label it exact. A missing usable summary
is a missed peer opportunity, not authority to synthesize one.

The recipient treats peer claims as unverified, makes its own prediction and
chooses an executable check. Record the action and the actual feedback. Only
the recipient's own response can become an eligible training row. The summary,
parent invitation and returned tool result remain attributed masked context.
Parent policies are not shared between parents. No new parent/peer turns during
the predeclared one-sleep withdrawal segment; log already pending/visible inputs.

## Evidence row (one action opportunity)

Record actual journal/hash references for each cell. Unknown stays unknown.

| Field | Required evidence |
|---|---|
| Arm start | First REQUEST actually rendering the new policy turn; inbox id/hash and parent source pins |
| Current object | Child-authored object/unfinished-work passage, not the parent naming it alone |
| Observation | Tool result with actual values and its rendered REQUEST, or explicit no result |
| Reflection | Child's task-relevant finding or uncertainty and the observation it uses |
| Chosen action | Specific child-authored next intention before the attempt |
| Occurred | Executed artifact/tool receipt, directly checkable calculation, or actual produced revision; label which |
| Feedback arrived | Actual receipt and first rendered REQUEST; queued is not arrived |
| Feedback used | Subsequent child choice cites or responds to the actual observation |
| Boundary carry | Exact compaction/retained-history record and post-boundary rendering of the same unfinished work |
| Unprompted continuation | Chosen action enacted without a new reminder; explicitly list old reminders still visible |
| Peer provenance | Sender response/commit, routed summary, recipient rendering, recipient's own prediction/test/restatement |

## At three completed sleeps

The threshold is event-based, not an invented wall-clock ETA. Inspect all three
complete cycles beginning with actual policy exposure. Count an intention change
only when the meaning of the chosen action changed in response to an observation
or reflection; different words/headers alone do not count. Require at least one
such connection per complete cycle, state carried at every actual compaction,
and no invented outcomes. If no compaction occurred, report that condition as
not exercised rather than calling compaction survival proven.

Use PASS / FAIL / INCOMPLETE with source-backed adjudication. Missing data,
unfinished sleeps, unavailable feedback, and observer delays are not automatic
FAIL. A failure needs the concrete counterexample (e.g. claimed successful run
with no receipt, repeated intention never attempted, or lost unfinished work).
No automatic retirement from keyword matching, phrase overlap, silence, absent
headers, a parent opinion, or elapsed time. A verified failed arm may be retired
under Rohin175 only after exact checkpoint/optimizer/RNG/context/journal custody;
record any in-flight work lost. Preserve all artifacts. Reassignment gets a new
version/segment and the successful source route is named, not copied invisibly.

These are heterogeneous exploratory arms. Passing is not evidence that LoRA
caused the behavior. Keep both in-context observations and separately blinded
clean-context adapter-ON/OFF probes; retain fixed C2's matched updates-ON/OFF
continuations as their own comparison.
