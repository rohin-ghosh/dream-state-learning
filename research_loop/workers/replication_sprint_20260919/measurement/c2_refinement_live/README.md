# C2 refinement live measurement sidecar

Read-only observation under the fixed prospective plan at
`../../operations/C2_REFINEMENT_MEASUREMENT_PLAN.md`. Only this directory is
written. No provider calls, credential inspection, native/service/provider
mutation, experiment launches, signals, git commits or pushes.

`observe.py` calls the existing source-bound TRAIN projection collector
(`post_recovery_correction_hourly_20260918/contract/reader.py`) over the original
`bash gpu/ovx3_ssh.sh` route. The exact native PID/start, guard, loaded record,
source epoch and all three original binding helpers are checked. The reader is
sent on stdin and executed with `python3 -B`; no remote file is installed.
The collector reads bounded journal records in place. Only projections under
1,900,000 bytes cross back; no bulk journal or checkpoint copy is made. Subsequent
captures losslessly deduplicate identical rendered external events; expansion
must reproduce the original collector's canonical digest. These are TRAIN
receipts, not sealed evaluation data, and are not sent to the parent.

Authored helpers and reports use `apply_patch`. JSON receipts are generated by
helpers with exclusive-create writes; previous cuts are never overwritten.
`BINDING_01.json` includes a known false negative in its API-text substring
check (JSON escaping). `BINDING_02.json` corrects that observation using decoded
JSON strings and additionally checks the provider receipt's exact instructions.
The original receipt remains preserved; the policy itself was not changed.

## Evidence interpretation

- STARTED, provider success, publication, INBOX, request visibility and committed
  ACT are separate events. A publication ID alone is not delivery.
- Select the first six committed ACTs whose requests follow the first actual
  new-policy INBOX. Group all new-policy publications delivered before the same
  next ACT; never count that ACT more than once. Keep ignored/invisible/incorrect
  responses, and preserve unknowns separately from assessed failures.
- `select` uses the existing audit's hash-linked request/response/commit/stage
  join. A missing join at an ACT receipt fails closed for explicit unknown-slot
  review, rather than silently selecting a later, easier ACT.
- INBOX record timestamps are **file mtimes** from the existing collector, not
  asserted exact native internal ingestion times. Provider times are separately
  recorded; DELIVERED observation times are not consumption times.
- Reconciliation verifies selected original INBOXs against existing publication
  and snapshot hashes. It does not fabricate missing `DELIVERED.json`, replay
  publications, prove downstream action uptake, or close the PARENT13 boundary.

## Bounded continuation

Run from the repository root; replace capture sequence/cursor only after reading
the previous receipt. No watcher or background process is installed.

```bash
python3 -B research_loop/workers/replication_sprint_20260919/measurement/c2_refinement_live/observe.py binding --output BINDING_NEXT.json
python3 -B research_loop/workers/replication_sprint_20260919/measurement/c2_refinement_live/observe.py capture --after PREVIOUS_THROUGH_INDEX --maximum 12 --output CAPTURE_NEXT.json
python3 -B research_loop/workers/replication_sprint_20260919/measurement/c2_refinement_live/observe.py select --output SELECTION_NEXT.json --inputs CAPTURE_01.json CAPTURE_02.json CAPTURE_NEXT.json
python3 -B -m unittest discover -s research_loop/workers/replication_sprint_20260919/measurement/c2_refinement_live -p 'test_*.py' -v
```

Pass **every intervening capture**, without gaps, to selection. The collector
refuses changed native identities; a new epoch needs a separate explicit
binding/window. Outputs are analysis only; no scientific or retention claim is
made from this single continuing life or from text still visible in context.
