# Proposed measurement and secondary absence probe

This is a proposal for the integrating measurement owner, not a deployed rule,
new acceptance gate, scheduler, optimizer schedule, or change to the thesis.
Strong parenting plus real environmental feedback is the main treatment.

## Baseline before any intentional withdrawal

Use the existing persistent cadence and matched frozen-sibling opportunities.
A small proposed pilot window is 12 committed ACT opportunities covering at
least math, reading/recall, and writing or reasoning. This is an analysis window,
not permission to stop lives or a claim that 12 observations prove learning.
If there is insufficient actual mixed work, collect it and adjust the parent;
do not promote the arm to withdrawal merely because time passed.

Before a new subject/policy addition, record the existing durable COMPLETE and
checkpoint references (adapter, optimizer, RNG, working state, record frontier,
source/manifest hashes). This workstream only specifies the receipt; it neither
creates nor loads a checkpoint. Preserve original failures if an operator later
tries a new approach from that checkpoint. Give each policy/fork a distinct
lineage and epoch; do not relabel a reset as uninterrupted improvement.

Per opportunity, keep source-bound records for:

| Field | What it distinguishes |
|---|---|
| Actual task/subject and parent policy epoch | Exposure to genuinely different subjects vs subjects named only in a brief. |
| THINK intention and actual committed ACT | The promised artifact/check, partial artifact, intention-only output, factual help request, unrelated output. Do not demand extra self-narration to manufacture reflection. |
| Parent INBOX, actual ACT request, ACT commit | Delivery, visibility, execution; unknown stage stays unknown. |
| Environment feedback reference/status | Scored/correctness feedback, execution failure, pending, or missing; silence is never a verdict. |
| Completed check and next changed action | Claimed checking vs an observable check that actually changes or justifies the result. |
| Repetition/language/parent response | Diagnosis and changed teaching intervention; never row eligibility. |
| Parent opportunities, actual turns, tokens and reminders | Cost of guidance, coverage and actual assistance, not just process uptime. |
| Sleep/checkpoint and recall condition | Uncued vs cued recall; supported / honest uncertainty / invention / no answer. All rows still train. |

Treat self-reflection as behavior with evidence: (0) no source-supported uptake,
(1) identifies a concrete discrepancy from actual feedback, (2) changes the next
relevant ACT and checks it, (3) reuses that correction in another relevant
attempt without a new reminder. Evidence missing because of transport,
compaction or unknown stage is **not observable**, not automatically level 0.
Log transport visibility and behavior separately. A counterexample may disprove
a conclusion even when the child verbally praises its own checking.

Label spontaneous, parent-prompted and environment-prompted checks separately.
Keep parent-free in-context reuse distinct from after-sleep and fresh-context
transfer. Count intention-only and actual artifacts without filtering either.
Retest at fixed generated-token budgets on released checkable tasks; held-out
evaluations stay outside the parent's view. Caption scores are secondary and
judge-dependent, not automatically humor quality. Do not use sealed test results
to choose the next parenting turn.

## Secondary, not a new centerpiece: one declared absence

**No actual taper is enabled by the brief or tests.** Only after a measured
baseline and a verified recovery mechanism would the operator consider one
small absence: no more than one committed ACT or 120 seconds, whichever comes
first, with an earlier return if help is requested or feedback fails. This is a
proposed bound to be implemented and measured, not an existing capability. A
clock expiry returns parenting; it does not terminate the child or its task.
Do not convert an ordinary provider latency/outage into an absence observation.

Before the window, the real parent's final turn would identify:

- That the absence is intentional and the exact observed-cycle/time return
  condition, only once an actual supervisor owns it.
- The ongoing actual object, uncertainty, and sources of environmental feedback.
- A longer-horizon choice: what result warrants continuing nearby, revising an
  assumption, or branching; the child chooses the checks and its retained text.
- A tested help route that shortens the window; absent recovery/feedback means
  **do not start this probe**, not withhold help from a live child.

No copy-ready absence announcement is supplied here: promising a return without
a bound supervisor would be misleading. If eventually run, log announcement
receipt, delivery/visibility, last parent turn, actual duration, continuing
environmental messages, child help requests, parent return, and reasons for
early recovery. On return, credit only observed work and resume strong parenting.
Never infer dependency merely from asking for missing judgment; that can be
appropriate uncertainty or a broken feedback channel.

Learning rate, presentations, row eligibility, frozen control and retention are
unchanged. Reduced parenting does not entail automatic reduced plasticity in
this candidate, even though the older schedule discusses it. Gradual versus
abrupt withdrawal is a later replicated comparison, not a result of this pilot.

## Refinement and replication discipline

Archive an unchanged-policy baseline; then change one proposed parenting factor
at a time (e.g. genuinely mixed objects vs math-only, or concrete checks vs
generic reminders), keeping task/feedback opportunities and guidance budgets
visible. Preserve all unsuccessful attempts and report all arms. Use multiple
independent training lineages; sampling seeds from one checkpoint are not that.
Study the earlier C2 checkpoint with source traces, not retrospective praise.
Improvements confined to the visible teaching context do not establish a slow
LoRA effect; frozen, fresh-context and adapter controls belong to the broader
sprint. This workstream has run none of those experiments.
