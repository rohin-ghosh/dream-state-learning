# Prospective every-sleep queue — proposal only

September17, 2026. Current R167 generation3 stays114 calls/19 checkpoints;
this proposal neither modifies its ledger nor authorizes another admission.
No child, parent, training, original fixed-readout or source-runtime change.

## Finite fixed schedule

Propose one explicitly enrolled existing lineage and eight consecutive future
sleep numbers, plus one initial comparator:9 checkpoint captures,
18 checkpoint-condition processes,54 calls, at most27648 generated tokens.
This is every sleep within that finite registered window, not indefinite
authority. Main must name the actual lineage, first sleep number, source-owner
custody/read ceiling and absolute campaign expiry from current evidence.
Do not infer a new root, reuse an expired source authority, or enroll a life
because its private retrospective responses looked favorable. Additional lives
or later sleep windows need a separate fixed plan/budget, not cap increases.

The immutable plan registers initial then every designated sleep, with both
conditions and all three exact generation3 prompts. No stride, score-gated
selection, adaptive sampling, first-hit stopping, or discretionary replacement
of missing/failed checkpoints. Preserve every registered negative, ambiguous,
truncated, failed, orphaned, late and missing cell distinctly.

## Capture and custody

An evaluator-only CPU observer checks only the named source's native COMMIT and
contiguous TRAIN journal. A durable SLEEP_COMPLETE must bind the exact COMMIT,
cycle, checkpoint hashes and committed sleep receipt/frontier. COMMIT without
that boundary is ORPHAN_PENDING, not eligible evidence. Source-owner attestation
binds the actual namespace, preserved prefix, observed-through time and birth
provenance; no global absence-of-compromise claim is inferred.

After a boundary is eligible, a bounded read-only copier captures only the
exact original COMMIT bytes and its allowlisted adapter files into a new
private destination; verify before/during/after identities and hashes, including
two-hop manifests. No optimizer/RNG payload, held readout, log, history replay,
adapter mutation or live learner pause. Copy/metadata size ceilings must be
declared separately in the new authority; changed/incomplete files stay pending
or failed, never silently substituted. Source movement cannot block a child.

## Frozen prompts, references and interpretation

Use the same three exact prompts, original birth/system bytes, greedy decoder
and512-token cap. Each condition/checkpoint gets a fresh process; every prompt
gets newly constructed context without previous replies, fingerprints, files
or parent messages. OFF actually disables the mounted adapter. Snapshot frozen
base and adapter before/after; maintain immutable source/runtime/tokenizer and
rendered-input provenance. No output enters an inbox, training or sleep.

Freeze extraction/scoring code before the prospective window. Freeze each
TRAIN-derived reference packet from that checkpoint's pre-evaluation history
before its outputs, retaining the exact historical object/version evidence.
Do not tune anchors or criteria using any earlier sealed result. Semantic
birth-cue and identity adjudication use the separately frozen private protocol;
string flags remain lexical candidates. Prompt1 is primary ON-not-OFF;
prompt2 and attention-control prompt3 stay independent. Initial and per-point
OFF matches are reported, not hidden gates. Faithful or cap-truncated identity
evidence is not discarded for lacking novelty/EOS. Correlated sleeps and
repeated OFF outputs are not independent subjects or proof of learning.

## Asynchronous execution and bounded resources

Persist a metadata-only queue state: REGISTERED → BOUNDARY_OBSERVED →
ADAPTER_COPY_VERIFIED → EXACT_GO_READY → RESERVED → RUNNING →
COMPLETE_AND_RELEASED. Separate terminal states include ORPHAN_PENDING,
SOURCE_CHANGED, REFUSED, FAILED, UNRESOLVED and WINDOW_EXPIRED.
Only an explicit new GO may move a verified copy to an admission attempt.
Journal polling, copying and evaluations never block native generation.

Proposed resource location is existing node2physical0/1 only after current
owners actually release and Main authorizes a new finite budget/window.
Use shared locks, unchanged privileged scan, initiator teardown, bounded
timeout and exact native/timeout/wrapper release. Preserve three charged calls
per condition; never retry uncertain consumed attempts. Allow a job only if
its full900-second window plus teardown fits the new absolute hard wall and
the existing lease-minus6h. Metadata observation may outlive a dispatch window
only under explicit separate source-read authority; no lease extension implied.
Consecutive ready jobs can run on release with no artificial clock waves.

semantic annotations and condition maps. Public COORDINATION sees registration,
counts/status, hashes, process release, resource usage and private appendix
references only. A same-account filesystem mode alone is not parent blindness:
the source/parent/repo-reader exclusion remains mandatory.

Missing before implementation/enrollment: exact next-boundary/source custody,
