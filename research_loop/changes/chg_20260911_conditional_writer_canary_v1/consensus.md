# Adjudicated consensus — conditional writer canary v1

Date: 2026-09-11

All three interpretations converge on the following order.

1. Finish already-running v6 mechanism and parenting scouts under their
   existing identities; archive and label them exploratory.
2. Do not birth a clean long-horizon child from any checkpoint that has seen
   the compiler/deployment gym.
3. Before spending a clean childhood, run the small conditional writer canary
   in `exact_scope.md`.
4. If it passes, the selected writer may enter a separately approved small
   parent-versus-sham canary. If it fails, do not promote the writer; continue
   cheap parenting-method scouts and make the writer/extractability
   characterization the paper path.
5. Do not finish or enforce the canonical C11 guard until the final paper-grade
   C11 run is next.

The canary's scientific question is deliberately narrow: can one frozen
Dream-LoRA-Think write carry a bank-specific synthetic situation-to-action association
under unseen surface forms, beyond a coherent marginal-preserving shuffled
association, while preserving the action interface and surviving one later
write?

This disposes the main disagreement between the audits. The rendering-only
rendering-factor test is cheaper but underidentified; the much larger
parenting factorial is premature. A six-root true-versus-shuffled association
test is the smallest design that distinguishes conditional carriage from the
broad-habit pathology already observed.
