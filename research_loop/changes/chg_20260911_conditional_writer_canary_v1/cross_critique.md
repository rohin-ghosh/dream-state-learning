# Adversarial cross-critique and dispositions

Date: 2026-09-11

## Proposed two-arm rendering test

The first proposal compared repeated episode rendering against a local
antecedent rendering. Cross-critique rejected it as the decisive test: a win
could come from diversity, length, regularisation, or generic instruction
tuning. A semantic shuffle is necessary. The repeated-rendering comparison is
therefore omitted from this canary and remains an optional engineering scout.

## Five versus six roots

Five histories would only be a fixed case series: even a 5/5 sign result has a
two-sided exact p-value of 0.0625. This canary uses six independently seeded
synthetic experience banks and reports roots individually. Its pass rule is a
stringent repeated-root engineering gate, not a population inference.

## What the shuffle must preserve

Event-wise answer reversal was rejected because it creates contradictions.
The control uses a fixed-point-free permutation of opaque tool identities
within matched mode-pair, action-pair, exposure, and direction strata. The
permutation is applied consistently to the state, outcome record, compilation
context, and target. Each control history is coherent; target/action
marginals, exposure, lengths, order, and loss geometry remain unchanged.

## Failed-control loophole

The first draft scored PI only against the true mapping. Both reviewers caught
that a collapsed PI could manufacture a favourable T-minus-PI gap. The primary
is now symmetric: each adapter is scored against both mappings and must prefer
its own. Both arms must independently fit their targets, beat OFF and the best
fixed routine on their own mapping, preserve the interface, pass non-harm and
spill checks, and survive the interference write. A failed arm invalidates the
root.

## Task accessibility and text memory

A null weight result is uninterpretable if the task cannot be used through the
native action interface. Shared adapter-OFF, GOLD-in-context, and frozen
candidate-blind TEXT-retrieval conditions are included. GOLD is called an
accessibility control, not a LoRA upper bound. TEXT retrieval misses remain
misses and no correct row is inserted by an oracle.

## Aggregate-score loophole

The primary measure is balanced correctness of strict native `ACT:` outputs,
not a broad task score. Best single-action, mode-only, and fixed-position
routines are computed and reported. A candidate cannot pass by reproducing a
global routine.

The spill check is likewise conditional rather than a pooled action marginal:
each wrong/unexposed control family has its own teacher-forced action-
distribution shift and gate, preventing cancellation across modes or action
pairs.

## Retention

Static re-reading is not retention. Every paired adapter is reconstructed from
the frozen base after one equal-sized unrelated experience bank, with an exact
1:1 old/new target-token mixture, and the original bank is re-tested.

## Execution authority

The first draft coupled prose approval directly to 24 GPU fits. This was
rejected because the exact generators, prompt forms, implementation bytes, and
run artifacts do not exist yet. Exact-scope ratification now permits only
implementation, materialization, and CPU fixtures. A second hash-bound GPU
manifest plus independent PASS reviews is required to execute.

## Parenting implication

A pass qualifies only this writer representation for an exploratory clean
parenting canary. It does not establish parenting, lifetime learning, general
memory, or C11 goal traversal. Parenting also needs child-authored executed
uptake, parent removal, matched sham interaction, and independent childhood
roots.

## C11 boundary

This is a disposable standalone mechanism canary under ordinary hygiene. It
cannot be relabelled as the final C11 run. The canonical C11 guard remains
ready but unfinished and unenforced until C11 is actually next.
