# PPC5r3 — minimal public four-assay intersection

Status: proposal only. No implementation, static sealer, model/tokenizer/
embedding call, training, canary, behavioral dispatch, GPU action, or scientific
claim is authorized. Prior PPC artifacts and exploratory organism runs are
provenance only and supply no evidence or authority.

## 1. Registered questions

PPC5r3 is the smallest controlled precursor to the Experience Model program.
It does not test a long-lived improving agent. It asks four separate questions:

1. **D1A supported selection:** in a direct provider-only assay with every
   semantic candidate supplied, does an evidence-gated READ-LoRA select the
   supported candidate better than its identical adapter-off provider, with
   wrong-life and matched-binding-shuffle specificity controls?
2. **D1B observable path dependence:** on a presealed decisive length-two or
   length-three path, does normalized action performance depend on every
   exactly matched interleaved response, survive a parity-matched sham, and
   exceed one-shot and open-loop schedules?
3. **D1C frozen DREAM context policy:** does assignment to one frozen
   same-model DREAM-selected reversible context improve subsequent action over
   prospective recency and recipient-local hash-permuted policies?
4. **D1D DREAM-to-SLEEP total policy:** does assignment to DREAM-selected
   evidence roots improve supported selection and downstream action over total
   recency and hash-permuted root policies, inclusive of the evidence dose,
   training, publication, inference, and resources each policy induces?

D1A is external candidate-conditioned discrimination, not closed-book storage.
D1B observes behavior, not private reasoning. D1C is a total context-policy
effect, not pure content quality. D1D is a total training-policy effect, not
fixed-dose root quality. All four are non-substitutable. Their sole conjunction
is explicitly non-mediational.

## 2. One frozen cognition, one isolated learned object

THINK and ACT use one byte-identical frozen model that emits only READ,
PREDICT, ACT, or STOP. DREAM is one separately scheduled call to the same
frozen model under a different public input. SLEEP alone trains a clean-base
READ-only LoRA. The adapter is mounted only inside the candidate provider and
may alter only candidate scores. It never enters THINK, DREAM, ACT, prompts, or
the public state directly.

The raw public ledger is append-only. DREAM publishes only a reversible view
of existing public record IDs and focus; it creates no evidence. SLEEP admits
only direct, closed, pre-boundary, public ACQUIRE outcomes. PROBE, future,
target-derived, cognitive, DREAM, scorer, and policy-target material can never
become positive rows.

## 4. Assay isolation

The exact component matrix is in `assay_contract.json`. Every arm is a paired
clone of a byte-identical pre-treatment snapshot. Arm labels and common-random
seed bundles are sealed before execution. D1A varies only the mounted provider
adapter and makes no policy call. D1B varies only schedule/intervention over a
fixed provider and artifact. D1C varies only installed context after one shared
DREAM call and disables SLEEP. D1D varies only root policy and its downstream
consequences; every arm installs the same RECENCY_CONTEXT and starts training
from the same clean base. Any unlisted difference is RUN_INVALID.

The matched-binding shuffle destroys the authentic request-object association
with a target-blind perfect derangement while preserving request multiset,
binding multiset, row count, update count, and per-row token count. The
wrong-life adapter comes from a recipient-disjoint, prospectively matched donor
roster without replacement or fallback.

## 5. Total execution and failure semantics

`machine_contract.md` binds exact state, model view, parse grammar, token and
logical debit precedence, event hash chain, terminal replay, provider scoring,
the three schedule modes, path oracle, intervention matching, DREAM policies,
evidence gate, root policies, writer order, trainer validation, and atomic
publication.

Nonintegrity missing calls never retry. They remain assigned and receive
directionally adverse finite bounds. DREAM empty/abstain/invalid,
projection-rejected, writer-empty, and deterministic training failure are
treatment-policy outcomes: downstream work continues with no view/root or
adapter-off and observed performance is retained. CONSTRUCTION_FAIL prevents
dispatch and blocks the dependent claim. RUN_INVALID halts the dependent run
and blocks it. The exhaustive mapping is in `analysis_contract.json` and typed
receipts make incompatible combinations invalid.

## 6. Scientific reduction

The recipient life is the sole sampling unit. Lower items, clones, and edge
positions are repeated measures, equally aggregated within life in canonical
order; lives are equally weighted. Each contrast uses exact paired
within-life label-swap randomization with a one-sided registered margin and
directionally adverse missing substitution. Every named gate is conjunctive.
Each assay p-value is the maximum of its gate p-values after all direction and
margin checks pass. Holm step-down controls the four assay hypotheses. The
four-assay intersection adds no fifth hypothesis.

D1B requires every edge-specific CUT and TWIN gate separately; no average can
rescue a failed edge. SHAM must remain noninferior to authentic, showing that
the intervention machinery alone is not destructive. D1D makes four required
endpoint-by-control contrasts. Resource normalization and semantic-overlap
strata are descriptive only and never rescue release.

Before model authority, a conservative registered power calculation must meet
the locked familywise probability floor for all four assays under the worst
registered missingness/effect scenario. Numeric alpha, margins, life count,
capacities, seeds, thresholds, model artifacts, and recipes belong to the later
run lock; algorithms do not.

## 7. Visibility and construction privilege

`visibility_contract.json` covers the exact product of eleven information
classes and fourteen stages from benchmark construction through claim release.
Hidden truth may be used only by no-model benchmark/twin construction and by
post-runtime endpoint scoring. A privileged router converts target-bearing
assignment into a target-free runtime intervention projection. The runtime
intervention stage never receives condition, item, target, truth, or role.
EVIDENCE_GATE may inspect typed eligibility; WRITER and TRAINER receive only
admitted projections/rows. REDUCER and CLAIM_RELEASE cannot affect runtime.

Every allowed derivation records source and output hashes. Fieldwise mutation
and taint tests must prove that forbidden or hidden data cannot alter model
bytes, scores, choices, debits, statuses, timing class, or outputs. Any runtime
influence is RUN_INVALID.

## 8. Authority and claims

All fourteen acceptance tests are global prerequisites at their declared
stages. Architecture ratification permits only the CPU/no-model implementation
scope in `scope_proposal.json`. Model reachability remains false through
conformance and static sealing. A populated run lock, two independently
implemented seals, fresh independent review, author advocate, and a separate
exact human run ratification are all required before the single allowlisted
dispatch preflight can permit any inference, tokenization, embedding, training,
canary, behavioral call, or GPU job.

Claims are emitted only by the pure release reducer from typed receipts. It may
emit an exact registered string or BLOCKED—never a paraphrase. The only finite
headline is:

> All four separately identified PPC5 assays passed on the locked
> recipient-life benchmark: supported candidate selection, observable
> every-edge interleaved-response dependence, frozen DREAM context-policy
> value, and DREAM_TO_SLEEP total-policy value. This is a non-mediational
> four-assay intersection, not an end-to-end learning mechanism.

No PPC5 result establishes learned THINK, learned DREAM, continual improvement,
prospective abstraction, schema compression, a flywheel, parenting,
populations, inheritance, or scaling.
