# v2 sealed assignment, manifest, and stage ledger

The only Stage-1/2 scientific invocation opportunities are generated by the
total canonical algorithm in `assignment_generator_contract.md` and validate
against `assignment_manifest.schema.json`. The Stage-0 manifest contains every
literal call/assignment/row ID, root, z/antipode, h/q, target, goal twin,
condition, lane, topology, coupling key/kind, sampler ID, selected-h cut,
stage, denominator, and replay flag; it is JCS-hashed before model work. This
ledger independently recomputes the same closed roster from these units:
ordinary recurrent Dream life = 48 Dream calls; shared Dream-1/two-continuation
fork = 64; iterative D1+D4 two-goal-twin life = 82 recurrent Think calls;
iterative D4-twin life = 62; one-shot Dream phase pair = 2; structured one-shot
D4 plan = 1. `PREDICT`, PASS, malformed, timeout, and early terminal attempts
are charged inside their assigned opportunity and never replaced. No result
may change the manifest array.

The first three rows are Stage 1: `128 Dream + 782 recurrent Think = 910`.
The remainder are conditional Stage 2: `356 Dream + 2,144 recurrent Think + 4
structured-only one-shot Think = 2,504`. The complete roster is exactly `484
Dream + 2,926 recurrent Think + 4 structured-only one-shot Think = 3,414`
scientific call opportunities. Canonical IDs are
`s1-call-0001..0910` then `s2-call-0001..2504`; a gap, duplicate, extra call,
or count mismatch rejects the manifest.

Stage-2 rows exist at T0 as assigned conditional rows but are `NOT_TRIGGERED`
unless the exact G01–G11 conjunction in `analysis_contract.md` is true. They
never enter a Stage-1 mean. Stage-1 and
Stage-2 summaries remain separate; “untouched” means byte/side/target/model
assignment sealed before Stage 1 and not model-facing or protocol-debugged, not
replication or an unconditional factor sample.  Any executable-environment
defect, code/config/model/tokenizer/extractor/reader/timeout/cache-policy or
runtime-envelope change, or root access beyond allowed Stage-0 certificates,
terminates the run;
it cannot be patched between stages.

Selected action-intervention support is intentionally narrow: the presealed
ordinary continuation is `h=0` on factor roots (and the analogous `q=0` only
where a q-specific control is specified); `z_side` is the T0 sampled z and its
antipode.  EMPTY, crossed, sham, memory-value, and action-redirection claims
are only about the listed selected-h rows.  The absent other-h cuts would add
`3 cuts x 1 h x 2 z x 62 = 372` recurrent Think calls, so they are not present.
No h-crossed corpus action row exists: the raw-A-to-Dream-2 selected-object receipt
and selected-h corpus-to-action contrast are separate clauses;
h-revision-to-action mediation is untested. Stage-1 gate bindings name every
required A/B, raw-A, provenance, SELF/control action, oracle, and manifest row
literally; no result-time selector is permitted.

The exact four structured one-shot Think assignments are:

1. `pcfl-untouched-factor-0000`, `family=factor`, `h=0`, `z_side=sampled`,
   presealed D4 target, `goal_twin=0`, AST corpus and iterative AST comparator.
2. The same factor life and target with `goal_twin=1`.
3. `pcfl-independent-0000`, `family=independent`, `q=0`, `z_side=sampled`,
   presealed D4 target, `goal_twin=0`, AST corpus and iterative AST comparator.
4. The same independent life and target with `goal_twin=1`.

Each is one open-loop action plan and is `ANALYSIS_PAIR_ONLY` with its iterative
AST comparator. Its coupling group and seed are distinct because topology does
not match. It must emit exactly four legal USE actions then LOCK; short,
illegal, malformed, early-lock, or timeout is zero and does not prove anything
about opaque or general recurrence.  No one-shot selected life includes an
antipode or alternate h/q continuation.

Outcome records use separate assignment, stage, invocation/process,
parse/reducer, endpoint, and terminal-reason fields. A legal wrong action is a
returned accepted process with endpoint zero, not a process failure. Malformed,
timeout, illegal, early-lock, unavailable-read, abstain, infrastructure, and
NOT_RUN outcomes remain in assigned denominators; unopened Stage-2 rows have a
null endpoint and explicit NOT_TRIGGERED status.

The only replay slots are `replay-001` for the first eligible failed scientific
call in canonical call-ID order and `replay-002` for the next distinct eligible
call. Eligibility is limited to engine start failure, engine process crash
before response bytes, transport EOF before response bytes, or device runtime
fault before response bytes. Timeout, malformed/illegal/wrong output,
unavailable read, forecast failure, and any failure after a response byte are
ineligible. Each replay uses the source call ID, exact rendered bytes, seed,
sampler/runtime envelope, and a fresh process for
`infrastructure-diagnosis`. It never replaces a scientific output or enters an
endpoint. No third replay exists; the maximum is 3,416 process opportunities.
