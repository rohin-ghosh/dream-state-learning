## 5. Outcomes, pairing, and failure

All rows and terminal codes are defined solely by `analysis_contract.md`.
Malformed, timeout, illegal, early lock, unavailable read, abstention, and
`NOT_RUN` are zero-valued and retained.  Factor contrasts pair identical
`(root,h,z_side,target_id,goal_twin)` rows.  Each independent q has separate
EMPTY and OBSERVED rows on the same `(q,z_side,target_id,goal_twin)` packet;
q values are never pooled for a positive effect.  First-action redirection is
reported only as a paired different-first-legal-action indicator, separate from
D4 success.  Ties have the predeclared value and code in the analysis contract.

`ANY_INDEPENDENT_SUCCESS` is true iff any of the eight independent SELF D4
endpoints is one. It is reported descriptively and is not itself the compound
alarm. `SPECIFICITY_CONCERN` is true iff either q has at least three of its four
failure-inclusive SELF successes, or both q values separately have strictly
positive SELF-minus-EMPTY and SELF-minus-OBSERVED means. Stage 0 exhausts the
finite vector/policy table in `analysis_contract.md`. Neither field is an
inferential test, changes a gate, or pools q. AST and one-shot values stay
separate and cannot rescue opaque failure.
