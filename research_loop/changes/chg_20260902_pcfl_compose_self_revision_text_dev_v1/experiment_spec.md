# PCFL-Compose self-revision text DEV: exact proposed protocol

**Change:** `chg_20260902_pcfl_compose_self_revision_text_dev_v1`  
**Status:** proposal only; human ratification required; no implementation or
run authority.  
**Paper role:** construct plus descriptive falsification, never confirmation.

## 1. Question and finite claim

This change asks one deliberately narrow question:

> In a fixed-source synthetic life, can one frozen prompted resolver first
> propose a predictive connection from public action/outcome episodes, then
> revise its own proposal after raw public validation events, after which a
> truth-blind representational sleeper and bounded text-memory resolver cause
> correct actions on never-executed compounds?

The model, not a comparator, owns durable selection. Opaque NOTE meaning is
undefined after emission; OPERATOR_AST is a separate structure-assisted lane.
The exact comparator is sterile and offline. A perfect public-prediction gate is a
separately named ceiling. The experiment does not include LoRA and cannot say
anything about parametric transport, compression, learned loops, or the
on-policy self-improvement flywheel.

The maximum positive primary-lane sentence is frozen as:

> Under a frozen recurrent prompt and deterministic lexical memory interface,
> a resolver wrote cited opaque text from public action outcomes, performed a
> second post-A Dream pass using only later raw public events, and the resulting
> life-specific text causally improved exact prospective predictions and
> executed actions on never-executed compounds in this minimal DEV construct.

“Self-revised from raw evidence” may replace “performed a second post-A Dream
pass” only if the separately specified public-prefix-identical continuation
fork is CPU-certified and passes its predeclared exact behavior test. Nothing
here establishes factor-program discovery, note truth, semantic compression,
record-level mechanism, naturalistic generality, post-context scaling,
learned-loop improvement, or LoRA transport.

## 2. Exact construct

Use the permutation convention, factorized and independent-table families,
and certificate rules in the bound sparse-construct and math advisories.
There are six tray slots; a public action is `USE(stem::suffix)`; every event
uses fresh handles. The mathematical `u/v/j` symbols in this file are private
certifier notation and never public labels. For each root, a factor-independent
label seed generates 14 collision-free eight-letter lowercase nonce strings,
then a separately sealed permutation assigns nine to stem positions and five
to suffix positions. No public prefix marks a role, hub, pair, family, orbit,
target, or root. The factorized family has nine stems, five suffixes, a
private orientation bit, and hidden life-specific permutations. The public
pre-validation graph is the unlabeled symmetric double-star with 13 edges:

```text
(u0,j0)
(u1,j0),(v1,j0)
(u2,j0),(v2,j0)
(u3,j0),(v3,j0)
(u4,j0),(v4,j0)
(u0,j1),(u0,j2),(u0,j3),(u0,j4)
```

`u0` and `j0` are visible high-degree hubs, but are never named as anchors in
the primary prompt. This is supplied topology, not graph discovery. The two
presealed revision actions are `(u1,j2),(v1,j2)` and the two disjoint audit
actions are `(u2,j3),(v2,j3)`. Neither orbit intersects any target.

At D4 stage `l`, the fixed menu is `(u_l,j_l)` versus `(v_l,j_l)` for
`l=1..4`; none of these eight compounds is executed before evaluation. D1 is
one presealed stage. Every target has exactly one legal successful sequence,
no shorter success, no wrong-prefix recovery, and a goal twin whose goal bytes
change while every non-goal target byte is identical. Each separate goal
packet is byte-identical across the complete hidden orbit.

For each factorized orbit root construct all 32 private worlds `H_(h,z)`, with
orientation-continuation bit `h in {0,1}` and stage-swap vector
`z in {0,1}^4`. Under the exact construction, target packets remain
byte-identical across `(h,z)` while the correct sequence is
`z xor h*1111`. Across either fixed h, all 16 correct D4 sequences are distinct.
The exact target-only values remain D1 action `1/2`, D4 first action `1/2`, and
D4 full trajectory `1/16`; h does not create 32 distinct target-visible
answers. A global two-life pair never establishes the `1/16` theorem.

After orbit-level acceptance, sample `z` uniformly with a sealed RNG and
materialize `z` and its predeclared antipode `z xor 1111`. The ordinary roster
uses one presealed h branch; the prefix-identical revision diagnostic adds the
other h branch while reusing the exact Dream-1 prefix. Sampling is independent
across roots. Both lives, h continuations, and every target remain nested under
their root for analysis. This design does not empirically exercise all 16
sequences or estimate four independent stage effects.

The matched independent-table family has the identical public interface,
schedules, graph roles, action counts, permutation marginals, target orbit,
goal/twin rendering, budgets, and failures, but independently samples every
compound transformation. Its never-executed target compounds are conditionally
independent of eligible evidence.

For the factorized revision diagnostic, Stage 0 constructs the two h
continuations from a shared tree. With `M=T(u0,j0)`, `R_i=M r_i`, and
`C_j=M c_j`, choose every `c_l` involutive and
`r_(v_l)=c_l r_(u_l) c_l`. Then BA completion `M c_j r_i` and AB completion
`M r_i c_j` swap the correct u/v action at every target while preserving the
target tray trajectory. Stage 0 must construct complete valid continuations
`V0,V1` of one public prefix. Tree events, public
labels, announced A actions, A before-trays, Dream-1 rendered bytes, seed,
trace, candidates, predictions, and commitment are byte-identical. Only the
ordinary A after-trays differ before fresh Dream-2 sessions; Dream-2 prompt,
eligible-handle shape, budgets, seed-by-role, and B request shape remain fixed.
The certifier must establish different correct B predictions and complementary
correct target actions at every stage while preserving the 16-sequence theorem.
Dream-1 runs once and its immutable bytes fork. No match bit, orientation name,
or score is public. This diagnostic is not a substitute for the separate
antipode life-binding comparison. Its exact construction remains bound to the
bound orientation-fork math audit; failure to certify removes “self-revision”
wording and blocks S1B rather than inviting an ad hoc repair. The matched
independent family has the same two-continuation public shape and budgets, but
its later unseen compounds remain conditionally independent.

## 3. Exact chronology and model ownership

```text
T0 seal roots/orbits, both h continuations, schedules, prompts, schema, budgets,
   arms, A/B/targets, certificates, and the independent null analogue
T1 release the 13 raw public tree events
T2 generic Dream-1 runs once per (root,z,lane) and commits <=2 candidate
   packages plus A predictions; clone its immutable bytes for the h fork
T3 expose exactly one presealed raw A continuation to each isolated branch
T4 fresh generic Dream-2 emits one RETAIN/REVISE/ABSTAIN and B predictions
T5 truth-blind sleeper freezes branch corpora and indexes
T6 render presealed target packets; Think reads, USEs, and LOCKs
T7 release sterile B outcomes to the scorer; execute cuts; score offline only
```

Dream-1 uses `prompts/generic_dream1.txt` as the primary recurrent resolver:
`K=2`, `R=13`, at most 13 event reads and 32 resolver operations. Of those
operations, at most 13 are `NOTICE`/`CONNECT`/cognitive-`REVISE`, at most two
are `PREDICT`, and one is terminal `COMMIT` or `ABSTAIN`; up to three
`PASS`/malformed attempts are charged without mutating state. The state has at
most 16 nodes, 4,096 live model tokens, and three raw event payloads. The
cumulative generated-token entitlement is 8,192 tokens: ordinary cognitive
operations and the terminal receive at most 256 each, `READ` receives at most
64, and each `PREDICT` receives at most 2,048. Temperature is `0.20` and top-p
is `0.95`. Each operation is a fresh model call carrying the exact bounded
state; the model chooses which event to read.

Dream-2 uses `prompts/generic_dream2.txt`, a fresh context and KV cache, at
most eight reads and 16 resolver operations. At most two reads address
candidate packages, two address raw A events, and four address source events;
at most five operations are `NOTICE`/`CONNECT`/cognitive-`REVISE`, at most one
is an audit `PREDICT`, and one is terminal `COMMIT(RETAIN|REVISE)` or
`ABSTAIN`; one `PASS`/malformed attempt is charged. State has at most 16 nodes
and 4,096 live model tokens, and the cumulative generated-token entitlement is
4,096. Temperature is `0.20` and top-p is `0.95`. Terminal RETAIN copies one
existing candidate's records exactly. Terminal REVISE emits one replacement
package, cites one or both parents, and may not create multiple active
hypotheses. ABSTAIN creates no active semantic memory.

Both recurrent phases use one sealed seed and no scientific retry. If an
exact-byte infrastructure replay is available, it must use the identical
input and seed in a fresh process; the first failure remains the scientific
result and denominator and the replay cannot replace it.

The recurrent resolver is the headline because the owner hypothesis concerns
connection through bounded traversal, not a single all-events batch. The
matched `prompts/one_shot_dream1.txt` and `one_shot_dream2.txt` control receives
the same eligible public information, `K=2`, `R=13`, record/package byte
limits, and cumulative generated-token entitlement. Recurrent execution
necessarily rereads state and uses more calls, so input tokens, calls, latency,
and estimated FLOPs are separately reported rather than falsely called
matched. If one-shot is within `0.05` of recurrent SELF on prospective
correctness and D4 action success, no recurrent-Dream advantage is claimed.

The frozen model for every text-generation and thinker arm is
`Qwen/Qwen2.5-32B-Instruct` at revision
`5ede1c97bbab6ce5cda5812749b4c0bdf79b18dd`, bf16, served through the already
available local vLLM runtime with prefix caching disabled and no request
truncation. No fallback model, provider API, or model-family change is allowed.

The primary and independent-table families use byte-identical generic prompts,
schema, renderer, budgets, seeds-by-role, parser, and stop behavior. The prompt
files are templates: substitutions replace only the named `{{UPPER_CASE}}`
markers with compact canonical JSON (`sort_keys=true`, separators `(',',':')`,
UTF-8, LF); every rendered prompt is retained and hashed.

`prompts/neutral_dream1.txt` and `prompts/neutral_dream2.txt` form a
prompt-scaffolding diagnostic only on the untouched factorized and matched
independent roots. They omit the explicit process verbs but use the same
opaque-note schema and budgets.
`prompts/operator_ast_*.txt` form a structure-assisted representation-by-family diagnostic;
`prompts/class_informed_*.txt` additionally supply the family. Neither may
rescue or support the primary opaque claim.

## 4. Behavior-first memory contract and diagnostic DSL

The primary `OPAQUE_NOTE_SELF` output is a NOTE envelope: ID, model-authored
UTF-8 text, public-event and premise-node provenance, and uncertainty. Note
meaning is opaque after emission. Sleep may check bytes, references,
provenance, caps, exact duplication, and the frozen surface-only lexical index;
it may not classify, truth-score, normalize, paraphrase, or interpret text.
The target reader returns one unchanged note or `NOT_FOUND`.

The separately labeled `OPERATOR_AST_SELF` diagnostic uses the closed typed
grammar and exact interpreter in `semantic_dsl.schema.json` and
`semantic_contract.md`. It supplies finite operator-algebra affordances and is
therefore structure-assisted, never the naturalistic headline. It uses fresh
sessions and cannot be derived by translating opaque output. Only it and the
structured oracle/class-informed arms support denotation scores, the 13-item
semantic-reader certificate, or record-level order/factor cuts.

All lanes share one `RESOLVER_STEP` envelope and the identical
READ/NOTICE/CONNECT/REVISE/PASS parser and state-update kernel. Dream adds
PREDICT/COMMIT; Think adds USE/LOCK. Phase/op cardinalities, candidate-handle
reads, terminal byte binding, acyclic provenance, exact query/postings,
canonicalization, byte limits, false-content symmetry, and the 13-item
2,510-byte AST fixture are specified in `semantic_contract.md` and the real
shared state tuple/reducer is hash-bound in `resolver_reducer.md`. Sleep receives
only public allowlists, never target manifests; changing every private target
manifest must leave its admission and index bytes identical.

## 5. Stage-1 text arm roster

Every model condition is a frozen, descriptive DEV arm. Branch labels are not
model-visible. All common candidates and raw A bytes freeze before branches.

1. **OPAQUE_NOTE_SELF:** primary; compile exactly Dream-2's model-owned opaque
   terminal decision.
2. **PERFECT_PUBLIC_GATE:** from the Dream-1 pool only, admit the candidate
   whose two precommitted A trays exactly match public A outcomes; ties use
   Dream-1 priority then canonical hash. It cannot repair or see B/targets/
   hidden truth. This is a public-signal ceiling, not the headline.
3. **NO_GATE_ALL:** compile every syntactically valid Dream-1 candidate and a
   syntactically valid Dream-2 revision, all marked `UNVETTED`.
4. **NO_GATE_HASH1:** footprint diagnostic choosing one valid Dream-1
   candidate by the smallest SHA-256 of its precommitted bytes, independent of
   outcomes, targets, and truth.
5. **NO_REVISION:** compile the first syntactically valid Dream-1 candidate in
   emitted priority order; A is never passed to a second cognitive call.
6. **EMPTY_MEMORY:** no notes, with identical reader/Think budgets.
7. **OBSERVED_TABLE:** exact extracted transformations for the 15 eligible
   public tree+A events, with no missing-compound completion or factor records.
8. **RAW_RAG:** target-time iterative retrieval over immutable raw public
   events, at both an equal-serialized-token frontier and a construct-sufficient
   frontier of at most 25 calls/15 unique events.
9. **EXACT_PROGRAM:** non-LLM public factor program; on the independent table
   it declares unseen targets unidentifiable. This is construct ceiling, not a
   baseline the organism must beat.
10. **ORACLE_SCHEMA_TEXT:** on factorized roots only, scorer-generated correct
   public-identifiable gauge-fixed atomic AST records, labeled as a
   memory/think ceiling. It is `NOT_APPLICABLE` on independent roots; hidden
   unseen transforms are never injected as memory.
11. **CLASS_INFORMED_TEXT:** separate class-informed AST prompts, same raw events,
    no hidden factors/order/outcomes/targets; tests known-family fitting. On
    independent roots it is explicitly a misspecified-family diagnostic, not
    a ceiling.
12. **ORIENTATION_DELETED:** on factorized roots only, the oracle-schema corpus
    with its single orientation/composition-law record removed and all other
    bytes fixed. It is `NOT_APPLICABLE` on independent roots.
13. **ONE_SHOT_DREAM versus RECURRENT_DREAM:** same opaque objective, envelope,
    eligible public information, K/R/byte limits, and cumulative generated-token
    entitlement; costs separately reported. Within `0.05` on prospective
    accuracy and D4 means no recurrent-Dream advantage.
14. **ONE_SHOT_THINK versus ITERATIVE_THINK:** same assigned memory items and
    cumulative generated-token entitlement; costs separately reported.
15. **OPERATOR_AST_SELF:** structure-assisted, fresh-session diagnostic on the
    open factor root and the matched independent root. It cannot rescue opaque
    failure or support the primary result.
16. **NATIVE_A_MEM:** only if an official or already-vendored faithful A-MEM
    implementation, revision, license, native write/link/retrieval flow, and
    complete index/call/byte accounting pass a pre-model review. Otherwise the
    entire arm is `NOT_RUN`; no simplified linked store may be called A-MEM.

The exact matrix is fixed as follows. The open factor runs forked opaque SELF;
ordinary z+antipode PERFECT, NO_GATE_ALL, NO_GATE_HASH1, NO_REVISION, EMPTY,
OBSERVED, both RAW_RAG frontiers, EXACT, ORACLE, CLASS_INFORMED,
ORIENTATION_DELETED, and OPERATOR_AST; four opaque whole-corpus interventions;
and three preregistered OPERATOR_AST structural cuts. The untouched factor
runs forked opaque SELF; ordinary PERFECT, EMPTY, OBSERVED, both RAW_RAG
frontiers, EXACT, ORACLE, NEUTRAL_OPAQUE, and ONE_SHOT_DREAM. The independent
root runs forked opaque SELF; ordinary EMPTY, OBSERVED, both RAW_RAG frontiers,
EXACT_ABSTAIN, NEUTRAL_OPAQUE, OPERATOR_AST, CLASS_MISSPECIFIED, and
ONE_SHOT_DREAM. The one-shot Think control runs on open-factor ORACLE and
OPERATOR_AST and independent OPERATOR_AST cells. No other cross-product is
implied. A-MEM's native interface is not forced through the common reader; if
admitted, it runs only its preregistered untouched-factor and independent
equal-token/native frontiers within the separate 512-call reserve.

## 6. Reader, thinker, and action contract

The iterative thinker uses `prompts/iterative_thinker.txt` and the shared
resolver envelope. For opaque memory, UTF-8 is normalized by Unicode NFC,
case-folded, and split into maximal Unicode alphanumeric tokens while each
literal public `stem::suffix` and its two already-public parts are preserved.
No stemming, synonym, relation lexicon, embedding, or ontology alias exists.
The same tokenizer handles the query. Records rank by descending query-token
intersection, then SHA-256 of unchanged canonical note bytes; zero overlap is
`NOT_FOUND`, and cursor returns the next item. The reader returns one immutable
note plus provenance or `NOT_FOUND`. For structured diagnostics only, exact
AST-field postings follow `semantic_contract.md`. No reader returns a completed
compound, factor table, target bundle, solution path, recommendation, or plan.
Every query byte, posting examined, cursor, returned byte, and call is counted.

Compiled/oracle/class-informed interfaces have D1 cap 4 records and 10 total
resolver operations; D4 cap 13 records and 31 total operations. D1 permits one
USE then LOCK; D4 permits exactly four stage-legal USEs then LOCK. RAW_RAG and
OBSERVED_TABLE may make at most 25 reads but expose at most 15 unique eligible
events. Equal-token RAG truncates by a presealed target-independent event-hash
order to the serialized-token size of the assigned compiled corpus; the
construct-sufficient point retains the 25/15 caps. An insufficient point is a
resource datum, not baseline failure. Native A-MEM uses frozen native limits
and reports them rather than inheriting an artificial cap.

The one-shot control uses `prompts/one_shot_thinker.txt`, receives exactly the
records actually available to its matched iterative arm in canonical
target-independent order, and has the same total output-token allowance. Its
plan is physically executed. All evaluations start from isolated clones;
target outcomes never enter another target, branch, memory, or checkpoint.

Goal twins intentionally change only goal bytes. For each fixed goal, the
complete public target packet is orbit-invariant. Success requires real USE
actions and LOCK. Wrong/illegal/malformed/timeout/missing/early-lock results
score zero.

## 7. Roots, checkpoints, and staged run gate

The implementation must accept arbitrary root IDs, but Stage 0 additionally
certifies the deterministic root set `pcfl-cpu-0000` through
`pcfl-cpu-0063` in each family, including all 32 private `(h,z)` states. Every
root is total: internal candidate rejections are logged, and no root silently
disappears. Hard CPU budget is 30 minutes per root and 24 CPU-hours total.

Stage 1 has exactly three independent roots, each at the honest
`MINIMAL_PRECONTEXT_CYCLE` consisting of 13 tree events, two A events, one
Dream/Sleep cycle, and disjoint B/targets. No row is called `0.75L`, `1.5L`,
`3L`, `6L`, post-context, or a lifetime checkpoint:

```text
OPEN_FACTOR_ROOT       = pcfl-open-factor-0000
UNTOUCHED_FACTOR_ROOT  = pcfl-untouched-factor-0000
INDEPENDENT_ROOT       = pcfl-independent-0000
```

The root string plus domain separator
`pcfl-compose-self-revision-text-dev-v1` seeds generation. After complete
orbit acceptance, `z` is the first four bits of
`SHA256(domain || "|" || root || "|sample-z")`; the antipode is xor `1111`.
The open root may expose outputs during harness inspection. Any semantic prompt,
schema, parser, budget, arm, target, or analysis change after its first model
byte requires a new change ID and leaves the untouched root unused.

Run stages are:

- **S1A open one-cycle canary:** open root sampled z+antipode, with both h
  continuations for opaque SELF sharing the exact Dream-1 object. Stop unless all
  construct/firewall tests pass; the exact program is 1.00 D1/D4 and exact on
  both continuation B predictions/actions; oracle-schema iterative D4 is at
  least 0.95; opaque Dream-1 has
  at least one package with both A predictions correct, generic Dream-2 selects
  a final opaque package with both B predictions correct, OPAQUE_NOTE_SELF executes at least one
  D4 target; both goal twins redirect first action; both h branches produce
  their registered B predictions and complementary target actions; and authentic
  opaque memory is directionally above EMPTY and antipodal/wrong-life
  whole-corpus swaps while a byte-matched target-independent sham does not
  redirect behavior. No record-level semantic cut is required. Structured
  oracle/class-informed cuts must independently validate their machinery.
- **S1B untouched specificity sentinel:** only after S1A passes, run untouched
  factor and independent sampled z+antipode, with both h/q continuations for
  opaque SELF reusing their respective exact Dream-1 objects.
  Stop unless factorized exact/oracle ceilings remain valid and the independent
  exact program reports the registered unidentifiable/abstention result;
  both factorized continuation branches must have exact B predictions and
  complementary target actions; factorized opaque SELF D4 is at least 0.10
  above each of OBSERVED_TABLE and
  EMPTY_MEMORY; authentic opaque memory redirects first actions relative to
  antipodal/wrong-life whole-corpus swaps; and no private/comparator mutation
  changes opaque SELF. On the independent root, report all eight nested D4
  SELF rows (two q continuations by sampled z/antipode by two goal twins)
  against the four ordinary-q EMPTY/OBSERVED rows. Three or more SELF
  successes, or a positive SELF-minus-both-controls direction for both q
  continuations, is a predeclared `SPECIFICITY_CONCERN` that blocks any claim
  but is neither a chance threshold nor a population test. The independent
  certifier must show an A-only/B-only/target-only acceptance factorization,
  B independence from tree+A, and an exactly uniform conditional 16-way target
  posterior after either q continuation. Exact branch sensitivity alone is not
  success: no public evidence identifies its independently coupled B/target
  continuation. Structured cuts are diagnostic only.
There is no S1C in this change. A scalable graph, factor-addition chronology,
recurrent prior-memory input, native-context crossing, and four-checkpoint
acquisition/retention/cross-era study require a new material change after this
minimal cycle works. Padding or repeating these 15 events can never create a
lifetime crossing. Each root/orbit is the only independent statistical unit;
sides, targets, goal twins, calls, and samples are nested.

## 8. Causal interventions and metrics

At the minimal-cycle sentinel, replay opaque SELF targets with authentic memory, the
antipodal life's whole corpus, a wrong-life whole corpus, and an equal-byte
target-independent sham whole corpus. Goal and model bytes are otherwise
fixed. Because opaque notes have no registered meaning, record-level orientation and
decisive-factor cuts apply only to deterministically structured
oracle-schema/class-informed corpora. Those cuts must change action in their
certified direction. False SELF content's executed behavioral consequences
remain exact endpoints; a memory perturbation that merely changes prose does
not establish use.

Record failure-inclusively:

- Dream-1 parsed/unique/malformed/abstain candidates, exact A accuracy,
  any-A-correct pool recall, diversity, calls/tokens;
- Dream-2 decision, abstention, byte preservation/change, B accuracy, and
  provenance validity; no opaque truth, repair, or corruption label;
- corpus notes/bytes/provenance depth/exact-duplicate rate and zero sleeper
  content additions;
- D1/D4 success, D4 first action, wrong/illegal/early action, abstention, LOCK;
- reads, NOT_FOUND, repeated/useful reads, workspace revisions/citations,
  actual prompt/output tokens, calls, latency, action cost; and
- authentic/empty/antipode/wrong-life/order-only/sham direction, structured
  diagnostic cuts, family specificity, and
  observed-table/raw-RAG/A-MEM frontiers.

Diagnostic estimands at the minimal-cycle sentinel are:

```text
memory_value     = Y(OPAQUE_NOTE_SELF)-Y(EMPTY_MEMORY)
life_binding     = Y(AUTHENTIC_OPAQUE)-Y(WRONG_OR_ANTIPODAL_OPAQUE)
selection_regret = Y(PERFECT_PUBLIC_GATE)-Y(OPAQUE_NOTE_SELF)
selection_value  = Y(OPAQUE_NOTE_SELF)-Y(NO_GATE_ALL)
revision_value   = Y(OPAQUE_NOTE_SELF)-Y(NO_REVISION)
proposal_gap     = Y(ORACLE_SCHEMA_TEXT)-Y(PERFECT_PUBLIC_GATE)
dream_loop_value = Y(RECURRENT_OPAQUE_SELF)-Y(ONE_SHOT_OPAQUE_SELF)
specificity      = [Y(OPAQUE_NOTE_SELF,F)-Y(EMPTY_MEMORY,F)]
                 -[Y(OPAQUE_NOTE_SELF,I)-Y(EMPTY_MEMORY,I)]
```

Exact primary endpoints are prospective A/B tray predictions and physically
executed target actions. Opaque note truth, precision, recall, coverage, law,
factor, and orientation are undefined and not scored. An optional blinded
human reading may be reported only as a frozen, non-gating diagnostic with two
independent coders and retained disagreement; it cannot select, repair, or
explain an exact endpoint.

Frozen result interpretations are:

- construct/exact/oracle failure invalidates every neural interpretation;
- opaque factor success plus matched-independent specificity, causal
  whole-corpus use, sham non-redirection, and both continuation outcomes
  licenses only the maximum behavior-first sentence in Section 1;
- opaque success with continuation failure licenses post-A utility but not
  self-revision;
- opaque+AST success are two separate results; AST never explains opaque notes;
- opaque failure plus AST success is structure-assisted program synthesis and
  a failed natural opaque path, not a rescued organism;
- opaque success plus AST failure preserves only the behavioral result;
- both failures with valid ceilings are a model/controller negative on this
  precontext assay; and
- a one-shot match within `0.05` removes every recurrent-Dream advantage claim.

Report paired root contrasts only as descriptive values. No paired randomization
test is called exact unless the within-root treatment assignment was genuinely
randomized/exchangeable. Any future inference must use root/cluster bootstrap;
a label sign-flip test must state and justify its exchangeability assumptions.

## 9. Stop and authority rules

Stop immediately and retain artifacts on construct failure, target leakage,
private-field visibility, comparator influence, family prompt mismatch, exact
program failure, oracle-schema failure, independent-table gain, missing
failure assignments, model revision drift, context truncation, malformed
provider output beyond the one exact-byte infrastructure replay, resource cap,
or repeated infrastructure fault. No threshold changes, prompt repair, seed
replacement, target dropping, or automatic LoRA proposal occurs inside the run.

S1A to S1B is a conditional portion of one exactly ratified text-only scope,
but requires an immutable signed gate receipt and a fresh review of all prior
artifacts. A failed gate ends the workflow. S1B completion returns only
`HUMAN_REQUIRED_FOR_ANY_NEXT_STAGE`.
