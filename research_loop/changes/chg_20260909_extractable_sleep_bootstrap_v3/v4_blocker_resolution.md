# V4 blocker resolution: extractable SLEEP + teachability bootstrap

Date: 2026-09-09

Status: successor-proposal input only. This document authorizes no
implementation, model or tokenizer execution, data or benchmark generation,
adapter or checkpoint work, GPU use, resource acquisition, external scientific
execution, publication, push, or scientific claim.

The simple architecture remains unchanged:

- THINK is the child's live thought/action/outcome stream.
- DREAM rebuilds finite active context and is disposable.
- SLEEP compiles grounded child experience and writes the personal LoRA.
- A separate birth bootstrap may teach general feedback-to-action computations.
- Longitudinal parent language is waking-only and never enters personal SLEEP.

The matrix contains one explicit cell for every stage-information pair. An
omitted stage or information type is a proposal failure rather than an

## 2. Candidate evaluation is not scientific evaluation

Disposable exams, standardized-advice clones, and final evaluation produce
scientific reporting products. Those products may alter reporting and audit
roots only. They cannot alter child, parent, repetition, DREAM, life-data,
compiler, cache, candidate, lineage, or release inputs.

Candidate preservation evaluation is a distinct private transaction stage and
type. It can read a staged candidate, the previous committed child, and the
frozen preservation/safety panel. It writes only a staged preservation receipt
and candidate verdict. It cannot update the parent, child life data, repetition
state, DREAM, compiler corpus, or scientific results. The lineage promotion
gate may consume that verdict solely to promote or reject the staged active
weight root.

## 3. Repetition state is control-plane-only

The repetition-state root contains reminder schedule, counts, order, adaptive
parent state, and descriptive acquisition/relapse measurements. It is readable
only by the appropriate parent controller, lineage transaction machinery, and
isolated auditor. It is not a personal SLEEP input.

Any child-authored restatement or enacted correction that is publicly grounded
is stored through the ordinary life-data root under the same evidence rules as
all other child traces. SLEEP therefore sees the child's experience, not a
projection of parent scheduling metadata. No separate semantic repetition
projection is introduced.

## 4. Equal mechanism, not identical realized writes

The fixed-curriculum comparison requires identical:

- initial writer implementation and configuration;
- exogenous reminder bytes and ages;
- child token/action budgets and task opportunities;
- compiler/support rules;
- initialized optimizer opportunity and declared dose rule;
- preservation gates and promotion policy; and
- disposable exam schedule.

Treatment-induced grounded traces, cumulative corpora, gradients, candidate
weights, preservation verdicts, and commit decisions are expected to differ.
Those differences are outcomes of the assigned birth and are never described
as identical writes.

## 5. Rejected-write retry classes

Every failed SLEEP has exactly one frozen class:

- **Operational crash:** an interruption before a valid candidate verdict may
  retry the exact same content-addressed snapshot once. The retry must bind the
  same inputs, seed, writer configuration, and attempt number. A second crash
  rejects the transaction and waits for the next evidence threshold.
- **Behavioral or preservation rejection:** no retry on the same data. The
  previous active weights remain, committed wake/parent/repetition roots
  survive, failed derivatives are quarantined, DREAM is rebuilt from surviving
  roots, and the next candidate waits for the next preregistered evidence
  threshold.
- **Source, dose, visibility, or provenance invalidity:** fail closed; no model
  work may retry until a separately authorized repair produces valid inputs.

The adaptive parent cannot observe candidate scores, verdicts, retry class, or
promotion decisions.

## 6. Safety ordering

Evaluation-product noninterference and rejected-SLEEP life preservation are
model-free prerequisites for the first affected evaluation, writer, candidate,
or model-execution packet, whether CPU or GPU. They are not merely GPU gates.

A successor gate-order fixture attempts each affected packet before these tests
pass and must show a closed failure. Only after both tests and their dependency
roots pass may later exact implementation and execution packets be considered.

## 7. Scientific interpretation remains narrow

- `Delta_R`: immediate selective use of standardized advice at birth, with no
  personal SLEEP.
- `Delta_F`: acceleration of the fixed-curriculum-plus-personal-SLEEP package.
- `Delta_E`: interaction with the adaptive parent+child+SLEEP package.
- Repetition: descriptive selective enactment unless separately randomized.
- Replay: dependence on the declared replayed sentinel closure, not natural
  unreplayed retention.
- Blindness: no incremental downstream-derived information in bootstrap
  construction, not absence of base-model prior knowledge.
- Cadence: randomized total package, not a natural direct/indirect mediation
  decomposition.
- Two-root screens license spending only; paper claims require separately
  frozen independent roots, inference, controls, review, and human authority.

## 8. Deferred exact contracts

The successor architecture does not silently choose execution constants. Exact
active-weight descriptors, serializers, merge tolerances, CAS/fsync protocol,
support resolver, cache identity, audit sidecar, bootstrap generators and
splits, six-computation rubric, structural-overlap rule, primary statistics,
safety comparators, writer factorial, replay closure/filler mapping, and GPU
packet remain separately hash-bound downstream contracts. A downstream choice
that changes graph, loop, visibility, claim, or acceptance-test semantics
restarts architecture deliberation.
