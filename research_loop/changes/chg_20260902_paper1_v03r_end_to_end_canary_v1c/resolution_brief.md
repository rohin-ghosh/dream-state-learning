# v1c resolution brief

Status: design input only. This file is not a ratification, implementation
authorization, model request, GPU authorization, or scientific result.

v1c preserves the v1b scientific question, frozen v03r world, one held-out
aligned seed-5 pair, target-absent recurrent construction, prospective text
interventions, and conditional two-life LoRA transport. It changes no Paper-1
goalpost. It resolves v1b consensus `95a5e147594e7804e0ab4d5fef6854745432675dc08a619ba7e82052975b98e1`
with the following minimum choices.

## Scientific boundary

- This is a game-specific, ontology- and proof-sequence-scaffolded, one-pair
  engineering-ceiling diagnostic.
- DREAM and SELF_CHECK are model calls, not truth verifiers. `SUPPORTED` means
  model-claimed support under the supplied public rows.
- The private world is read only by the offline scorer after every runnable
  trace has sealed.
- The diagnostic cannot establish generic constructive memory, reliability,
  superiority, scale, saturation, durability, learned agency, rank-pyramid
  behavior, or autonomous discovery.
- The later MEMORY-versus-LOOP LoRA split, rank response, cascades, and base
  promotion remain outside this change.

## One exact stage order

1. Human ratification can authorize CPU implementation only.
2. CPU implementation, static closure, golden vectors, resolved executable
   lock, and P1CB01--P1CB04 plus P1CB06 preflight seal.
3. Fresh independent reviewer and separate advocate review the CPU-to-DEV
   packet. Only two approvals authorize DEV.
4. Execute and seal DEV; only a reviewed DEV pass authorizes held-out T.
5. Before any held-out provider dispatch, deterministically project and seal
   both public event streams, E-to-M plans, the shared target-absent probe,
   host-only withheld final-goal coordinates/question, state-token
   vocabularies, and the prospective public DIST-control manifest under
   `public_projection_contract.json`.
6. Complete both held-out target-absent lives through M0, target-absent
   THINK0, and the fixed OWN and DIST return branches. A THINK0 DEFER is a
   trace-local nonfatal terminal: it fixes OWN to NO_FOCUS, leaves DIST fixed,
   and makes return-feedback credit impossible, but it does not stop either
   return branch or classify Stage T before aggregate scoring.
7. Seal M0/M1 manifests, fixed M1_OWN transport corpora, fidelity rows, and
   the shared candidate registry. Reveal the already-sealed public final-goal
   question, never its answer or private truth.
8. Prospectively compile and seal path and, when feasible, sham manifests and
   all six text-arm plans/readers; an unavailable sham gets a sealed T-SHAM
   non-dispatch plan rather than a reader.
9. Execute every prospectively runnable T arm without scoring, cancellation,
   or retry; seal every trace; score offline.
10. Only a reviewed T pass authorizes exactly two conditional LoRA fits.
11. Seal both fits, fidelity reads, and L traces; score; obtain terminal
    reviewer and advocate dispositions; stop at the human terminal.

Missing dreamed ROLE_EQUIV or CAUSAL_JOIN candidates is
`VALID_STAGE_FAILURE/MISSING_REQUIRED_ABSTRACTION`, not a precondition error.
If the candidates exist but no legal matched sham can be constructed,
T-M0/T-OWN/T-DIST/T-TWIN/T-PATH still run and T-SHAM receives exact
zero-attempt non-dispatch rows. Aggregate Stage T is
`VALID_STAGE_FAILURE/SHAM_NOT_IDENTIFIABLE`: a system/control-identifiability
failure, never an invalid benchmark precondition.

## Public events and cognitive rows

- `public_projection_contract.json` is the sole raw-v03r-to-typed-public
  mapping. It binds the `lands/v03r.py` dependency closure through
  `lands/v03.py` and `lands/skins.py`, the aligned surface atoms, exact
  kind/payload mapping, probe, withheld goal, and seed-5 state tokens.
- Raw public events are closed CPU projection artifacts only, and every public
  projection/control byte seals before any held-out provider dispatch.
- Each event deterministically becomes one witnessed M row before WAKE.
- Model-visible DREAM, SELF_CHECK, and thinker citations use only M row IDs.
- Every kind has exact arity and atom namespaces. The anchor in ROLE_EQUIV or
  ROLE_APPLICATION is an `animal:` atom; there is no `anchor:` namespace.
- No generated reason, prediction, confidence, selector receipt, audit field,
  private field, result, answer, or donor identity can enter later cognition,
  selectors, rows, compiler views, candidates, or training.

## Proposal then immutable row

There is no mutable memory-row status transition.

1. DREAM emits PASS or one immutable proposal object `Pxxxxxx` containing
   kind, exact fields, 2--8 M citations, and audit-only prose/confidence.
2. A schema-valid new proposal receives exactly one SELF_CHECK call over the
   proposal, its cited rows in identical order, and at most eight additional
   rows. A duplicate proposal is logged and receives no second memory owner;
   its reserved SELF_CHECK slot is not dispatched.
3. SELF_CHECK emits SUPPORTED, CONTRADICTED, or UNRESOLVED. Its prose,
   prediction, and confidence remain audit-only.
4. Only SUPPORTED creates one immutable DREAMED M row. False self-approved
   rows remain eligible and can damage behavior. CONTRADICTED, UNRESOLVED,
   malformed, or illegal checks create audit receipts but no cognitive row.
5. `SELF_REVIEW_SAME_EVIDENCE` requires no additional support row.
   `MODEL_CLAIMED_DISTINCT_LINEAGE_SUPPORT` requires the model to identify at
   least one supplied additional row whose public-event lineage is nonempty
   and disjoint from all proposal-premise lineages. The harness checks only
   IDs and lineage disjointness, never semantic entailment.
6. A SUPPORTED row retains every model-identified support premise: its
   citations are the proposal citations in emitted order followed by all
   emitted support-row IDs in their supplied additional-row order, with
   first-occurrence deduplication. A check is illegal if this union exceeds
   eight. Depth is one plus the maximum depth over this full union and lineage
   is the union of every cited row lineage.
7. One semantic hash has one canonical row owner. Later identical CREATEs are
   duplicate audit events. Conflicting missing-field values remain separate
   rows and cause reader CONFLICT.

Witnessed rows are immutable records with origin/status/basis
`WITNESSED/WITNESSED/WITNESS`, zero citations, depth zero, and external
event-lineage provenance. Dreamed rows are immutable records with
`DREAMED/SUPPORTED/{SELF_REVIEW_SAME_EVIDENCE|MODEL_CLAIMED_DISTINCT_LINEAGE_SUPPORT}`,
the exact canonical proposal-plus-identified-support citation union, and depth
`1 + max(cited depth)`. Cycles are impossible because both proposal premises
and additional support rows must be owned before its slot. SELF_CHECK remains
same-model blinded self-review: its output never licenses a truth-verifier or
precision-improvement claim.

## Recurrence and seeds

- Prefix: 46 WAKE slots. After WAKE indices 3,7,...,43 append two
  REACTIVATE slots. Then append 16 SLEEP slots: 84 proposal slots total.
- Return: OWN and DIST each use 16 slots numbered 84--99. Corresponding arm
  slots share seeds.
- Evidence pools contain only WITNESSED or model-SUPPORTED rows. There is no
  unresolved trigger pool.
- WAKE trigger is the new witnessed row, followed by at most five prior
  evidence rows sharing exact typed atoms.
- REACTIVATE/SLEEP triggers cycle through UNDER_LINKED, RECENT, SUPPORTED with
  exact candidate predicates, counters, and deterministic ties.
- Only selected triggers increment their branch-local selection counter once
  when request state seals; neighbor appearances do not.
- M0 counters copy into OWN and DIST; branches then evolve independently.
- Request seeds use SHA-256 over exact profile and slot bytes. Profiles are
  DREAM, SELF_CHECK, THINK0, THINK1_DEV, THINK1_TEXT, and THINK1_LORA. Slots
  never include life, latent bit, branch result, or answer.

## Thinker state and accounting

- THINK0 and THINK1 receive closed state objects, one exact previous-read
  union, and discriminated scratch nodes.
- Each trace has twelve registered operation opportunities. Operations 1--11
  append nonterminal nodes. A valid nonterminal operation 12 executes and is
  retained in the trace but is not appended to scratch because there is no
  next request; it seals `VALID_STAGE_FAILURE/BUDGET_EXHAUSTED`. No call 13.
- COMMIT or DEFER can terminate a trace at any operation. THINK0 DEFER fixes
  NO_FOCUS and continues both return branches; THINK1 DEFER is an unsuccessful
  trace. Neither assigns the aggregate stage class until the prospective arm
  set has sealed and is scored. Model malformed/illegal output is a valid
  system failure. Provider/runtime/truncation/output-limit failure is
  infrastructure invalidity. CONFLICT is a legal read result.
- Published call counts are ceilings. Every post-terminal opportunity is a
  non-dispatch ledger row with a closed reason and zero attempts/tokens, not a
  fake provider receipt.

## Registered public DIST control

DIST is derived and sealed before any held-out model dispatch from the public
event projection and the public source/target probe, not from v03r audit-only
matched-distractor fields. Hold
the probe target fixed. Resolve the unique route/effect pair for the probe
source and compute its absolute episode-index gap. Candidate controls are all
other sources with exactly one route and exactly one same-target effect whose
absolute gap is greater than the frozen 12-observation local-window budget.
Select the candidate minimizing `(abs(candidate_gap-primary_gap), source
atom)` lexicographically. For seed 5 this must reproduce source
candyland, target confluenceland, route M000002, and effect M000026 in both
twins. Any mismatch is pre-dispatch `INVALID_PRECONDITION`. If THINK0 defers,
OWN receives NO_FOCUS while DIST still receives this fixed public control.

State-token vocabulary is the ASCII-byte-sorted unique RECIPE label field
values in the pre-dispatch sealed typed public projection. It must byte-equal
the values in recipient M0 witnessed RECIPE rows and is reused unchanged in
every recipient T/L arm.

## Prospective path and sham

After goal reveal, register from each M1_OWN corpus:

- `R_role`: eligible ROLE_EQUIV rows whose animal equals the final animal;
- `R_causal`: eligible CAUSAL_JOIN rows whose source and target equal the
  final source and final target.

Path excludes both sets and their provenance descendants. Offline scoring,
after all T traces seal, determines correctness under frozen private truth.
A row is structurally used only if its returned H handle is cited by a later
THINK or BACKTRACK node on the retained scratch prefix causally ancestral to
terminal COMMIT and is also cited by COMMIT. Decorative terminal citation,
uncited retrieval, prose mention, and wrong rows do not qualify. The
prospectively sealed T-PATH removal must also lose paired success before the
set-level causal-use claim is admitted.

Sham is an injective assignment from sorted path exclusions to protected-
frontier-filtered rows. Among equal-status edges, minimize globally: number of
kind mismatches, then total exact reader-projection token-mass difference,
then the lexicographic assigned semantic-hash vector. Require candidate pool
size and total difference `<= max(2, ceil(0.05 * path_token_mass))` or seal
SHAM_NOT_IDENTIFIABLE for T-SHAM only while the other five text arms still
run. No result-dependent alternative assignment exists, and full causal Stage
T pass is impossible without paired T-SHAM retention.

## Exact Stage-T green conjunction

Both lives must terminate THINK0 with the exact non-NO_FOCUS REQUEST_RETURN
for the shared public probe. T-OWN must solve the pair; T-M0 and T-DIST must
each lose paired success. In each T-OWN trace, at least one OWN-only admitted
CAUSAL_JOIN matching the sealed focus, absent by semantic hash from M0 and
M1_DIST, must be offline-correct and structurally used under the rule above.
The earlier twin/path/sham requirements remain conjunctive: exact donor-valid
T-TWIN behavior with structurally used donor roots, paired T-PATH loss, paired
T-SHAM retention, offline-correct structurally used ROLE_EQUIV and CAUSAL_JOIN
roots, and complete validity/accounting/review. Thus ordinary M0 memory or
unfocused extra dreaming cannot make the canary green; the measured return
feedback loop must contribute.

## Reader and LoRA transport

Text and LoRA are not byte-identical delivery systems. They share one sealed
semantic-row manifest and one closed thinker-facing read-result projection.

- Text resolves an exact one-null typed query against eligible closed rows.
- The LoRA scorer receives one exact cue plus a presealed candidate roster.
  It selects one exact completion by full-token conditional log likelihood.
- The candidate registry binds each completion to the completed semantic row
  in each backend. A selected candidate absent from that backend is NOT_FOUND;
  multiple values are CONFLICT; one present semantic row becomes the same
  closed thinker-facing projection used by text.
- The projection contains a request-local read handle, kind, fields, status,
  and semantic hash, but not creation citations, depth, row ID, backend ID, or
  host-side provenance. THINK scratch cites the read handle. Offline artifacts
  bind handles back to rows after traces seal.
- Thus adapter selection supplies every model-visible semantic field; host
  provenance cannot carry the answer or graph into the thinker.

Four deterministic compiler views derive from each semantic row: forward
field completion, reverse field completion, declarative recognition, and
question recognition. Exact UTF-8/JCS templates, missing indices,
cue/completion boundaries, round-trip decode, tokenization, EOS, collation,
ordering, RNG, optimizer, and step counts must be closed before DEV. Touches
apply only to LoRA examples, never to text.

Exactly two rank-64 Qwen2.5-7B adapters train from pristine bases, one per
life, from already sealed M1_OWN rows. Each separately must pass 44/48 fixed
cues. The same 32B thinker and request bytes are used for own/donor arms; only
the mounted backend changes, and it is unmounted after each atomic read.

## DEV and review identities

- OFFLINE_REGISTERED_GOLD uses a G namespace and a fixture-only schema. It
  never enters held-out memory ownership or proposal IDs. DEV and heldout
  share the thinker operation/parser/scorer, not the gold storage schema.
- Restore the exact ten long P1CB replacement IDs mandated by v1a consensus.
- P1CB01 occurs wholly after ratification during CPU implementation and before
  DEV, never before implementation.
- Every transition uses closed JCS review packet, assignment, disposition,
  artifact-reference, and authority-token schemas with exact inventories.
- Reviewer, implementer, producer, and advocate identity/fresh-context
  receipts are platform attestations; JSON validates their binding but does
  not claim cryptographic proof of human/model independence.
- Rejection, missing bytes, changed bytes, invalidity, or actor overlap stops
  the exact transition. The advocate cannot override the reviewer.

## Fixed ceilings and scope

The v1b ceilings remain ceilings: at most 216 DEV controller calls, 632
heldout-text calls, 48 conditional LoRA-thinker calls, 896 total calls, two
fits, 96 fidelity cases, and 48 online recognition reads. No retry.

Replication, additional seeds/skins, prompt/model/rank sweeps, learned LOOP
adapters, cascades, Action World, RML/PCFL, longer lifetimes, durability,
publication, external actions, credentials, leases, and spend are forbidden
inside v1c. Every result stops at the human terminal.
