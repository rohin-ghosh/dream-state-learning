# Adversarial critique: adaptive parent development

Date: 2026-09-07

Verdict: **REVISE.** The corrected direction is viable, but the current brief
is not yet ratifiable.

## Critical defects

1. **Authority conflict.** The new brief and old v4 topology cannot both be
   normative. A field-level supersession must replace v4's stateless,
   target-blind pinned parent, old identities/root semantics, and claims while
   retaining only explicitly revalidated safety/provenance invariants.
2. **One parent was becoming a team and memory platform.** The online treatment
   needs one exact fixed-weight parent policy and one bounded model-visible
   notebook. Codex/Fable/Rohin proposals belong to governed curriculum
   revisions outside the online parent. The immutable audit log is not
   automatically model-visible, and initial v5 should not add an unbounded
   retriever.
3. **Final identity contradiction.** A causal parenting comparison requires
   taught and untreated children forked from the same birth checkpoint. The
   mature teaching state must split into a shared pedagogy core and a
   child-specific record; the treated child's private history cannot initialize
   the control child's parent-present cell.
4. **Causal estimand was underspecified.** Adaptive task choice, difficulty,
   curriculum, and corrections form a total developmental package. A
   correction-only claim requires yoked exposures; otherwise name the package
   honestly. Four within-root cells are paired observations, not independent
   replicates. One selected adult supports conditional, not population-wide,
   claims.
5. **Process-only cannot be guaranteed.** An answer-aware natural-language
   tutor can transmit answer information through wording, timing, strategy,
   curriculum, and the child's restatement. Loss masking prevents direct
   imitation but not indirect gradient influence. Default claim: audited
   answer-aware tutoring, retained effects, and acquisition changes. Strong
   answer-free process-learning claims require an answer-blind arm or a
   mechanically answer-invariant channel.
6. **Freeze semantics conflicted.** Freeze immutable source checkpoints,
   policies, split, budgets, and analysis. Clone-local parent/child updates may
   occur under those rules, must be discarded after the root, and never inform
   later roots.
7. **Evidence was confused with favorable selection.** Every valid public
   action/outcome pair, including failures and failed teaching, remains
   evidence. Whether a lesson helped is a label, not an admission filter.
   Compiler replay changes dose, never independent evidence count.
8. **Current scout cannot instantiate the proposal.** It uses one backend as
   both parent and child, has no persistent parent, admits favorable whole
   episodes, uses episode-level evidence, rebuilds history from sampled
   corpora, and gates against base rather than the previous child.

## Minimum coherent adjudication

- Explicitly supersede the incompatible v4 fields.
- One exact fixed-weight parent per lineage; one bounded visible notebook; one
  separate immutable audit log.
- Keep the architecture simple: `THINK -> public outcome -> PARENT lesson/state
  update -> DREAM context rebuild -> SLEEP transactional child write`.
- Parallel branches gather short isolated experience; pool all valid canonical
  evidence, never independently trained adapters.
- Fork treated and untreated developmental children from the same birth state
  and save both adults if the final claim is causal parenting.
- Split reusable pedagogy from child-specific teacher memory before final
  roots.
- Compare every child candidate to the previous committed child.
- Until a stronger channel is built, claim audited answer-aware tutoring and
  measured retention/acquisition rather than guaranteed answer-free process
  learning.

## Human choices exposed

1. One-child demonstration or paired causal development.
2. Total adaptive-parenting package or correction-only/yoked-exposure claim.
3. Answer-aware tutoring or stricter answer-invariant process claim.
4. One autonomous online parent or an explicitly named team-parent treatment.
5. Development budget/downside tolerance and later exact parent/model/scope
   ratification.
