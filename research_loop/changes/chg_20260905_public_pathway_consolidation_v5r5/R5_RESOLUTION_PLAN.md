# PPC5r5 closure plan

Status: working successor plan only. It has no normative authority and does
not authorize implementation, model calls, training, behavioral work, GPU
work, or scientific claims. It will be superseded by exact r5 proposal bytes.

## Scientific invariant

Do not enlarge or shrink the r4 scientific question. Preserve four separate
generator-population assays and only their qualified, non-mediational
intersection:

1. supported complete-table READ selection;
2. observable every-edge interleaved response dependence;
3. frozen same-model DREAM context-policy value;
4. DREAM-selected evidence-to-READ total-policy value.

THINK, DREAM, and ACT remain frozen. The only trained object is an isolated
READ-scoring adapter. No result licenses closed-book storage, learned cognition,
continual improvement, compression, parenting, population learning, or scaling.

## R01 — define the sampled population, not only its hash

The generator contract will bind:

- source bytes/version and the finite parameter-space schema;
- an ordinal-independent parameter law;
- counter-based entropy expansion and one disjoint slice per proposal;
- fixed sample ordinals and pre-entropy gate memberships;
- a prospective proposal/rejection limit and every rejection receipt;
- the complete lower-unit support required for each gate;
- one recipient plus its own recipient-disjoint, exactly matched donor bundle;
- common-random call/action seed bundles;
- no outcome-dependent redraw, exclusion, replacement, or seed shifting.

Independent draws may coincidentally produce the same donor semantic identity.
That collision is retained. No global uniqueness filter, cross-draw matching,
or rematching is permitted. Only movement/reuse of a donor artifact across
recipient draws is forbidden. Rejection sampling is part of the exact pure
definition of G, not an analyst exclusion: every proposal and rejection is
retained, the acceptance predicate is fixed, and exhaustion blocks the run.
Static benchmark construction and its complete proposal/rejection trace are
sealed **before** run authority. Proposal exhaustion therefore blocks the run
rather than becoming stochastic run missingness. The registered power statement
is explicitly conditional on the already-passing sealed construction and
applies to draws from G's accepted, constructible recipient-bundle law. It must
never be presented as an unconditional probability that a fresh benchmark-
construction attempt both succeeds and releases; that stronger probability is
outside this assay unless construction succeeds with probability one on the
locked proposal support.

## R02 — one acyclic transition object and one total vocabulary

Retire `ledger_event` and `terminal_receipt`. The only transition object is:

```text
state_body -> transition_event -> state_receipt(ledger_head=event_hash)
```

Genesis uses the fixed empty-ledger head and no event. Terminal state uses the
ordinary three-object chain; cold replay adds nothing.

Publish one closed operation/result/terminal vocabulary and a machine-readable
controller row registry for every D1A-D1D program, phase, operation, error,
missing result, debit, queue action, next phase, endpoint effect, and terminal.
There is no implementation-selected default.

## R03 — make queues structurally exclusive

Each slot binds both controller-before and controller-after. Every QUEUED slot
has exactly one ordered effect, FLUSHED XOR DISCARDED. REJECTED has no effect.
FLUSHED structurally requires provider/intervention/public-event references and
forbids a discard reason; DISCARDED does the reverse. The terminal event binds
all and only remaining unexecuted slots. A queue-coverage object materializes
the bijection.

## R04 — close every decisive edge

Replace the legacy path proof with:

- a path-suite manifest containing the complete canonical multigraph and every
  simple path inside the READ budget;
- one ordered selected-path record;
- every nonempty proper subset mask and oracle input/output;
- one full-set proof;
- every alternate-path proof;
- for each `(path_template_id, edge_position, edge_id)`, the raw source event
  and preimage plus separate CUT, TWIN, and SHAM construction proofs;
- run-wide cross-item source-disjointness evidence.

Each edge gets separate gates. Averaging, missing an edge, reorienting
SHAM-AUTHENTIC, or substituting a singular SHAM fails.

## R05 — make restricted stages actually condition-free

The causal provider has one constant algorithm identity and only an opaque
nullable mount handle. Its ingress/receipt contains no arm or provider-kind.
Authentic and shuffled SLEEP rows use one row contract. Privileged assignment
and routing resolve treatment before emitting a restricted projection that
contains only opaque instance identity, final public bytes, locked debit/token/
length classes, and opaque lineage. Low-entropy matching hashes never cross the
projection. Taint fixtures cover all 182 visibility cells.

## R06 — eliminate generic semantic payloads

Every inventoried object gets a type-specific closed schema with:

- exact fields and status-dependent nullability;
- role-labeled, ordered artifact and byte references;
- exact role cardinality;
- raw byte length/hash and bundle-contained paths;
- aligned domain and self-hash names.

No `payload_ref` may stand in for an unspecified semantic record. Invalid raw
model bytes remain private but are byte-bound.

## R07 — exact statistics from observations to power

All authority-bearing probabilities, margins, alpha levels, bounds, and
p-values are reduced integer rationals. Each gate binds its fixed membership
and ordered observation references.

- Superiority margin: `0 <= margin < 1`.
- SHAM noninferiority uses `SHAM - AUTHENTIC` and `-1 < margin <= 0`.
- Population threshold: `1/2 <= pi0 < 1`.
- `cp_tail_alpha = alpha/4`, fixed by the run lock.
- `d_i == margin` fails; `p == threshold` passes; rate equal to ceiling fails.
- Missingness includes the same exact one-sided CP upper certificate as safety.

Each release-critical paired, safety, and missingness gate gets a closed power
object whose critical set includes the p-value, strict effect/rate, and strict
CP conditions. Familywise power uses only the registered Bonferroni sufficient
event and a union lower bound; no independence is assumed.

## R08 — make shared-DREAM missingness deterministic

Context/root capacities are prospective run-lock constants, not realized DREAM
cardinality. If the shared DREAM call is missing, only policies/endpoints that
consume its output are missing. RECENCY and PERMUTED controls still build their
fixed-capacity views from the sealed eligible universe. D1D provider and action
endpoints still execute under every root/training status; no dose is adjusted.

## R09 — derive acceptance, never accept a claimed PASS

Inventory closed schemas for fixture case, negative mutation, expected output
or failure, executed case result, mutation result, implementation identity,
implementation independence, endpoint coverage, and per-gate power. Remove
subject-supplied PASS fields from fixture and coverage inputs. A pure validator
may emit a PASS result only from exact counts, zero defects, all mutation
matches, complete evidence roles, and two distinct root implementations; its
status is output, not evidence for itself.

Split the pre-authorization deadlock explicitly:

- T01 before ratification is only source/hash/schema/intake validation by the
  already-authorized generic architecture-intake validators. It requires no
  PPC5 implementation artifact.
- PPC-specific two-implementation fixture conformance is post-ratification and
  pre-model. It is not part of the pre-ratification T01 intake check.
- T02-T12 are post-ratification **PRE_MODEL** deterministic conformance tests
  over the authorized isolated implementation and must pass before any model,
  tokenizer, embedding, trainer, canary, behavioral process, or GPU process is
  reachable. Calling them merely PRE_GPU is forbidden.
- T13 binds the populated run lock, dual static seals, review/advocate, power,
  and separate human run ratification at PRE_MODEL_EXECUTION.
- T14 is a postrun, prerelease cold replay and decision audit.

## R10 — role-close authority and exports

Every authority stage has its own schema and exact ordered role/type/cardinality
registry. Human evidence is mandatory at the two human stages. Review FAIL is
non-overridable. Exactly two distinct sealers are structural. Preflight binds
dispatch ID/ordinal, executable, mounted artifacts, run lock, authority, and
immediate state; DENY requires zero spawned processes.

Keep the acyclic release order:

```text
runtime reduction
  -> candidate claim_decision (no T14/authority/release dependency)
  -> non-releasing T14 cold replay of lives/reducers/decisions/boundaries
  -> preclaim_authority
  -> claim_release/export package
  -> optional post-release audit
```

Every released component/intersection and every export structurally carries
the exact registered literal, fixed qualification, complete forbidden-claim
list, overlap manifest, construction-scope receipt, decisions, Holm, T01-T14,
and authority. Paraphrase or detached qualification fails.

T14 never depends on a release artifact, and candidate decisions never depend
on T14 or preclaim authority. PRE_SCIENTIFIC_CLAIM authority consumes the
passing T14 receipt; release consumes that authority. This order is structural,
not a prose convention.

## R11 — version and self-hash closure

Every r5 schema carries the r5 schema version and an r5 `$id`; no inherited r3
or r4 identifier is permitted. Every top-level runtime, evidence, fixture,
acceptance, and authority object carries schema version 5 and an exact self-
hash computed under the single registered canonicalization rule. Proposal
source documents are instead bound byte-for-byte by `change.json.context_files`,
avoiding impossible self-hashing files. The inventory binds every runtime
schema ID, contract, producer, and self-hash field; the proposal context
manifest binds every normative source path and expected file hash. Validators
reject unregistered files, missing files, extra semantic payload types,
aliases, and path/schema/hash disagreement.
