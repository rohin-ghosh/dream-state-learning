# Independent science attack on the v2 rework resolution

Date: 2026-09-09

Scope: read-only audit of `v2_rework_resolution.md` against `AGENTS.md`, both
bootstrap interpretations, `critique.json`, `consensus.json`, and Rohin's
verbatim directive. No implementation, benchmark generation, model/tokenizer
execution, adapter training, GPU use, or scientific claim is authorized.

## Verdict

The v2 rework makes the right high-level separations, but it is not yet a
scientifically closed successor proposal.

- R3a can identify **immediate selective use of standardized advice at birth**
  after two design repairs. It cannot identify accelerated learning from
  parenting.
- R3b can identify a **bootstrap-by-adaptive-parent-policy effect on the whole
  parent + child + personal-SLEEP package** if development and examinations are
  made disposable, matched, and root-randomized. It cannot isolate a stable
  child-receptivity property, parenting alone, or a weight-only mediator.
- Taken together, R3a and R3b are useful triangulation. They still do not
  identify child-level bootstrap-enabled parenting acceleration unless a
  longitudinal fixed-parent-policy assay is added, or the claim is narrowed to
  the ecological package interaction.
- R2's proposed neutral is an active **direct-solution practice** condition,
  not a scientifically neutral condition. It is usable only under that name,
  with a no-bootstrap reference and stronger semantic diagnostics.
- The human's required notion of repetition is not operationalized. The
  document audits computations in bootstrap targets but does not measure the
  child's later unprompted, relevance-selective repeated enactment.
- R4 establishes code/data nondependence only in part. It does not establish
  structural or conceptual final-task blindness, and it cannot erase final-task
  knowledge already present in `M0` or a pretrained demonstrator.

Under `AGENTS.md`, the accurate disposition is **rework, then new exact-byte
deliberation and human ratification**. The document's no-authority status is
correct; its opening statement that it "resolves" the blockers is premature.

## 1. R3 does not yet identify one common acceleration claim

### 1.1 The standardized assay is sequentially confounded as written

R3a says to score the change from an unaided attempt to an advised attempt.
If these are two attempts on the same live episode, the advised score includes
second-attempt practice, observation of the first result, and state changes.
If they are merely different paired tasks, uncontrolled pair difficulty can
create the same problem. "Within-child change" is therefore not yet an
identified advice effect.

Repair: evaluate disposable clones of the same frozen checkpoint from the same
initial state and paired sampling seed:

- clone A receives no advice;
- clone B receives the byte-identical correct process advice;
- optional clones receive a prespecified irrelevant/shuffled advice item and a
  specifically wrong item;
- none of the clones writes, sleeps, updates the parent, or contributes an
  episode to the continuing lineage.

Counterbalanced parallel forms are acceptable only if item pairing is frozen
before results. Advice wording must be unseen, and the evaluation families,
action vocabulary, and task skins must be absent from both bootstrap corpora.
Holding out wording alone tests paraphrase robustness, not domain-general
receptivity.

The standardized estimand should be written explicitly as

`Delta_R = [Y_T(correct advice) - Y_T(no advice)] - [Y_N(correct advice) - Y_N(no advice)]`.

The wrong and irrelevant conditions need directional predictions. A gain under
all advice conditions is generic compliance, not selective teachability. Text
paraphrase is diagnostic only; the primary `Y` must be a mechanically scored
next action and public outcome.

### 1.2 R3a measures immediate receptivity, not learning acceleration

Personal SLEEP is correctly disabled in R3a. That makes the assay clean, but it
also means the assay observes one-step advice use, not conversion of repeated
parenting into durable learned behavior. A positive `Delta_R` supports only:
"the teachability birth used this class of novel process advice better at
birth." It does not establish faster development, retention, or parenting.

### 1.3 R3b is a valid package estimand only after tighter controls

With adaptive parenting and personal SLEEP active, the randomized interaction
includes all treatment-induced changes in parent messages, child behavior,
selected lived evidence, compiler outputs, gates, and later weights. Calling
personal SLEEP an intended mediator is accurate. Calling the result child
receptivity or parenting alone is not.

The no-parent cells must not mean inactivity. They need the same developmental
tasks, turns, action opportunities, context budget, wall-clock policy, and four
write opportunities as parent-present cells, with a frozen neutral/solo policy
filling only the parent resource opportunity. Otherwise the parent contrast
also changes experience and compute dose by construction.

Every longitudinal exam must run on a disposable checkpoint clone under clean
context, with parent text, briefs, ledgers, retrieval, and training disabled.
Exam episodes and standardized-panel responses must never return to the parent,
compiler, ledger, or continuing child. "Parent absent" without these rules is
not enough. Reusing one fixed item panel at every saved age should be avoided;
use frozen parallel folds or cloned counterfactual evaluations that cannot
affect the lineage.

For normalized parent-absent score `Y` at fixed ages, freeze one primary
interaction before generation. A suitable screen statistic is the interaction
in gain-curve AUC:

`Delta_E = [AUC(T,parent) - AUC(T,solo)] - [AUC(N,parent) - AUC(N,solo)]`,

where each curve is expressed relative to that lineage's entry score. Report
all four raw entry scores and curves. Time to a common absolute threshold is
secondary because a better birth can cross sooner without learning faster;
predeclare treatment of non-crossers, preferably a horizon-limited summary
rather than dropping them.

This `Delta_E` identifies bootstrap modification of the selected adaptive
parent-policy + SLEEP package. If the desired claim is instead that the child
learns faster from the same parenting, add a longitudinal assay in which parent
messages, timing, information, and repetition schedule are fixed identically
across births. Personal SLEEP can remain active if it is explicitly part of the
learning mechanism. Without that arm, narrow the claim.

### 1.4 Minimal statistics

Retain the v1 benchmark interpretation's simple canary rule for the ecological
interaction: on a frozen `[0,1]` score, require `Delta_E >= +0.03` in the same
direction on each of two independent curriculum roots, with no preregistered
preservation bound violated. Freeze a separate practical margin for `Delta_R`;
using the same `+0.03` would be a new proposal choice, not something established
by v1. Passing either rule licenses only a separately powered replication. It
is not a confidence interval or a science claim. Tasks, ages, advice items, and
training seeds are repeated measurements; the independent unit is the
root/lineage assignment. Two roots cannot support population inference,
however many tasks are scored.

## 2. R2's neutral condition is not scientifically neutral

Revealing the operative rule or next valid action changes the conditional
information, target entropy, and effective task difficulty. It also directly
trains reading a supplied instruction and executing it, which is adjacent to
the claimed advice-to-action construct. Calling padding "semantically inert"
does not match these quantities. Aggregate action-validity and favorable-
outcome rates do not repair the difference.

There is also an internal strain: if the neutral child is given the correct
next action and executes it, unfavorable outcomes cannot generally be yoked to
the teachability example without stochastic adversity or deliberately poor
behavior. The proposal must say which one applies. Matching or selecting on a
post-action favorable/adverse stratum can also change the examples admitted to
the two corpora.

The `80%/5%` semantic audit is too weak to define the intervention. For a
192--240-row corpus, it permits roughly 38--48 teachability targets to omit
their declared computation and 9--12 neutral targets to contain one. Those are
not independent samples, and the thresholds say nothing about instruction
following, correction salience, target predictability, or pretraining loss.
The two-percentage-point outcome rule is only about 4--5 rows at this corpus
size and is weaker than exact pairwise yoking where yoking is possible.

Repair:

1. Rename `BN` to the **direct-solution active control** and define the causal
   contrast accordingly: feedback-computation schooling versus equally dosed
   direct-solution task practice.
2. Carry `M0` as a no-bootstrap diagnostic reference. At minimum require `BN`
   to be noninferior to `M0` on frozen generic capability, interface, and
   advice-selectivity panels. Otherwise `BT - BN` can be manufactured by damage
   to `BN`.
3. Audit every row, not a sample. Freeze clause-level rubrics, use independent
   label-blinded coders, publish counts and disagreements, and adjudicate before
   training. Corpus purity is a manipulation check, never the behavioral
   outcome.
4. Pair source instance, target action, action position, mask, target-token
   bucket, update opportunity, and outcome mechanically where possible. Report
   rather than claim equality for irreducible input-information and difficulty
   differences.
5. Before training, score `M0` on both rendered conditions to expose large
   differences in success, target NLL, invalid-action rate, and cue
   informativeness. Freeze a tolerance or stratification rule before selecting
   rows; do not select pairs using later final-task performance.
6. If the scientific target is specifically selective advice uptake, use the
   correct/irrelevant/wrong advice counterfactual panel in R3a. No corpus-only
   neutral can substitute for that behavioral falsifier.

These repairs make the arm interpretable; they do not make its semantics
identical to `BT`, which is neither possible nor necessary.

## 3. Repetition is currently asserted, not measured

The directive requires repetition on the THINK/parenting side until the child
independently restates **and enacts** the lesson. R2 measures whether bootstrap
targets contain one of six computations. R3 measures advice gain and aggregate
development. Neither specifies repeated parenting opportunities, fading,
relapse, or spontaneous reuse. The acceptance-test bullet mentioning a
"dose-matched repetition" control has no object, endpoint, or directional
prediction.

Repair each parented lesson with an immutable `lesson_id` and log separately:

- number and spacing of parent reminders;
- number of varied relevant opportunities and matched irrelevant
  opportunities;
- whether the computation was invoked with no current parent cue;
- the next dispatched action and public outcome;
- fade time, context-reset probe, and any relapse-triggered restoration.

The primary repetition endpoint must be behavioral:

`selective enactment = P(correct strategy-dependent action | relevant, no cue)
- P(strategy-shaped action | irrelevant, no cue)`.

Score paraphrastic self-restatement separately and never let it rescue a null
or harmful action effect. A lesson can be called behaviorally acquired only
under a frozen rule requiring successful unprompted enactment on multiple novel
relevant cases, low misapplication on irrelevant cases, and persistence after
context reset. The exact count must be ratified before generation; it cannot be
chosen from the observed curve.

If the project wants the stronger claim that repetition itself causes learning,
randomize otherwise eligible lessons to one exposure versus spaced repetitions
across varied cases, balance total turns/tokens with non-lesson neutral
activity, and preregister the bootstrap-by-repetition contrast. Without this
randomization, report reminder dose and subsequent enactment descriptively.
Either way, parent prose remains in waking context and the audit ledger only;
it never becomes a personal SLEEP target. Child-authored text becomes eligible
only through the same grounded thought/action/outcome support rules, not because
it repeats the parent's words.

## 4. R4 does not yet establish credible final-task blindness

The four public families and disjoint nouns/APIs are useful lexical separation,
but `QUERY`, `ESTIMATE`, `ALLOCATE`, and `INTERVENE` can still teach an
isomorphic hidden-rule, exploration, allocation, or causal policy used by the
final gym. Final-byte mutation invariance proves that the builder does not
mechanically read those bytes; it does not prove conceptual independence,
absence of shared generator code, or absence of human design leakage.

Further, `M_birth_T` contains all knowledge already present in `M0`. A public
benchmark or final-task pattern may already be represented in `M0` or the
pinned demonstrator. The defensible claim is therefore **no incremental
final-task-derived information in bootstrap construction**, not that the birth
model is final-task blind.

Repair:

1. Freeze and hash bootstrap generators, prompts, corpora, selection receipts,
   and both birth checkpoints before final instances, keys, and solution-bearing
   metadata are created or mounted. Generate sealed final instances afterward
   under an independent root and inaccessible seed.
2. Run the bootstrap build in an allowlisted environment with no final-task
   repository, manifest, generator, evaluation probe, or result store mounted.
   The isolated auditor may see both sides only after the bootstrap bytes are
   frozen and must return only pass/fail plus non-content-bearing hashes.
3. Bind source-code dependency identities, RNG namespaces, demonstrator
   visibility, mechanical selection rules, and a prohibition on manual
   selection informed by final scores. The demonstrator may see bootstrap
   hidden state only to the extent explicitly ratified; it may never see final
   artifacts.
4. Predeclare a structural-overlap table covering observation topology,
   horizon, feedback timing, hidden-state inference, action semantics/cardinality,
   transition dynamics, reward shape, and solution algorithm. Enumerate allowed
   common language and THINK/NOTE syntax. An independent reviewer must reject a
   one-to-one policy isomorphism even when vocabulary differs.
5. Evaluate `M0`, `BN`, and `BT` on sealed final tasks. Use `M0` to measure
   pre-existing benchmark competence; use `BT - BN` only for the incremental
   schooling contrast. Do not reinterpret base-model knowledge as bootstrap
   leakage or bootstrap transfer.

Mutation invariance remains a valuable build-integrity test after these
repairs. It is not, by itself, a scientific target-blindness certificate.

## Required successor-proposal disposition

Before any implementation packet exists, the successor proposal must bind:

- the three separately named estimands: immediate standardized receptivity,
  adaptive parent+SLEEP package acceleration, and—only if added—fixed-policy
  child learning acceleration;
- clone-based advice counterfactuals and directional wrong/irrelevant-advice
  predictions;
- the direct-solution-control label, `M0` diagnostic, and exact neutral audit;
- behavioral repetition/fading/relapse receipts and any randomized repetition
  contrast;
- disposable clean-context exams and matched solo-development resources;
- incremental target-blindness language, a temporal/ACL firewall, and a
  structural-overlap audit;
- one normalized primary score, the ecological `+0.03` two-root canary rule, a
  separately frozen standardized-receptivity margin, adverse bounds,
  missing/non-crossing handling, and a later root-level replication.

Until those bytes pass fresh independent interpretation, cross-critique,
adjudication, and explicit human ratification, the feasible claim is only:
"We have a proposal for testing whether target-blind schooling may improve
selective advice use and may amplify one adaptive parenting-plus-SLEEP
developmental package." It is not yet evidence that the bootstrap expedites
learning.
