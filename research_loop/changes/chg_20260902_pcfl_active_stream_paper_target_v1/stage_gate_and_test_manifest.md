# Stage gates and acceptance-test manifest

Status: proposal only. Passing any future test establishes only its stated
contract; it never grants successor, ratification, execution, GPU, or claim
authority.

## Gate sequence

```text
architecture proposal
  -> fresh interpretations
  -> adversarial critique
  -> adjudicated consensus ending human_required/rework/reject
  -> later exact human-ratified implementation scope
  -> implement the minimal A0 construct/controller harness
  -> A0 paper-killer algebra/nonadaptive-reader audit
  -> A1 causal-boundary certification
  -> A2 exact cognition-byte hash freeze before any model call
  -> fresh independent A0--A2 implementation/cognition-manifest review
  -> explicit human authorization of the exact hash-bound scientific model-call scope
  -> only then B0 known-good reader/planner canary
  -> B1 two-root common-history representation killer
  -> B2 same-root 3L flywheel pulse
  -> only after B0--B2 pass, B3 eight-root/full-checkpoint text DEV
  -> B3 evidence/resource lock and independent descriptive-claim review
  -> terminal DEFERRED_NEW_PREREGISTRATION
  -> any Stage C requires a new proposal, untouched roots, fresh review, and explicit human ratification
```

No arrow is automatic.

The architecture specification, target/clone/cell manifests, test definitions,
and expected/falsifying outcomes freeze before implementation. Evidence
produced by code is never required before that code exists: executable
construct/visibility evidence is required after implementation and before
Stage B; DEV empirical compiler/baseline/resource evidence is required before
B3 lock; this protocol produces no confirmation or scientific-claim evidence.
Because `change.json.required_before` has
only `implementation`, `gpu_run`, and `scientific_claim`, the JSON maps
Stage-A execution checks to `gpu_run` and B3 descriptive/integrity checks to
the coarse `scientific_claim` enum; this prose makes them B3 locks and denies
any current claim or Stage-C transition.

## Stage-A construct gate

The stages below are ordered paper-killer gates. All pass before any
scientific/experiment model request; the configured architecture-deliberation
role calls are outside this gate and end at `human_required`.

Implement only the minimal generator/certifier/controller harness, then run

## Stage-B text DEV gate

Stage B is also ordered. `B0` injects known-good memory and verifies exact
reads, nonadaptive-versus-recurrent separation, fresh-handle executed action,
the frozen multi-sample duplicate/disagreement/malformed/abstain reducer,
unique instance IDs and Dream-2 additions, ordinary fixed-event-slot
Dream/snapshot/checkpoint trigger receipts and tie order, every checkpoint
status eligibility, deterministic multi-match cursor/exhaustion and
constant-shape unavailable slot, target/truth/result/realized-length-blind
mutation goldens,
paired compiler-seed equality/assignment-independence, semantic/outcome cuts,
and failure plumbing. `B1` then runs the byte-identical
common-history representation sentinel at 3L on two roots. `B2` runs one
AUTH/TWIN/NULL flywheel pulse plus binding-only and matched-action sentinels on
those same roots. Any failed decisive sign stops expansion. Only after B0--B2
pass may `B3` retain those assignments and expand the frozen surface to all
eight DEV roots and all four checkpoints; A4 follows the D4/flywheel evidence
lock if the deadline requires ordering. No failed row is replaced.

B3 lock requires all eight assigned DEV roots and all of the following
descriptive/falsification checks. Passing them does not authorize Stage C or a
population claim; it only leaves open a later request for a new preregistration:

1. `AS-PROG` itemwise D4 value `1.00`; separately, MECH direct witnessed-atom
   extraction/read fidelity is at least `.90`, with denominator equal to every
   assigned fully supported ordinary public witness atom and failures scored
   zero. This `.90` diagnostic never applies to ordinary or common-history
   integrative action value;
2. target-only/null action value at or below the registered headroom ceiling;
3. SELF Dream-1 prospective bytes before outcomes and model-owned Dream-2
   revision from raw public outcomes on at least six of eight roots;
4. `AS-SELF-TEXT` post-native cross-era AUC at least `.15` above `AS-NONE`
   and no more than `.05` below the selected `AS-EXT` DEV frontier;
5. authentic versus twin/null causal-cascade DEV summaries have the registered probe,
   information-gain, delta, and later-action signs on at least six of eight
   roots, and `SELF-DELTA` directionally exceeds RAW-AO, ACTION-ONLY, and
   WITNESS/MECH on the integrative targets while outcome and executable
   semantic interventions exceed their shams; the binding-only trio redirects
   only its decisive binding, the recurrent reader exceeds nonadaptive reads,
   and generic SELF exceeds the strongest non-SELF common-history condition;
   class-informed-only success fails the generic SELF gate;
6. lagged memory does not solve new targets; on the exact preassigned first-
   acquisition and 6L OLD rows, the frozen P3 components `A_w - tau_w`,
   `L_w - tau_w`, and `L_w - A_w + .05` have the required DEV signs, where
   `tau_w=max(.50,B_OLD,w+.20)` and `tau_w>1` is invalid; every failed or
   zero-acquisition root remains in all three components; complete old/new cuts
   harm cross-era value more than shams;
7. no shortcut, visibility, reset, target-selection, scorer, candidate,
   resource, or failure-denominator violation; and
8. every assigned 908-row/root B3 cell and failure is sealed, all eight raw
   P1--P4 vectors and components are reported without inferential conversion,
   and the complete 7,264-row B3 surface fits the separately authorized
   128-H100-equivalent-hour/2-TB or exact provider-token/dollar cap.

A valid failure is `STOP_TEXT_CAUSAL_VALUE_NOT_ESTABLISHED`. DEV thresholds
are spending rules, not p-values or paper evidence.

## Stage-C status: `DEFERRED_NEW_PREREGISTRATION`

This protocol has no Stage-C execution, fixed confirmation roster, population
test, power claim, resource cap, or C1--C4 scientific-claim gate. B3 is the
scientific endpoint and remains DEV/falsification/descriptive even if every
directional sign is favorable. Its independent review must verify that exact
label and return `DESCRIPTIVE_COMPLETE`, `NULL`, `NOT_RUN`, or `REJECT`; review
never grants claim or execution authority.

Only after B3 is sealed may a new proposal use its complete distributions and
costs for prospective planning. That new proposal must use untouched roots;
freeze a finite-sample-valid analysis or explicitly model-dependent
assumptions with a strict variance/assumption margin; size for end-to-end
gate-passage power; bind its complete roster, failures, and resource envelope;
receive fresh independent review; and obtain explicit human ratification
before dispatch. A failed premise or infeasible roster is
`STOP_CONFIRMATION_INFEASIBLE`, not a selective rerun or borrowed authority.

component control only inside a future separately ratified
`DEFERRED_ASSOCIATIVE_LORA_PREREGISTRATION` before a future LoRA claim; it is
not that successor's headline.
