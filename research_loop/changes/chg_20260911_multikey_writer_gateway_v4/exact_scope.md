onto controls. R5 amplified one supplied routine and proliferated actions.

## 3. Frozen geometry, identity, and randomness relations

One fail-if-exists development run has roots `R0` and `R1`. They are disjoint
in opaque identities, cases, source/report surfaces, and RNG streams while
sharing one frozen model, protocol, writer recipe, parser, reducer, and
threshold registry. They are engineered robustness roots, not independent
population samples. They are never pooled to rescue failure.

Each root predeclares 24 ASCII candidate tools: ordinals 0–11 in orientation
stratum A and 12–23 in stratum B. Each tool has visible ASCII modes `m0/m1`;
legal actions are opaque ASCII `a0/a1`. "Lowest" always means ascending
integer ordinal, independent of discovery order. Root registries are disjoint
by construction. The later tokenizer preflight must prove distinct identifier
token sequences and row-wise equal encoded target lengths for
`ACT: a0<EOS>` and `ACT: a1<EOS>`; otherwise stop before source generation.

Select four eligible tools per stratum. For selected tools:

- stratum A, `M+`: `m0→a0`, `m1→a1`;
- stratum B, `M+`: `m0→a1`, `m1→a0`;
- `M−` complements all sixteen assignments.

Each map therefore has sixteen tool×mode keys, eight targets per action, and
two eight-key orientation strata. Both strata must pass separately.

The later execution manifest must enumerate every root, world, tool, mode,
case, form, prompt, task, condition, replicate, request, adapter, and stage
identity and every derived seed. It must bind a domain-separated seed
derivation and prove these relations before source:

- every `R0` RNG stream is disjoint from every `R1` stream;
- within a root, the matched `W+` and `W−` fits use the same initialization,
  dropout, item-order, and dataloader seeds while remaining separate fits;
- primary generation uses one seed per root/key/form/replicate shared across
  `OFF/W+/W−`;
- spill generation uses one seed per root/family/prompt/replicate shared
  across `OFF/W+/W−`;
- a replay uses the identical request bytes and identical seed; and
- no seed value, RNG state, or output can be selected from a prior result.

Changing any condition-common spill seed for only one condition is a geometry
failure before execution. Concrete identity bytes, seed integers, tokenizer
receipts, and request bytes remain later-manifest material; their equality and
disjointness relations are fixed here.

Before the first source request, the `sealed_evaluation_materializer` renders
and hashes the entire candidate-tool evaluation bank while source selection is
unknown. The bank is the finite union of every ordinary-held and explicit-map
oracle prompt row that any one of the 24 candidate tools per root can induce,
including both modes, every bound form/map/family/task slot, every condition
and replicate schedule entry, and every root-fixed control entry. Evaluation
prompts are candidate-local: their bytes may depend on the indexed candidate
tool, mode, map, form, family or task slot, root-fixed controls, and frozen
manifest data, but never on which other tools will be admitted or on an
admission result. The later manifest binds the exact complete index, entry
count, entry order, prompt bytes, condition assignments, condition-common
seeds, per-entry hashes, and one bank-root hash. No renderer may run after the
first source request.

The materializer has no model, trainer, adapter, source-result, admission, or
evaluation-result capability. Its sealed bank and index are inaccessible to
every source, fitting, and evaluation execution principal. They can be opened
only by the post-admission `trusted_evaluation_selector` under the exact
four-commit rule in section 8. A missing entry, extra entry, collision, hash
mismatch, wrong seed relation, or pre-source renderer/registry/tokenizer/
workload fault is `NOT_RUN` with stop reason `PREFLIGHT_FAILED` and null root
labels, `scientific_pair`, and `run_pass`; it is never `SOURCE_INVALID`.

## 4. Lived source

Before model execution, each candidate tool×mode key has eight ordered,
provenance-only case IDs in each mirror world. All candidate source
trajectories for both roots are acquired under a frozen schedule before either
root's eligibility result can affect fitting. A source trajectory is exactly
two assistant emissions in one continuing conversation:

1. the child sees tool, mode, and an order-bound but semantically unordered
   legal-action vocabulary and emits one strict initial ACT;
2. the trusted outcome harness alone reads the hidden mapping and inserts one
   public binary success/failure observation; and
3. the same child session emits one strict final ACT for the next occurrence.

Both emissions have maximum input length 512 and maximum 16 generated tokens.
There is no semantic retry, answer repair, or within-case replacement. A
missing, invalid, empty, multi-ACT, authoritative-DONE-containing, truncated,
or model/transport-error emission is preserved and makes the case ineligible.
An infrastructure retry may replay only identical request bytes and seed, is
recorded, and may not change the model-visible conversation; the later
execution manifest must set its maximum.

The child/model never sees the sealed mapping, correctness, admission, case
ID, report material, parent advice, a worked action, or a historical LLVM
routine. The outcome harness may read the map only to emit the public bit. The
eligibility reducer may read parsed final actions and the map only after every
candidate source trajectory in that root finishes. Neither privileged object
may enter child-visible logs, compiler input, or training rows.

A case is pair-eligible for one key only when the child's final ACT is correct
in both mirror worlds. Retain the lowest two pair-eligible case ordinals per
key. A tool is eligible only when both modes have two such cases. Select the
lowest four eligible tools in each preassigned stratum. Fewer than four is
`SOURCE_INVALID`: no top-up, redraw, stratum switch, repair, or changed dose.
Publish all attempts, failures, and eligibility bits before fitting.

Each world then has exactly 32 endpoints: 16 keys × 2 cases, balanced 16/16
between actions.

## 5. Fixed DREAM derivative and write

The lived initial action and outcome remain immutable provenance but are not
model-visible training context, removing the two-action repeat/flip shortcut.
The fixed derivative is:

`visible tool + visible mode + neutral endpoint frame -> exact child-authored successful ACT`.

Each endpoint receives four predeclared native-dialect renderings. Across two
endpoints, each key has eight distinct visible surfaces. The child-authored
final action is copied byte-exactly exactly once as assistant target
`ACT: <action>` followed by EOS; it is never normalized, repaired, or replaced
by an evaluator. Mapping, correctness, outcome, admission, case ID, and report
content are absent from training bytes and loss metadata.

Each adapter has `16 × 2 × 4 = 128` items. Within root, `W+` and `W−` have a
fixed row bijection: contexts, render indices, item order, supervised-position
vectors, EOS counts, encoded target-length vectors, optimizer steps,
initialization/dropout seed, and node match row-wise, while targets are exact
map complements. Target token multisets are equal. Any mismatch is
`SOURCE_INVALID`.

Four adapters (`R0/W+`, `R0/W−`, `R1/W+`, `R1/W−`) start separately from the
same locally cached frozen Qwen2.5-7B-Instruct revision. The frozen recipe is
unpacked, chat-templated, target-masked, all-projection LoRA rank 8, alpha 16,
dropout 0.05, AdamW `3e-5`, two epochs, batch size 1, maximum length 2048, EOS
on, no packing, and no SVD initialization. Each encoded item is at most 256
tokens. Four-fit maximum is 262,144 training token-passes.

## 6. Surface registries and total raw-byte parser

Source, training, primary, teacher-forced, explicit-map, spill, and interface
templates occupy separate registries. Registry IDs are globally unique. Every
registry rendering is ASCII. For registry collision checks only, canonicalize
bytes by replacing each maximal nonempty run from
`{HT=0x09, LF=0x0a, VT=0x0b, FF=0x0c, CR=0x0d, SP=0x20}` with one `SP=0x20`,
then remove leading and trailing SP. Canonical bytes must not collide across
families. A held rendering has neither a reused template ID nor canonical
rendered bytes; it does not claim semantic independence. A near-neighbour
tool differs from its trained tool by exactly one ASCII byte and must have a
different tokenizer sequence; concrete bytes are later-manifest material.

The parser consumes an arbitrary byte string plus exactly one transport state
from `OK`, `TRUNCATED`, or `ERROR`. It splits only at byte `LF=0x0a` and removes
that separator. It performs no CRLF, Unicode, whitespace, case, or code-fence
normalization; a CR remains part of its line. In line order:

- `ACT: a0` and `ACT: a1` are authoritative ACT lines only when the entire
  line is those exact ASCII bytes;
- `DONE` is authoritative only when the entire line is those exact ASCII
  bytes;
- a line beginning with exact bytes `ACT:` but not equal to either valid ACT
  line is a malformed-ACT event;
- a line beginning with exact bytes `DONE` but not equal to `DONE` is a
  malformed-DONE event; and
- every other line is non-authoritative prose, including lines surrounding an
  exact marker in a code fence. An exact marker on its own fenced line remains
  authoritative.

This produces an ordered event list, ACT count, DONE count, malformed flags,
and transport state for every byte string. Non-ASCII or control bytes in a
marker-candidate line make it malformed because it cannot equal a valid line.
`ERROR` or `TRUNCATED` is always invalid; a complete ACT observed before
truncation does not rescue the trial.

Stage overlays are exact:

- Each source emission is valid only with transport `OK`, no malformed event,
  exactly one ACT, and zero DONE events. Any other result makes its case
  ineligible.
- Each primary or explicit-map-oracle emission is strictly valid only with
  transport `OK`, no malformed event, exactly one ACT, and no DONE before that
  ACT. Invalid emissions remain denominator zeros. For fitted-adapter primary
  emissions only, more than one ACT also triggers the structural flood gate;
  OFF and oracle emissions are diagnostic and cannot trigger it.
- Each spill emission is parsed by the same raw parser. Its legal-ACT-presence
  indicator is one exactly when at least one authoritative `a0` or `a1` ACT
  occurs, including in a multi-ACT or otherwise invalid emission; it is zero
  for missing/error/truncated emissions with no such ACT. Spill invalidity and
  multi-ACT rates are reported, but do not enter the structural interface gate
  and do not remove the emission from the 32-trial family denominator.
- An interface task has an ordered sequence of at most four emissions. A task
  is structurally valid when every transport state is `OK`, there is no
  malformed event, each turn has at most one ACT, the whole task has one to
  four ACTs, the first authoritative event is not DONE, there is at most one
  DONE, no ACT occurs after DONE in the same or a later turn, and the
  controller emits no later turn after DONE. ACT followed by DONE in the same
  emission is valid. Reaching four turns without DONE is valid if the other
  rules pass.

Only the sixteen fitted interface tasks per root—eight under `W+` and eight
under `W−`—must be structurally valid. The same eight tasks under OFF are
parsed and reported but action presence, DONE order, and task validity under
OFF cannot veto an adapter pass. There is no best-of-action or
best-of-trajectory scoring or repair at any stage.

## 7. Exact binary64 score and receipt conventions

For teacher-forced reads, `L_z(h,a)` is the sum of token log probabilities of
the exact assistant continuation `ACT: <a><EOS>` under condition `z`; there is
no length normalization. Each runtime-provided token log probability is
converted once to IEEE-754 binary64, then accumulated with `fsum` in tokenizer
position order. Any missing, NaN, or infinite token or aggregate makes the
required likelihood missing/non-finite. The later tokenizer check makes both
targets equal length.

All reducer inputs and intermediates are binary64. Every finite sum or mean
uses `fsum` over the explicitly stated canonical order followed by one
binary64 division. For two finite likelihoods `x0,x1`, normalization uses
`m=max(x0,x1)` and
`lse=m+log(fsum([exp(x0-m),exp(x1-m)]))`; probabilities are
`exp(xi-lse)`. The later execution manifest hash-binds the reducer language,
version, build, binary64 behavior, `fsum`, `exp`, and `log` runtime. Reducers
never round before comparisons.

Authoritative floating receipts use lowercase hexadecimal binary64 notation
equivalent to `float.hex()`. Negative zero is canonicalized to
`0x0.0p+0`; NaN and infinity are forbidden. Decimal displays are
non-authoritative. Thresholds are the following exact binary64 values:

| decimal name | authoritative hexadecimal |
|---:|---|
| 0.05 | `0x1.999999999999ap-5` |
| 0.20 | `0x1.999999999999ap-3` |
| 0.25 | `0x1.0000000000000p-2` |
| 0.50 | `0x1.0000000000000p-1` |
| 0.75 | `0x1.8000000000000p-1` |
| 0.80 | `0x1.999999999999ap-1` |
| 0.875 | `0x1.c000000000000p-1` |
| 0.90 | `0x1.ccccccccccccdp-1` |
| 0.95 | `0x1.e666666666666p-1` |
| 1.00 | `0x1.0000000000000p+0` |

For key `k`, let `a+(k)` be its `M+` action, `a−(k)` its complement, and let
`h(k,j)` for `j=0,1,2,3` be the four canonical teacher-forced forms:

`q_z(k) = fsum_j[L_z(h(k,j),a+(k)) - L_z(h(k,j),a−(k))] / 4`

where each bracketed subtraction is first rounded to binary64 in ascending
`j` order, and

`I_k = q_W+(k) - q_W−(k)`.

For fitted adapter `s` in `{+,-}`, its own target is `a_s(k)`. The paired
form-level held-target NLL gain over OFF is

`D_s(k,j) = L_Ws(h(k,j),a_s(k)) - L_OFF(h(k,j),a_s(k))`.

Sort the four finite `D_s(k,j)` values ascending by numeric value, breaking
ties by ascending `j`. The exact midpoint even median is

`d_s(k) = fsum([D_s(k,(2)), D_s(k,(3))]) / 2`,

where `(2)` and `(3)` are one-based sorted positions. The adapter mean key
gain is

`mu_s = fsum_k[d_s(k)] / 16`

in ascending stratum then tool ordinal then mode order. Optimization is
inconclusive if any `d_s(k) < 0.50` for either adapter or if
`abs(mu_+ - mu_-) > 0.25`. Equality passes. This is a median of paired gains,
not a difference of medians; `mu_s` weights the sixteen key medians equally,
not the 64 forms directly.

For each spill family `f`, its sixteen prompt ordinals are `p=0..15`. For
adapter `s`, calculate prompt-level adapter-versus-OFF TV:

`TV_s(f,p) = 0.5 * fsum_a[abs(P_Ws(a|f,p) - P_OFF(a|f,p))]`

over actions in order `a0,a1`, then

`TV_s(f) = fsum_p[TV_s(f,p)] / 16`

in ascending prompt ordinal. It is the equal-prompt mean of TVs, not TV after
pooling prompt distributions. A family fails TV only if `TV_s(f) > 0.05`.

For generated spill, let `E_z(f,p,r)` be the legal-ACT-presence indicator from
section 6 for replicate `r=0,1`. Define

`rate_z(f) = fsum_{p=0..15,r=0..1}[E_z(f,p,r)] / 32`

in prompt-major then replicate order, and

`delta_s(f) = rate_Ws(f) - rate_OFF(f)`.

It is a signed increase; a decrease is not adverse and equality at 0.05
passes. All 32 trials remain in each condition/family denominator.

For generated primary accuracy, a correctness indicator is one only for a
strictly valid emission whose sole ACT equals the scored map action; every
other observation is zero. For any condition/map panel, compute
`recall_a0` and `recall_a1` as the `fsum` of their correctness indicators in
ascending stratum, tool, mode, form, and replicate order divided once by the
fixed number of observations whose scored-map target is that action. The
authoritative balanced accuracy is exactly

`BA = fsum([recall_a0, recall_a1]) / 2`

in action order `a0,a1`. Strict validity uses all 128 own-map trials per fitted
adapter and 64 per stratum. Its numerator is `fsum` of binary64 zero/one
strict-validity indicators in the same canonical order, divided once by 128
or 64. Per-stratum generated accuracy uses its 64 correctness indicators in
canonical order divided once by 64. OFF and cross-map scores are reported but
do not relax fitted own-map validity.

The authoritative full-panel binding mean is

`mean_I = fsum_k[I_k] / 16`

in ascending stratum, selected-tool ordinal, then mode order `m0,m1`. Define
the four mirrored binary64 component differences, each rounded once by its
binary64 subtraction before outer aggregation:

`tau_plus  = BA_W+^M+  - BA_W−^M+`

`tau_minus = BA_W−^M−  - BA_W+^M−`

`g_plus    = BA_W+^M+  - BA_OFF^M+`

`g_minus   = BA_W−^M−  - BA_OFF^M−`.

Then the authoritative mirrored statistics are the ordered outer sums

`tau = fsum([tau_plus, tau_minus]) / 2`

`g   = fsum([g_plus, g_minus]) / 2`.

No algebraically rearranged expression, unordered sum, or fused computation
is authoritative for BA, `mean_I`, `tau`, or `g`.

The fixed-panel stability statistic for mean `I_k` uses exhaustive stratified
tool-cluster resampling. Index selected tools `0..3` by ascending ordinal
within each stratum. Enumerate all concatenated tuples
`(A0,A1,A2,A3,B0,B1,B2,B3)` in lexicographic order, each coordinate in
`0..3`, for exactly `4^8 = 65,536` ordered resamples. Carry both modes and all
within-tool form observations with every sampled tool occurrence. For each
tuple, compute the equal-weight mean of its sixteen carried `I_k` values by
`fsum` in tuple-coordinate order and within-tool mode order `m0,m1`, divided
by 16. Sort the 65,536 finite means ascending by numeric value, breaking ties
by original lexicographic resample index. The fixed-panel 5th-percentile
stability statistic is the 3,277th sorted value, one-based (index 3,276), even
when all values are identical. It is a preregistered fixed-panel stability
gate, not a confidence interval or population inference.

## 8. Split visibility principals, sealed evaluation bank, and frozen reads

All surfaces, reducers, object schemas, and access tables are hash-bound
before source. The following objects are distinct and may not alias:

- `sealed_source_map`: the exact `M+/M−` map object;
- `source_admission`: case eligibility and selected ordinals;
- `public_lived_trajectory`: model-visible source turns and public outcome;
- `compiled_training_row`: visible state, exact child target, mask, and
  nonprivileged geometry only;
- `sealed_evaluation_bank`: the complete pre-source immutable bank, exact
  index, per-entry hashes, and bank-root hash;
- `ordinary_held_prompt`: a selected immutable primary, teacher-forced, spill,
  or interface byte entry with no explicit map, admission, lived history, or
  training rendering;
- `oracle_rendered_map_prompt`: a selected immutable explicit-map oracle byte
  entry rendered before source and exposed only after the four-commit barrier;
- `selected_evaluation_subset`: immutable selected prompt entries and their
  already-bound index, count, order, condition, replicate, seed, and hashes;
  and
- `generated_or_scored_result`: immutable raw outputs or likelihoods supplied
  one-way to scoring.

Access is principal-specific:

- `source_child` reads only the public source request and its continuing public
  conversation.
- `outcome_harness` reads the sealed map and parsed initial ACT only to append
  the public bit; it cannot read admission or held/oracle objects.
- `eligibility_reducer` reads the sealed map, parsed final ACTs, and case
  ordinals only after source closure and writes `source_admission`.
- `trusted_compiler` has read-only access to `source_admission` solely to
  select the admitted verified trajectories. It also reads their public state,
  exact final child target, and provenance for verification; it cannot change
  admission. It writes only `compiled_training_row` and cannot serialize map,
  correctness, outcome, admission, case, initial action, or held/oracle
  content into model-visible bytes or loss metadata.
- `trainer` reads only committed compiled rows and the frozen recipe.
- `four_commit_barrier` reads only four adapter stage identities, states, and
  hashes. No held or oracle object can load unless all four equal `COMMITTED`.
- `sealed_evaluation_materializer` is the sole renderer and runs before the
  first source request as specified in section 3. After sealing, neither it nor
  any other principal may render or mutate evaluation bytes.
- `trusted_evaluation_selector` is the sole selector. Only after
  `source_admission` is final and all four adapter stages equal `COMMITTED`, it
  may read exactly the sealed bank index plus read-only `source_admission` and
  expose `selected_evaluation_subset`. It selects the exact indexed entries
  induced by the admitted lowest four tools per stratum and has no authority
  to render, normalize, repair, rewrite, append, delete, reorder, resample, or
  alter any prompt byte, hash, seed, count, order, map, form, family, task,
  condition, replicate, or condition-sharing relation. It cannot read source
  transcripts, model outputs, scores, or adapter contents. Its output is an
  immutable subset proof against the sealed bank root.
- `oracle_generator` reads only the prompt bytes of the selected
  `oracle_rendered_map_prompt` entry; the execution dispatcher mounts the
  already-bound frozen OFF condition separately. The generator receives no
  subset metadata besides prompt bytes. It cannot read the raw sealed map,
  bank/index, admission, ordinary held objects, compiled rows, or lived
  history.
- `ordinary_generator` reads only the prompt bytes of the selected
  `ordinary_held_prompt` entry; the execution dispatcher mounts the already-
  bound `OFF/W+/W−` condition separately. The generator receives no subset
  metadata besides prompt bytes. It cannot read either map object, bank/index,
  oracle prompt, admission, compiled rows, or lived history.
- `teacher_forced_reader` has the same selected ordinary-prompt and prompt-
  bytes-only restrictions and emits only candidate continuation likelihoods.
- `scorer_reducer` reads immutable results, the sealed map, condition IDs,
  canonical grouping ordinals from the selected subset, and thresholds only
  after generation. It cannot read the full bank/index. Its outputs cannot
  affect source, selection, compilation, fitting, retries, seeds, prompts, or
  model calls.

Tests must reject direct fields, aliases, serialized copies, logs, exceptions,
caches, filenames, hashes, counts, stage order, and feedback edges that evade
this split. They must also prove complete pre-source candidate-bank closure,
bank inaccessibility before selection, selection only after final admission and
four commits, exact subset membership and hash proofs, compiler admission
read-only behavior, generator prompt-bytes-only behavior, and that the selector
cannot alter bytes, seeds, counts, order, conditions, or sharing relations.
This is typed stage isolation for a small scout, not a process sandbox or C11
security claim.

Held and oracle bytes open only after all four adapter stages are committed:

- **Primary:** per root, 16 keys × 4 forms × 2 condition-common replicates × 3
  conditions (`OFF/W+/W−`) = 384 emissions, maximum 512 input and 16 output
  tokens. Score the sole ACT of a strictly valid trial against both maps.
- **Teacher-forced binding/NLL:** per root, 16 × 4 disjoint forms × 3
  conditions × 2 candidate continuations = 384 sequence scores, maximum 512
  tokens.
- **Explicit-map oracle:** per root, 16 × 4 forms × 2 maps = 128 frozen-base
  emissions, maximum 512 input and 16 output tokens. Require strict exact-
  action accuracy at least 0.90 separately by root, map, and stratum. Invalid
  outputs are denominator zeros.
- **Spill generation:** exactly 16 prompts in each of four families × 2
  condition-common replicates × 3 conditions = 384 emissions per root,
  maximum 512 input and 16 output tokens. Families are: unseen tool/known
  mode; tokenizer-verified near-neighbour unseen tool/known mode; trained tool
  and mode in an explicitly non-policy relation; trained tool with mode
  omitted.
- **Spill TV:** the same 64 family prompts × 3 conditions × 2 candidates = 384
  sequence scores per root, maximum 512 tokens.
- **Interface:** eight fixed four-tick tasks × 3 conditions = 24 tasks per
  root, at most four emissions per task, maximum 2,048 input and 128 output
  tokens per turn. Only the sixteen fitted condition-tasks are gating.

## 10. Exact per-root scientific reducer

A root scientific label is nullable until its required evidence exists.
Apply the following checks in order whenever their inputs are available:

1. `SOURCE_INVALID`: only after that root's first source request, a root-local
   source shortfall; source visibility, authorship, provenance, parsing, or
   immutable-attempt failure; admission count, balance, pairing, or canonical-
   selection failure; or post-source trusted-compilation target provenance,
   row-count, complement-bijection, mask, or matched-geometry failure. No
   failure discovered before the first source request can receive this label.
2. Likelihood integrity precheck: any required likelihood or numeric
   intermediate that is missing, NaN, or infinite yields `ASSAY_INVALID`
   without evaluating the optimization arithmetic.
3. `OPTIMIZATION_INCONCLUSIVE`: any `d_s(k) < 0.50`, or
   `abs(mu_+ - mu_-) > 0.25`.
4. `ASSAY_INVALID`: explicit-map strict accuracy below 0.90 in either map or
   stratum.
5. `INTERFACE_OR_FLOOD_INVALID`: either fitted adapter's own-map strict
   validity is below 0.95 overall or below 0.875 in either stratum; any fitted-
   adapter primary emission has multiple ACTs; or any of the sixteen fitted
   interface tasks violates section 6. OFF, oracle, and spill multi-ACT output
   cannot trigger this label.
6. `BINDING_WITH_SPILL`: all source, optimization, oracle, fitted interface,
   and non-spill binding gates pass, but at least one `delta_s(f) > 0.05` or
   `TV_s(f) > 0.05`.
7. `MULTIKEY_BINDING_PASS`: all preceding checks plus every spill and binding
   gate pass.
8. `GATEWAY_NEGATIVE`: every other valid completed result, including combined
   binding and spill failure.

The seven label values remain mutually exclusive; steps 2 and 4 share the one
`ASSAY_INVALID` value. Source-valid roots stopped before fit or evaluation do
not receive a fabricated later label.

Non-spill binding gates per root are:

- own-map generated balanced accuracy at least 0.80 for both adapters;
- own-map generated accuracy at least 0.75 in each stratum for both adapters;
- `q_W+(k) >= +0.50` and `q_W−(k) <= -0.50` on at least 12/16 keys, including
  at least 6/8 in each stratum;
- `mean_I >= 1.00` and the fixed-panel 5th-percentile stability statistic is
  strictly greater than zero;
- mirrored `tau >= 0.50` under the component-subtraction and ordered outer-
  `fsum` definition in section 7; and
- mirrored gain `g >= 0.20` under the component-subtraction and ordered outer-
  `fsum` definition in section 7.

All decimal comparisons above mean the exact hexadecimal thresholds in

## 11. Exhaustive lifecycle and nullable run reduction

The future development root is unique, atomically fail-if-exists, realpath-
resolved, symlink-refusing, no-overwrite, and disjoint from all child, parent,
CompilerGym, PCFL, and C11 roots. Individual stages transition only
`PLANNED→RUNNING→COMMITTED|FAILED`; all failures and rejected replays persist.
Only a later-manifest-declared narrow infrastructure failure may replay
identical bytes and seed with the prior attempt preserved. Hash mismatches,
semantic failures, undeclared errors, and exhausted retries never retry.

The run receipt has exactly one `run_status` from:

- `PLANNED`: no source, fit, or evaluation stage has begun and no preflight
  failure has terminalized the run; deterministic and tokenizer preflight may
  be not started, in progress, or successfully complete with preserved
  receipts;
- `RUNNING`: at least one source, fit, or evaluation stage is nonterminal;
- `NOT_RUN`: no source, fit, or evaluation stage began because authority,
  deterministic or tokenizer preflight, review, ratification, or pre-source
  resource projection was absent or failed. Deterministic materialization and
  an authorized tokenizer preflight may have run and produced preserved
  receipts without changing `NOT_RUN`;
- `STOPPED_UNLABELED`: at least one source, fit, or evaluation stage began but
  a fail-closed stop left at least one root without a scientific label; or
- `TERMINAL_LABELED`: both roots have scientific labels.

The first submitted source request is the sole boundary between preflight and
source-started semantics. Before that boundary both root statuses remain
`NOT_STARTED` and both scientific labels, `scientific_pair`, and `run_pass`
remain null. Every preflight failure, including candidate-bank, registry,
tokenizer, seed-relation, workload, path, or capability failure, produces
`run_status=NOT_RUN` and `stop_reason=PREFLIGHT_FAILED`. The same class of
root-local provenance, admission, or compiled-geometry fault discovered only
after the boundary follows section 10 and may produce `SOURCE_INVALID`; timing
is fixed by the stage receipt, not by when a report happens to be read.

Each root has exactly one `root_status` from `NOT_STARTED`, `SOURCE_RUNNING`,
`SOURCE_READY`, `SOURCE_INVALID`, `FIT_RUNNING`, `FIT_COMMITTED`, `FIT_FAILED`,
`EVAL_RUNNING`, `EVAL_FAILED`, or `LABELED`. Each adapter retains its own stage
state and hash. A root's `scientific_label` is nullable. `SOURCE_INVALID`
sets both root status and scientific label to that value. A completed reducer
sets root status `LABELED`. A source-ready root stopped because its mate is
invalid, or a root with fit/evaluation/infrastructure failure, has null label.

Every `NOT_RUN` receipt has exactly `stop_reason=PREFLIGHT_FAILED` and one
`preflight_failure_detail` from `AUTHORITY_MISSING`,
`DETERMINISTIC_MATERIALIZATION_FAILED`, `TOKENIZER_PREFLIGHT_FAILED`,
`CANDIDATE_BANK_FAILED`, `SEED_RELATION_FAILED`, `WORKLOAD_PREFLIGHT_FAILED`,
`PATH_PREFLIGHT_FAILED`, `CAPABILITY_PREFLIGHT_FAILED`, `REVIEW_FAILED`,
`RATIFICATION_MISSING`, or `PROJECTION_OVER_CAP`. Every
`STOPPED_UNLABELED` receipt has exactly one `stop_reason` from
`CAPABILITY_VIOLATION`, `PATH_OR_STAGE_VIOLATION`, `SOURCE_INVALID`,
`DECLARED_RETRY_EXHAUSTED`, `UNDECLARED_INFRASTRUCTURE_FAILURE`, `FIT_FAILURE`,
`HASH_OR_RECEIPT_FAILURE`, `EVALUATION_FAILURE`, or
`RESOURCE_LIMIT_EXCEEDED`, and its `preflight_failure_detail` is null.
`stop_reason` and `preflight_failure_detail` are both null for `PLANNED`,
`RUNNING`, and `TERMINAL_LABELED`. A model/transport error that the protocol
assigns to a fixed denominator is not an infrastructure stop merely because
its score is zero. `SOURCE_INVALID` is the run stop reason only when a source-
invalid root leaves `scientific_pair` null; when both roots have scientific
labels and the pair is non-null, their labels carry the scientific result and
both failure fields remain null.

`scientific_pair` is either JSON null or the ordered two-element JSON array
`[R0_scientific_label,R1_scientific_label]` and is non-null exactly when both
labels are non-null. `run_pass` is a nullable JSON boolean: it is null exactly when
`scientific_pair` is null, true only for
`(MULTIKEY_BINDING_PASS,MULTIKEY_BINDING_PASS)`, and false for every other
non-null pair. No partial label, lifecycle stop, pooled mean, best root, best
adapter, automatic dose/rank change, or replacement root can rescue a run or
be represented as completed scientific evidence.
