# PCFL core + clean-child boundary v1 — adjudication candidate

Date: 2026-09-10

Status: **proposal only; not ratified**. This file authorizes no
implementation, benchmark/data generation, model/provider call, training,
adapter/checkpoint work, parenting, evaluation, GPU use, claim, or release.

## Plain-language ruling

We must never parent an evaluated child.

There is one immutable clean developmental source. Parenting and classroom
work may advance only descendants whose complete inputs are verified as
target-blind for the eventual evaluation family. When we want to measure the
child, we copy a registered clean snapshot into a new evaluation root. That
copy may think, DREAM, SLEEP, learn, and receive a root-local teacher for the
duration of the registered evaluation. It is nevertheless terminal: nothing
it produces may alter the clean child or its parent.

```text
clean birth -> target-blind classroom -> immutable clean snapshot
                                             |
                                             +-> disposable evaluation life
                                                    |
                                                    X no edge back
```

The forbidden return edge includes adapters and weights, optimizer state,
training rows, episodic memory, context summaries, DREAM/SLEEP products,
parent notes, teacher playbooks, task outcomes, scores, rankings, schedules,
thresholds, hyperparameter choices, and favorable-child selection. A missing
or unverifiable ancestry record fails closed. Known CompilerGym-derived
`L_B`, `R_B`, `R2`, `R3`, `R4`, `RP`, `R2_B_seed3`, `bootstrap_v1`, and
`bootstrap_v2` artifacts remain development-only and cannot be ancestors or
selection evidence for a clean CompilerGym claim.

## What is simple and what is laboratory machinery

The cognitive architecture remains only:

- THINK: the continuous state-to-state stream of thoughts, plans, judgments,
  feelings, actions, and public outcomes.
- DREAM: context management for the finite active workspace.
- SLEEP: compile grounded experience, then write it into the personal LoRA.

The boundary below is experimental hygiene around that architecture. It is
not another cognitive organ.

## Adjudicated implementation staging

### Stage 0 — CPU semantics, explicitly no scientific child

First implement only a `DEV_NONCLAIM` PCFL semantic kernel and explicit-text
M reducer. It uses no model, no LoRA, no parenting, no clean child, and no GPU.
Its receipts are permanently ineligible as child state or scientific
evidence. Its purpose is to settle the world before building the laboratory:

- canonical public state, action, event, atom, link, goal, and transition-row
  objects;
- deterministic root/twin generation plus shortcut and identifiability
  certificates;
- a trusted environment/controller that alone sees the sealed root;
- an actor API that can receive only the finite public view;
- the exact M phase machine, including a defined two-probe join;
- explicit-text atoms/links/null/deranged carriers;
- bridge, twin/redirection, uncertainty sham, REACHOUT-off, and old/new cuts;
- one noncompensatory root-level M result vector; and
- exhaustive CPU tests for visibility, topology, lexical shortcuts,
  interventions, reset semantics, nesting, replay, and scoring.

This stage may prove only deterministic benchmark-software behavior. A later
text-model smoke test, if separately authorized, is engineering evidence only.

### Stage 1 — smallest claim-bearing ancestry guard

Before any E0, LoRA M, L, C, parenting, or claim-bearing model run, implement
the minimum guard actually needed by that run:

1. `CleanSourceReceipt`: an authenticated immutable birth record binding the
   exact child snapshot, base/model/tokenizer, bootstrap and committed corpus,
   writer/compiler, parent developmental state, prior ancestry, exposure
   tuples, and admission authority.
2. `ExperimentPlan`: exact purpose, split, source receipt, unit universe,
   phase/visibility rules, interventions or tapes/codecs, environment and code
   identities, randomness, budgets, failure/retry/stopping rules, reducers,
   and permitted output sink. Science-mode defaults are forbidden.
3. Role separation: a trusted controller sees private root/seed/intervention
   data; the actor sees only canonical `visible_view`; the compiler sees only
   admitted public evidence; the reducer sees only the complete registered
   terminal receipts.
4. OS enforcement: the source is mounted read-only, each experiment root/arm
   has an isolated writable store/process/session/cache/RNG namespace, and no
   worker possesses a promotion capability for the source.
5. Root-local transaction: accepted SLEEP state inside a disposable life
   atomically advances its adapter, corpus, compiler/writer receipt, memory,
   and root manifest together. Rejection advances none. There is no directory
   scan for “latest,” arbitrary lineage path, or `DONE`-file trust.
6. Tamper-evident receipts: exact source pre/post hashes, maximal readable
   inputs per role, commands/environment/randomness, outputs, failures, and
   terminal state are recorded. These receipts audit the enforced boundary;
   hashes alone do not prove target blindness or every human/remote-model
   causal input.

The guard authenticates bytes and capabilities, not metaphysics. It must say
when provider-side state, human memory, shared-resource timing, or another
side channel could not be excluded.

### Stage 2 — independent scientific packages

- E0 independently establishes that the frozen writer transports eligible
  native thought/action continuations into usable weights without interface
  damage.
- M tests connected experience, goal traversal, information-seeking
  expansion, grounded write, and delayed old-plus-new use. Explicit-text M
  must work before LoRA M can be interpreted.
- L compares independent paired lineages on a byte-identical exogenous
  experience stream: full learning versus one certified evolving
  `ACTIVE_TEXT_FIXED` baseline. Evaluation actions do not alter the later
  learning stream. Units are lineages, not checkpoints.
- C is a separate rate--distortion experiment over one canonical public
  semantic ledger. It reports semantic text compression unless the measured
  expanded ledger exceeds the full charged adapter/decoder byte crossover.
- Parenting and the final 2x2 remain a separate packet upstream of a
  `CleanSourceReceipt`; they do not become PCFL-kernel machinery.

M, L, and C do not pool units, errors, or claims.

## Exact contamination policy

### Clean developmental input

An input is eligible for a clean lineage only when an upstream authority can
verify its complete ancestry and its exposure set is allowed for that
lineage's declared future use. A filename, copied directory, hash without an
authority record, or successful parse is not ancestry.

The adaptive parent may improve through its own target-blind classroom
history, context, notes, tools, and files. It may not inspect evaluation
descendants or learn which advice improved a sealed deployment score. Parent
state is versioned and bound alongside the child state.

### Evaluation descendants

Each evaluation cell begins from a read-only clone of the same eligible clean
snapshot under a prebound plan. A continual-learning cell may keep its own
SLEEP updates across its registered lifetime. A parent-present cell may keep
root-local teacher context if the plan permits it. Those are experimental
treatments, not clean-lineage promotions. At terminal state the entire root is
sealed for reduction and then discarded or archived as contaminated-for-
upstream-use.

### Research feedback

DEV results can motivate a later plan only on a registered disjoint reserve
family. They cannot modify the already named clean child/parent or its
bootstrap, corpus, writer, teaching curriculum, thresholds, or learning
hyperparameters and then support a same-family clean claim. Confirmation unit
sets, order, exclusions, retry rules, stopping rules, reducers, and release
point are bound before the first result is visible. Strict human blinding is
claimed only if a separate administrative principal actually enforces it.

## Blocking semantic choices before Stage 0 implementation

The deliberation must bind, rather than allow code defaults for:

1. the finite relation algebra, link authorship, grounding, and path-validity
   rules;
2. the A/B goal-probe join and exactly what public information returns;
3. separate legal-path, terminal-answer, and shortcut/guess scores;
4. opaque symbol permutation and balanced presentation/action/answer laws;
5. the uncertainty object, candidate experiment set, costs, outcome alphabet,
   and information-gain score;
6. matched exposure units and nonsemantic padding rules;
7. exact state that survives each reset, fork, DREAM, SLEEP, and delayed cut;
8. timeout, invalid action, refusal, malformed output, writer rejection, and
   missing-artifact values; and
9. the root-level noncompensatory reducer and conditional stopping semantics.

## Required pre-science negatives

Before a claim-bearing run, CPU tests must demonstrate rejection of:

- forged, path-only, copied, aliased, or unknown source ancestry;
- any known quarantined CompilerGym ancestor for a clean CompilerGym use;
- sealed-root, seed, intervention, oracle, future-goal, or sibling leakage to
  the actor through inputs, argv/env, filenames, logs, errors, or caches;
- `TEST_ONLY` or failed-certificate laundering;
- root/branch/arm cross-talk and L opposite-arm feedback;
- rejected or partial state becoming the next SLEEP parent;
- concurrent, torn, or stale root-local promotion;
- source mutation before, during, or after a descendant life;
- evaluation results reaching the clean child or adaptive parent; and
- partial confirmation results changing later units or stopping.

## Claim order and stop rules

1. CPU semantic/certificate gates.
2. Explicit-text M engineering ceiling.
3. E0 native writer transport and safety.
4. LoRA M with registered controls.
5. Certified `ACTIVE_TEXT_FIXED`, then L lifetime curves.
6. Separate C rate--distortion.
7. Parenting/final 2x2 only under its own clean packet.

Failure at an upstream gate stops its dependent claim. A downstream metric
cannot rescue a failed source, visibility, writer, or explicit-text gate.

## Remaining human decisions after formal deliberation

Formal consensus must present exact bytes for:

- the Stage-0 PCFL semantics and reducer;
- the `CleanSourceReceipt` and `ExperimentPlan` schemas;
- the authority/process/isolation boundary for the first claim-bearing run;
- the exact accepted clean source and quarantine denials;
- whether confirmation is preregistered only or independently human-blinded;
  and
- the requested implementation/test scope, with model/GPU/science authority
  remaining separately gated.

Until those bytes are ratified, both Stage 0 and the lineage guard remain
unimplemented proposals.
