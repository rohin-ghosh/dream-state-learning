# RML G1/G2 interpretation B: faithful model-facing factorial after D0

**Status:** independent science-design input only. This document authorizes no
implementation, model call, GPU work, benchmark promotion, or scientific
claim. Material adoption requires the repository deliberation, ratification,
implementation-review, and pre-GPU gates.

## 1. Design objective

The first model-facing work after a valid D0 should preserve the project’s
causal object rather than turn RML into a graph-query benchmark:

```text
ordinary wake goal and public state
-> model chooses local reads, hypotheses, and actions
-> executed actions produce connected public experience traces
-> target-blind offline replay and cross-episode proposal
-> deterministic evidence admission and text compilation
-> fresh model reconstructs a small cited path
-> later executed action
```

G1 asks whether a frozen model can constructively use sufficient local memory
without receiving a stored solution. G2 asks whether authentic wake traversal
and offline cross-episode reorganization add useful supported text memory over
direct compilation, replay, and strong external-memory baselines. Neither
stage tests LoRA transport, lifetime scaling, a learned resolver, or the
on-policy flywheel.

D0 remains an instrument gate. Its exact world, legal-history ceiling, Bayes
controller, target certificates, and hidden program may create and audit
model-facing fixtures offline. They are not cognition and are never exposed as
a graph, program, proof, query sequence, candidate list, or verifier response.

## 2. Non-negotiable construct boundary

The model-facing organism is one frozen resolver used in two modes:

```text
THINK: goal/state -> QUERY_LOCAL -> UPDATE/BACKTRACK -> ACTION/DEFER
DREAM: bounded replay -> compare/re-derive -> PROPOSE/PREDICT/DEFER
```

The operations and schemas are shared. Mode, trigger, objective, grounding,
and output permissions differ. Shared weights are a controlled condition, not
a presumed scientific advantage.

The following are prohibited in every headline model input:

- hidden world programs, proof paths, shortest paths, target manifests, twin
  identity, Bayes state, scorer outputs, acceptance receipts, or evaluator
  outcomes;
- a global semantic graph, incident-neighbor list, visited set, frontier,
  program interpreter, or target-conditioned candidate catalog;
- a query containing a desired answer, hidden relation, target-specific
  direction, complete plan, or anchor not copied from a visible public field,
  prior local read, or public outcome;
- support labels, root counts, confidence derived from hidden truth, reader
  ranks/scores, alternate candidates, backend identity, or timing;
- a deterministic correction, repair, suggested next query, or action from a
  checker after the model commits an operation.

The common reader returns exactly one local atom or `NOT_FOUND`. It does not
return a chain. The model must place returned atoms into bounded working slots,
choose the next visible anchor, backtrack on a miss or conflict, and release
one environment action at a time. The explicit provenance graph is an audit
shadow only.

## 3. Model operations versus deterministic evidence admission

| Function | Model operation | Deterministic process | Scientific restriction |
|---|---|---|---|
| Wake cognition | choose a generic local anchor; update or backtrack; execute, defer, or stop | validate one-operation syntax and execute the chosen legal action | the harness cannot redirect an operation or fill a missing argument |
| Wake trace | emit cited read/workspace slots and unresolved dependency type | seal invocation, operation, public outcome, and next-state hashes | co-retrieval and traversal frequency are selection signals, never evidence |
| DREAM | select from a bounded target-blind replay bundle; propose one scoped atom and future prediction | enforce schema, source-time ordering, and proposal budget | DREAM cannot declare its claim supported or inspect later confirmation |
| Model CHECK | predict a consequence, seek a counterexample, revise, or defer | record `CRITIC_APPROVED`, `CONTRADICTED`, or `UNRESOLVED` as a model judgment | critic approval alone never admits factual training data |
| Evidence admission | none | after commitment, attach an ordinary later public outcome; check chronology, roots, taint, scope, and exact comparator result | admission cannot generate, repair, rank, broaden, or normalize a semantic claim |
| SLEEP compilation | none in the primary G2 compiler | deduplicate eligible atoms, preserve status/provenance, and emit fixed one-atom views | the compiler cannot infer a missing edge or execute a hidden program |
| Memory read | choose an anchor and consume one returned atom | enforce frozen snapshot, budget, and backend channel | no graph neighborhood, candidate list, or answer-conditioned retrieval |
| Evaluation | choose reads and actions under the frozen resolver | score sealed public behavior and recompute causal cuts after completion | scorer information never returns to life, memory, DREAM, or later evaluation |

Deterministic admission establishes only that a committed, scoped candidate has
the declared public support under frozen rules. It is not a verifier of the
model’s reasoning and does not make a model-created rule universally true.
Unsupported, critic-approved-only, malformed, future-dependent, or tainted
claims remain provisional or rejected.

## 4. Shared artifacts and chronology

Every G1/G2 world-life has an append-only public event stream, immutable
semantic/status log, bounded branch workspaces, typed wake traces, typed replay
bundles, and sealed memory snapshots. The required chronology is:

1. seal evaluation targets and counterfactual twins outside cognition;
2. execute an ordinary wake collection block and seal its public outcomes and
   traversal records;
3. form target-blind replay bundles from eligible past handles;
4. have wake or DREAM commit local candidates and executable predictions;
5. execute a predeclared ordinary confirmation block whose actions do not
   depend on candidate content;
6. mechanically attach matches or contradictions from distinct later public
   roots;
7. compile only eligible supported content into a frozen text snapshot;
8. clear model context, cache, workspace, and process state;
9. evaluate fresh held-out J/P/X tasks read-only; discard all evaluation
   outcomes and require identical pre/post source-life hashes.

Repeated wording, compiler views, replay frequency, wake-path frequency, and
multiple DREAM samples inherit the same root set and add no support. A trace
can select what to revisit but cannot support its own semantic proposal.

## 5. G1 — model-usable gold reconstruction

### 5.1 Purpose

G1 is a construct-validity gate for the model controller and reader. It must
show that a frozen recurrent model can retrieve local sufficient semantics,
build a cited working path, revise or defer, and execute the correct later
action without a stored solution.

Use one fluid/thermal development pack and at most four predeclared D0-valid
counterfactual world-life pairs. Before model calls, add CPU-certified
model-facing J, P, and X decks:

- `J`: one connected old-to-new plan of six to twelve actions; removing the
  early bridge makes every legal recent-only plan fail;
- `P`: one local edge is unwitnessed, but a prospectively committed and later
  supported schema predicts it; witnessed atoms alone remain below ceiling;
- `X`: a normal rule is contradicted by an ordinary outcome; success requires
  information gathering, backtracking, and use of a supported scoped
  exception on a separately sealed analogous target.

No individual memory record may contain more than one local relation or a
two-action bounded shortcut. No record may encode the target, complete parent
set, decisive terminal action, or full plan. Legitimate direct-record closure
must be exactly zero.

### 5.2 Core 2 x 2 factorial

Cross memory content with controller use:

| Cell | Memory content | Read policy |
|---|---|---|
| `G1_A_OPEN` | gold supported witnessed one-edge atoms only | all generic anchor queries committed before any return |
| `G1_A_REC` | identical witnessed atoms | recurrent generic anchor-only reads; later queries may use earlier returned values |
| `G1_C_OPEN` | atoms plus gold chronologically supported local shortcuts, prospective schema, and scoped exception | all queries committed before any return |
| `G1_C_REC` | identical connected gold content | recurrent generic anchor-only reads with update/backtrack |

Required controls are `G1_NONE_REC` (no lifetime memory), `G1_C_TWIN_REC`
(type-matched counterfactual-twin content), and a hidden legal-history ceiling.
The ceiling and exact graph/program controllers are offline diagnostics and
competitors only. Their operations are never converted into model queries,
workspace entries, demonstrations, or credit for `G1_C_REC`.

The content factor identifies whether local connected/schema/exception memory
adds information beyond witnessed atoms. The controller factor identifies
whether later reads actually depend on earlier local returns. The twin control
tests authentic life binding.

### 5.3 G1 budgets

Freeze the exact model revision, tokenizer, chat template, serialization,
generation configuration, attention mask, and native-context projection before
dispatch. Use one fixed resolver across cells.

- maximum 12 resolver operations and six memory queries per evaluation item;
- one local atom per read, maximum 256 model-visible tokens per read and 1,536
  memory tokens total;
- maximum eight one-edge path slots, eight public-outcome slots, and sixteen
  typed workspace nodes; no free-form persistent notes;
- maximum 256 new tokens per resolver operation; deterministic decoding;
- exactly one environment action per released branch and the registered
  J/P/X action cap; malformed, illegal, multi-operation, or truncated output
  consumes the operation and releases no action;
- no retry, repair, fallback model, or extra query after budget exhaustion.

All cells receive identical goal/state bytes and applicable reader schema.
Actual calls, tokens, reads, latency, failures, and action costs are reported;
unused budget is not silently converted into reflection.

### 5.4 G1 gate

G1 passes only if all are true on the predeclared development deck:

1. direct-record closure is exactly zero;
2. `G1_C_REC` action value is at least `.85` separately on J, P, and X;
3. its constructive cited-path rate is at least `.80` under offline mechanical
   path checking performed only after the item is sealed;
4. `G1_C_OPEN` mean action value is at most `.35`;
5. `G1_A_REC` remains at most `.35` on P, proving that witnessed atoms do not
   already determine the prospective edge;
6. masking the complete cited memory cut changes the decisive model operation,
   and matched twin substitution yields the twin-valid operation, on at least
   `.80` of credited `G1_C_REC` successes;
7. missing-edge and conflict fixtures cause a query, backtrack, or defer rather
   than an unsupported decisive action;
8. the legal-history ceiling is at least `.85`, no-memory and registered
   leakage predictors remain within their D0 bounds, and evaluation does not
   mutate source life.

If the recurrent gold arm fails, the model-facing construct is invalid and G2
does not start. If the open arm exceeds `.35`, the task is solvable by static
lookup/precommitted fan-out and must be redesigned. A correct action without a
valid cut remains a behavioral success but receives no constructive-memory
credit.

The strongest positive G1 statement is:

> A frozen recurrent model used bounded local gold memories to reconstruct
> cited working paths and execute J/P/X actions that a precommitted-read
> controller could not execute under the same interface.

It says nothing about learned memory, dreaming, compilation, LoRA, development,
or the flywheel.

## 6. G2 — wake traces, DREAM, and evidence-bound text compilation

### 6.1 Purpose and common experience

G2 tests learned content formation in text before weights are involved. For
each world, one frozen wake collector receives ordinary, target-blind source
missions. It chooses bounded reads and one action at a time; its released
actions are executed, and public outcomes become the life. The resulting
experience deck and authentic wake trace are then frozen and replayed
byte-identically to every G2 arm.

This preserves `wake thinking -> executed action/outcome -> connected trace`
while holding experience constant for attribution. It does not test whether a
memory intervention improves future evidence collection; that remains G5.
Collector failure or weak evidence is retained for that world and cannot be
replaced using downstream performance.

### 6.2 Primary 2 x 2 content factorial

Cross wake-trace binding with offline candidate source:

| Cell | Wake trace | Offline content formation |
|---|---|---|
| `G2_WAKE_AUTH` | authentic invocation-bound trace | compile eligible wake-local candidates; no DREAM |
| `G2_WAKE_SHUF` | type/count/frequency/length-matched binding-shuffled trace | same wake-only path |
| `G2_CROSS_AUTH` | authentic trace and replay grouping | shared resolver performs bounded cross-episode DREAM re-derivation |
| `G2_CROSS_SHUF` | matched shuffled trace/group binding | same shared DREAM budgets and seeds |

Every candidate remains non-evidentiary until a distinct later public outcome
supports it. Shuffling preserves public event bytes, trace operation counts,
status/type bins, token lengths, replay-bundle sizes, proposal slots, model
budgets, and compiler rules while breaking the authentic binding between a
traversal and its lived referents.

### 6.3 Identification anchors

Add only the anchors needed to dispose of alternative explanations:

- `G2_COMPILER_ONLY`: eligible witnessed/supported atoms receive deterministic
  deduplication and fixed views; no resolver-created semantic candidate;
- `G2_REPLAY_ONLY`: authentic traces select/replay episodes, but the model may
  emit traversal statistics and retrieval shortcuts only, not a new
  cross-episode semantic relation;
- `G2_CROSS_NO_WRITE`: identical authentic shared DREAM calls and scratch
  candidates as `G2_CROSS_AUTH`, but no candidate becomes durable semantic
  content;
- `G2_CROSS_SPECIALIZED`: a separately prompted DREAM resolver receives the
  same bundles, calls, samples, tokens, seeds, and output schema as the shared
  resolver;
- `G2_FORGED_STATS`: an attack replacing traversal statistics with
  frequency/type-matched forged values while preserving cited public roots;
- `G2_SHUFFLED_GROUPING`: an attack shuffling episode grouping while preserving
  episodes and bundle sizes.

The four primary cells plus compiler/replay/no-write/specialized anchors form
the inferential matrix. Forged statistics and shuffled grouping are mechanism
attacks, not extra opportunities to select a winning condition.

Mandatory external competitors on the identical fixed deck are honest native
context, raw episodic RAG, hierarchical reflection, native A-MEM, exact
witnessed graph, explicit generator-aware program induction, and procedural
skill memory. Their native interfaces and complete resources are reported.
They are competitors, not teachers: no returned graph/program path enters a
headline model prompt or compiler corpus. If they win, the scientific result
favors explicit structured memory.

### 6.4 DREAM and compilation budgets

Use the same frozen resolver as G1 for the shared condition. Before any later
confirmation outcome, freeze bundle IDs, sample counts, seeds, and proposal
slots.

- at most eight replay bundles per life/checkpoint, target-blind and selected
  from new events, old events, anomalies, contradictions, and bounded wake
  traces by a frozen schedule;
- exactly four DREAM samples per bundle, maximum 384 new tokens per sample,
  temperature `.7`, top-p `.9`, with independently derived frozen seeds;
- one proposed local atom and one executable prediction per valid sample; at
  most four public roots and two earlier supported parent atoms;
- malformed output consumes its preallocated sample and is never replaced;
- shared/authentic, shared/shuffled, no-write, and specialized comparisons
  match calls, samples, input/output token caps, bundle counts, and seeds;
- the compiler retains at most 256 supported canonical atoms by a frozen
  chronological/type-round-robin rule and emits the same fixed one-atom views
  per retained atom; truncation is target-blind and outcome-independent;
- G2 evaluation uses exactly the G1 recurrent thinker, reader, workspace,
  operation, query, and action budgets.

Compiler-only necessarily uses less model compute. Its unspent calls are not
converted into cognitive output; resources are reported rather than falsely
declared equal. Causal call matching is exact for authentic/shuffled,
durable/no-write, and shared/specialized contrasts.

### 6.5 G2 execution scale and gate

Run text-only DEV first on the same maximum four fluid/thermal world-life pairs
at one mechanically recertified post-working-window cut. This is an engineering
and information-value gate, not confirmation. Only after a new exact approval
may the frozen matrix run on six predeclared descriptive calibration pairs.
Neither sample supports a paper-level population claim.

G2 passes for later same-corpus transport work only if:

1. zero admitted positive claim depends on an evaluation target, agenda answer,
   unsupported workspace, forged statistic, critic approval alone, future
   evidence, scorer, hidden truth, or compiler-generated semantic edge;
2. every derived positive claim was committed before its distinct confirming
   public outcome and has mechanically valid root provenance;
3. `G2_CROSS_AUTH` recovers at least `70%` of `G1_C_REC` gold-memory gain over
   no memory and is no more than `.10` below the strongest native external
   baseline on each critical DEV stratum;
4. authentic trace versus matched shuffled trace loses at least
   `max(.15, .5 * G_trace)`, where `G_trace` is the positive authentic-trace
   gain over the appropriate no-trace/compiler anchor;
5. `G2_CROSS_AUTH - G2_CROSS_NO_WRITE >= .10` in mean action value;
6. residual DREAM credit requires `G2_CROSS_AUTH` to exceed both
   `G2_COMPILER_ONLY` and `G2_REPLAY_ONLY` by at least `.10` in mean action
   value; a later confirmation must place a simultaneous one-sided lower bound
   above zero;
7. adequacy of one shared resolver requires noninferiority to
   `G2_CROSS_SPECIALIZED` with margin `-.05`; noninferiority does not establish
   superiority or biological identity;
8. accepted-edge precision and coverage, provisional/contradicted rates,
   false-memory use, defer calibration, cited-path validity, final action,
   calls/tokens, and complete resource vectors are reported separately;
9. masking/twin substitution retains the G1 `.80` causal-use threshold, and
   evaluation/source snapshot isolation remains exact.

If compiler-only matches the shared full condition, delete wake-trace and
residual-DREAM content credit. If authentic and shuffled traces match, delete
wake-connected-trace credit. If no-write matches durable memory, delete the
compilation/write contribution. If specialized beats shared outside `-.05`,
delete the one-resolver adequacy claim. If the explicit graph/program baseline
wins, report it as the stronger system; do not attribute its reasoning to the
model-facing arm. Failure of the text value gate blocks LoRA training.

The strongest positive G2 statement is:

> On a fixed common experience deck, authentic model wake traces followed by
> bounded target-blind cross-episode model proposals and deterministic
> evidence admission produced supported text memory that causally improved a
> fresh recurrent model’s later J/P/X actions beyond compiler-only, replay,
> shuffled-trace, and no-durable-write controls.

This does not establish that DREAM is necessary in general, that one resolver
is superior, that the resolver policy was learned, that weights store a graph,
that LoRA helps, that experience improves with memory, or that capability grows
with lifetime.

## 7. Failure and budget semantics

Failures are first-class observations:

- `NOT_FOUND` and `CONFLICT` are model-visible local read outcomes; the model
  may backtrack or defer within the original budget;
- malformed, multi-operation, illegal, truncated, or repeated-blocked model
  output consumes its slot and is never repaired or reprompted;
- budget exhaustion terminates the branch as `BUDGET_EXHAUSTED`; evaluation
  value is zero unless the registered metric explicitly scores defer;
- an unsupported or tainted proposal remains provisional/rejected; it cannot
  enter positive text, and its absence is not silently filled by the compiler;
- contradiction creates an append-only status event and a new revision is
  required; an old claim never returns to supported;
- a backend failure is never converted to `NOT_FOUND`; after scientific
  dispatch, unavailable exact response recovery makes the cell indeterminate,
  with no regenerated model sample;
- infrastructure failure before any scientific dispatch may resume only the
  identical hash-bound cell; partial science cells and zero-valued model
  failures are preserved;
- no world, target, trace, sample, arm, or seed may be replaced because it is
  difficult or unfavorable.

Resource matching applies only to identified causal contrasts. Every arm still
reports environment actions, resolver/DREAM/compiler calls, input/output
tokens, reader work, candidate enumeration, records/roots/views, retained and
active bytes, failures, latency, and energy where available. A gain explained
by extra model calls, hidden candidate scans, or larger retained semantics is
reported as such and receives no matched-mechanism credit.

## 8. Visibility and preserved traces

Model-visible data are limited to the current public goal/state, allowed past
public replay events, bounded workspace, last one-atom reader return, repeat
fingerprint, remaining budgets, and mode-specific schema. Audit, evaluation,
scorer, hidden program, target certificate, trace assignment, admission
receipt, and comparator data remain outside cognition.

Preserve every successful and failed operation as:

```text
PUBLIC_STATE
-> ASSISTANT_OPERATION
-> READER_OR_ENVIRONMENT_RESULT
-> NEXT_PUBLIC_STATE
```

Also preserve invocation mode, frozen snapshot hashes, visible-handle origins,
read misses/conflicts, updates, backtracks, proposals, predictions, malformed
bytes, defer/stop reason, and budgets. For later LOOP-policy work, remove
hidden answers, proof graphs, solvers, scorer/evaluator artifacts, trace-arm
assignment, and post hoc causal labels from all model inputs and targets. Train
only model operation tokens under a separate future authorization.

## 9. Promotion boundary

The permitted sequence is:

```text
ratified and independently reviewed D0
-> separately ratified G1 DEV
-> frozen G1 review and gate
-> separately ratified G2 text DEV
-> frozen G2 review and gate
-> separately ratified descriptive calibration
-> future G3 same-corpus transport proposal
```

No green CPU result, model agreement, DEV score, or this interpretation
releases the next node. G1/G2 do not authorize LoRA, three-pack confirmation,
post-native growth claims, randomized on-policy work, or scientific promotion.
