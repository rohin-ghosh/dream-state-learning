# PCFL M0--M-TEXT bound v2: adjudication candidate

Date: 2026-09-10

Status: **proposal input only**. This document is not human ratification and
authorizes no implementation, fixture materialization, CPU benchmark run,
model/provider/tokenizer call, training, LoRA/adapter/checkpoint operation,
GPU use, parenting, clean-lineage mutation, scientific execution, claim,
promotion, release, or submission.

## Plain-language decision

Build only the ruler needed for the first useful measurement.

The repository already has tested symbolic graph mathematics in the frozen
FeltCraft V7 files. It does not have a PCFL world, public event stream, reader,
phase machine, connected-memory carrier, intervention suite, or reducer. The
next implementation should therefore be a **thin PCFL-specific CPU fixture**,
not another generic platform. It must be runnable and independently testable
on its own, but it is not a paper result or a new scientific milestone.

Design that fixture around the first text-model assay now. Freeze the semantic
objects, public views, reader returns, transformations, and handoff receipts
that M-TEXT will consume. Implement and authorize M-TEXT separately after the
CPU fixture passes. This avoids building CPU semantics that have to be changed
once prompts, tokenization, recurrence, and model behavior enter the system.

The first paper-facing assay is deliberately narrow:
**can one fixed model causally use supplied, grounded, connected textual
memory to traverse different goals, choose an informative experiment, and use
old plus newly observed information after a reset?** It does not yet claim
that DREAM discovered the links, that LoRA stored them, that a child learned,
or that performance improves across a lifetime.

## Adjudicated architecture direction

1. Keep the complete Dream--LoRA--Think program and its M, E0, M-LORA, L, P,
   C, and O packages. Sequence them; do not collapse them.
2. Do not revive `PCFL-D0-EXACT-V2`, Compose v2, or the combined PCFL v1
   proposal. They are design sources with explicit rework verdicts, not
   implementation authority.
3. Keep FeltCraft V7 unchanged and outside the PCFL authority graph until a
   new exact, hash-bound PCFL reuse edge is independently reviewed and human
   ratified. Reuse bytes and mapped primitives, not prior authority or its
   failed scope audit.
4. The next exact implementation package is `M0-THIN`: direct PCFL modules for
   the finite world/deck, public events and views, phase/join/reset state,
   finite reader, provenance/support, carrier transforms, uncertainty assay,
   root receipts, and CPU conformance tests. It contains no model, training,
   writer, LoRA, child, parent, lineage, scientific estimator, or GPU path.
5. M0 is a standalone CPU software package but not a standalone research
   product. Its narrow output/interface is co-designed with
   `M-TEXT-SUPPLIED`; M-TEXT implementation and execution require their own
   later approval.
6. A deterministic algebraic materializer may be proposed for M0 only if the
   universe has no RNG, seed search, candidate ranking, favorable-root
   selection, retry, or replacement. Its output must be checked by a genuinely
   independent invariant checker and frozen before any model-facing use. A
   materializer/checker agreement is software evidence, not scientific ground
   truth.
7. The number of syntactic roots/twins is an engineering coverage choice, not
   a scientific sample size. Alias/order variants and within-root cells are
   repeated measures. Any later scientific `N`, precision rule, split, margin,
   estimator, and stopping rule belongs to M-TEXT or a confirmation package.
8. After M0 conformance, the first scarce model budget goes to a tiny consumed
   DEV M-TEXT smoke for parser, headroom, recurrence, and shortcut failures.
   E0 specification proceeds independently in parallel. M-LORA waits for
   M-TEXT, E0, and the clean guard.

## Graph, loop, claim, visibility, and test deltas from PCFL v1

### Graph delta

```text
FeltCraft V7 bytes (external reference; unchanged)
        |
        | later exact PCFL reuse edge
        v

        |
        v

```

No arrow is launch authority. No green CPU receipt unlocks a model, writer,
LoRA, GPU, scientific claim, or successor package automatically.

### Loop delta

The simple organism is unchanged:

- THINK is the recurrent stream of states, plans, judgments, actions, public
  outcomes, and revisions.
- DREAM manages active context and, in later separately tested packages,
  proposes connections from eligible public child experience.
- SLEEP validates/compiles grounded experience and transactionally writes a
  personal LoRA only after E0.

M0 implements none of these as a learned child. M-TEXT-SUPPLIED tests only the
causal usefulness of an explicitly supplied connected-memory representation.
Target-independent DREAM authorship is a later extension so discovery and use
cannot hide one another.

### Claim delta

- M0 may support only: the frozen CPU software implements the ratified finite
  semantics, visibility, intervention, provenance, and reducer contracts.
- M-TEXT-SUPPLIED may support only: under its frozen model, roots, bytes,
  baselines, and resources, supplied connected text was or was not causally
  useful for the registered relay tasks.
- It cannot support DREAM authorship, experiential learning, parametric
  memory, compression, parenting, accumulation, lifetime improvement,
  baseline saturation, population generality, or an on-policy flywheel.
- Every failed/unrun gate must retain its registered adverse value and remove
  the corresponding stronger language; it cannot be rescued by a downstream
  diagnostic.

### Visibility delta

M0 must bind one closed actor-readable view and command surface. Before a
registered separating public action, paired worlds must be byte-identical to
the actor. Afterward, only fields descended from the ordinary public outcome
may differ. Goals, private schedules, root IDs, arms, scores, interventions,
future events, oracle values, goldens, filenames, errors, reader ordering,
padding, and query agendas cannot become covert channels.

Carrier construction occurs before goals and can use only registered public
evidence. The join from isolated goal branches releases one exact public
projection and excludes abandoned thoughts, retrieval transcripts,
workspaces, hidden correctness, scores, timing, and sibling handles. Repeat,
retry, budget, and reset state are explicit and exhaustively tested.

### Test delta

The M0 implementation proposal must prospectively bind tests for:

1. exact manifest/hash/runtime/dependency verification;
2. finite algebra, multiple legal paths, bridge necessity, and delayed
   old-plus-new necessity;
3. paired-prefix equality, balance, public-taint closure, and private-field
   mutation attacks;
4. strict canonical bytes, schemas, padding, semantic IDs, and expected-reject
   objects;
5. complete capability/query-agenda denial;
6. exact branch fork, join, phase, reset, repeat, retry, and lost-response
   behavior;
7. chronological provenance, independent later support, root deduplication,
   aliases, legal diamonds, true cycles, contradictions, and revocation;
8. carrier-transform specificity for authentic, atoms-only, truthful-null,
   deranged, bridge-cut, twin/binding, sham, reachout-off, old-cut, and new-cut
   variants;
9. separate experiment choice, realized information, acquisition, and delayed
   value;
10. path, answer, and shortcut separation with all-path masking and twin
    substitution;
11. adverse/failure mappings and an environment-root reducer that cannot
    inflate `N`; and
12. independent deterministic reproduction with no selection, repair, retry,
    or replacement.

The M0 packet must also freeze the narrow M0-to-M-TEXT handoff: canonical
semantic rows, public reader return, prompt projection fields, renderer and
tokenizer/cut inputs or an exact preparation boundary, and receipt schema.
It must not authorize any model call.

## Unresolved choices assigned to the formal deliberation

The five roles must resolve rather than defer:

- the exact finite semantic universe and whether the 64-root `(k,h)` proposal
  is retained, reduced, or replaced;
- the precise primitive-by-primitive V7 compatibility/reuse table and the
  disposition of V7's failed independent scope audit;
- materializer versus pre-materialized-byte authority, including which exact
  outputs require a second human freeze;
- every closed M0 type, state transition, failure precedence, transformation,
  reducer field, and test oracle;
- the exact model-facing handoff fields that M0 freezes without implementing
  M-TEXT; and
- whether an exact renderer/tokenizer identity belongs in M0 inputs or in a
  separately ratified deterministic preparation packet.

If those choices remain outcome-changing after consensus, recommendation must
be `rework`; the packet is not implementation-ready.

## Adjudication of the fresh reviewer disagreement

One review recommended a manifest-first M0; another rejected a standalone
64-root platform and required M0/M-TEXT co-design. Both concerns are retained:

- M0 is independently runnable CPU software, so its semantics and tests can be
  checked before any model spend.
- M0 is not a standalone paper product, and its actor-visible output is frozen
  only as the exact input boundary of the first M-TEXT assay.
- Deterministic no-selection materialization is allowed only if ratified; it
  never promotes itself or supplies scientific evidence.
- M-TEXT execution remains separately authorized after M0 passage.

This is the shortest path that preserves scientific identifiability and does
not spend the deadline on a second general-purpose ruler.
