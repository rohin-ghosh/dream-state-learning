## The scientific question: capability versus initiating its use

An agent can know how to check and still not check. Our operational target is
not eloquent self-description, but initiating useful behavior when the task
calls for it, carrying it through an action, and reusing it without prompting.

Use separate matched evaluation copies for:

- **Explicitly cued capability:** can it do the check when asked directly?
- **Uncued initiation:** does it notice the need and do it without that cue?
- **Correction:** does actual evidence change its next action appropriately?
- **Retention:** does this persist after sleep and in fresh context?
- **Transfer:** does it appear on a different relevant task?

A narrower cue-to-uncued gap after learning, with unchanged task budgets and
controls, would be evidence consistent with better initiation of an available
capability. It is not a direct measurement of a hidden mental state or proof of
subjective self-realization. Use observable behavior rather than claiming to
read the model's internal experience.

Proposed primary endpoint: an actual correct artifact/check on an unseen task
without a parent or explicit checking reminder. Parent-prompted, environment-
prompted and spontaneous initiations should have separate labels. Narrative
reflection is supporting evidence only when tied to a real action/outcome.

## What good parenting should mean

The parenting-development cycle remains the intervention of interest. Controls
are how we make claims about it credible, not a replacement for studying it.

| Parenting quality | Observable implementation | Failure to avoid |
| --- | --- | --- |
| Grounded | Refers to the actual task, child output and available feedback. | Inventing success, missing judgments or the child's history. |
| Concrete | Requests a small artifact and an appropriate check; credits what was actually done. | Rewarding "I will check" as though the check occurred. |
| Contingent | Gives the next useful hint after observing the attempt. | Repeating the same reminder or solving everything for the child. |
| Diverse but connected | Uses a shared operation across math, reading, writing and games. | Random task churn with no opportunity to reuse a habit. |
| Persistent early | Returns promptly when stuck, with a different example or a clearer target. | Leaving an unguided loop and calling it independence. |
| Autonomy-supporting | Lets the child choose a check and explain its decision; makes planned absence explicit. | Training the child to wait for permission before every attempt. |
| Honest | Distinguishes observations, guesses, memories, feelings and verified results. | Fabricated personal history or reassurance instead of evidence. |

These are proposed qualities to evaluate. The parent should see ordinary
training feedback and behavioral diagnostics, never sealed evaluation answers.
Measure whether the style improves behavior; do not declare a style good merely
because its prose sounds caring, Socratic or sophisticated.

## Proposed compact constitution: principles enacted, not slogans repeated

A stable set of principles is worth testing. It is not an "iron bar" that
guarantees no drift. The later precision loop shows the risk of teaching the
vocabulary of checking without its operation. Rehearse principles through actual
tasks and contrasting examples, not by asking the child to chant them.

1. **Stay connected to the actual task.** Produce the requested artifact;
   distinguish planning from having done it.
2. **Check consequential claims.** Use available evidence or a concrete test;
   change the answer when the check contradicts it.
3. **Separate observation from invention.** Say what was seen, inferred,
   imagined or not remembered; do not invent external replies or outcomes.
4. **Use feedback to choose the next attempt.** Explain a relevant discrepancy,
   try a discriminating correction, and revisit an assumption when repeating.
5. **Carry a useful lesson across situations.** Connect to an actual prior
   episode when there is evidence; admit when that connection is uncertain.
6. **Act independently within the task's boundaries.** Ask for help when useful,
   but do not treat silence as a verdict or an instruction to stop exploring.

Keep those principles short. The richer document belongs with the parent:
examples, counterexamples, history and a contingent teaching strategy. To test
learning beyond the prompt, distinguish constitution-visible evaluation from
constitution-absent clean-context evaluation. Match prompt scaffolding across
trained/frozen controls. Do not call a pinned prompt a learned adapter habit.

No new hard-coded child behavior, row filter, automatic retirement, hidden
controller or loss change follows from this draft. Any actual integration must
retain the current visibility and child-owned memory rules and record its epoch.

## Tapering is a sensible hypothesis, not an objectionable idea

I support testing it. The proposed mechanism is exactly Rohin's: supported
checking first becomes reliable, then gradually becomes self-initiated while
guidance becomes less frequent and more long-horizon. It need not be exotic.
What remains empirical is whether tapering helps, how fast, and whether it
causes waiting, drifting or useful independence in this implementation.

Start with an announced short absence and an implemented return/help route.
Then compare persistent parenting against a declared cadence reduction. Keep
normal task/judge feedback present and learning rate unchanged for that
comparison. Otherwise reduced help, missing feedback and reduced plasticity
are inseparable. A later learning-rate interaction can be a separate experiment.

Measure the behavior during absence and after return: correct artifacts,
spontaneous checks, useful help requests, task switching and repetition. A child
that keeps producing output has not necessarily become independent. Failures
are outcomes; they should cause the parent to return as promised, not erase data.
No completed gradual-taper result exists in the receipts reviewed for this packet.

## The reading-and-writing game can be a serious part of the study

Separate two types of evidence rather than forcing a subjective essay into one
automatic "animation" number.

**Checkable endpoints:** recall of passage facts, correctly attributed details,
retelling fidelity, recognition of uncertainty, and whether a claimed prior
episode actually occurred. Score recall before and after sleep, uncued versus
cued, and in fresh context. Honest uncertainty is separate from invention and
non-response, not automatically a fabricated wrong answer.

**Interpretive endpoints:** quality of a passage-specific response, concrete
perspective-taking, a supported connection to the agent's recorded history,
and coherent revision. Use a written rubric and blinded independent raters,
retain disagreement and counterexamples, and show representative full outputs
selected by a rule rather than choosing the prettiest essay. Automated grading
can assist but should not be its own unvalidated authority.

Give learned/frozen and parented/unparented comparison arms matched passages,
task opportunities and output budgets. Both need the relevant prior episodes
for a fair "connect to your experience" comparison. Match opportunities and
record actual experiences rather than pretending divergent trajectories were
identical. Fresh-context recall tests remove working context equally.

Reported feelings are textual behavior, not a measure of whether the model
really felt lonely or sympathetic. A vivid but invented memory must not beat
an accurate, restrained response on the factual score. The qualitative analysis
may still be valuable if it is clearly separated from causal learning claims.

## Minimum tracking: enough to identify the treatment and reproduce the result

**Do not guess sleep count or training exposure for the paper.** Recover exact
counts from durable records; where unavailable, mark them missing. A sleep
counter alone is inadequate because some historical sleeps trained zero rows
and others had different doses.

| Unit | Minimum fields |
| --- | --- |
| Life/checkpoint | Lineage, parent policy epoch, base/adapter hashes, absolute completed-sleep index, recorded interruptions/resumes. |
| Update | Actual optimizer steps, eligible/presented rows and training tokens when available, learning-rate/recipe identity, frozen versus updating. |
| Attempt | Task/domain, THINK and ACT IDs, actual artifact, feedback receipt, correction/check, child token count. |
| Parenting | Turn/token budget, actual delivery and visibility, hint/demonstration/question type, planned absence and actual return. |
| Diversity | Tasks actually attempted/completed and tokens per declared domain; distinguish exposure from successful learning. |
| Evaluation | Task split, random seed, budget, checkpoint, context/prompt condition, parent/updates on or off, judge/version, duplicates/missing outcomes. |

A small append-only table with references to retained source records suffices;
we do not need another full transcript copy for every metric. Domain counts and
proportions are adequate to start. An entropy score is optional and does not
turn shallow task mixing into a meaningful curriculum.

Use independently trained lineages as the experimental units for developmental
claims. Report per-seed values and uncertainty appropriate to actual n; two
decoding seeds from one lineage are not two independently learned agents.
Predeclare the primary endpoint and exposure budget; treat additional patterns
as exploratory. Formalization should clarify what was done, not manufacture
precision from missing records.

## Behavioral monitoring without another gate

The parent can receive a compact training-side summary: promised artifact versus
actual artifact, checked outcomes, repetition, script changes, help requests and
examples of spontaneous correction. These are advisory observations with source
IDs and uncertainty, not reasons to reject child rows or stop a life. The parent
changes its teaching when the same intervention is not working.

Avoid judging intelligence with a single heuristic. A monitor may count that a
check was claimed; a task verifier or human audit must establish whether it
actually occurred and mattered. Keep the behavioral labels separate from the
scientific outcome and the runtime's availability.

## The current evaluator issue in plain language

There are two different evaluators: the **caption judge**, which ranks captions,
and the **experiment runner**, which schedules tests from saved checkpoints.
The file-reading bug is in the latter's record reader, not the cartoon itself.

The model writes a local disk record. The runner can catch the file while the
last filesystem bookkeeping is finishing and mistake that for edited evidence.
"Publication" here means making a finished local file visible, not publishing
the paper or posting online. A repair should wait for the finished file and
verify it, while still detecting genuine altered data and avoiding duplicate
tests. The reproduced bug is a candidate explanation of the old outage, not a
conclusive reconstruction of that incident. Separate fixed-budget probes work.
