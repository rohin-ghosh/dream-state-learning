# Fresh audit: parenting, running SLEEP, and increasing lifetime

Date: 2026-09-12 UTC

Status: watcher-side scientific design audit only. This note changes no
builder-owned source, model, run, or claim authority. It does not authorize
implementation, GPU work, release, or submission.

## Verdict

The latest four-branch lifetime skeleton is the right causal core, but it is
not paper-ready yet:

```text
                    deployment SLEEP shadow     deployment SLEEP promoted
matched development          M-FROZEN                    M-RUN
targeted parenting           P-FROZEN                    P-RUN
```

Its root-level interaction can test whether the **benefit of promoting SLEEP
writes** differs after targeted parenting. It cannot by itself establish
increasing-lifetime improvement, external-memory superiority, connected
knowledge, or compression. The current synthesis already makes this
distinction correctly (`research_notes/2026-09-12_end_to_end_goal_closure_synthesis.md:151-207`).

Three collisions must be removed before a preregistration:

1. The repository uses H1/H2 for several different outcomes. Name the tests
   by object: `PERSIST` (parent-absent childhood skill), `DEVxSLEEP` (the
   four-cell interaction), and `LATE` (the stronger increasing-lifetime
   conjunction).
2. Adaptive Parent v5's adult-by-parent-presence 2x2 is a **tutoring** test,
   not the parenting-by-SLEEP factorial. It should run, if desired, on
   disposable terminal descendants and have a separate estimand
   (`research_loop/plans/adaptive_parent_development_v5_consensus.md:145-188`).
3. `ACTIVE_TEXT_NATIVE` must remain a separate on-policy systems opponent.
   Putting its graph/derived-memory machinery into every four-cell branch
   donates part of the claimed mechanism and changes the estimand. The
   repaired role matrix already separates same-semantics, common-raw, and
   native active-text roles
   (`research_notes/2026-09-11_strong_evolving_active_text_baseline_cross_critique.md:34-63`).

No present result supports the lifetime claim. The current evidence audit
reports an ungated historical mean of `+0.019` (SE `0.011`), negative mean
terminal disjoint performance, late harm, and no qualified evolving-memory
comparison (`research_notes/2026-09-11_current_evidence_paper_gate.md:30-39`).
The currently running post-outcome and writer jobs are still diagnostics, not
H1/H2 evidence (`research_notes/2026-09-12_astra_guard_and_postoutcome_audit.md:137-148`).

## Design audit

### Randomization and independent units

One independent unit must be one **fresh clean birth block**, not one branch,
program, visit, checkpoint, decode, or adapter. Within each block:

1. create two byte-identical children;
2. randomly assign targeted parenting versus an active, dose-matched neutral
   developmental treatment;
3. after childhood and complete parent/context deletion, fork each adult into
   promoted and true-shadow SLEEP;
4. keep all four branches on one node, randomize GPU and launch positions, and
   use one arm-independent exogenous-randomness tape; and
5. distribute whole blocks across nodes.

The tape address must include root, episode occurrence, decision,
continuation, and technical replicate, but never arm, adapter, device, cache,
or wall time. Equal tape addresses preserve common exogenous randomness after
policies diverge; they do not pretend the resulting on-policy histories stay
identical. This law is already specified at
`research_notes/2026-09-11_strong_evolving_active_text_baseline_cross_critique.md:218-233`.

The mature `pedagogy_core`, teacher model/spec, and parent state-transition
rule are frozen before confirmation. Each root starts from that same snapshot;
root-local parent adaptation is allowed, then discarded. Cross-root parent
learning would make treatment depend on launch order. This is consistent with
Adaptive Parent v5's freeze rule
(`research_loop/plans/adaptive_parent_development_v5_consensus.md:134-143`).

Use a concealed arm map for analysis until the endpoint table and inclusion
receipts are frozen. Analyze root-block contrasts. Exact sign-flip/randomization
inference over blocks is the clean primary test; a root-level t interval and a
hierarchical task model are sensitivity analyses. Nested programs and decoding
repeats improve measurement, not `n`.

### Treatment and controls

The developmental control should be called **matched/neutral**, not
"unparented," if it receives equal teacher calls and context. Match teacher
model, turns, timing, tools, context occupancy, tokenizer-counted parent dose,
child-generated-token budget, task opportunities, and SLEEP opportunities;
only the targeted teaching content differs. The one-root canary specification
already states most of this (`research_notes/2026-09-11_minimal_causal_parenting_h2_consensus.md:34-53`).

`FROZEN` must mean true shadow SLEEP: compile, train, validate, preserve the
candidate, and consume the same technical RNG/work, but never mount it. `RUN`
differs only by transactional promotion of a technically accepted candidate.
After promotion, trajectories and corpora may diverge; that is the recursive
effect being tested, not a matching failure
(`research_notes/2026-09-11_minimal_causal_parenting_h2_consensus.md:67-86`).

Bind one common nonparametric-memory policy for the four cells. It may be no
persistent wake text or the same narrow append-only public raw/RECALL lane in
all four; it may not be a derived active-memory system whose updater performs
the abstraction or traversal under study.

`M-FROZEN` is the correct **matched regular developmental agent**. If the paper
also says "ordinary raw-base agent," add a raw frozen-base anchor on the same
exam deck and label it secondary; it does not replace the matched control and
does not identify parenting.

### Contamination and phase boundaries

Confirmation must use fresh-base roots. No R2/R3/R4/R5/RP, bootstrap v1-v3,
`lineage3_*`, or `parent_scout_*` artifact is clean-eligible
(`research_notes/2026-09-12_astra_guard_and_postoutcome_audit.md:58-73`).
Before deployment delete parent messages, childhood restatements, raw/derived
stores, indexes, embeddings, caches, query state, lesson/brief text, and legacy
RECALL state. Each evaluation visit is a sterile disposable descendant; no
score, output, selection, or experience returns to the live child or parent.
The repository's canonical lineage rule already requires one-way benchmark
descendants (`research_notes/64_iclr_paper_core_and_benchmark_v2.md:160-167`).

The remaining global society/sibling view can bridge a task-exposed lineage
into a clean child; it must be disabled or recursively admitted. Exact copied
parent lines in loss-bearing child targets need refusal/audit, with
paraphrastic echo measured rather than silently called clean
(`research_notes/2026-09-12_astra_guard_and_postoutcome_audit.md:23-37`).

No L launch is scientific until the response-only cumulative writer, actual
action/outcome provenance, first-passing predeclared fit-seed schedule,
previous-child safety comparison, and atomic corpus+adapter promotion pass the
E0 prerequisite (`research_notes/64_iclr_paper_core_and_benchmark_v2.md:169-190`).

### Inference and token budgets

Use a **generous, equal actor budget**, not compression pressure. Choose the
smallest budget on disjoint DEV for which another increment has less than the
predeclared useful score/action gain, then freeze it across all confirmatory
arms and exams. The current `16 x 400 = 6,400` generated-token envelope is only
a candidate; the existing design correctly says the CompilerGym comparison is
`NO_GO` if already-valid DEV cannot show that it is sufficient
(`research_notes/2026-09-11_strong_evolving_active_text_baseline_cross_critique.md:244-256`).

Within the factorial, equalize actor-generated tokens, legal action
opportunities, task tape, exam calls, teacher dose, SLEEP schedule, update-token
ceiling, fit-seed policy, and shadow work. Let the child choose the split
between thought and action. Do not claim equal compute: input tokens, training,
storage, retrieval/index work, latency, energy, and teacher cost are reported
separately, as required at
`research_notes/2026-09-11_strong_evolving_active_text_baseline_cross_critique.md:258-270`.

### Estimands

Use seven frozen examination cuts over source-disjoint acquisition cohorts.
At every cut, evaluate a sterile clone on one difficulty-balanced held-out exam
deck. Invalid and missing actions remain zero. Define fixed equal-weight value
`V_c(Tj)` before DEV and entry-centered, time-normalized trapezoidal AUC:

```text
AUC_c = trapz_j(V_c(Tj) - V_c(T0)) / (T_last - T0)
D = (AUC_P-RUN - AUC_P-FROZEN)
  - (AUC_M-RUN - AUC_M-FROZEN)
```

Test in fixed order:

1. `P-RUN > P-FROZEN` in AUC;
2. `D > 0`.

The first prevents a positive interaction produced only because SLEEP harms
the matched child. Passing both supports `DEVxSLEEP`, not increasing-lifetime
improvement. The current synthesis states this boundary explicitly
(`research_notes/2026-09-12_end_to_end_goal_closure_synthesis.md:163-176`).

`PERSIST` is separately measured immediately after childhood and parent
deletion using fresh trigger and contraindication cases:

```text
PERSIST = (P_ON - P_OFF) - (M_ON - M_OFF).
```

Correct non-use is scored separately; lexical restatement is not uptake. The
same roots may provide this preregistered earlier endpoint under fixed-sequence
gatekeeping, but its disposable exams never feed L.

Release `LATE` only if **all** frozen predicates pass: positive absolute
`P-RUN` post-anchor slope, positive anchor-to-terminal gain, positive slope
advantage over the qualified evolving-text system, old-skill and early-
deployment retention noninferiority, and a terminal practical margin. AUC can
pass on a transient bump or slower decline, so it cannot substitute for this
conjunction (`research_notes/2026-09-12_end_to_end_goal_closure_synthesis.md:192-207`).

### Strong baselines

Preseal the native active-text implementation, roots, tape, updater, retrieval,
budget, endpoints, and conditional launch rule **before** opening P-RUN
confirmation output. After `P-RUN>P-FROZEN` and `D>0`, launch a saved fifth
branch from the same parented adult: `P-TEXT`, with childhood LoRA frozen, an
empty text store, and its own public on-policy evidence. Compare `P-RUN` with
`P-TEXT` as a total systems effect; do not call it a carrier comparison. The
same-source text-versus-LoRA assay remains separate. These distinctions are
already frozen conceptually at
`research_notes/2026-09-11_strong_evolving_active_text_baseline_cross_critique.md:34-63`.

Do not say the text system "saturated" from a nonsignificant slope. Require a
frozen equivalence band on each late increment, remaining oracle/task headroom,
and a doubled-retrieval-budget check also inside the band; otherwise report
only the two finite curves. The current synthesis imposes this rule
(`research_notes/2026-09-12_end_to_end_goal_closure_synthesis.md:209-227`).

A LEAFE-like comparator is **claim-conditional**, not part of the minimum
factorial. Run a presealed bounded terminal recovery/batch writer only if the
paper will say periodic SLEEP beats reflective batch internalization. It is not
a faithful LEAFE reproduction and cannot establish active-text saturation or
continual learning. The existing bounded definition and claim limit are at
`research_loop/advisory/20260906_one_parent_child_strong_memory_baseline_gate_v1.md:165-201`; its old 48-program geometry must be rewritten to the final L horizon
before use. If it is absent, cite LEAFE as prior work and omit superiority to
batch reflection.

### Sample size and stopping

One canary root is executor/directional evidence only and is excluded from
DEV and confirmation. Eight DEV roots may freeze budget, horizon, seven cuts,
plateau-anchor candidates, endpoint reliability, and root covariance; DEV is
never pooled with confirmation and may not choose the largest observed
treatment effect.

For confirmation, the independent sample size is the number of root blocks.
The historical interaction SD `0.027` comes from only four gated lives and a
different estimator, so it is a weak planning prior, not a variance estimate
to treat as known. Under a two-sided 95% / 80%-power normal approximation for
SESOI `delta=0.020`,

```text
N ~= ((1.96 + 0.84) * sigma / 0.020)^2.
```

This gives `N ~= 15` at `sigma=0.027`: **16 roots are only a structural
minimum**. `N=24` covers approximately `sigma<=0.035`; `N=32` covers
approximately `sigma<=0.040`. Freeze a variance-only rule selecting
`N in {16,24,32}` before treatment directions are released. If the resulting
powered N exceeds the resource ceiling, the confirmatory interaction is
`NO_GO`, not a low-power headline. Multiple branches or decode repeats never
increase N. The prior candidate reached the same structural warning and
approximately-16-root conclusion
(`research_notes/2026-09-11_minimal_causal_parenting_h2_consensus.md:135-157`).

Sixteen roots power only the single `DEVxSLEEP` interaction under the
optimistic SD. The complete `LATE` conjunction and active-text equivalence may
need more precision; power those contrasts separately or label them
exploratory. Use fixed-sequence/IUT gates rather than choosing whichever
endpoint passes.

Hard rules:

- writer/E0 or clean-lineage failure -> L is `NOT_RUN`;
- `PERSIST` failure -> no persistent-parenting claim and L is exploratory;
- candidate rejection -> keep the previous adapter, count the rejected write
  and continue; no retry chosen from task performance;
- missing/invalid task outputs -> zero under intention-to-treat;
- contamination/infrastructure exclusions use frozen mechanical rules before
  arm outcomes are opened; preserve and report every failure;
- no efficacy-based early stopping, endpoint switching, post-hoc horizon
  extension, or outlier removal; and
- launch `P-TEXT` and the bounded batch comparator only under their already
  sealed conditional rules.

## Minimum decisive design

The minimum paper-worthy longitudinal experiment is therefore:

1. Pass E0 plus one authentic post-outcome source qualification and one
   two-bank cumulative-replay retention check.
2. Freeze one targeted developmental competency, one active neutral treatment,
   one parent snapshot/state-transition rule, one clean root contract, and one
   generous actor budget.
3. Run and exclude one complete four-branch executor canary.
4. Run eight disjoint DEV blocks; freeze the horizon, seven cuts, exam deck,
   AUC, late anchor/margins, active-text implementation, and the variance-only
   `16/24/32` confirmation rule.
5. Raise fresh confirmation blocks and run `PERSIST`, then the four-cell
   `DEVxSLEEP` factorial at the selected N.
6. If both factorial gates pass, launch the already-sealed `P-TEXT` descendants
   on those saved parented adults and read the noncompensatory `LATE` release.
7. Optionally run the adult-type x parent-present tutoring 2x2 on disposable
   terminal descendants. Never fold its temporary assistance into `D`.
8. Run the bounded terminal batch comparator only if its superiority sentence
   is intended.

This is smaller and cleaner than combining parenting, parent-present tutoring,
active text, batch recovery, and increasing lifetime in one factorial. It
still directly answers the paper's core developmental question while making
each stronger sentence earn its own control.

## Maximum claims

- `PERSIST` only: the exact targeted developmental treatment caused a durable,
  adapter-carried disposition after parent/context removal in the tested model
  and task family.
- `DEVxSLEEP`: targeted development increased the finite-horizon benefit of
  promoting gated SLEEP writes relative to a dose-matched neutral childhood.
- `LATE`: over the registered finite horizon, the parented running learner
  improved absolutely after the anchor, retained earlier competence, and beat
  the exact qualified evolving-text system in late slope and terminal value.
- tutoring 2x2: the exact mature parent changed the tested adults' acquisition
  under audited answer-aware assistance.

Even all four do not prove universal parenting efficacy, graph geometry in
weights, connectedness mediation of the lifetime slope, physical compression,
indefinite self-improvement, sentience, or superiority to LEAFE without the
separate comparator.
