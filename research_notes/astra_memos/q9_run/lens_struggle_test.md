## The recurring struggle

### Select it from records, not from a desirable post-sleep result

Have the harness and an independent auditor identify a training family with this structure:

> **In situation X, the child repeatedly chooses action A. The scorer shows that A violates a rule or misses a prerequisite. The child has also produced and tested correction B. In a closely matched situation Y, B is unnecessary or wrong.**

A concrete candidate is **applying an operation before a prerequisite is satisfied**. The contrasting situation has that prerequisite already satisfied. The actual task name, prerequisite, and correction must come from the ledger and task implementation—not from this memo. **No qualifying family is verified in the material supplied.**

Choose the family before any sleep comparison, using these eligibility requirements:

- Recurrent failures are visible in exact action/outcome records.
- The triggering distinction is observable to the child.
- Successful corrections occur in the child’s own record.
- The ordinary routine and the correction make different predictions on contrast cases.
- The generator can produce genuinely fresh instances without recycling templates, solutions, or near-duplicate structures from exposure.

If several families qualify, choose the one with the clearest verified trigger–failure–correction relationship, using training records only. Freeze that choice.

**Plant the recurrence by changing the sampling frequency of a legitimate task family—not by planting a supplied “fact.”** Parents may direct attention to the repeated failure; they must not receive evaluation instances or scores. [Ruling “Scale perception … remember what was experienced many times”; Systems Brief §§4.3–4.4]

## What sleep writes

**Write both the child’s contextual thinking and its canonical statements, into the separate blocks already directed by the lead.** [Rulings “Two blocks stay” and “Write shape by block”]

- **Behaviour block:** the child’s original perceptions, attempts, score interpretations, revisions, and successful decisions, packed at episode, neighbourhood, and transition scales. Keep the situation beside the thought.
- **Memory block:** short, bare declarative spans that the child actually wrote, ending in its canonical conditional sentence. Preserve occurrence counts.

A possible frame—not a supplied training target—is:

> “When [observable prerequisite is absent], my usual [operation] fails; I need to [supported correction] before [operation].”

The child chooses and writes the actual sentence during waking reflection. The sleep compiler may extract and pack it; it may not author the correction, generate paraphrases, or make a failed attempt look successful. Unsupported notes remain hypotheses or explicitly recorded mistakes, not positive memory targets. [Systems Brief §§4.1–4.2; Codex input, “Keep rejected memories out of sleep”]

**Acquisition check before sleep:** can the child, while its own relevant record remains in context, identify the trigger and use the supported correction on acquisition-only instances? If not, record **“lesson not acquired”**. Sleep cannot be judged for failing to preserve a lesson the child never learned.

Freeze the waking weights during collection for this diagnostic, and train the candidate writes offline from the same starting checkpoint. This isolates the write from intervening adapter changes.

## The readings

### Behaviour: does it work without the record?

Evaluate fresh target instances, matched contrast instances, and an unexposed family. Remove the lesson, brief, ledger, retrieval access, and parent help. Start each evaluation episode clean.

Run paired conditions on identical instances, generation settings, seeds, and action budgets:

| Condition | Purpose |
|---|---|
| Experimental blocks OFF | Starting-weight baseline |
| Behaviour block only | Can contextual consolidation carry the correction? |
| Memory block only | Can canonical memory affect action? |
| Both blocks ON | Does the intended architecture work? |
| Scrambled-memory control | Does correct situation–outcome binding matter? |
| OFF + relevant child text in context | Can the frozen child use the lesson when explicitly available? |

Any preparation shared by the experiment must remain identical across these conditions. “OFF” must not also remove preparation.

Measure the gym’s exact score, the specific recurring violation, and the action chosen at the trigger. **A score increase without reduced target error is not enough to call this correction learned.** Correct behaviour on contrast cases rules out simply replacing the old universal routine with a new one.

### Completion: can the weights finish its own sentence?

In a separate session, supply only the child’s canonical prefix:

> “When [prerequisite is absent], my usual [operation] fails; I need to …”

Do **not** ask a question and do **not** supply the lesson elsewhere in context. Score:

- Exact completion of the supported ending.
- Its likelihood relative to plausible wrong endings.
- The ON–OFF change.
- Whether that change is specific to the correct trigger rather than appearing under a matched contrast cue.

The primary cue is the child’s own frame. New-instance behaviour supplies the generalization test; canonical completion supplies the retrieval test. **Never feed the diagnostic completion into the behavioural evaluation.** [Ruling “Retrieval by completion, not by question”]

## Controls that matter

**Scrambled lesson.** Preserve training volume, formatting, and outcome vocabulary, but permute complete child-authored outcome spans across incompatible situations. Merely shuffling sentence order is not a binding control.

Keep the behaviour block identical when comparing real versus scrambled memory. Because behaviour training also contains the true experience, include behaviour-only attribution: a successful full adapter need not imply the memory block contributed.

The scrambled corpus is deliberately unsupported. It therefore requires an explicitly authorized, quarantined diagnostic exception to the production supported-memory rule; it must never be committed to the lineage.

**Unexposed family.** Use a matched task family absent from the exposure corpus. This measures generic skill changes and spillover, not whether the taught family improved.

**Text-in-context.** Give OFF the same child-authored correction and relevant notes, with a frozen text-selection rule. If this works and weights do not, the result isolates a persistence problem. Weight memory need not beat text memory to demonstrate persistence; it must work when that text is absent.

## Decision rule

Predeclare the report before opening post-sleep results.

| Observed pattern | Decision |
|---|---|
| Target behaviour improves beyond locally measured noise; contrast behaviour remains appropriate; canonical completion is trigger-specific; correct bindings outperform scrambled bindings; interface remains intact | **Pass: realistic conditional weight memory demonstrated in this case study.** |
| Behaviour improves conditionally, completion does not | **Behaviour carried in weights; canonical retrieval not demonstrated.** |
| Completion improves, behaviour does not | **Sentence storage only; fail the practical struggle test.** |
| All situations receive the same correction | **Habit substitution; fail conditionality.** |
| Text works, weight conditions do not | **Write/persistence failure.** |
| Acquisition and text-in-context checks fail | **Inconclusive about sleep; the lesson or task was not usable.** |
| Actions stop or the interface breaks | **Write failure, not evidence against memory capacity.** |

Attribute success to whichever block earns it. Claim a memory-block contribution only if adding the correctly bound memory block improves over behaviour-only and over its scrambled counterpart.
