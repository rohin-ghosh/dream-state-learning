## 1. SEQ-017: what the text-memory result actually says

### 1.1 The present claim is too strong

For R2 seed0, frozen-plus-brief scores **0.5291** versus final adapter **0.5262** on the eight-program panel; on the disjoint panel it scores **0.2731**, versus final adapter **0.2145** and mid-life adapter **0.2731** [SEQ-017].

That supports three distinct statements:

- **The weights changed behavior.** Adapter ON/OFF differences and increased recipe lock-in establish that [SEQ-001/M12; R2-only erratum].
- **Training on self-generated experience can consolidate a behavior.** This remains a defensible procedural description.
- **The adapter learned useful experiential knowledge unavailable in its written memory:** **not established.** Nor is improved adaptation to new situations.

The notebook’s interpretation—“the weights carry exactly what the text carries and nothing more”—is not justified. Equal scores do not imply equal stored information. The adapter could contain additional useful information that these panels never elicit, additional harmful information, or a different mechanism producing the same routine.

The stronger warning comes from the surrounding evidence: final R2 adapters average **−0.017** against frozen on the disjoint panel; final-minus-mid is negative in six lives and positive in none; almost every above-base result is the same fixed routine [SEQ-012].

### 1.2 If all other 15 lives repeat it

The sharpest honest sentence is:

> **Across 16 lives, the frozen model given each child’s final written brief matched or exceeded its trained adapter on both evaluated panels; these tests provide no evidence that weight consolidation adds useful capability beyond an explicit text memory of the experience.**

Add “within a prespecified practical-equivalence margin” if “matches” means statistical equivalence rather than literal point estimates. Do **not** write “the adapter learns nothing” or “self-learning is disproved.”

**Decision:** Finish all planned text-memory cells before launching more old-protocol lives. Report paired differences by life, with arms separated and gated checkpoints labeled as selected. Use a provisional **0.015 score margin**, but calibrate it with new same-condition repeats; the existing ~0.0066 replicate SD is not the uncertainty of every new contrast [SEQ-011].

**Measure / reversal:** Measure adapter-minus-text differences, per-program behavior, collapse incidence, and inference cost. I change my mind about “no useful increment” if a prespecified comparison shows a reproducible adapter advantage beyond the margin, especially on problems requiring different actions rather than the universal routine.

### 1.3 The separating experiment: conditional information missing from the brief

The two hypotheses are not mutually exclusive: an adapter may store what the brief says *and* nothing useful beyond it. The question is whether its behavior contains **recoverable, experience-specific information conditional on the brief**.

Run this crossed evaluation:

| | No brief | Own brief |
|---|---:|---:|
| Frozen | F | F+B |
| Adapter | A | A+B |

Add **routine-only text** as a control. If that matches the full brief, the “memory” benefit itself is probably just recipe transmission.

Then build a **brief-omission challenge**:

1. Identify ledger-supported distinctions absent from the final brief—ideally situations where different feedback warrants opposite next actions.
2. Confirm that the ledger actually contains opportunities to learn those distinctions.
3. Test new instances, with identical visible context across F+B and A+B.
4. Include paraphrased triggers and negative controls where the same strategy should *not* fire.

If existing ledgers contain no such distinctions, that experiment is unidentified. Use a small prospective diagnostic: randomly assign hidden family-to-response mappings, expose the child to them, exclude those mappings from the evaluation brief, and test new instances. Random assignment prevents pretrained knowledge from supplying the answer. This diagnostic can use disposable adapters; it need not create another taught lineage.

**Measure / reversal:** Primary endpoint is correct conditional action on brief-omitted distinctions, not prose similarity. Reproducible A+B > F+B establishes useful information beyond that particular brief. Failure supports **behavioral sufficiency of the brief on these tests**, never “nothing else is stored.” Swapping or corrupting a brief is a secondary cue-conflict test, not by itself a storage assay.

## 2. The write mechanism: fix conditional supervision before buying capacity

### 2.1 Critique of the proposal

**Context stripping is a credible culprit, not yet the culprit.** A context-free “reconsider your plan” trains a marginal habit; it does not teach when reconsideration is warranted. But contextualizing a bad ledger can still teach a contextualized bad habit.

| Proposal | My judgment | Measurement that would change the decision |
|---|---|---|
| Whole episodes plus short pieces | Test now. Preserve triggers and outcomes, not merely longer text. | Better held-out trigger discrimination without increased unnecessary reflection. |
| Neighborhood packing | Helpful for batching; dangerous if it creates fictitious cross-episode context. | A separate packing test improves conditional behavior at matched tokens without order sensitivity. |
| No repeat caps | Keep all occurrences in the archive. I disagree that frequency should automatically confer training authority. | Full-frequency training improves transfer without raising boilerplate mass, lock-in, or collapse; otherwise revise sampling. |
| Rank 32 | Accept as the fixed sprint setting, not an explanation of improvement. | A later token-matched rank comparison establishes an advantage; tonight’s contextual A/B cannot. |
| Cumulative retraining from base | Clean provenance, but quadratic total work if every sleep replays all accumulated data. It also preserves earlier bad lessons. | Measured training time remains below a collection interval and retention improves; otherwise reduce write frequency or use an explicit replay budget. |
| Asynchronous clone merge | Merge **ledger data**, not independently trained adapter deltas. | Track staleness and per-gym retention; sustained lag above one round or dominance by one gym requires slower publication or fewer collectors. |

Sixteen GPUs do not mean sixteen collectors **plus** a writer, evaluators, and local parents. Reserve those services first. Maximize useful experience, not process count.

### 2.2 Concrete sample construction

I would use the following writer:

**Episode view**

- Chronological sequence of actual observations, public interaction, child messages, actions, and feedback.
- Parent/environment text is **conditioning context with zero target loss**.
- Target loss applies only to the child’s generated tokens, including its own actions.
- Causal attention prevents a pre-action thought from seeing its future outcome. A later reflection may see that outcome.
- Private reflection follows its actual available history. It is not moved before the experience it discusses.

**Local view**

- One child thought/action as the target.
- Its real antecedent context: current task or goal, relevant recent observation, preceding action, and feedback when available.
- No hindsight labels written by a parent. No fabricated “situation” header.
- Oversized histories are handled with bounded actual transcript windows, with truncation logged—not an unvalidated summarizer.

**Mix and packing**

- Start at **50:50 supervised child-token budget** between episode and local views. This is a test setting, not a privileged ratio.
- Preserve real repeated occurrences. Log the extra exposure caused by representing an occurrence in both views.
- Shuffle episode order each epoch.
- Pack related episodes for efficiency, but reset positions/use block attention so independent episodes cannot attend to each other.
- For episodes exceeding supported context length, use chronological overlapping windows and score each episode-view target once. Report that these are windows, not whole episodes.

**Measure / reversal:** Log target-token mass by boilerplate, action, feedback-conditioned revision, gym, and episode length; also record truncation and effective exposures. Reject this construction if it improves training loss but not held-out conditional choices, or if useful supervision is overwhelmed by repeated generic text.

### 2.3 Failure modes to expect

- **Boilerplate domination:** longer sequences supply more generic tokens, not more lessons.
- **Order memorization:** “after this family, use that routine.”
- **Hindsight leakage:** outcomes accidentally enter the context of earlier decisions.
- **Self-imitation of mistakes:** faithfully learning an incorrect reflection.
- **Cross-episode leakage:** adjacent examples become an artificial conversation.
- **Repetition feedback loop:** a ritual generates more ritual data and therefore more training authority.
- **Asynchronous dilution:** fast or verbose clones dominate the cumulative ledger.
- **Stale-policy poisoning:** rollback changes the serving adapter but the next cumulative retrain reinstates its harmful descendants.
- **Capacity confounding:** changing rank, context, sampling, and optimizer together makes a positive result uninterpretable.

For rollback, retain every raw row but version the eligible training manifest. A rollback must identify the adapter, ledger frontier, optimizer state, and subsequent suspect data. Otherwise it is cosmetic.

**Measure / reversal:** Track whether the first post-rollback write reproduces the same failure and whether failures correlate with source adapter/version. If clean replay still reproduces it, the explanation is not merely contaminated post-rollback data.

## 3. Freeze the child tomorrow—but do not confuse minimal format with minimal preparation

I interpret “never changes” as freezing the **harness, interface, preparation recipe, and inference policy**, not preventing the intended adapter updates.

### 3.1 Likely failures in the first 200 problems

1. **Interface failure:** prose about an action, malformed `ACT:`, multiple actions, invalid arguments.
2. **Turn confusion:** no task-level end token becomes endless narration or repeated action.
3. **Nudge dependence:** it learns to wait for the harness to authorize action.
4. **Unproductive persistence:** different-looking guesses without information gain.
5. **Ritual reflection:** lengthy diagnosis that never changes the next decision.
6. **Saturation/floor effects:** success is nearly impossible, or random partial credit looks like competence.
7. **Abrupt degradation after a write:** low thought count is only one possible symptom.

The LockGym warning matters: approximately 4% frozen lock-opens and random partial credit around 0.50 make aggregate reward a poor persistence instrument [supplied gym-survey summary]. It needs a tractable tier, not exhortations to try harder.

### 3.2 Minimal preparation I would choose

**Default: a short birth brief plus interactive interface practice. No pre-trained thought corpus.**

The brief should state only:

- the goal and available feedback;
- the exact `ACT:` syntax;
- that ordinary text is not executed;
- that actions can be revised after feedback;
- how task completion and budget exhaustion are signaled externally.

No compiler recipe. No mandatory reflection vocabulary. No parent-authored reasoning targets.

Allow the child to attempt a few interface tasks, receive literal parser feedback, and explain the interface in its own words if it wishes. Those generated words may enter the first write. “Own words” is a provenance constraint, **not evidence that the substantive idea originated independently**.

**Preparation test:** Compare brief-only, brief-plus-own-words practice/consolidation, and interface-only examples on matched initial tasks. This is a disposable pretest, not three ongoing lineages.

**Measure / reversal:** Across the first 200 problems, record valid-action rate, nudge rate, time/tokens to first valid action, completion recognition, task success, and repeated-invalid-action loops. Choose the least preparation reaching provisional **≥98% valid submissions and <5% nudge-dependent problems** without reduced success. Add interface examples only if simpler preparation misses that bar. If external example targets are trained, disclose that exception to “child-only targets”; alternatively mask them and train only the child’s responses.

### 3.3 The brake and rollback need correction

**Bluntly: “turns <0.5× frozen” is not a reliable collapse definition.** A competent agent can legitimately become shorter; an incompetent agent can consume all 16 turns. R4 601 produced a 0.1139 candidate while still using 16 chunks [SEQ-015].

Keep the requested ratio as a warning/brake, but pair it with valid-action rate, abandonment, and task performance. Measure generated tokens as well as turns; segmentation otherwise changes the metric.

Likewise, “below best-ever for three sleeps” without a margin will repeatedly roll back against a noisy maximum. Use a replicated development benchmark reference, a prespecified noise-aware margin, and no floor decay. Preserve the three-sleep patience rule rather than restoring a per-sleep score veto.

**Measure / reversal:** Audit false alarms against successful short trajectories and missed failures against verbose unsuccessful ones. If brevity alone reliably predicts independently measured failures, strengthen its role; if not, do not force extra thought to satisfy it. If patience allows irreversible ledger contamination or frequent catastrophic failures, shorten the observation window for those operational failures—not for ordinary score dips.

With no task end token, the API still needs fixed per-turn generation limits and the harness needs a hard per-problem budget. Set the idle nudge threshold from the frozen pilot’s action-latency distribution, then freeze it.

**Measure / reversal:** Nudge dependence and timeout frequency determine whether that threshold is usable. If nudges dominate behavior, preparation failed; increasing the timeout is not the first remedy.

## 4. Parenting with repetition: teach a discrimination, not a slogan

### 4.1 Resolve the parent architecture

The holistic-parent ruling and gym-specific rooms are compatible only if the rooms share **one child model and frontier estimate**. Two Astras are proposal and verification roles, not two independent sources of developmental truth. Identical-model agreement is not independent evidence.

A sleep brief should contain, within ten lines:

1. One concrete public observation, with episode references in metadata.
2. One provisional explanation, explicitly uncertain.
3. One conditional lesson: **when X happens, consider Y**.
4. One contrast: **when X is absent, Y may be wasteful or wrong**.
5. One question or behavioral experiment for the next session.
6. One observable success criterion.

It should **not** contain a universal recipe, required wording to rehearse, a catalog of virtues, unsupported praise, an answer to a hidden test, or instructions to manufacture long reflections. The `REHEARSAL_TAIL` is instruction content; it counts toward the brief budget, not as a loophole around it [Astra room smoke notebook].

**Measure / reversal:** Compare lesson-linked action changes on trigger/no-trigger tasks and performance after the brief is removed. If a brief increases lexical overlap without improving discrimination, rewrite or withdraw the lesson. Increased overlap alone is neither learning nor proof of failure; SEQ-003 establishes echo, not its functional consequence.

### 4.2 Detecting performed reflection

Do not grade the private reflection rows or comment back on them. That would violate the specified private-phase contract. Evaluate their **downstream consequences**.

At saved checkpoints, use matched, parent-free diagnostic branches with equal total budgets:

- ordinary reflection opportunity;
- the same budget available for further acting;
- a changed-feedback situation in which the old lesson must be revised.

Look for revision following contradictory feedback, calibration improvement, fewer repeated failed actions, and correct withholding of a lesson when its trigger is absent. Judge public actions using environment logs, not self-reported outcome echoes—the old efficiency instrument was confounded by disappearing `[OUTCOME]` markers [SEQ-011].

**Measure / reversal:** Reflection earns its budget if it improves these subsequent decisions or success per total token/action budget. If it only increases note length or familiar phrases, I would stop prescribing reflection and instead teach the missing feedback-to-action discrimination. A null inference-time reflection test does not, by itself, establish that reflection rows are useless for later consolidation.

### 4.3 Repeat/new cadence

Start with **two-thirds varied practice of the current lesson, one-third new or contrastive situations**, interleaved rather than blocked. Repeat the underlying decision, not identical sentences. Include cases where applying it is wrong.

Fade the parental cue after two parent-free blocks show reliable triggered use and restraint—for example, **≥80% correct use and ≤10% false application**—then retain spaced checks at later sleeps.

**Measure / reversal:** Track trigger sensitivity, false application, cue-free retention, and performance on changed surface forms. Persistent errors justify more contrastive practice; good retention justifies advancement. If extra repetitions increase slogan similarity while false application remains high, more repetition is the wrong intervention.

The central parent should inspect disagreement, frontier estimates, and these public transfer checks—not continuously generate more teaching text. It advises asynchronously and never holds the writer.

**Measure / reversal:** Log contradictory briefs, stale advice, review latency, and downstream lesson interference. Add central review effort only if it measurably reduces those failures; token expenditure is not a parenting outcome.

## 5. What I would cut, and what is worth a paper

### 5.1 Smallest defensible paper

**Primary question:**

> When self-generated experience is consolidated into an adapter, does it produce benefits beyond keeping the agent’s own written memory—and does preserving context reduce ritualized behavior?

There are two possible deliverables:

- **Minimum paper-worthy empirical result:** Complete the life-level text-memory comparison, fixed-recipe controls, and mid/final degradation analysis. The contribution is a controlled negative result and a demonstrated evaluation confound: apparent experiential improvement can be reproduced by explicit recipe memory.
- **Stronger mechanism result:** Add the matched contextual-writer experiment showing improved conditional transfer, or showing that contextualization fails to rescue it.

Paper-worthiness is not an acceptance guarantee. Sixteen heterogeneous lives are not sixteen replications of one protocol; report strata. Sixteen clones of the new child are **one lineage**, not sixteen independent experimental units.

**Measure / reversal:** The minimum result needs completed paired controls, uncertainty, provenance, and behavior-level confirmation of the recipe explanation. If text-memory matching does not replicate, pivot to explaining the heterogeneous cases rather than averaging them away. If the writer effect fails replication across another ledger or seed, call it a pilot.

### 5.2 Keep the mandated lineage, but narrow its claim

Run one target-blind lineage with **two already-functional classrooms**, starting with tractable persistence and then conditional rule learning. Do not install three new worlds to make the curriculum look broad.

Final CompilerGym evaluation must use genuinely untouched programs/families where possible. The existing panels are development evidence now. Exclude all compiler-derived corpora, adapter weights, lessons, and recipe-containing briefs from this lineage; the parent prompt also needs this exclusion. Existing compiler knowledge in the team makes auditability essential.

Compare:

- frozen, same harness;
- frozen plus the lineage’s target-blind final brief;
- trained adapter under matched text conditions;
- fixed compiler references, including the already measured recipe and `-Oz`.

Use equal interaction budgets and record initial performance, learning-curve area, and improvement with target experience. Give each baseline its own permitted evolving text memory rather than sharing another agent’s target experience. Any target-time writing protocol must be specified before opening the test.

**Measure / reversal:** A steeper held-out adaptation curve beyond frozen-plus-memory and fixed recipes supports a lineage-specific transfer result. A higher first score followed by the same routine does not establish learning-to-learn. One lineage cannot establish that parenting generally causes better learning.
