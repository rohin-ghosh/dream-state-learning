## Bounded question

Can a child make publicly supported action records, fit those exact child bytes,
reload the candidate, and then form subsequent experience/material using the
changed adapter across two SLEEPs? Compare mounting versus withholding the same
first candidate. This isolates publication in a small developmental mechanism
diagnostic; it does not isolate parenting, certify a birth, or establish H1/H2.
An unchanged output, formation failure or finite weak learning is an outcome,
not grounds to replace the root or add an unregistered efficacy stop.

The first slice is deliberately **PROMOTE/SHADOW only**, with three maximum
fits. The proposed MISBOUND helper remains available for a separately logged
follow-up, not a third live arm here. This is smaller than the watcher's suggested
five-fit comparison and does not complete that proposal. Watcher confirmation
and release ladders are advisory, not added prerequisites for this diagnostic.

  Generated truth remains private to the environment/evaluator. No compiler
  programs, RuleGame examples, previous learner, perception/reflection adapter,
  or final deployment-gym material enters this root.
- Each action commits raw child bytes before the ordinary SUCCESS/FAILURE
  feedback. The child then receives a fixed process-only recording instruction.
  Under the explicit public two-action law it may name the other action after
  failure; the compiler checks support but never invents or repairs its target.
- Preserve exact raw action/record bytes, source receipts, order and rejects.
  Parent/process text, hidden truth and evaluation outputs never enter sleep
  bytes. Teacher text can condition the recording call only.
- Wake action and recording calls use the current mounted adapter. Thus writes
  can reach parameters used for subsequent experience and extraction; this is
  connectivity, not evidence that learning efficiency improves. Admission is
  still externally checked, limiting claims about internalized learning policy.

## Frozen first-slice sequence

1. Baseline:16isolated action-only readouts, eight old/eight future keys.
2. Shared first wake:8action/outcome/record sequences from the frozen base.
3. One authentic first SLEEP candidate from admitted exact child records.
   PROMOTE mounts it; SHADOW retains the **same candidate bytes** but stays base.
4. Separate16item readouts for each arm, then second wakes over the same8new
   keys from each branch's own state. Actions/outcomes/records may diverge.
5. Separate second SLEEP fits from each branch's own admitted old+new union,
   each initialized from the frozen base with a fresh optimizer. PROMOTE mounts
   its new candidate; SHADOW preserves its candidate but remains at base.
6. Separate final16item readouts. Clear context, parent text, records and caches
   for reports. Report calls never feed later wakes or fitting.

Maximum128generation calls and three fits. Cumulative refitting is explicit:
no adapter averaging, warm-start mutation or persistent-optimizer claim. The
shared first fit is physically performed once; report actual/shared costs rather
than inventing independent per-arm compute. Later corpus-size differences are
part of the induced experience/material pathway, not a fixed-corpus estimand.

accuracy complete life. Record exactly which stages executed; do not call a

## Analysis, stopping and claim boundary

Report each arm's old8/new8 correct action counts before experience, after the
first SLEEP and after the second, plus legality, malformed/length outputs,
formation/admission counts, source support, runtime and token exposure. Primary
descriptive contrast is PROMOTE minus SHADOW after each write; old-key changes
provide this short-loop retention check. The baseline is shared, not replicated.
One root is an exploratory instrumented attempt, not a statistical or general
learning claim. There is no efficacy threshold, best-checkpoint selection or
automatic birth/parenting/final-C11 promotion. MISBOUND and independent roots
are later decisions informed by this complete evidence, not hidden replacements.

Abort on integrity/visibility/source drift, unsupported trained byte, wrong
adapter mount, nonfinite state, truncation, unexpected work, ownership or deadline
failure. Preserve failed roots, raw captures and candidate artifacts. No automatic
retry or changed dose. Main validates CPU and native-tokenizer receipts and logs
the exact frozen source/configuration before launch. This protocol alone is not
an executed test, an ancestry certificate or evidence that the mechanisms work.
