# PCFL native bridge: smallest next implementation steps

2026-09-13. Read-only API audit; no tests rerun, source edits, network, native
calls, launches or new framework. Main's independent 22-test runtime result is
not duplicated here. Runtime/source remain frozen for archival.

## Decision

Prioritize **production definition -> concrete excluded-root render/work
manifest -> native C0 actor with deterministic text READ -> one raw reduction**.
Zero-fit requires no learned adapter, child formation, CAL execution or writer
numerical run. Do not wait for a formal C11 implementation. Do not, however,
treat the unresolved D experiment definition or today's fixture plan as a
production construct certificate.

The current closure requires the full prepared contract before first model
generation (`2026-09-13_pcfl_v22_minimum_execution_closure_contract.md`, §§2–3).
That is a concrete sequencing constraint, not a reason to implement a general
lifetime system. Main can finish its finite static registries while connecting
the zero-fit worker. If Main instead chooses a zero-fit-only operational
release, record that explicit scope amendment; this memo does not silently
waive the closure or require a new review/ratification framework.

### A. Core: close the experiment definition first

**`bind_production_world(binding)`**, feeding existing `build_root`,
`expand_cube`, `render_task`, `render_reachout`, `WorldSession` and
`audit_construct`:

- Main supplies the isolated distractor frontier, port semantics, literal
  D0/D1 public result bytes, receipt fields/IDs and terminal/post-commit
  transition; also the exact relevant probe public-result bytes. Resolve
  affected inventory slots and typed public/private visibility once.
- The current fixture's Z/Y/q construction is not the missing authority. Do
  not invent new endpoints here. D must visibly distinguish its two outcomes
  while changing neither pre-outcome information nor relevant routes/rows.
- Complete the existing finite construct checks: 32 worlds, 64 delayed tasks,
  192 route/cut decisions; actual four-cell outcome/collision tables and
  registered projection/shortcut coverage. Current audit reports fixture
  route algebra, not completed D certification (`core:972–1037`).

This is **essential experiment definition**, as extracted in
`research_notes/analysis/2026-09-13_pcfl_distractor_and_opaque_id_production_bindings.md`,
§§2–4. It is not formal C11 or a request for another model-consensus gate.

### B. Core -> preparer: build actual caller registries

**`materialize_pcfl_bindings(world_binding, tokenizer, environment, resource_binding)`**
should return the current preparer's `bindings` and measurement receipt,
using its existing validation rather than a competing contract:

- Exact required binding keys: `source_pins`, `implementation_pins`,
  `environment`, `root_registry`, `slot_registry`, `counterpart_registry`,
  `replay_registry`, `batch_registry`, `core_registry`, `diagnostic_registry`,
  `intervention_registry`, `locality_registry`, `work_registry`,
  `profile_registry` (`prepare:81`). Supply `core.registries()` as detached
  **data**, retaining `core_api`/`prepare_api` as separate loaded modules.
- Seven roots carry `{id,role,seed,old_bit,canonical_r,primary_reachout,wire,
  topology,cube}`. `wire=core.to_data(root)` uses the real qualified inventory.
  Corpus slots carry `{id,source,row_type,phase,support,bank,taint,request}`;
  banks bind chronological handles and fields, not convenient ideal edge order.
- Use public `prepare.root_skeleton_digest(bindings)` before replay selection.
  Existing `_select_replay` computes the finite selection and
  `_replays_and_batches` validates supplied replay/epoch arrays; there is **no
  public joint schedule materializer**. Add one small deterministic caller
  routine returning the first valid paired 5×40×4 assignment and counterpart
  evidence. Do not reuse the tests' invented banks/schedules as science.
- Tokenizer caller data: actual local revision/files/chat-template hash,
  qualified opaque-ID substitutions, byte offsets, token IDs, response/EOS
  masks and categories covering all required inventory/views. Existing
  `build_root(inventory=...)` accepts the completed inventory; core candidate
  generation is not tokenizer qualification. No PAD/equal-token reserve.
- Finish all decisions first; receipt `decisions_hash=prepare.digest(bindings)`;
  then `build_execution_contract`, canonical bytes and contract digest.
  Later child spans substitute into these named slots; they do not choose
  banks, replay, batches, parsers or wrappers. A mismatched formation stops.

### C. Preparer -> runtime: expand the native zero-fit manifest

**`expand_native_zero_fit(contract, tokenizer)`** must bind:

- All 640 delayed + 160 reachout task IDs (four excluded roots), exact
  production public messages/render hashes, balanced surfaces, common seeds,
  sampler settings, C0 mount, wrong-root counterpart and scorer panel.
  The existing scripted plan's `runtime-test/` seeds and appended service
  instruction are test choices, not automatically production-approved bytes.
- Each of 800 tasks joins its sealed work rows; predeclare up to 13 actor
  continuations and 12 deterministic lookup slots for each of the 96 service
  tasks. Thus zero-fit has **800–1,952 actor generations, up to 1,152 text
  lookups, zero memory-model calls and zero fits**. Unused slots remain unused,
  not retried or replaced. Private labels/oracles never enter requests.
- Bind dynamic public-history joins to literal templates, input token maxima,
  the cumulative 2,048 actor / 4,096 returned-token / 12-read per-task limits,
  cold loads, device UUID/product and lease deadline. Current work rows have
  hashes/caps, but no complete executable public request/continuation mapping.
- Keep the 64-item C0 NATIVE_CONTEXT result panel reusable for later paired
  retention. Preserve every denominator and failed/missing item. Registered
  shortcut certification remains separate from simply passing 800 tasks.

**`validate_prepared_execution(contract, profile_receipts, local_bindings)`**
is a bounded completion of existing validation, not a new evidence system.
Check loaded source/contract hashes and rendered/tokenized coverage once;
read the declared maximum-shape profile captures, match shape/UUID/product/
accounting to work rows, and perform the prescribed summed-device-time bound.
Profile receipts already have an API: `{id,kind,contract_sha256,path,shape,
gpu_uuid,product,device_seconds,accounting,evidence_sha256}`. They are supplied
after contract sealing without changing its decisions. Full closure requires
the four declared profile classes; do not replace them with a natural early
EOS timing or parallel wall time. No additional attestation service is needed.

### D. Runtime: one thin native worker/controller

**`NativeZeroFitBackend.generate(request, limits)`**, `count_tokens(text)` and
`close()`, plus **`run_native_zero_fit(contract_path, expected_hash, profiles,
run_root, deadline)`**:

- Reuse the genuine mechanics in `gpu/astra_l2_public_record_dev.py:576`
  (`Native`: qualified tokenizer render, vLLM raw/token receipt, optional LoRA
  request) and `:703` (`run_stage`: owned process, deadline, cleanup/vacancy).
  They are **patterns, not drop-in APIs**: L2 has its own plan/probe schema,
  ENGINE/PARAMS, 32-token response validation and filesystem stage semantics.
  PCFL zero-fit mounts C0 only; deterministic `core.read_query` needs no LoRA
  worker. Never import L2 experiment constants or use its validator unchanged.
- Keep raw capture richer than today's scripted five-field response: actual
  rendered prompt/input IDs, output text/bytes/IDs, finish reason, decoding
  parameters, model route, timestamps and owned process/device identity.
  Return the existing runtime summary fields from that capture, retaining a
  hash/path to the original; validate counts against actual token lists.
- Reuse `_task`'s bounded loop and real scorers after connecting sealed public
  requests. Add actual per-work input/time checks and controller interruption;
  the current post-return clock check cannot interrupt a hung native call.
  Count cold-load/service/generation/release device time without double count.
- Persist a fresh run's request/response/task records and terminal release;
  reduce them **once** with the same public core APIs, with no extra model
  generation. `close()` alone is not the outer owned-process/vacancy check.
  No parent/child calls or success rows are to be synthesized for this bridge.

## 3. Runtime -> writer: later, not prerequisite execution for zero-fit

After successful ceilings, **`capture_disposable_formation(...)`** supplies
the 20 native opportunity captures to existing `audit_formation(contract,
bundle)` (`runtime:115`). It must retain actual public prompt/history and
receipt joins. That API returns original payloads, exact span bindings, core
rows/queries and a frozen-bank check; it does not create a native writer call.

**`bind_writer_sources(formation_audit, original_captures)`** supplies the
writer's exact existing API:

```text
build_fit(contract, corpus_id, queries, rows, generations, controls, binding)
validate_fit(fit)
encode_fit(fit, tokenizer)
train_fit(fit, tokenizer, base_factory, out)
```

`generations` must be `{raw,sha256,origin:'CHILD_NATIVE',capture_sha256}` and
contain only actually used generation payloads—not all eight action calls.
Bind each row's full-generation hash and byte offsets using runtime
`span_bindings`; core admission offsets describe its supplied row substring.
Do not change row bytes or transform fixture/control ancestry into authentic.
For CAL AUTH `controls=[]`. Supply binding keys `contract_sha256`,
`authority_sha256`, `custody_sha256`, `objective`, `layout`, `learning_rate`,
`phase`, `selection_receipt_sha256`, `init_seed`, `dropout_seed`,
`base_state_sha256`, `writer_sha256`, `shared_trainer_sha256`.
Main binds pooled-response-token mean / four-unpadded-forward layout once;
fresh factory returns `(model, exact_environment_dict)` matching official C0.

**Concrete writer bug-to-bridge:** `_require_execution_contract(contract)`
(`writer:317`) calls preparer validation **without `profile_receipts`**;
`train_fit` has no way to supply them. Even after the hardcoded missing list
is replaced, real externally supplied profiles would be absent on this path.
Minimal fix: explicit profile-receipt passthrough into that validation call
(or exact loading from already-declared paths), not a fake green Boolean or
profiles added to and thereby changing the sealed contract.

Then implement **`run_calibration_readout`** and feed exact integrity/safety/
acquisition Booleans into existing `prepare.calibration_transition`. LOW
`3e-5` first; HIGH only after valid, safe acquisition failure; no HIGH after
custody, truncation, locality, canary or retention failure. Fits remain final
200 updates with 1,800s cap and separate 3,600s CAL readout allowance. No DEV
fit dispatch before this sequence. These functions do not yet exist here.

## 4. Finite evidence boundary; what not to add

Main's ordinary native captures, local source/model/tokenizer bindings,
request/adapter joins and owned-process release can satisfy the relevant
checks. Verify those concrete records and stop asking once matched. A hash
with no underlying record or a scripted Boolean is insufficient; that does
**not** mean every real capture needs a second hardware-authentication proof.
The writer's always-false custody/report flags describe its current limited
API scope, not an impossibility of Main verifying the capture chain.

No final C11 guard, generalized life engine, extra teacher control, matched
parent-removal study or amortization test is required to execute this bounded
zero-fit slice. Existing source separation, fixed rosters and process/lease
checks still apply. PCFL substrate success would not establish parenting,
amortization, H1/H2 or full mission completion; those scientific claims remain
separate, not additional launch gates invented by this memo.
