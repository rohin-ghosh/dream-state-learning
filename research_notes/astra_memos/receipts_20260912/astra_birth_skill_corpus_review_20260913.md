## Concrete checks

1. **Actual public classroom response grammar.** `_interface` AST-selects the
   existing `interaction_v3` action/record parser, record instruction and equality/
   null relation definition from `rulegame_parenting_diagnostic.py`; it does not
   invent a new response schema. All positive perception/judgement targets have
   exactly `try`, `observed`, `predicted`, `relation`, with integer triples,
   Boolean observations/predictions or null. Wrong observations, fabricated
   predictions, wrong types/relations, duplicate JSON keys and extra prose fail
   the existing record scorer. This is response compatibility, not identical
   native prompts or tokenization: the development wrapper deliberately omits
   native `Observed fields` and supplies raw events instead.
2. **Authored evidence joins.** Independently parsed the selected final ACT and
   outcome text with a small regex/Boolean checker, rather than deriving expected
   values through the component's parser. Across all six skill/split builds,
   all72 supported rows agree on triple, observation, prediction and relation;
   all24 judgement negatives are insufficient as declared. Proofs point to the
   selected source/event and public bytes. Outcome-triple mismatch is rejected;
   the preceding dev distractor is not used as the selected result. Opposite
   authored outcomes for one triple are independent hypothetical situations,
   not truth claims about one shared hidden world. No hidden rule was evaluated.
3. **Absent is not ambiguous.** Missing canonical pre-ACT prediction supports
   `predicted=null, relation=unavailable`; it does not prevent faithful recording.
   Duplicate/conflicting canonical predictions or `PREDICT: uncertain` make
   source admission false, not a null-belief target. Missing/mismatched outcome
   also makes admission false. A post-ACT forecast is not a prior prediction.
   These are the existing literal parser's categories, not a semantic classifier
   for arbitrary natural-language or noncanonical prediction spellings.
4. **Train/dev separation and bounded shortcuts.** Train selected triples are
   `(-4,1,7)` and `(2,-5,9)`; dev uses `(11,-8,3)` and `(-6,12,5)`, a distinct
   wrapper and preceding `(20,21,22)` distractor. All five checked overlaps are
   zero for each skill: row IDs, rendered-input hashes, non-null target strings,
   selected triples and selected raw-event bytes. Every positive triple crosses
   the full six prediction/outcome cases: observation3/3, prediction2/2/2 and
   relation2/2/2. A triple/template or constant preceding result therefore cannot
   determine the positive target fields. This is not universal shortcut freedom:
   there are only two selected triples/split and shared semantic templates/cases;
   explicit malformed-prediction or foreign-triple negatives are simple authored
   perturbations, not broad judgement evidence. Shared sources across skills are
   deliberate correlations, not independent replications.
5. **Anchor-only variants.** For every skill in both splits, exact supplied anchor
   bytes including leading spaces/trailing newline are preserved as one added
   system message. Removing that message makes the inputs identical; every other
   row field except input hash/messages is identical, including source, proof,
   target, target hash and row ID. Order seed changes ordering only. Source/case/
   proof labels are metadata, not rendered answers. This does not certify what a
   native runner will prepend or prove anchor-withdrawal persistence.
6. **Scorer does not claim unexpressible skills.** All24 judgement negatives have
   no training target; empty output, None, ABSTAIN, JSON null and arbitrary JSON
   still receive `passed=None / unsupported_native_abstention`, never successful
   refusal. Positive-only export cannot become a balanced judgement birth.
   Reflection's reusable procedure is explicitly an author-supplied parent
   message. Its exact-wording scorer is tagged `exact_authored_restatement_only`;
   even adding one trailing space fails it, demonstrating why it is not semantic
