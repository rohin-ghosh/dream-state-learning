## Alternatives and smallest useful intervention

| Alternative | What it tests / recommendation |
| --- | --- |
| Another prompt, example or few-shot demonstration | Still asks for autonomous serialization, but adds another output-informed prompt treatment; an ID-filled demonstration risks content scaffolding. Not the preferred next step after explicit LF disclosure failed identically. |
| **Single-line LF envelope during generation** | Preferred bounded intervention if the installed backend supports it correctly. Allowed decoded response language is a nonempty sequence excluding CR/LF, followed by exactly one LF: conceptual full-match regex `[^\r\n]+\n`. Termination is allowed only after that LF, with no subsequent visible text. Apply only to EVENT/LINK. This knows no identifiers, fields, receipts, action choices or expected outcomes. All malformed semantic contents remain possible and must fail the unchanged parser/judge. |
| Late EOS interception only after a syntactically complete line without LF | Potentially narrower distribution intervention: untouched earlier decoding, prevent termination at a lexical completion until the LF is generated. However, it needs a correctly implemented token-state hook, EOS/end-token accounting and capture validation; not demonstrably a smaller engineering patch in this actor. Do not implement by taking an already returned response and making a continuation call. |
| Full EVENT/LINK lexical grammar constraint | Preserves selection among opaque values only if it includes the whole lexical alphabet rather than allowed/current IDs or target rows. Still scaffolds considerably more than the observed newline problem, including field order/types/widths. Reserve as a separately declared alternative, not a silent fallback if the LF envelope fails. |
| Globally ignore EOS, impose minimum length or merely raise max tokens | Does not specify exactly one terminal LF and can produce spillover or length failures. Do not treat as an equivalent precise intervention. |
| Strip/append LF, tolerate missing LF in admission, fix fields, select the expected line from candidates | Not permitted in this diagnostic: repairs returned bytes, changes admission, or supplies semantic content. A descriptive semantic-only score of failed raw output may be reported separately, but cannot produce an authentic admitted bank. |

The envelope is an intervention in model decoding, not evidence that formatting was learned. Even though it supplies no semantic values, it changes the allowed distribution and can change the eventual semantic output; do not promise the old 90-byte prefix will recur. The scaffold may determine the LF while the model selects the content. Report **child semantic choices under externally constrained serialization**, not unconstrained authorship of every formatting byte. The whole returned raw response remains the actual generated span and must be stored unchanged.
