# Active-text role closure amendment v1

Date: 2026-09-11

Status: **design closure only.** This amendment authorizes no implementation,
materialization, model/tokenizer call, training, adapter operation, parenting,
GPU use, scientific claim, release, or submission.

This closes the four successor fields required by
`2026-09-11_strong_evolving_active_text_baseline_closure_review.md` at commit

## 1. Exact paired-root fork

One independent direct-system root is one **sealed parent-deleted child**
forked into the two potential-outcome branches:

```text
SEALED_CHILD -> DLT_NATIVE
             -> ACTIVE_TEXT_NATIVE
```

The order is mandatory:

1. select the child under the separately registered lineage law;
2. delete parent/nursery messages, stores, indexes, embeddings, caches,
   retrieval/query state, services, capabilities, and process state;
3. seal the remaining scientific child state: model/tokenizer/config bytes,
   inherited child adapter bytes if registered, THINK interface, and empty
   deployment-memory roots;
4. copy that sealed state twice and prove every scientific-state file digest,
   byte length, and aggregate manifest digest is identical;
5. only after the equality receipt exists, mount the branch policy.

`DLT_NATIVE` may promote post-fork SLEEP writes and uses only its registered
native episodic ledger/RECALL. `ACTIVE_TEXT_NATIVE` keeps the identical
starting model and inherited adapter active but frozen, performs no post-fork
parameter update, and evolves only its registered external-text system.
Branch labels and runtime paths live outside the sealed scientific-state
manifest. Both branches receive the same public opportunity and arm-
independent randomness tape. Every scientific root clones the same
preselected sealed-child artifact; roots are independent public-opportunity
draws conditional on that fixed child. A different-child population estimand
would require a separate preregistration, and separately selected children
can never be paired post hoc.

## 2. SESOI chronology and exact DEV selection

The CompilerGym native-baseline selection SESOI is fixed now as
`delta_AUC = 0.010` in root-level normalized lifetime-AUC units. The
equivalence interval is exactly `[-0.010,+0.010]` for
`AUC(CG-AGG)-AUC(CG-RAW)`. AUC uses the already required fixed checkpoint grid
and root-first trapezoidal integration, divided by the registered horizon.

This value and its test must be hash-sealed **before any CG-RAW/CG-AGG DEV
output is opened**. DEV may estimate paired-root variance and confirmation N;
it cannot change `delta_AUC`.

- If a two-one-sided 5% equivalence test places the effect inside the fixed
  interval, select the simpler `CG-RAW`.
- Select `CG-AGG` only if the one-sided 95% lower confidence bound for its
  root-paired AUC advantage exceeds `+0.010`.
- Every other outcome is `DEV_INCONCLUSIVE`; use `CG-RAW` as the conservative
  registered system and report the inconclusive AGG comparison.

Latency never selects the scientific system. Confirmation outputs cannot
alter this choice.

## 3. One identifier-normalization law

All active-text retrieval ranking uses **registered public-slot order**, not
first-appearance order.

For each public identifier type, the sealed public roster assigns exactly one
zero-based ordinal independent of semantic value, arm, carrier, insertion
order, result, or hidden truth. Ranking sees only
`NORM/<PUBLIC_TYPE>/<ZERO_PADDED_PUBLIC_SLOT_ORDINAL>`. Original opaque bytes
are restored after row selection for actor rendering.

A missing slot, duplicate `(type,ordinal)`, two handles mapped to one slot,
one handle mapped to two slots, or roster mutation after seal fails the store
certificate. Restart rebuilds from the same sealed roster. Registered twins
and store swaps preserve corresponding public slots; insertion order and
surface-string renaming therefore cannot change ranks or ties. All ties use
the registered public slot ordinal followed by immutable public event ordinal.
