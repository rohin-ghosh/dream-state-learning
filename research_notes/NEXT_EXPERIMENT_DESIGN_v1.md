# NEXT EXPERIMENT DESIGN v1 — "taught to learn", the smallest honest test, revised

Synthesis of the design workflow (4 designers, 3 judges, 3 critics), 2026-09-10. Starting point: the winning design (MV-1, "minimum-viable"). Grafted: the judges' suggestions that survived the critics. Resolved: every fatal and major critic attack (section 10 states each attack and what changed). Nothing here enters the ICLR 2027 characterization paper (abstract 09-18, paper 09-25); this is the first experiment of Rohin's thesis programme. Read-only synthesis: no GPU work was done and no code was changed for this document; every "verified" claim below was re-checked against the repository or the analysis JSON on the laptop.

Plain-language glossary (used throughout): a **life** = one child (Qwen2.5-7B-Instruct plus a rank-8 LoRA adapter) playing 1,024 program-optimization situations with a **sleep** (adapter retrain from the birth base on the compiled text corpus) every 32; a **cycle** = one sleep; a **situation** = one program instance with a fixed budget of 16 thinking chunks, ended only by the harness; a **state** = a segment of thinking inside a situation that the child closes with a review; a **paired probe** = the same fixed panel of programs played with the adapter ON and OFF at the same age with the same generation seeds; **L(t)** = ON minus OFF at cycle t, the life's learning gain; a **harmful pair** = ON minus OFF below −0.03; **recipe lock-in** = the adapter making the child apply one fixed pass sequence everywhere (measured: adapter-ON means repeat exactly at 0.4878 = the birth-prompt recipe); **ritual** = the frozen 09-09 detector for templated thinking; **JS shift** = how much the distribution of first actions changes between consecutive cycles (the "did behaviour change at all" gate); an **arm** = a set of lives sharing one recipe; a **lineage root** = a fresh child created because a mechanism changed.

---

## 0. One screen

- **Question.** Does a child that was *developed* before deployment — Stage 1: a structure bootstrap from a target-blind source; Stage 2: a 512-episode childhood in two persistence gyms with a critic that never gives answers — improve **faster per unit of experience** during autonomous continual learning in a gym held out **by source**, than an undeveloped child running the **identical** mechanism?
- **Primary comparison.** D (developed) vs B (regular), **K = 6 vs 6**, matched curriculum order, **co-located on the same node in pairs**, same v7 stream, same arm-neutral gate, same panels, parent absent at deployment. Readout at cycle 16 (deployment episode 512) on report panel v2, each arm against its own frozen reference (adapter OFF). Verdict rule F1 (section 7): L_D − L_B ≥ +0.02 in ≥ 5 of 6 pairs (false-positive rate 0.011 under the *measured* between-life SD of 0.027; the null is uninformative below a true effect of about +0.04 — said plainly in every write-up).
- **Baselines inside every life.** Adapter-OFF paired probe (the regular frozen agent); the 2×2 probe cells (adapter ON/OFF × text memory present/absent) at four ages, so weights effect, text effect and their interaction are read per life; the 8-program legacy panel at three checkpoints for continuity only.
- **Baseline arms.** A (same runner, v6 stream with DONE — the mechanism control, K = 2 in wave 1); E (text-memory agent living the whole life with no adapter, brief refreshed every wake — the ruled "always a baseline agent", K = 2); C (bootstrap only) and P (parenting only) complete Rohin's 2×2 {none, bootstrap, parent, both} at K = 3 each in wave 2.
- **One mechanism change (new lineage root, "v7a"):** no end token; harness-ended situations; child-ended states (`REVIEW:` closes a state, never the situation); the last review pinned into the next state and into the next situation; `RETURN: <state id>` brings an earlier state's plan and review back for revision. Everything else — writer, rank, budget, sleep cadence, RECALL — is unchanged; two organizational compile changes (child-authored review exemplars enter; model-written PRINCIPLE lines and exact-template duplicates leave the training corpus) apply to every new arm behind flags with a byte-identity test.
- **Not run.** Plasticity; conversations; clone merges and the evaluator classroom; k-branching (pilot only if a third node is granted); a contingent per-situation critic (sibling arm only if GPUs free); parenting-style or valence comparisons.
- **Budget and window.** ≈ 2,150 GPU-hours executed inside a 16-GPU lease of ≈ 4,000 GPU-hours held (two 8×A40 nodes, 09-18 evening → 09-29). Ten experiment days from Sat 09-19 (D1) to Mon 09-28 (D10); the build happens 09-11 → 09-18 in GPU-free slots. A third 8-GPU node is requested for 09-22 → 09-29; if granted it carries the replication wave (D×4 + B×4). The lease quota is a rolling 30-day window over booked hours (idle nodes count); the increase request goes in on 09-11 with the lease request.
- **Pre-registration.** PREREG v1 (arms, panels, probe cells, gate parameters, the D-admission rule, the wave-2 rule, every falsifier with cycle, metric, margin, K) is hashed and posted to the coordination log before the first launch on D2; v2 before wave 2. Thresholds move only through a new dated entry labelled post hoc.
- **What changed from the winning design (top ten).** (1) K raised from 4 to 6 on the primary and the null recomputed from the measured between-life SD; (2) matched pairs co-located on one node, critic on both nodes; (3) arm-neutral gate floor plus an entry-level admissibility band, so a schooled base cannot buy itself a looser gate or more headroom; (4) two distinct-seed reps at the decision checkpoints and the adapter's identity recorded in every probe file; (5) efficiency and backtrack instruments recomputed from the harness's action rows instead of the child's echoed outcome lines (verified defect); (6) Stage 2 dosed at 512 episodes across two gyms (LockGym first, rule game v2 with a Brier-scored quiz) with a 40-instance exam whose tolerance comes from a measured noise band, and a written "treatment delivered" rule; (7) the strongest available model (32B-AWQ) as critic, fed the child's reviews; (8) review quality measured by template-independent instruments (carry-over, calibration, counterfactual specificity), with the four-slot template conformance reported separately; (9) report panel v2 built from student-solution programs under a search-headroom rule with content-hash and shared-symbol checks, sealed by two sealers; (10) the text-memory agent's brief-refresh defect fixed and E promoted to a fixed part of the plan.
- **Sign-offs needed before D1 (section 14).** Rohin: rule game v2 and LockGym drafts; panel v2 criteria; recipe removal from the birth prompt; v7a (without k-branching) as the lineage root; PRINCIPLE lines out of the corpus (the 09-04 vs 09-07 reconciliation); the step-fade reading of repetition. Codex: provenance schema and negative tests (hard precondition of the D launch); gate form (provisional commit vs 2-rep); bootstrap writer; branch write unit (for the pilot only); co-sealing panel v2.

## 1. Hypothesis — in Rohin's words, then in operational form

**Rohin's words (IDEAS 2026-09-10, "the killer metric").** "A developed agent shows a higher rate of improvement per unit of experience than the baseline agent on task distributions the parent never showed — *did it acquire a better learning algorithm*, not *did the classroom pretrain it*." Parenting is "a curriculum of gyms that each instil a trait — persistence first — and return environmental feedback that makes the child learn on its own; the parent model is one feedback channel inside those gyms, the world's outcomes are the other, and the child's own reactions to those outcomes are what sleep writes." What we train is "state-to-state reasoning: plan, execute to a self-determined end, meta-review, and the review is remembered so it conditions the next state"; the model "should be taught recurrent chain-of-thought — reasoning that returns to and revises its own earlier reasoning". "The gym is the world; the benchmark is the protocol inside it; always have a baseline agent." Judge parenting "by what the child does afterwards in gyms it has not seen — first and second derivatives vs the baseline agent — not by how much the parent talked."

**Operational form (H1, minimal).** Let L_X(t) = ON(t) − OFF for arm X at deployment cycle t on report panel v2, where OFF is that arm's own frozen reference (clean base for A, B, E; bootstrap base B1 for C; schooled base S_i for D and P). Then, with the preconditions of section 7 holding, L_D(16) − L_B(16) ≥ +0.02 in at least 5 of 6 matched pairs, and the slope difference [L_D(16) − L_D(4)] − [L_B(16) − L_B(4)] is positive in the same pairs. This is the second derivative in its smallest measurable form: the *rate* of gain on a program family the parent never saw, entry level separated from acceleration.

**Mechanism sentence (Codex, kept as a hypothesis, never as a claim).** Bootstrap teaches the habit of making and revising rules; parenting teaches when to use that habit; lived outcomes supply the evidence; sleep makes the child's own successful use persistent.

**Alternatives killed by construction, not by argument.**

| alternative explanation | how the design kills it |
|---|---|
| the frozen model could already do it | adapter-OFF probe at every checkpoint, per arm, on the same seeds |
| the text memory explains it (review M4) | 2×2 probe cells at 256/512/768/1024 in every life; arm E lives the whole life on text only with the brief actually refreshed |
| the childhood pretrained the deployment task | Stage-1 source and Stage-2 gyms contain zero compiler content (leak-scanned for the full pass list at seal time); deployment is every arm's first contact with the gym; exposure domains are derived from the gyms actually instantiated, not declared |
| the stream change itself (v6 → v7) produced the effect | arm A (v6 stream, same birth prompt) vs arm B; the harness-only cell prices the birth-prompt change on the frozen model |
| entry-level offset masquerading as learning | OFF(0) per arm from 3 reps; the entry-level admissibility band; the claim is about L and the slope, never about OFF_D > OFF_B |
| a looser gate for the developed arm | arm-neutral floor (clean-base reference measured once with ≥ 6 reps); per-arm acceptance rate reported beside every curve |
| node or hardware differences | every D_i–B_i pair lives on one node; a node term is pre-registered and F1 is read within node |
| selection on the report panel (review F1) | gate on panel v1b, report on panel v2, legacy 8-panel reference only; overlap is a hard error |
| heavy-tailed single probes (one same-adapter pair differed by 0.065) | two distinct-seed reps at the decision checkpoints; readout = mean of four draws; adapter identity recorded; min/max reported |
| bootstrap or parent contamination (Codex STOP) | fail-closed provenance guard with negative tests, ratified by Codex before any D launch; every life carries a manifest |
| the developed arm was never actually developed | written "treatment delivered" rule executed by script from the Stage-2 logs before any deployment number is read |
| the review detector rediscovers the bootstrap's own template | template-independent review measures (carry-over, calibration, counterfactual specificity) are primary; template conformance is a separate descriptive column |
