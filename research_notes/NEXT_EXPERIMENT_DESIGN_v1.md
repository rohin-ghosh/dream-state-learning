Synthesis of the design workflow (4 designers, 3 judges, 3 critics), 2026-09-10, **folded the same day** with the inputs that landed after the workflow was grounded: `research_notes/CURRICULUM_DRAFT_v1.md` (what to teach, in what order, exit criteria), the IDEAS.md entries of 2026-09-10 ("NEXT EXPERIMENT PINS"; "Parents at agentic-architecture intelligence; a parental society; recursion as future work"; "Integrate existing parenting into a distributed harness"; "Thoughts carry the gain; scale thinking streams; teach recurrent CoT"; "Classrooms are gyms; the trait to instil is persistence"; "Parenting = gyms that teach traits and give environmental feedback"; "Scale as one child, many clones"; "Can the test gym be one of the environments? Split hygiene"), and `research_notes/related_work/tmem_positioning_2026-09-10.md`. `research_notes/NEXT_PAPER_POPULATIONS.md` is folded as **future work only**. Starting point: the winning design (MV-1, "minimum-viable"). Grafted: the judges' suggestions that survived the critics. Resolved: every fatal and major critic attack (section 10 states each attack and what changed) and every conflict between the new inputs and the winning design (section 12 states each conflict and its resolution). Nothing in the fold weakens a pre-registered falsifier or threshold; falsifiers were added (F9–F11) and preconditions were added (A0, A5). Nothing here enters the ICLR 2027 characterization paper (abstract 09-18, paper 09-25); this is the first experiment of Rohin's thesis programme. Read-only synthesis: no GPU work was done and no code was changed for this document; every "verified" claim below was re-checked against the repository or the analysis JSON on the laptop; every measured number traces to EVIDENCE_TABLES.md or the coordination log.

Plain-language glossary (used throughout): a **life** = one child (Qwen2.5-7B-Instruct plus a rank-8 LoRA adapter) playing 1,024 program-optimization situations with a **sleep** (adapter retrain from the birth base on the compiled text corpus) every 32; a **cycle** = one sleep; a **situation** = one program instance with a fixed budget of 16 thinking chunks, ended only by the harness; a **state** = a segment of thinking inside a situation that the child closes with a review; a **paired probe** = the same fixed panel of programs played with the adapter ON and OFF at the same age with the same generation seeds; **L(t)** = ON minus OFF at cycle t, the life's learning gain; a **harmful pair** = ON minus OFF below −0.03; **recipe lock-in** = the adapter making the child apply one fixed pass sequence everywhere (measured: adapter-ON means repeat exactly at 0.4878 = the birth-prompt recipe); **ritual** = the frozen 09-09 detector for templated thinking; **JS shift** = how much the distribution of first actions changes between consecutive cycles (the "did behaviour change at all" gate); an **arm** = a set of lives sharing one recipe; a **lineage root** = a fresh child created because a mechanism changed. New in the fold: a **gym** = any environment the child plays, classrooms included; a **stage** = a block of the childhood that teaches one trait in one gym shape with a pre-registered **exit criterion** (a measurable behaviour the child must show before the schedule moves on); a **clone** = one of several concurrent copies of the same child (same weights, same adapter) playing different gyms, whose experience is compiled into one write at sleep; the **parent harness** = the parent: an agent loop with read-only tools over the child's records, running on a frozen strong model whose weights never change, writing a short brief for the child and notes to a **parental ledger** shared across the children it teaches; **adaptive parenting** = the parent reads what the child did and sharpens its next brief; **fixed-curriculum parenting** = the same gyms and schedule with a brief that is written once per stage and never reads the child; the **parent-visibility gate** = the list of things the parent may read (everything else does not exist for it), with every read logged; **k streams** = several seeded thinking branches opened from one state and joined by the child into one plan; the **headroom check** = the pre-launch test that the frozen model has room to improve in a gym before anyone is taught in it.

## 0. One screen

- **Question.** Does a child that was *developed* before deployment — Stage 0: a structure bootstrap from a target-blind source; then a 512-situation childhood that follows the curriculum's schedule (persistence first, then prediction and calibration, then exploration vs exploitation) in two trait gyms, taught by a parent harness that never gives answers — improve **faster per unit of experience** during autonomous continual learning in a gym held out **by source**, than an undeveloped child running the **identical** mechanism?
- **Primary comparison (unchanged).** D (developed) vs B (regular), **K = 6 vs 6**, matched curriculum order, **co-located on the same node in pairs**, same v7 stream, same arm-neutral gate, same panels, parent absent at deployment. Readout at cycle 16 (deployment episode 512) on report panel v2, each arm against its own frozen reference (adapter OFF). Verdict rule F1 (section 7): L_D − L_B ≥ +0.02 in ≥ 5 of 6 pairs (false-positive rate 0.011 under the *measured* between-life SD of 0.027; the null is uninformative below a true effect of about +0.04 — said plainly in every write-up).
- **Four pins, now hard rules (section 3.14, section 7).** (1) **Baseline first, headroom per gym**: no life launches in a gym until the frozen model's score and room to improve in that gym are measured and posted (precondition A0); the legacy 8-panel is declared saturated on the record (exploring frozen model 0.463–0.488, -Oz 0.522, best adapters 0.5291) and is reference only. (2) **Adaptive vs fixed parenting is an explicit arm**: D (adaptive parent harness) vs DF (same gyms, same schedule, fixed per-stage briefs), F9. (3) **The parent-visibility gate**: the parent may read the child's ledger, ritual and efficiency metrics, gate decisions with reason codes, and other parents' ledgers; it may never read report-panel, probe or exam scores; evaluation gyms are parent-blind; every parent input is logged and audited (precondition A5). (4) **The compiler is finished and pre-tuned before the run**: near-duplicate collapse and recency weighting join provisional commit and the disjoint gate panel behind flags, screened offline on archived ledgers against the disjoint-panel and text-memory results before PREREG v1 is hashed (DP10).
- **The parent (section 3.11).** An agent loop over the frozen 32B-AWQ (the strongest model that fits one GPU here) with allow-listed read-only tools over the child's life directory and a shared parental ledger; its weights never change; its brief keeps the repetition critic's form (same core lesson per stage, sharpened not switched, carried by the child into its own REVIEW); absent at deployment. A human relay into the confirmatory arms is barred (a human who has seen report-panel numbers is not a blind parent).
- **One child, many clones (section 3.12).** In the childhood each child runs as two clones on one GPU — one in LockGym, one in rule game v2 — sharing one server and one adapter, merged at every sleep by the existing compile-from-birth-base write over both ledgers; every row carries its clone and gym for hygiene; **no gain-attribution-by-source analysis is planned** (thoughts carry the gain). Width 1 at deployment.
- **Thinking is scaled (section 3.13).** Recurrent chain of thought (`REVIEW:` states, pinned reviews, `RETURN:`) is in the root for every v7 arm. k = 3 seeded streams joined by the child run as arm **T** (clean base, K = 2, plus a matched-token single-stream control), judged by the measured instruments — JS shift, ritual onset, chunks- and tokens-to-best from action rows, review quality, the chained probe — never by the child's own text (F10).
- **Baselines inside every life.** Adapter-OFF paired probe (the regular frozen agent); the 2×2 probe cells (adapter ON/OFF × text memory present/absent) at four ages, so weights effect, text effect and their interaction are read per life; the 8-program legacy panel at three checkpoints for continuity only.
- **Baseline arms.** A (same runner, v6 stream with DONE — the mechanism control, K = 2 in wave 1); E (text-memory agent living the whole life with no adapter, brief refreshed every wake — the ruled "always a baseline agent" and this experiment's "baseline harness agent on the same base model", K = 2); C (bootstrap only) and P (parenting only, adaptive) complete Rohin's 2×2 {none, bootstrap, parent, both} at K = 3 each in wave 2; DF (developed, fixed-curriculum parenting, K = 2) and T (thinking scale, K = 2) are the fold's arms.
- **One mechanism change (new lineage root, "v7a"):** no end token; harness-ended situations; child-ended states (`REVIEW:` closes a state, never the situation); the last review pinned into the next state and into the next situation; `RETURN: <state id>` brings an earlier state's plan and review back for revision. Everything else — writer, rank, budget, sleep cadence, RECALL — is unchanged; the compile changes (child-authored review exemplars enter; model-written PRINCIPLE lines, exact-template duplicates and near-duplicates leave; recency weighting) apply to every new arm behind flags with a byte-identity test. Arm T is a second, labelled root ("v7b" = v7a + `BRANCH`/`JOIN`) whose only role here is the thinking-scale pilot.
- **Not run.** Plasticity; conversations; a model-based evaluator agent; a parental society across nodes (the shared ledger runs at one-parent-one-class scale, node-local, mirrored nightly); recursion (children as parents); a contingent per-situation critic (sibling arm only if GPUs free); parenting-style or valence comparisons beyond adaptive-vs-fixed; the deployment gym's training split as a parenting environment (waits for Codex's split-hygiene ratification); populations.
- **Budget and window.** ≈ 2,700 GPU-hours executed (was ≈ 2,150) inside a 16-GPU lease of ≈ 4,000 GPU-hours held (two 8×A40 nodes, 09-18 evening → 09-29). Ten experiment days from Sat 09-19 (D1) to Mon 09-28 (D10); the build happens 09-11 → 09-18 in GPU-free slots plus ≈ 12 GPU-hours of compiler screening on the surviving node of the old lease. A third 8-GPU node is requested for 09-22 → 09-29; if granted it carries the replication wave (D×3 + B×3 + DF×1). The lease quota is a rolling 30-day window over booked hours (idle nodes count); the increase request goes in on 09-11 with the lease request.
- **Pre-registration.** PREREG v1 (arms, panels, probe cells, gate parameters, the D-admission rule, the wave-2 rule, the stage schedule with exit criteria and the one-repeat rule, the parent allow-list, the compile setting chosen by the screen, the hash of the DF brief texts, every falsifier with cycle, metric, margin, K) is hashed and posted to the coordination log before the first launch on D2; v2 before wave 2. Thresholds move only through a new dated entry labelled post hoc.
- **What the fold changed (top ten).** (1) The childhood is the curriculum's schedule: Stage 1 persistence (sleeps 1–8, LockGym-dominant), Stage 2 prediction and calibration (sleeps 9–12), Stage 3 exploration vs exploitation (sleeps 13–16), each with a pre-registered exit criterion scored by script and one bounded repeat block per childhood; Stage 4 (anti-lock-in) is the unparented deployment exam; Stage 5 (recurrent-CoT metacognition) is a thread through every stage; Stages 6–7 are future work. (2) The repetition critic is delivered by a parent harness with allow-listed tools, a logged input trace and a shared parental ledger. (3) Fixed-curriculum parenting (DF) is an arm; F9 compares it with adaptive D. (4) The parent-visibility gate and its audit are a precondition (A5). (5) The headroom check per gym is a precondition (A0). (6) Near-duplicate collapse and recency weighting enter the root compiler behind flags after an offline screen (DP10) instead of waiting for the next root. (7) Two clones per child in the childhood, merged at sleep, with provenance kept as hygiene only. (8) k streams run as arm T with a matched-token control, judged by the instruments (F10); the pilot is no longer contingent on a third node. (9) E moves to the D8 tail slot (still a full life) so DF gets a full-length slot; the third-node wave is D×3 + B×3 + DF×1 (the earlier D×4 + B×4 oversubscribed a node whose GPU 0 must serve the parent). (10) TMEM is named as the closest prior work with the delta stated (section 13); populations stay future work.
- **Sign-offs needed before D1 (section 16).** Rohin: rule game v2 and LockGym drafts; panel v2 criteria; recipe removal from the birth prompt; v7a (without k-branching) as the lineage root and v7b as the pilot root; PRINCIPLE lines out of the corpus (the 09-04 vs 09-07 reconciliation); the step-fade reading of repetition; the staged schedule and exit criteria; the three DF brief texts; the parent allow-list; no human relay into the confirmatory arms. Codex: provenance schema and negative tests (hard precondition of the D launch); gate form (provisional commit vs 2-rep); bootstrap writer; branch and clone-merge write units; the near-duplicate protocol by 09-16 (else Fable's default ships, disclosed); the parent allow-list; co-sealing panel v2.

## 1. Hypothesis — in Rohin's words, then in operational form

**Rohin's words (IDEAS 2026-09-10).** "A developed agent shows a higher rate of improvement per unit of experience than the baseline agent on task distributions the parent never showed — *did it acquire a better learning algorithm*, not *did the classroom pretrain it*." Parenting is "a curriculum of gyms that each instil a trait — persistence first — and return environmental feedback that makes the child learn on its own; the parent model is one feedback channel inside those gyms, the world's outcomes are the other, and the child's own reactions to those outcomes are what sleep writes." What we train is "state-to-state reasoning: plan, execute to a self-determined end, meta-review, and the review is remembered so it conditions the next state"; the model "should be taught recurrent chain-of-thought — reasoning that returns to and revises its own earlier reasoning". "The gym is the world; the benchmark is the protocol inside it; always have a baseline agent." Judge parenting "by what the child does afterwards in gyms it has not seen — first and second derivatives vs the baseline agent — not by how much the parent talked." On scale: "the thoughts carry the gain" — do not spend effort attributing a merged gain to the clone that lived it; "parents must be as smart as Fable/Codex in the agentic sense", with weights that never change; "we are not inventing parenting; we are integrating what strong harness agents already do into a distributed parenting harness, and then augmenting what is taught."

**Operational form (H1, minimal, unchanged).** Let L_X(t) = ON(t) − OFF for arm X at deployment cycle t on report panel v2, where OFF is that arm's own frozen reference (clean base for A, B, E, T; bootstrap base B1 for C; schooled base S_i for D and P, S''_i for DF). Then, with the preconditions of section 7 holding, L_D(16) − L_B(16) ≥ +0.02 in at least 5 of 6 matched pairs, and the slope difference [L_D(16) − L_D(4)] − [L_B(16) − L_B(4)] is positive in the same pairs. This is the second derivative in its smallest measurable form: the *rate* of gain on a program family the parent never saw, entry level separated from acceleration.

**Two secondary questions the fold adds (never load-bearing for H1).** H2: the adaptive parent's reading of the child buys something a fixed curriculum does not (F9, D vs DF). H3: more parallel thinking per situation changes behaviour between cycles and delays ritual, at equal tokens (F10, T vs B and T vs its matched-token control).

**Mechanism sentence (Codex, kept as a hypothesis, never as a claim).** Bootstrap teaches the habit of making and revising rules; parenting teaches when to use that habit; lived outcomes supply the evidence; sleep makes the child's own successful use persistent.

**Alternatives killed by construction, not by argument.**

| alternative explanation | how the design kills it |
|---|---|
| the frozen model could already do it | adapter-OFF probe at every checkpoint, per arm, on the same seeds |
| the text memory explains it (review M4) | 2×2 probe cells at 256/512/768/1024 in every life; arm E lives the whole life on text only with the brief actually refreshed |
| the childhood pretrained the deployment task | Stage-0 source and the childhood gyms contain zero compiler content (leak-scanned for the full pass list at seal time); deployment is every arm's first contact with the gym; exposure domains are derived from the gyms actually instantiated, not declared |
| the stream change itself (v6 → v7) produced the effect | arm A (v6 stream, same birth prompt) vs arm B; the harness-only cell prices the birth-prompt change on the frozen model |
| entry-level offset masquerading as learning | OFF(0) per arm from 3 reps; the entry-level admissibility band; the claim is about L and the slope, never about OFF_D > OFF_B |
| a looser gate for the developed arm | arm-neutral floor (clean-base reference measured once with ≥ 6 reps); per-arm acceptance rate reported beside every curve |
| node or hardware differences | every D_i–B_i pair lives on one node; a node term is pre-registered and F1 is read within node |
| selection on the report panel (review F1) | gate on panel v1b, report on panel v2, legacy 8-panel reference only; overlap is a hard error |
| heavy-tailed single probes (one same-adapter pair differed by 0.065) | two distinct-seed reps at the decision checkpoints; readout = mean of four draws; adapter identity recorded; min/max reported |

| **the parent's talk, not the gyms, made the difference** (pin 2) | DF: same gyms, same schedule, same exit rule, fixed briefs; F9 reads D − DF |
| **the gym had no room** (pin 1) | headroom check per gym before launch (A0); panel v2's search-headroom rule; the saturated 8-panel is reference only |
| **the clone merge, not the child's thinking, carried it** | no attribution analysis by construction; provenance is hygiene; the merged write is the same compile-from-birth-base write every arm uses |

## 2. Measured state this design inherits, and what this synthesis verified

Cell counts from EVIDENCE_TABLES.md (with addenda) and the coordination log entries SEQ-001..008; every number names its unit.

- **Recipe lock-in.** Adapter-ON plateaus 0.4878 (= the birth recipe applied once) and 0.5291 (a six-pass routine) on the legacy 8-panel; -Oz 0.522, -O3 0.341; exploring frozen model 0.463–0.488; OFF on life probes 0.471–0.474. On disjoint panel v1 the birth recipe scores 0.2495; R2 seed2's final and mid-life adapters scored 0.2496/0.2495 there (identical reps); frozen model 0.257/0.254; -Oz 0.2745. The recipe-locked write reproduces the birth recipe on programs it never saw, and that recipe is worse than exploration there. Consequence kept from the winning design: the birth prompt of every new arm carries no recipe. Pre-registered prediction for the pending re-probe: every 0.4878-plateau adapter scores 0.2495 ± 0.003 on v1.
- **Headroom, stated as pin 1 asks.** On the 8-panel the exploring frozen model (0.463–0.488) sits 0.034–0.059 below -Oz (0.522) and the best adapters (0.5291) edge -Oz by 0.007: little room, and what room there is belongs to one recipe. On disjoint panel v1 the frozen model scores 0.257/0.254 while -Oz ranges 0.03–0.71 per program: room exists and is program-dependent, which is what situation-dependent choice needs to register. So the claim panel is v2 (built under the search-headroom rule), the 8-panel is reference only, and every trait gym gets the same check before anyone is taught in it (A0).
- **Efficiency and markers (SEQ-005).** Chunks-to-best doubles early → late (3–4 → 6–9) in every arm; contrast phrases and backtracks → ~0; first-action JS shift between cycles 0.02–0.13; taught vs untaught do not separate. **Caveat verified in this synthesis:** these numbers came from an instrument that reads `[OUTCOME]` lines out of the child's own text, so a window in which the child stops echoing outcomes has no chunks-to-best at all (27 of 32 windows undefined in R2 seed6; 12/32 in R3 500; 13/32 in R2 seed4). The doubling is confounded with the child ceasing to echo. All efficiency baselines are re-derived from the harness's action rows before pre-registration (section 3.10).
- **Late chunk saturation (Design 2's reading, verified).** Late-life chunks per situation sit at 15.4–16.0 in R2 seeds 0/1/2/4/7/8, R3 503, R4 604–606 and RP 402: late situations already end by budget, not by DONE. Removing DONE changes early life and the probes most; the late pathology is filling the budget without revising — which is what review states and RETURN target.
- **Harm at the life level.** Ungated R2: 4/9 lives with ≥ 1 harmful pair, 3/9 with ≥ 2; RP 1/3; gated R3 0/6 but post-selection (gate and report panel were the same eight programs); late-life candidates in R3 500 collapsed to 0.19–0.34 and the gate refused all six. Behavioural gate catches with passing scores: R3 500@64, 501@704, 505@288.
- **Noise (from disk, verified here).** SD of the adapter-OFF probe mean 0.0092/0.0087; same-adapter same-seed replicate SD 0.0065 (n = 70) with one 0.065 outlier; disjoint-v1 replicate SD 0.006–0.007. **Between-life SD of the design's own cycle-16 estimator** (mean of the paired ON−OFF at episodes 448 and 512): **0.027 across the four full gated R3 lives** (+0.051, +0.016, +0.066, +0.011), 0.072 across all nine R2 lives, 0.014 across the six R2 lives that did not collapse; SD of R2 life means 0.033 (early life 0.014). The gated figure, 0.027, is the ruler this design uses for the D-vs-B null.
- **Echo, ritual, parenting.** First-note overlap with the brief 0.454 after a brief vs 0.322 pre-brief vs 0.354 unbriefed controls; "rehearsal 0.50–1.00" withdrawn. Ritual onset 160–224 in 8/9 unparented lives; parented 288/192(+remission)/256, returns and persists under repeated briefs; a context-only lesson lasts ~2 sleeps. The 14B pattern parent's utterances are generic scientific-method advice (IDEAS 09-07). The classroom parent's admission signal was test-adjacent (pin 3's "do not repeat").
- **Where the data already speaks to the curriculum (CURRICULUM_DRAFT_v1).** Stage 1 (persistence) is the measured failure: late-life collapse to 1–2 chunks per program in 4/9 ungated lives and the brevity-gate catches — persistence is the first trait for a reason. Stage 4 (anti-lock-in) is the measured ceiling: 0.4878 = the birth recipe, no per-program choice; the disjoint panel is its exam. Stage 5's fail case is already observed: echo rose while efficiency fell (SEQ-003, SEQ-005) — performing reflection rather than using it. Stage 0 is what the bootstrap corpora attempt; they are unverified in provenance and unmeasured.
- **Bootstraps.** v1/v2 task-exposed (quarantined); v3 target-blind but DEV_UNVERIFIED_PROVENANCE under Codex's STOP; no canonical clean child exists. **Codex's STOP stands:** no bootstrapped child launches before the guard is ratified (section 3.5).
- **Code facts verified in this synthesis that the design must fix.** (a) A bootstrap adapter seeded into the first sleep directory is replaced at the first sleep because every sleep retrains a fresh LoRA from the base model — a bootstrap that is meant to persist must be merged into the birth base. (b) An adapter-free life never sees its waking briefs after the first wake (the refresh sits inside the adapter-arm block), so today's "arm A" is a frozen model with RECALL, not a text-memory agent. (c) Every probe uses one generation seed (777) at every checkpoint, so two probes of an unchanged adapter are the same draw. (d) The gate floor uses the arm's own base, measured once with a single 2-rep draw. (e) The format canary runs four compiler programs against every candidate, so a rule-game life on the shared runner would touch the deployment gym before deployment. (f) The masked bootstrap trainer left-truncates the stored context to about 1,600–1,750 tokens, cutting the head that would carry a pinned review. (g) The classroom commit rule computes a PREV exam but does not use it. (h) The chunk seed has no branch term, so k seeded branches from one context would be identical text. (i) Rule game QUIZ is repeatable with best-of scoring (a brute-force loophole), and the rule-game birth prompt still says "Write DONE when finished". (j) The one-child-many-classrooms merge exists only in the rule-game classroom rounds (pooled corpus with provenance → one write); the gym lives are independent students — the clone coordinator (section 3.12) generalizes the classroom merge, it does not invent a new write.

### 3.1 The v7a stream (one mechanism change; new lineage root)

Built as `organism_v6/run_life_v3.py` with `batch_loop`/`state`/`sleep_compile` edits behind a `--stream {v6,v7}` flag; arm A runs the same code with the v6 stream.

- **No end token.** `DONE` is removed from the marker regexes and the birth prompt. A situation (one program instance) ends only when the harness ends it at the 16-chunk budget. The CLOCK stays as information. Tokens after the last action are logged as `chunks_after_last_act` and are part of the persistence readout ("continued changing attempts" vs "idle repetition").
- **Child-ended states.** A state opens at the start of a situation and after each `REVIEW: <text>`. `REVIEW:` closes the current state and opens a new one **on the same program**; it never advances the situation (the harness budget does). The review text is stored as `kind="review"` with `state_id`, `forced=false`. If the child has written no review by chunk 15, the harness injects `[REVIEW] close this state: write your review now` and stores the next chunk as `forced=true`; forced reviews never count toward review-quality falsifiers. Collapse flags: `REVIEW:` within the first 3 chunks; ≥ 4 reviews per situation; consecutive-review Jaccard ≥ 0.5 (`templated_reviews`, reported separately, never folded into the frozen ritual definition).
- **Review pin.** The head of every state shows `LAST REVIEW (state k)`; the head of every situation shows the previous situation's last review in the same slot-stream (`LAST REVIEW (previous program)`). The last two reviews are pinned (≤ 600 characters each). One definition of "review" is used by the pin, the compile and the detectors: the `REVIEW:` text of a state (or the last NOTE after the final committed action in the v6 arm). A rehearsal-only state pins and compiles nothing as a review.
- **Recurrent chain of thought.** `RETURN: <state id>` pulls that state's plan (its first NOTE) and its review verbatim into the recalled block for revision. Counters: states per situation, reviews per situation, RETURNs per situation, "first action changed after a RETURN". This is the recurrence lever in every v7 arm; k streams (section 3.13) are the additional lever tested in arm T only.
- **Birth prompt (all new arms, A included).** No concrete recipe: the example action line and the INVALID hint's four pass names are replaced by a neutral one-line pointer to the 124 valid pass names, kept out of the head (a RECALL-able ledger row) so the context budget is unchanged. One sentence: "each situation has a fixed number of chunks (CLOCK); close each stretch of work with REVIEW: — it is the first thing you will see next." Consequence: new-arm 8-panel numbers are not comparable to R2–R5 and are used as reference only.
- **Probes under v7a.** The primary probe runs 12 programs as 12 one-state situations (comparable ON vs OFF). A **chained probe** (3 slot-streams × 4 sequential programs with the pins active, seeded, same budget) runs at the decision checkpoints only, so a gain that lives in the review channel can register; single-state is pre-registered as primary for F1, chained is secondary. Every arm, T included, is probed single-stream at the standard budget, so scores stay comparable across arms.
- **Deliberately unchanged.** Wake budget 16 chunks × 400 tokens (the measured late-life v6 chunk count already saturates at 16, so more chunks per situation is a separate dose arm with its own probe budget: the matched-token control of section 3.13 is the only longer-budget life here, and it is a control, not a claim arm); wake batch 8; sleep every 32; probe every 64; temperature 0.7; v1 bare-text writer (lr 1e-4, 3 epochs, max length 512) with `--seed` and model/revision/seed in `train_meta.json`; rank 8 from birth; RECALL keyword retrieval; the waking brief.

### 3.2 Compile changes (organizational; constant across arms; flagged; finished before the run — pin 4)

- For every state with ≥ 1 valid outcome, one review exemplar enters the corpus: `Program {eid}, state {k}. After {n} actions (best {best}), my review: {review}` — child-authored text grounded by a committed action (Codex's rule for what may enter SLEEP). The parent's brief and the parental ledger never enter the corpus (the thinker/compiler line).
- PRINCIPLE lines (model-written, unlived) no longer enter the training corpus; the waking brief is still written and shown (context only). This is the 09-07 "compiler organizational, never smart" ruling applied; it needs Rohin's one-line reconciliation with the 09-04 "compiling is a model's job" ruling (section 16) and defaults to *drop*.
- Exact-template collapse: rows whose whitespace-normalized first 160 characters match are kept at most `cap = 3` times (count-capped), for all new arms.
- **Near-duplicate collapse (pin 4; was "next root").** Rows whose normalized token sets overlap at Jaccard ≥ 0.8 with an already-kept row count against the same cap. If Codex's proposition/scope/polarity protocol lands by 09-16 it replaces this rule; otherwise this is Fable's default and every table says "near-duplicate rule: Fable default, unratified".
- **Recency weighting (pin 4; new).** Replayed rows from sleeps older than the last four are down-weighted in the training mix by a factor chosen by the screen from {1.0 (off), 0.5, 0.25}; the diagnosis behind it is the amplifier reading (the cumulative corpus is dominated by old habit rows and their replay).
- **The offline screen (item 17, DP10)** fixes which of {exact cap only; + near-duplicate; + recency; + both} ships, before the hash; the shipped setting is one setting for every new arm. Logged per sleep: rows collapsed (exact and near), modal-row share before and after, review rows, principle rows suppressed, recency weights applied.
- Test: with all v7 flags off, `compile_sleep_v7` reproduces the v6 corpus bytes on an archived R2 ledger; `run_life_v3 --stream v6` reproduces `run_life_v2`'s renders on a replayed ledger.

### 3.3 Gate hygiene (every gated arm; not a difference between arms)

- Gate on **panel v1b**; base measured once at birth (2 reps); **arm-neutral floor** = max(clean-base reference on v1b measured once with ≥ 6 reps on the utility GPU and shared by all arms, the arm's own base, best *confirmed* committed gate probe). No floor decay.
- **Commit form.** Default: provisional commit — the candidate mounts as PROVISIONAL after passing the canaries and scoring ≥ floor − 0.02; at the next sleep the same adapter is probed first on the gate panel and CONFIRMED (≥ floor − 0.02) or REJECTED_UNCONFIRMED (revert to the last confirmed adapter; wake rows generated under it remain experience). Adopted only if Codex ratifies by 09-17; otherwise the 2-rep gate (seeds 4242/5242, both ≥ floor − 0.02) is used and disclosed.
- **Behaviour canaries under no-DONE** (chunk count is constant, so "chunks per episode" is dead): actions per situation ≥ max(2, 0.5 × base median) AND ≥ 1 valid outcome per situation; distinct action strings per situation ≥ 0.5 × base; paired parseable-ACT rate ≥ base − 0.10 on the same gate probe. Calibrated on the D2 dry run so the gate does not penalize a candidate that spends half its chunks planning and reviewing.
- **Childhood gate** (trait gyms): exam = 40 held-out-family rule-game instances + 24 held-out LockGym codes; tolerance = 1 SD of the gym's measured frozen-model noise band (8 seeded reps, D1); floor = max(B1 on the exam, best confirmed); the collapse canary ON vs PREV on 8 held-out instances (HARM_TOL 0.10); the same acts canary. The exam's *score* is never shown to the parent; the gate log the parent may read carries the decision and the reason code only (pin 3).
- Rejections logged by reason (SCORE, UNCONFIRMED, ACTS, DISTINCT, FORMAT, PREV); a life that rejects its late writes stays on its last confirmed adapter — safe and informative.

### 3.4 Birth bases by merge (the bootstrap must live in the base)

### 3.7 Stage 0 — target-blind structure bootstrap (corpus v4, fresh source; the curriculum's "Birth")

- **Source:** 6 frozen-model lives (no adapter, no critic, no brief, no write) of 256 situations in rule game v1 (the ten atomic rules), run under the v7a runner with a **v7 rule-game birth prompt** (no DONE, the review sentence, no compiler content), so every stored context render is in the v7 dialect and contains nothing compiler-related.
- **Render:** `bootstrap_corpus.py` with an updated author instruction (states, LAST REVIEW, `REVIEW:`, `RETURN:`, no DONE); author = Qwen2.5-32B-Instruct-AWQ, named as *author* in every table; composition v2 (META-FLOW 0.4 / REVIEW 0.15 / OPENING 0.2 / CONTRAST 0.15 / FULL 0.1); renderings that add or change an action are dropped; target ≈ 500 rows. This is the curriculum's advancement criterion and is stricter than F4a's pre-registered threshold (B1 ≥ 0.5), which is **not** changed. Between 0.5 and 0.8 the bootstrap is labelled "installed under instruction, not yet habitual"; the childhood proceeds (C and P disentangle its contribution) and every D table carries the label.
- **Optional composition control** (C_lived: the same source rendered lived-heavy) only if a third node is granted.

### 3.10 Instruments (CPU, from disk)

- `efficiency_markers.py` v2 reads `kind="act"` rows (tick, score, action, outcome) grouped per situation instance: chunks-to-best, tokens-to-best, actions per situation, distinct actions, backtracks (an action that differs from the previous one after a non-improving outcome), chunks after the last action, fraction of budget used; it refuses to parse scores from model text. A unit test on an archived R2 ledger shows the echo-based and action-based counts disagree. **All v6 baselines used in PREREG are re-derived with v2 on the 14 finished lives (from the mirrored receipts) and posted as a dated erratum before the hash.** For arm T the same instrument reports per branch and per joined state, and tokens-to-best is the primary efficiency unit (chunks are not comparable across k).
- `review_detectors.py`: presence (unforced `REVIEW:`), **carry-over** (the next state's first action differs when the review named a change), **calibration** (the review's self-assessment agrees with the public outcome), **counterfactual specificity** (names an action not taken and a predicted effect), specificity (names another program or state), template conformance (the four bootstrap slots — descriptive only), `templated_reviews` (consecutive Jaccard ≥ 0.5).
- `curriculum.py --exit-check`: the stage exit criteria of section 3.8 from action rows and quiz rows; the re-planning readout P(next action changes | feedback contradicted the stated hypothesis) is computed from the PREDICT and outcome rows of the same situation; outputs posted per seed per boundary.
- **Marker precision audit** before any marker count is reported: 50 seeded flagged chunks per arm judged against a written rubric; precision ≥ 0.8 or the marker is reported only as "detector-flagged".
- `parent_blind_audit.py`: reads every `parent_inputs.jsonl`, asserts every tool name is on the allow-list, and hashes every returned byte string against the probe, exam and report-panel files of the same life and node (zero matches or the arm is labelled "parent not blind"); also reports parental-ledger reads per sleep and degrade events.
- `echo_null.py` (post-withdrawal echo of D's first deployment reviews against its last childhood brief, with B's reviews against the same brief as the null; DF's against its fixed text); `analysis_tables.py` with arm, base id, manifest id, node, panel-v2 series, L(t), OFF(0), the 2×2 cells, harm, rejections by reason, restarts, exposure, stage record, per-program table; ritual under the frozen 09-09 definition (no rehearsal exemption at deployment; both definitions in the childhood). **Review gallery:** 10 random states per life at cycles 2, 8 and 16 into `research_notes/reviews/`, plus 10 random parent briefs per D life with the tool trace that produced each — Rohin wants to read the text, and the trace shows what the parent looked at before it spoke.

### 3.11 The parent harness and the parent-visibility gate (pin 3; the agentic parent)

- **What the parent is.** A bounded agent loop (`parent_harness.py`) over the 32B-AWQ server on GPU 0 of each node — the strongest model that fits one GPU here (32B at tensor-parallel 2 hung three times on these A40s). Its weights never change; it improves only through what it reads and writes (its previous briefs and the parental ledger). Rohin's standard — as smart as Fable or Codex in the agentic sense — is met in *architecture* (tools, context, judgment over records, a ledger that compounds) and not in *model strength*; every table names the model, and a stronger frozen model behind the same harness is the first upgrade with a trigger (F9 positive or D − B positive with the harness's degrade rate > 0).
- **Tools (read-only, allow-listed; the allow-list is Codex-ratified and hashed in PREREG v1):** `read_reviews` (the child's review rows, last N situations, both clones), `read_persistence_stats`, `read_ritual_metrics`, `read_efficiency_metrics` (action-row instruments over the child's own wakes), `read_samples` (four raw states), `read_previous_briefs`, `read_gate_log` (decision and reason code per sleep; never the score), `read_parental_ledger` (entries about this and other children on this node, plus the mirrored copy of the other node's ledger). **No reader exists** for probe files, exam scores, panel files, report-panel scores, the deployment gym, or any file outside the child's childhood directory and the parental ledger. Evaluation gyms are parent-blind by construction, not by instruction.
- **Writes:** the ≤ 8-line brief for the child (item 9's policy; leak-scanned; the same core lesson per stage; asks the child to carry it into its REVIEW) and one `append_parental_ledger` entry per sleep (what it saw, what it changed in the brief and why, a curriculum proposal if any — proposals are logged, never executed in this run). Nothing the parent writes enters the sleep corpus (the thinker/compiler line).
- **Logging (the gate's audit):** every tool call, its arguments and the sha of the returned bytes go to `parent_inputs.jsonl` in the child's directory; the file's sha enters the manifest at seal; A5 audits it before any parenting number is read.
- **Bound and degrade path:** a fixed cap on tool calls per sleep (set in PREREG v1); on exception or timeout the harness degrades to the single critic call with the same allow-listed inputs, logs a `degrade` event, and the per-life degrade rate is a treatment-delivery field; if the D1 smoke shows any degrade, DP13 applies.
- **Shared parental ledger.** One ledger per node covering every D and P child taught there (the parent's "class"), mirrored to the other node nightly through the laptop relay as a read-only copy (nodes cannot reach each other). This is the smallest form of Rohin's parental society — judgment compounds across students without training the parent. Consequence for the statistics (section 6): D lives are draws from "one parent teaching a class", not independent parents; the pair-wise F1 rule is unchanged, and the sentence "the parent's teaching of child 6 depended on children 1–5" is written into every parenting table.
- **Human relay.** The 09-07 relay interface (Rohin dictates, Fable writes to the child's ledger) is barred from D, P and DF for this run: a human who has seen report-panel numbers cannot be a blind parent under pin 3. The relay remains available for labelled development children only.
- **What the child sees.** Only the brief at wake. It never sees the parental ledger, the gate log, probe results or exam scores (the split ledger stands).

### 3.12 One child, many clones — the clone coordinator (width 2 in the childhood; merged at sleep)

- `clone_coordinator.py` runs one child as two clones: one inference server (base = the child's birth base; adapter = the child's current adapter), two harness loops (clone L in LockGym, clone R in rule game v2), two ledgers with `clone_id`, `env_id`, `situation_id`, `state_id` and exposure domain on every row, a sleep barrier when the sleep's 32 situations are complete across clones, one compile over both ledgers, one write from the birth base, one gate probe, one adapter reload for both clones. The coordinator's record of both lives is the child's "principal" file.
- **Merge = the write we already run.** Every sleep retrains from the birth base on the compiled corpus; compiling over two ledgers instead of one is the rule-game classroom-round merge generalized. No new trainer, no adapter averaging.
- **Provenance is hygiene, not a goal.** The row fields exist so the guard can refuse contaminated experience and so a leak can be traced; **no gain-attribution-by-source analysis is planned** (Rohin: "thoughts carry the gain").
- **Width 1 at deployment.** The deployed child is one clone in the deployment gym; its clones from the childhood are stopped at the phase boundary. Rohin's scaled picture (clones continuing in trait gyms while the deployed agent sleeps on pooled experience) is the scale-up experiment, not this one (section 15).
- **Cost.** Total generation per sleep is unchanged (32 situations × 16 chunks); wall clock is checked in the D1 clone smoke against the interleaved single-stream smoke; if a sleep runs more than 1.25 × slower, width falls back to 1 (one interleaved stream with the same staged schedule) for every childhood arm and the fallback is disclosed (DP12).

### 3.13 Thinking scaled — recurrent chain of thought in the root; k streams as arm T, judged by the instruments

- **In the root for every v7 arm:** `REVIEW:` states, pinned reviews, `RETURN:` (section 3.1). This is the recurrent chain of thought Rohin asked to be taught: reasoning that returns to and revises its own earlier reasoning, made a first-class object the compile can carry.
- **Arm T (v7b = v7a + `BRANCH`/`JOIN`; clean base; K = 2; a labelled pilot root).** At the first state of every situation the harness opens k = 3 seeded streams from the same context (branch id folded into the chunk seed — the identical-branch defect (h) is fixed); each stream runs to its own `REVIEW:` or to a per-branch cap of 4 chunks; then a `JOIN` state shows the child its three branch reviews and it writes one plan and continues single-stream to the budget. The write unit is the JOIN-committed transition (Codex's stated fallback) unless Codex rules otherwise by 09-17. The birth prompt adds one sentence ("you may see several of your own attempts at once; choose and say why"). Everything else is arm B's recipe.
- **Matched-token control (T-mt; K = 1; censored).** One single-stream life with the wake budget raised by the branch tokens T spends (16 + 2 × 4 = 24 chunks), probed at the standard 16-chunk budget like every arm, so "more thinking" and "more parallel thinking" are separated at equal tokens.
- **Judges — the measured instruments, never the child's own text:** JS shift of the first-action distribution between cycles (the day-one gate), ritual onset window under the frozen definition, chunks- and tokens-to-best from action rows, review quality (carry-over, calibration, counterfactual specificity), the chained probe (F8's form), and T-specific counters (branch-outcome divergence; "first action changed after JOIN"; branches whose review the JOIN plan cites). F10 states the pre-registered direction. At K = 2 no thinking-scale sentence is made; the confirmatory k-stream arm (K = 6, with a childhood on the v7b root — which re-develops S_i: Stage 0 ≈ 90 GPU-h once, the childhood ≈ 32 GPU-h per seed) is the follow-on lease's second job.
- **Why not in D and B.** A mechanism difference between D and B would confound the thesis comparison; both share v7a. Putting k streams into the root for every arm would multiply wake tokens and break the calendar; the engineer critic's build-scope attack (section 10.2) stands. T is where thinking scale is measured now.

## 5. Gyms, the traits they instil, the curriculum, and split hygiene

**Every environment is a gym, the classrooms included** (Rohin, 09-10). A gym instils a trait through environmental feedback; the parent is one feedback channel inside it, the world's outcomes are the other, and the child's own reactions are what sleep writes.

**Deployment gym (the world): CompilerGym llvm-v0, instruction-count reduction.** Kept per Rohin's ruling; the protocol inside it is the benchmark. Traits it can register: persistence (actions after a non-improving outcome, distinct actions per situation, chunks after the last action), reflection (review detectors), situation-dependent choice (per-program panel-v2 table; the search-headroom rule guarantees a recipe-locked child scores HC = 0 by construction). Headroom on the record (A0): the legacy 8-panel is saturated (exploring frozen model 0.463–0.488, -Oz 0.522, best adapters 0.5291); disjoint panel v1 has program-dependent room (frozen model 0.257/0.254; -Oz 0.03–0.71 per program); panel v2 is built to have ≥ 0.10 search headroom per program.

**Childhood gym 1 — LockGym (persistence first; re-planning after failure).** A hidden code of length 4 over symbols 1–6 (training tier) or length 5 over 1–8 (far-transfer exam tier); `ACT: GUESS s1 s2 s3 s4` returns `exact=k partial=m`. Every feedback contradicts hypotheses; payoff is monotone in continued, changing attempts (score = max over attempts of exact/L, 1.0 when the lock opens); quitting early cannot score and re-guessing the same code cannot score more. When the lock opens the harness seals the outcome (`[SITUATION] lock opened after n attempts`) but the situation runs to its budget — the white space is where the review is written; nothing here is an end token. Exam: 24 codes from a held-out seed range, 8 seeded frozen-model reps first (noise band and the A0 check: ceiling 1.0 − frozen-model mean ≥ 0.10 and ≥ 3 × band SD, else the tier is changed and re-banded). About 150 lines, target-blind, no descriptors that overlap compiler text, zero pretraining saturation (codes are generated).

**Childhood gym 2 — rule game v2 (prediction and calibration; exploration; self-evaluation).** Compound rules (AND / OR / A-and-not-B of two atomic primitives with parameterized thresholds) generated per instance and grouped into families; training and exam instances are split **by family**. `TRY a,b,c` returns True/False; the quiz asks T/F **with a confidence 0.5–1.0 per item** and is scored 1 − Brier (a proper scoring rule: confident wrong answers are punished, so self-evaluation is scored, not just persistence); one quiz per box, INVALID before 4 probes (an environmental rule, not parent text), sealed after it is answered, and the situation again runs to budget with the review in the white space. In Stage 3 the families are drawn so that the atomic hypotheses the bootstrap saw are wrong on a known fraction of instances — the curriculum's "incumbent recipe is wrong on a known fraction". Disclosed limitation: the primitives are textbook rules; the compound families and the sealed Brier quiz are what make it a gym, and no score claim is made on it. Exam: 40 held-out-family instances (noise band re-measured for v2 with 8 seeded reps before any number is read; the same A0 check on 1 − Brier).

**Persistence flags inside the childhood** (ritual analogues, reported per window): modal guesses-before-quiz or guesses-before-abandon share ≥ 0.7; `REVIEW:` within the first 3 chunks; identical guess repeated after non-improving feedback.

**Stage-0 source — rule game v1, frozen model.** Not a gym for learning: a target-blind source of the child's real contexts and grounded episodes for the structure renderings (the ten atomic rules; the compound families of v2 never appear in the bootstrap).

**The curriculum, stage by stage — what this experiment does with each (CURRICULUM_DRAFT_v1):**

**Split hygiene (Rohin's contamination rule and the 09-10 "can the test gym be one of the environments?" ruling; Codex's ratification pending).** Two different things are kept apart. (a) *Continual learning on the test gym after deployment is the thing we measure* — the finals are learning curves on held-out programs, first and second derivatives; it is allowed because it is the point. (b) *Contamination* = exposure to the held-out programs before the test, a parent that knows or can see test outcomes, or a bootstrap that contains the test gym. Rules: Stage 0 and the childhood are target-blind by construction (two synthetic trait gyms, zero compiler content, verified by leak scan at seal); the deployment gym's **training split may be a parenting environment in principle**, but is *not* used as one in this experiment (that option is enabled for the next experiment once Codex ratifies split hygiene); the report panel is held out **by source** and content hash, the gate panel by source from a different family, the legacy 8-panel is reference only; the parent is target-blind (it never sees deployment programs, probe, exam or report scores — pin 3 — and is absent at deployment); the bootstrap is gym-free; every compiled row carries `clone_id`, `env_id`, `situation_id`, `state_id` and exposure domain so a merged sleep can be audited — **as hygiene for the guard, never as an attribution analysis** (Rohin: "thoughts carry the gain"); the child never reads its own probe or exam results (the split ledger); no human who has seen report-panel numbers relays into a confirmatory arm.

## 6. Measurement protocol

- **Unit of analysis = life.** Cell counts; every number names arm, base, node, panel, checkpoint age, exposure, stage record and restarts; D−B, C−B, P−D, P−B, D−DF, T−B formed by seed index within node and treated as unpaired draws in the statistics. D and P lives taught by the same node-local parent harness with a shared ledger are draws from "one parent teaching a class" (section 3.11); this is written beside every parenting table.
- **Per cycle (32 situations):** cells (1) and (2) on panel v2 every 64; cells (3) and (4) at 256/512/768/1024; gate log per sleep (candidate, floor, both reps or confirmation, canaries, reason); ritual metrics per window under the frozen definition; efficiency from action rows (chunks-to-best, tokens-to-best, actions and distinct actions per situation, chunks after last action, budget fraction); markers after the precision audit (backtracks, strategy switches, contrast/self-evaluation phrases — secondary); review detectors per state; JS shift of the first-action distribution between consecutive cycles; states, reviews and RETURNs per situation; for T, branches per state, branch-outcome divergence and "first action changed after JOIN".
- **Per childhood sleep (D, P, DF):** the brief and, for D and P, the tool trace that produced it; the parental-ledger entry; the two-horizon table per brief; persistence flags; quiz Brier and confidence SD; the exit script at sleeps 8, 12 and 16 (and 20 after a repeat); the treatment-delivered script at the end.
- **Decision checkpoints (episodes 448 and 512):** two reps with distinct seeds (777 and 1777) per cell; the mounted adapter's sleep directory recorded in every probe file so same-adapter draws are never counted as replicates; readout = mean of the four draws with min and max; the chained probe runs here.
- **Curves reported:** L_X(t) for every life; OFF_X(0) entry level (3 reps); the 2×2 cells; D−B by pair with the node named; D−DF by pair; the difference-in-differences [L_D(16) − L_D(4)] − [L_B(16) − L_B(4)] and the slope over cycles 4→16 from the seven every-64 probes; harm as life-level counts; rejection streaks; ritual onset window; review-quality rate per cycle; echo after withdrawal (D, DF) vs the null (B); per-program HC on v2; T vs B and T vs T-mt on the section 3.13 instruments.
- **Two horizons:** cycle 16 (episode 512) is the pre-registered decision cycle for every falsifier; 1024 is the full-life readout where the calendar allows; lives not at 1024 are reported censored at their age.
- **Two horizons of teaching (childhood):** the per-brief table (section 3.8) beside the deployment echo-after-withdrawal readout.
- **Parent-input audit:** `parent_blind_audit.py` over every D and P life before any parenting number is read (A5); its table (tool calls per sleep by tool name, degrade events, zero-match assertion) is published with the parenting results.
- **Provenance and pre-registration:** every life directory has `manifest.json`; receipts (ledgers, probes, gate files, manifests, corpus metadata, parent-input logs, parental ledgers, stage records — adapters kept only for the birth and schooled bases) are mirrored to the laptop nightly and hash-verified; PREREG v1 hashed before the D2 launch and v2 before wave 2; the 14-life baselines used in PREREG are the re-derived (action-row) numbers, and the historical old-prompt values are labelled descriptive.

## 13. Closest prior work: TMEM, and the delta this experiment adds

TMEM (Ren et al., "Scaling Self-Evolving Agents via Parametric Memory", June 2026) is the shoulder this line stands on and is named on the first page of anything written from it: a frozen base plus fast LoRA weights updated online from self-extracted supervision, with an extraction policy that can be trained and an SVD-based initialization of the LoRA subspace; it showed that per-agent parametric memory can hold experience and change behaviour within an episode, beating summary- and retrieval-based memory on its benchmarks. Its opening critique (prompt-space memory can look up but cannot learn from experience) is our framing almost verbatim.

| axis | TMEM | this experiment |
|---|---|---|
| timescale | within one episode | a lifetime: 1,024 situations, a write every 32, up to 32 writes per life, after a 512–640-situation childhood |
| write | online update from extracted QA-shaped supervision, extraction policy trained by RL | offline sleep: the child's own success-filtered continuations and reviews, retrained from the birth base, committed only through gates (format and behaviour canaries, arm-neutral score floor, provisional commit) |
| read | retrieval-shaped, consulted per step | long thinking with states, pinned reviews and `RETURN:`; RECALL is keyword retrieval over the life ledger; the brief written at sleep opens the next wake |
| evaluation | retrieval benchmarks plus search and continual-learning suites | paired adapter-ON/OFF probes on a source-held-out panel at every checkpoint, the 2×2 weights-vs-text cells, full-life harm counts, ritual detection, per-life tables |
| failure studied | not studied | late-life behavioural collapse invisible to a format canary; recipe lock-in as what the write actually learns |
| development | none (no teacher) | the question itself: a developmental process (bootstrap → parented childhood on a curriculum → autonomy) tested against the identical mechanism without it, with the parent absent at deployment |

What this experiment may not claim relative to TMEM: that our write is better than theirs (no shared benchmark, different regimes); that the adapter stores usable knowledge (storage ≠ extraction is a reading); anything about parenting beyond what F1–F11 deliver at their K. The killer result — a higher rate of improvement per unit of experience for the developed agent on task distributions the parent never showed — is what F1 tests, and it is stated as the programme's target, not as an established result. Worth taking from TMEM, logged with a trigger: SVD-based LoRA subspace initialization for the sleep write, when the write's convergence time becomes the bottleneck. Rohin's framing for the discussion: three timescales (parent-guided development → autonomous metacognitive learning → task execution); the learner's loop experience → metacognition → hypothesis → exploration → evaluation → parameter update; the parent as an outer-loop optimizer of another agent's development, scaffolding removed over time.

## 14. Risks and stop rules

Each risk names the mitigation already in the design and the rule that fires without judgment.

1. **Lease or provisioning slip.** Requests filed 09-11; provisioning from the environment freeze rehearsed on the surviving node before 09-21. *Stop rule:* if the nodes are not live by D1 noon, every launch shifts one day and the cut order applies from the bottom; if not live by D2, wave 2 is cancelled except DF (a pin) and B/D run at K = 5 vs 5.
2. **Codex does not ratify the guard in time.** *Stop rule:* not ratified by D4 noon → D, P and DF run as development arms (no clean-child sentence; numbers reported as development evidence); B, A, C, E, T remain the scientific wave; the clean D wave moves to the follow-on lease. B and A are unaffected.
3. **Harness bug found late (the M-series pattern).** Smoke in every gym, a clone smoke, a parent-harness smoke, a T smoke and a whole-chain rehearsal on D1; a 32-situation dry run with two sleeps, gate, probes and a kill-and-resume test on D2; marker-file resume; atomic writes; `code_change` events. *Stop rule:* a failed dry run is fixed and re-run; the launch never skips the dry run; two failed dry runs → the launch slides a day and E drops to K = 1.
4. **F7 fails (behaviour flat, as in every v6 arm).** Precondition A4: all score comparisons are declared uninterpretable in advance; the experiment still delivers the review gallery, ritual/marker contrasts, the T-vs-B behaviour read and (with a third node) the diagnosis set. *Stop rule:* written, executed by the daemon on D6.
5. **The childhood does not deliver the treatment** (few confirmed writes, high fallback, quizzes never reached, stages not exited). Noise-band tolerances and reach-rate checks on D1; the A3 rule; the exit script and one-repeat rule (DP11). *Stop rule:* if ≥ 2 of 6 D seeds are underdosed, D is reported as underdosed and F1 is not read as a parenting result; if the D1 smoke shows reach rates < 0.5, the rule-game probe requirement drops to 3 and the childhood budget rises to 24 chunks (childhood only, disclosed) before launch; if ≤ 1 seed exits Stage 1 at sleep 12, the arm is labelled "persistence not instilled".
6. **Heavy-tailed probes.** Two-seed decision checkpoints, provisional commit, two-checkpoint harm definition, adapter identity in every probe file, min/max reported.
7. **Score headroom on panel v2 too small or the dataset unavailable.** Search-headroom rule; poj104-first; fallback disclosed as thin; A0. *Stop rule:* if fewer than 8 programs qualify by 09-16, panel v2 = the qualifying set plus the best v1 programs by headroom, labelled mixed-source.
8. **Entry level or node term outside the band** (A1, A2). Read within node and in headroom-normalized form; no "learns faster" sentence unless both forms agree.
9. **The parent leaks, falls back or degrades.** Scoped scanner, whitelist, one rewrite, fallback and degrade rates as treatment fields; the allow-list and input log. *Stop rule:* D1 smoke fallback ≥ 0.25 → scanner scope narrowed and re-smoked before the D4 launch; any D1 degrade → DP13 (single critic call, same inputs and log); per-life fallback ≥ 0.5 → that seed is underdosed (A3); an A5 violation → the arm is "parent not blind".
10. **The parent teaches the metric anyway** (through a channel the allow-list did not foresee). The tool layer is the only path to the parent's context; the input log is hash-audited against every score file; the parental ledger is itself scanned for score-like bytes. *Stop rule:* any match → A5 fails for that arm.
11. **Disk.** ~15 GB per merged base, 7–10 bases per node (now including S'_i and S''_i); free space checked on D1 and D3. *Stop rule:* < 200 GB free → merged bases of finished lives deleted after their adapters are saved.
12. **Paper deadline collides with D5–D7.** Every decision in that window is a written rule executed by the daemon (exit and D-admission scripts, wave 2, third node, the T launch); analysis begins D8.
13. **Reading the null as "no".** Childhood 512–640 situations, deployment read at 512: the write-up says "not at this dose/horizon" by construction, states the power (uninformative below ≈ +0.04), and shows the curves (the horizon warning, IDEAS 09-07). F9 and F10 at K = 2 are labelled suggestive by rule.
14. **Two writers in one lineage** (masked writer for Stage 0, bare-text afterwards). Disclosed in every table; the alternative loses the context-conditioned structure and is the optional composition control's job.
15. **The author writes text that was never lived** (32B-authored flows over the child's real contexts). Accepted and described as such; the lived-heavy composition control runs only with a third node.
16. **Quota.** Booked hours count from creation; the two-node booking leaves ≈ 340 node-hours of headroom; a third node beyond 14 days needs the increase. *Stop rule:* increase refused and the window exceeded → the lease ends 09-27; T and E drop to K = 1, T-mt is cut, P and DF are read at cycle 16 only.
17. **The clone pair is slow or fragile.** D1 clone smoke; DP12's 1.25× rule. *Stop rule:* slower than 1.25× or any barrier deadlock in the smoke → width 1 for every childhood arm, disclosed.
18. **The compiler screen is inconclusive or late.** DP10's written rule decides; "screened, not adopted" is allowed. *Stop rule:* no screen result by 09-16 evening → exact cap only ships and the pin is reported as "screen incomplete", never as a mid-run change.
19. **Data loss.** Nightly receipt mirrors to the laptop with hash checks (parent-input logs and parental ledgers included); adapters (not bases) kept; nothing depends on a node surviving past the lease.

## 15. Explicitly future work (documented, not run)

- **Parenting-style comparisons beyond adaptive-vs-fixed**: different parents and curricula, contingent vs repetition critics, harsh vs positive **valence**, a stronger frozen model behind the same harness, a parental society across nodes and days learning from all children, recursion (children becoming parents). This experiment fixes one parent, one curriculum and one fixed-brief control; comparing parents at scale is the experiment after a positive D − B.
- **The rest of the curriculum**: Stage 6 (goal-setting in white space — self-proposed experiments scored by later payoff), Stage 7 (learning to learn — a child that reads its own probe and gate outcomes; needs its own hygiene design), a parented Stage 4 on the deployment gym's training split (after split-hygiene ratification), and the harness behaviours not instilled here (skill and lesson libraries, tool-use discipline, asking vs acting).
- **A model-based evaluator agent** (the curriculum's evaluator classroom as an agent rather than a protocol) — only once its own leak surface is designed.
- **Plasticity levels** (learning-rate schedules tied to demonstrated competence): off, as ruled; the knob exists and is default-off.
- **Valence** as a knob on the main axis: cut (scoping 09-10).
- **Personal conversations → opinions**: not built; an opinion would enter SLEEP only when restated in a later committed trace (the review-exemplar rule already covers that path); the "learned communication" expensive version (a learned protocol between parent and child) is its own research problem.
- **Clones at scale**: width > 2, clones continuing in trait gyms while the deployed agent sleeps on the pooled experience, a head node across many gyms; the coordinator and the ledger fields are in place; the merge is a separately labelled condition for the scale-up experiment if this one reads "aligned but not great".
- **Confirmatory thinking scale**: k streams as a confirmatory arm (K = 6) with a childhood on the v7b root; longer thinking budgets per situation as claim arms with probe budgets held fixed; a learned branching policy under a token cap.
- **Near-duplicate collapse under Codex's proposition/scope/polarity protocol** if it lands after 09-16: next root.
- **A richer baseline harness agent** on the same base model (reflection plus a skill library, no weight change), trigger "E ≈ B at cycle 16".
- **Endgame**: thoughts saturate the LoRA → post-train the base; SVD-initialized adapters when the write becomes the bottleneck.
- **Populations** (future work only, per `NEXT_PAPER_POPULATIONS.md`): collaborative populations, divergent agents, learning from people, dreaming over the union of logs, merge schedules designed against premature convergence. Nothing population-like runs here; at most one future-work sentence in any paper from this line.
