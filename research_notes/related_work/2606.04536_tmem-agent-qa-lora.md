# Scaling Self-Evolving Agents via Parametric Memory
arXiv: 2606.04536  
Authors: Tao Ren, Weiyao Luo, Hui Yang, Rongzhi Zhu, Xiang Huang, Yuchuan Wu, Bingxue Chou, Jieping Ye, Jiafeng Liang, Yongbin Li, Yijie Peng

## Abstract
Existing memory-augmented LLM agents store past experience exclusively in prompt space, as textual summaries or retrieved passages, while keeping model parameters frozen throughout a rollout. Such agents can \emph{look up} what they have seen but cannot \emph{learn from} it: their policy is unchanged by experience, and any information dropped from the context is permanently lost. We introduce \texttt{TMEM}, a self-evolving parametric memory framework in which the agent not only compresses history into explicit memory but also absorbs distilled supervision into fast LoRA weights $Δ_t$ via lightweight online updates, genuinely altering its future behavior within a single episode. We formalize this as an agentic decision process with fast-weight rollout dynamics: actions are sampled from $π_{θ_0+Δ_t}$, while extraction actions produce supervision that updates $Δ_t$ for subsequent decisions. This view makes the extraction policy directly optimizable by RL: training $θ_0$ improves not only task actions but also the quality of the data used for online LoRA adaptation. We further propose SVD-based initialization of the LoRA subspace to accelerate online convergence. Experiments on LoCoMo, LongMemEval-S, multi-objective search, and CL-Bench show that \texttt{TMEM} consistently outperforms summary-based and retrieval-based baselines across different model scales.

## Our differentiation
(Fable, 2026-09-13; from the abstract and the summary in WHAT_TO_PARENT_FROM_THE_LITERATURE_2026-09-12.md — verify against the paper before citing.)

TMEM writes grounded QA pairs about the current session into a small LoRA (rank 6, last four FFN layers, A frozen from SVD, only B trained) with a frozen base when the context exceeds a budget, then clears the context; across episodes GRPO on outcome reward trains the full base to write pairs that make its own future updates useful. Same as ours: frozen base, LoRA as the memory store, the agent writes its own memory records, an outcome signal shapes the writer.

Where ours differs:
1. Lifetime vs episode. TMEM's adapter is per-episode scratch memory, reset between episodes. Ours is lifetime memory in one adapter, rewritten at sleep with rehearsal, so what is learned in one episode is available in all later ones.
2. No trained call step in TMEM. The model is not taught to cue its own memory inside reasoning; the stored facts act implicitly. Our junction skill is exactly that call step, and it is what the flywheel needs to compose stored items (untested as of 2026-09-13).
3. Writer shaping. TMEM trains the writer by GRPO on task reward; ours is shaped by a parent (level 2) and a mechanical provenance/outcome gate at sleep. Our register is first-person procedural records with outcomes, not QA pairs.
4. Behaviour and memory in one adapter. TMEM stores facts; we also install behaviours (habits, skills) in the same adapter and have to keep them from erasing each other (SEQ-104/113/118/159).

Claim discipline: TMEM (and Physics of LMs) already show "the agent's own written records, trained into a LoRA, are retrievable and useful". We do not claim that as new; our level-0 results (SEQ-113/118) replicate the regime in our form. Our TMEM-shaped pretest cells (C_tmem: rank 6, last four layers, SVD init, SGD 5e-4 × 5 epochs) collapsed on 23/23 lives — a recipe difference, not evidence against TMEM.
