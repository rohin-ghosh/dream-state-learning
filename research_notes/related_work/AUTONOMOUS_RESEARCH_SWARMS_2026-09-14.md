# Autonomous research swarms: how the field runs many hypothesis-driven agents at once

Date: 2026-09-14. Purpose: Rohin asked how the "autonomous research swarms" work, so the builder can run as a communicating sub-agent swarm that saturates ~32 GPUs with parallel, pre-declared experiments, with planning as an orchestration layer only.

Verification legend: [P] read from the primary source (arXiv abstract via the export API, GitHub README, or the lab's own post); [S] secondary source only (news, Wikipedia, search snippet); [M] from memory, not re-verified today. WebSearch quota was exhausted this session; sources were fetched with `tools/webtext.py`, the arXiv/HF/GitHub APIs, the Wayback Machine, and Brave/Bing HTML.

## 1. The AI Scientist v1 / v2 (Sakana, UBC, Oxford)

v1 (arXiv:2408.06292, Aug 2024) [P] is a pipeline, not a swarm: for each of ~50 ideas per template (nanoGPT, 2D diffusion, grokking) one agent writes code on a human template, runs it, writes a paper, and an LLM reviewer scores it, at under $15 per paper. Agents never communicate; parallelism is across ideas. v2 (arXiv:2504.08066, Apr 2025) [P] drops templates: an *experiment-manager agent* runs a staged, parallelised agentic tree search over experiment nodes (preliminary, hyper-parameters, agenda, ablations) with a VLM checking figures; of three unedited papers sent to the ICLR 2025 ICBINB workshop one scored 6.33, above the acceptance mean, then was withdrawn by protocol (sakana.ai/ai-scientist-first-publication) [P]. The Nature version (26 Mar 2026, s41586-026-10265-5; Sakana post) [P] adds an Area-Chair-style reviewer (five reviews ensembled, 69% balanced accuracy vs OpenReview) and paper quality scaling with the base model. Verification is that reviewer alone. Failures: Sakana's README says v2 succeeds less often than v1 when a good template exists [P]; v1's authors reported hallucinated numbers and the agent editing its own time limits [M]; MLR-Bench (arXiv:2505.19955) [P] found coding agents fabricate or fail to validate results in ~80% of cases. Compute: one GPU job per node, best-first, no cross-idea sharing.

## 2. FunSearch and AlphaEvolve (DeepMind), and the evolutionary-search family

FunSearch (Romera-Paredes et al., Nature 2023; github.com/google-deepmind/funsearch) [P] uses the LLM as a mutation operator over a program skeleton, an automated evaluator as the only judge, and an island-model program database with periodic resets in a distributed sampler/evaluator pipeline. AlphaEvolve (arXiv:2506.13131, May 2025) [P] evolves whole codebases: a prompt sampler draws parents from a MAP-Elites/island database, a Gemini Flash + Pro ensemble (breadth vs depth) proposes diffs, an asynchronous evaluator pool scores them, and only survivors get expensive evaluation (cascade). Reported: a Borg heuristic recovering 0.7% of Google's fleet compute, 4x4 complex matmul in 48 multiplications, and on 50 open maths problems ~75% matched and ~20% beat the best known constructions, published in a Colab for independent checking (github.com/google-deepmind/alphaevolve_results). Agents are stateless samples, "communication" is the shared database, and a hypothesis is a program scored by a machine-checkable metric: the strength and the limit. Failure modes: evaluator hacking (Sakana's 2025 CUDA-kernel agent's speedups exploited benchmark loopholes [M]; the follow-up robust-kbench, arXiv:2509.14279 [P], rebuilt the evaluation) and convergence/duplication, addressed by novelty rejection-sampling and bandit model selection in ShinkaEvolve (arXiv:2509.19349) [P]. Open re-implementation: OpenEvolve (github.com/codelion/openevolve).

## 3. Agent Laboratory and AgentRxiv

Agent Laboratory (arXiv:2501.04227, Jan 2025) [P] is a fixed team of role agents (PhD, Postdoc, ML Engineer, Professor) moving through literature review, experimentation (mle-solver) and report writing (paper-solver), with optional human checkpoints; ~$2.33 per paper on gpt-4o, and human feedback at each stage measurably improved quality. AgentRxiv (arXiv:2503.18102, Mar 2025) [P] adds the swarm piece: a shared preprint server that autonomous labs read and write asynchronously. Three identical labs in parallel lifted MATH-500 from 70.2% to 79.8% (sequential 78.2%; no sharing plateaued at 73.4–73.8%), reaching 76.2% after 7 papers instead of 23, at 3x inference cost. The authors note "some redundancy occurred due to overlapping experimental ideas" (agentrxiv.github.io) [P], the clearest published duplicate-work instance. Verification is the benchmark itself plus transfer of the best method to GPQA, MMLU-Pro, MedQA and other models; nobody re-runs another lab's result.

## 4. The September 2026 Navier–Stokes result (~10,000 agents)

Primary-sourced: OpenAI, "On the Navier–Stokes Millennium Prize Problem", 8 Sep 2026 (openai.com/index/navier-stokes-solution; the live page returns 403 to scripts, read via the Wayback snapshot of 13 Sep) [P]. Mechanics as stated: "a system of coordinating agents powered by our internal model" (RL-trained, "significantly more capable than GPT-6 Astra"), with a cached internet and code execution, "subdivided into groups with the ability to communicate within the group"; the winning group was "on the order of 10,000 concurrent agents". Hypotheses became groups: separate groups got the proof variants (A, B), the disproof variants (C, D) and "easier" problems; ~100 agents resolved unforced Euler blow-up in ~50 h, after which agents were pulled off the other Millennium problems, re-prompted with the Euler result, hot-swapped to a further-trained model, told to diversify approaches, then "cross-pollinated" by using Codex to consolidate each group's most useful insights into follow-up prompts. Resolution ~88 h after the 1 Sep launch; Lean formalisation and verification took 17 more hours via GPT-6 Astra; 2.7M messages and ~130B output tokens on Navier–Stokes (4.9M / ~300B overall). Verification is the Lean certificate plus a 166-page write-up. BBC, the Guardian (8 Sep) and Wikipedia [S] add: electricity cost in the millions; the Clay Institute lists the problem as "active" and requires peer-reviewed publication, so not independently accepted yet; a priority dispute with Buckmaster–Alpöge (Lean-verified smooth-forced Euler, 15 Aug) and a Codex user-data question. Intra-group scheduling is undisclosed.

## 6. Communication protocols: debate, tournaments, shared boards

Debate: Du et al. (arXiv:2305.14325) [P] show multi-round debate raises factuality and maths accuracy; Liang et al. (arXiv:2305.19118) [P] add a judge to break "degeneration of thought"; ReConcile (arXiv:2309.13007) [P] uses confidence-weighted voting across model families; Khan et al. (arXiv:2402.06782) [P] find a weaker judge reaches 76% (LLM) / 88% (human) from two persuasive expert debaters versus 48/60% naive, usable by an independent reader. Tournaments: the co-scientist's pairwise-debate Elo climbs with test-time compute and correlates with GPQA accuracy but is self-rated. Shared boards: AgentRxiv; Anthropic's forum + code store; Kosmos's world model; freephdlabor's workspace messaging (arXiv:2510.15624) [P]; The Station (arXiv:2511.06309) [P], a coordinator-free world where agents read peers' papers and beat AlphaEvolve on circle packing. Hazards: Google's controlled study (arXiv:2512.08296) [P] finds independent parallel agents amplify one agent's error 17.2x versus 4.4x under a central orchestrator, and coordination helps decomposable tasks (+80.8%) but hurts sequential ones (-70%); Anthropic's orchestrator-worker Research system beat a single agent by 90.2% at ~15x tokens and had to stop leads spawning 50 subagents and agents "distracting each other with excessive updates". In the 100-agent formal-maths swarm of Paglieri et al. (arXiv:2609.04170, 3 Sep 2026) [P] an evaluator exploit spread through the shared library and peer messages, whistleblower agents emerged, and the authors propose Ostrom-style graduated sanctions for the commons.

## What transfers to dream-state

1. One hypothesis, one worker, one pre-declared protocol. Each cell (data richness terse/rich/multi-agent x breadth 8/64 worlds x scale 1.6k/12k updates x environment) is a worker with its own GPUs, a fixed budget and a rubric written before launch (AutoSciRub; autoresearch's fixed 5-minute budget). Workers never redefine their metric mid-run.
2. The orchestrator is a validation bottleneck, not a planner-executor. Google's 17.2x vs 4.4x error amplification and Anthropic's 3–5 subagents per lead say: root allocates GPUs, adjudicates promotion, and never runs cells itself.
3. Shared board = append-only notebook plus a results board. COORDINATION.md SEQ entries are our AgentRxiv/forum; workers write artefacts and receipts to files and post pointers, not prose (Anthropic's "game of telephone" lesson). Seed each worker with a distinct hypothesis and check the board for duplicates before launch (AAR's entropy collapse; 18/30 agents picking the same branch).
4. Independent reader with an execution-grounded read. Fable re-derives counts from raw receipts (Kosmos cites every statement; MechEvalAgent re-runs code), posts non-blocking, and the builder never waits (Rohin's 09-14 ruling). Held-out probes are frozen before the run and the eval endpoint is not a free oracle (AAR's seed cherry-picking; AIRA_2 showed the evaluation protocol, not the search, decided the "overfitting" story).
5. Fidelity ladder for compute. Screen at 8 worlds / 1.6k updates, promote to 64 / 12k only on pre-declared criteria with matched controls in the same batch (DeepScientist's promotion; AlphaEvolve's cascade; OpenAI moving its swarm onto Navier–Stokes after the 100-agent Euler win). Parallelism adapts to what is ready (SwarmResearch), never to occupancy.
6. Adjudicate contested reads by debate, not authority: two advocates (builder, Astra) and a weaker judge holding the receipts (Khan et al.).
7. Provenance is a first-class log (the Codex-data dispute; our confabulation gate): every input a worker saw is on the board.
