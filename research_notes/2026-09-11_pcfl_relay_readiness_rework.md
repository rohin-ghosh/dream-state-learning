# PCFL learned-relay readiness and rework synthesis

Date: 2026-09-11

Status: read-only scientific and execution synthesis. No implementation,
source generation, model/tokenizer call, training, GPU use, parenting, claim,
release, or C11 authority follows from this note.

## Fresh-review verdict

Two fresh, independent reviews of relay notes 58--60 converged on **REWORK /
NO-GO for execution**.

- Scientifically, the relay has the right four-part skeleton for bounded E2,
  E4, and E5 claims, but several interventions do not yet identify the claimed
  causal links.
- Operationally, no learned PCFL relay package exists. Current artifacts are
  reusable engineering patterns or CPU-only historical fixtures, not PCFL
  implementation or evidence.
- E6 cannot be obtained by repeating one-cycle roots. It needs a separate
  sequential same-life experiment after the one-cycle relay works.

The reviews agree that the next honest PCFL deliverable is a complete CPU M0
instrument and explicit-text development relay. A LoRA relay waits on E0
writer qualification.

## C11 boundary

C11 is a fixed-policy, fixed-topology, supplied-memory ceiling. It may validate
the public world/read/scorer topology, goal-dependent routes from supplied
records, bridge/derangement/twin controls, and supplied old-plus-new delayed
use. A guard pass is governance evidence only; a later C11 scientific pass is
still limited to this supplied-memory ceiling.

C11 cannot establish self-authored experience, DREAM/SLEEP, LoRA transport,
writer retention, online learning, recurrence, parenting, accumulation,
lifetime slope, or the complete organism. The learned-organism PCFL relay is a
separate experiment with separate roots, denominators, carriers, and claims.

## Scientific repairs required in one successor

One later controlling successor must explicitly supersede unbound notes 58,
59, and 60 and resolve the following before source implementation.

1. **Prospective child and locks.** Bind the child-selection function and prove
   `parenting lock < relay lock < parenting unblind`. Existing unsealed or
   already inspected children can support development only.
2. **Writer qualification.** Do not freeze the relay LoRA recipe by intuition.
   Require conditional multi-key carriage, wrong-life/adapter-off specificity,
   interface and non-harm, survival through one identity-disjoint cumulative
   write, and exact PCFL-row read fidelity. V6 plus its later retention stage
   is the current smallest path.
3. **Actual acquisition.** Phase A must commit the relation key/domain and the
   complete outcome-to-row map before acting; the public outcome selects the
   row. Requiring the child's pre-outcome value prediction to be correct
   preferentially admits already-known facts and cannot show acquisition.
   Positive public uncertainty before action is required for the word
   `newly acquired`.
4. **Meaningful links.** A link requires more than syntactic co-mention and a
   success symbol. The root theorem or matched single-atom substitutions must
   prove both linked atoms are necessary for the supporting action. Otherwise
   the object is only a syntactic co-use record.
5. **E2 controls.** Promote resource-matched `ATOMS_PAD` to a scored arm. Build
   truthful null links only over atoms present in every arm. Match component
   size, anchor reachability, shortest paths, endpoint presence, candidate
   incidence, slot accessibility, hit/miss shape, types, degrees, ages, and
   bytes. Add a same-authentic-build read-time link permutation/cut so semantic
   use is separated from training interference.
6. **Goal causality.** Use paired same-start goals for the primary
   `goal -> path/action` contrast; keep bridge cut and truthful twin
   redirection. Call a DEV-selected policy a frozen baseline, not an exhaustive
   confirmation-distribution ceiling. Use structural symmetry or an exact
   generator-prior Bayes optimum for shortcut ceilings, plus a symbolic graph
   controller and leaked oracle as positive checks.
7. **Complete E5 path.** Carry a matched sham signal through its naturally
   selected action, public outcome, compilation, write, reset, and the same
   sealed D goal. Add the total-path `AUTH - SHAM` delayed-value contrast, the
   AUTH-vs-SHAM gap-identification contrast, and a Phase-C action/outcome
   binding permutation or twin. Retain reachout-off, no-write, sham-write,
   D-time binding redirection, and exact old-plus-new path use.
8. **Strong active text.** The exact semantic text carrier is an assay ceiling,
   not the full active-memory baseline. Add candidate-blind retrieval over
   eligible raw records, and certify recall, citation identity, store-swap
   sensitivity, usage, matched public outcomes, tools, token budget, and write
   latency. It need not lose to LoRA for the mechanism claim.
9. **Separate releases.** Replace one omnibus chain with nested fixed-order
   endpoints `E2 -> E4 -> E5`. A failed E5 must not erase a valid E2 or E4
   result. Missing cells remain adverse-filled. Recompute root count and
   resource bounds only after the repaired controls are fixed.
10. **E6 handoff.** State explicitly that a one-cycle root is not a lifetime.
    E6 later uses sequential cycles inside each independently initialized
    life, future-goal blindness at every write, unrelated-write retention,
    recurrence/write/bridge ablations, and an evolving active-text comparator
    with at least three fixed checkpoints after its prospective plateau.

## Minimum implementation surface

No `pcfl_core`, `pcfl_m`, `pcfl_lineage`, or certified active-text package is
currently present. A scoped build needs:

- canonical schemas, strict byte parser, IDs, renderers, and mutation goldens;
- deterministic world/twin generator and exhaustive root theorem;
- append-only public ledger and total `G_atom`, `G_link`, `G_new` compilers;
- finite one-hop reader and a resolved adaptive-policy closure rule;
- A/B/C/D phase machine, interventions, sterile resets, and fresh-process
  branch isolation;
- clause-specific reducer, adverse failure values, resource ledger, and
  immutable receipts;
- clean-lineage guard with one-way evaluation descendants;
- exact-text runner and scripted/leaked-oracle checks;
- only after E0 passes, transactional LoRA writer/reader and its adapter-off,
  wrong-life, retention, rollback, and row-fidelity checks; and
- later, a certified active-text system and longitudinal E6 runner.

Historical FeltCraft, RML-D0, Stage-B, and LoRA code may donate patterns only.
Their identities and results cannot be relabeled PCFL.

## Information-efficient build/run order

1. Bind one repaired relay contract; zero GPU.
2. Implement/test CPU M0, lineage guard, controller closure, interventions,
   reducers, and a fully scripted positive relay; zero GPU.
3. Run one exact-text parser/session canary, then four fixed DEV roots; extend
   to eight only if at least two of four complete the noncompensatory text
   core. Treat this as development triage, not population evidence.
4. Independently qualify E0. Current writers do not qualify.
5. On one text-positive root, run only three initial LoRA builds: authentic
   old deck, deranged old deck, and authentic old-plus-new row. Add truthful
   null, sham-write, and other controls only if the core survives; a successful
   full-claim root still executes every required control.
6. Run at most eight LoRA DEV roots for covariance, tails, and cost. Freeze a
   later confirmation only from disjoint DEV and power E2/E4/E5 separately.
7. Build and certify the evolving active-text comparator, then design E6 as a
   separate same-life recurrence study.

This preserves the full Dream--LoRA--Think objective while stopping GPU spend
at the earliest failed causal link.
