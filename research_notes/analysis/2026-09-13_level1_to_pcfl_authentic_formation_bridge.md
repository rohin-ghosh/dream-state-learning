# Smallest bridge from authored Level-1 execution to authentic PCFL formation

**Date:** 2026-09-13 UTC  
**Status:** design only; no source, model, fit, adapter mutation, or GPU execution  
**Evidence:** completed Level-1 rosters; terminal `level1_real_record` attempts
1 and 2; passed PCFL vertical v2.1 design  
**Question:** does the already-fitted Level-1 perception procedure help a
child turn its own strictly executed public action and world outcome into an
exact PCFL EVENT/LINK record on a fresh transfer surface?

## Ruling

Run one **zero-fit formation-transfer screen**, in parallel with PCFL v2. Do
not add another writer experiment and do not wait for this screen before
materializing PCFL's CPU world gate.

The screen has four read-only child states on two fresh excluded PCFL roots:

```text
OFF
PERCEPTION_SEED_0
PERCEPTION_SEED_1
PERCEPTION_SEED_2
```

Every state receives the same eight prescribed public action opportunities per
root. The model must emit each action through the literal strict interface;
the real route world executes it; the model then writes an EVENT from the
actual receipt and LINKs from its own accepted EVENT rows. There is no target
record, parent, checker answer, future route goal, sleep, or fit in context.

This is the shortest causal bridge because:

- all three Level-1 perception fits are used, so no seed is selected from its
  downstream performance;
- prescribed actions make the executed experiences identical across states,
  separating record conversion from action selection;
- actual execution preserves the action -> outcome -> child-record chain;
- content and strict serialization are scored separately; and
- the rows use the exact PCFL grammar and world, so the screen directly
  de-risks the formation gate rather than inventing another proxy gym.

It is a **trained-skill transfer screen**, not parenting or self-learning. The
Level-1 targets were researcher-authored. No output from this screen enters a
PCFL DEV child or a later training corpus.

## 1. What the completed evidence says

### Level 1

The first completed roster showed stable authored procedure execution at the
tested dose: contradiction, goal completion, prediction, and update judgement
all reached `48/48` held content and `48/48` strict in all three learner seeds.
The second roster's terminal summary reports perception at
`47/48, 48/48, 48/48`; self-reflection, repetition, and meta-reflection reached
`48/48` in all three seeds. Three narrow canary regressions occurred outside
perception: repetition seeds 0/1 and meta-reflection seed 2.

These are explicit open-book authored-situation procedures. They do not show
that the fitted child can act, perceive its own experience, or form a record
that the PCFL compiler can use. Perception is the only minimum state to test
here because its authored policy already asks the model to select the latest
event and bind action, prediction, and outcome. Adding the other skill adapters
would answer different questions and multiply cells.

## 2. Exact experimental unit and cells

Use two fresh **formation-only PCFL skeletons**, permanently excluded from
PCFL DEV, confirmation, parenting, and lifetime pools. Preseal `O=0` on root A
and `O=1` on root B. Both roots must pass the already-frozen full PCFL CPU cube,
collision, and scorer audits before this screen; only their OLD formation
prefix is exposed here.

The experiment has exactly:

```text
4 child states x 2 independent roots = 8 cells
0 new fits
```

The scientific replication unit for the treatment is the upstream optimizer
seed (`n=3`) over one fixed two-root transfer panel. The two roots are world
replicates, not 24 independent memories. OFF is one deterministic shared
reference, not three independently trained controls.

All adapters are mounted read-only from their sealed second-roster hashes.
There is no adapter averaging, selection, continuation, or promotion.

## 3. Exact world and interaction

Reuse the accepted PCFL v2 OLD topology and opaque-ID generator without
changing any route fact. The model never sees the mnemonic slot names.

Per root, present the eight OLD action receipts in their frozen chronology:

```text
e0: S_L --a_O--> A
e1: A   --b---> H
e2: H   --c---> G_L
e3: S_R --d---> B
e4: B   --f0--> G_R0
e5: B   --f1--> G_R1
e6: S_L --a_(1-O)--> X
e7: Z   --u---> Y
```

The supported LINK set is:

```text
e0 THEN e1 VIA A
e1 THEN e2 VIA H
e3 THEN e4 VIA B
e3 THEN e5 VIA B
```

### 3.1 Prescribed but genuinely executed actions

For each slot the public task says which already-public source and port to
exercise. It does **not** reveal the destination or receipt. The child must
emit exactly:

```text
PREDICT: <opaque_destination_or_UNKNOWN>
ACT: EXPLORE <source> VIA <port>
```

The final prompt lines contain the literal contract and one syntax-only example
whose node/port tokens come from a disjoint forbidden namespace. Copying the
example fails both parsing and world execution. The requested source/port is
the same across all four child states; each state receives a fresh reset copy
of the same world. A strict valid ACT is executed by the real environment once.
There is no retry, alias acceptance, parser repair, or extra action.

Supplying the action choice is intentional. This screen isolates whether an
authored perception skill transfers into record formation; it does not test
planning or autonomous exploration. PCFL's later reachout stage tests action
selection.

### 3.2 EVENT formation

Immediately after a valid action, return the ordinary public destination and
receipt. Then ask for exactly one line in the frozen PCFL grammar:

```text
EVENT <event_id> AT <source> DID <port> GOT <destination> EVIDENCE <receipt_id>
```

The request supplies the globally valid grammar and one reserved opaque EVENT
handle, but no completed row, destination, or expected answer. The child must
copy source, port, destination, and receipt from its own action/outcome. The
compiler either accepts the raw line unchanged or rejects it unchanged.

On events 1, 3, 5, and 7, include one earlier real action/outcome transcript as
a chronological distractor before the selected latest receipt. This prevents a
fixed first-receipt copier from passing while preserving actual history. The
selected receipt is identified only as "the action just executed," matching
the public interaction contract.

### 3.3 LINK formation

After all eight EVENT opportunities, make three target-free LINK requests over
the child's exact accepted EVENT lines:

```text
COMMIT ALL LINKS FROM <e0>
COMMIT ALL LINKS FROM <e1>
COMMIT ALL LINKS FROM <e3>
```

The request supplies only the source EVENT handle and the global grammar:

```text
LINK <link_id> FROM <event_id_1> THEN <event_id_2> VIA <shared_node> EVIDENCE <receipt_id_1>,<receipt_id_2>
```

The e0/e1 requests require one line each and the e3 request requires two lines,
sorted by child-visible event ID. Reserved opaque LINK handles may be supplied
as nonsemantic interface slots; no target EVENT, shared node, evidence pair, or
candidate LINK is supplied. If prerequisite EVENTs were rejected, the LINK
opportunity remains in the denominator and is marked
`NOT_CALLED_UPSTREAM_EVENT_FAILURE`; no fixed renderer fills it.

No old or future route goal is shown anywhere in this screen.

## 4. Strict thinker/compiler boundary

The child alone emits every action line and every semantic EVENT/LINK field.
The compiler may verify strict syntax, execute a strict ACT, join a record to
the exact public receipt, verify chronology, verify endpoint equality, and
accept/reject the complete raw span. It may expose the previously accepted
EVENT rows during initial same-context LINK formation, exactly as PCFL v2
allows.

It may not:

- turn a bare `TRY`/`EXPLORE` into `ACT:`;
- infer, repair, normalize, or render a semantic record field;
- omit malformed attempts from the fixed denominator;
- insert a Level-1 target, teacher text, hidden rule, route, goal, or answer;
- choose a more favorable action or regenerate after an error; or
- send any screen output into SLEEP, an adapter, or an authentic lineage.

The literal action grammar and reserved handles are interface scaffolds, not
learned intelligence. Record content remains child-authored.

## 5. Pre-inference CPU gates

All must pass exactly before any model load:

1. Both excluded roots pass the complete PCFL eight-world construct gate.
2. The 16 prescribed actions execute once and reproduce the bound 16 receipts
   under an independent oracle.
3. Those receipts support exactly 16 EVENT and 8 LINK rows; no other endpoint
   match is silently labeled authentic.
4. Every public prompt is byte-identical across the four child states for the
   corresponding root/slot.
5. Destination and receipt are absent from every pre-action prompt; complete
   EVENT/LINK strings and target semantic fields are absent from every
   formation request.
6. Syntax-example tokens, Level-1 train/held IDs, PCFL DEV/CONF IDs, and both
   excluded-root namespaces are pairwise disjoint where required.
7. A recursive leak scan finds zero future goals, hidden O/R/D fields, routes,
   scores, target arrays, candidate rows, or adapter labels in model-visible
   bytes.
8. The strict parser rejects missing/multiple/lowercase markers, fences, extra
   prose after commitment, copied syntax examples, mismatched receipt IDs,
   wrong endpoints, and unsupported LINKs.
9. Two independent reducers agree on all action, EVENT, LINK, format, content,
   source, and denominator labels for deterministic fixtures.

Any failure is `FBR_ASSAY_INVALID`; do not run.

## 6. Fixed metrics: content is primary, format is separate

Every scheduled opportunity stays in its original denominator.

### Actions, denominator 16 per state

- `action_content_valid`: source and port equal the prescribed public action;
- `action_strict`: exact two-line contract, no extra action or prose;
- `world_executed`: strict action executed once and returned the bound receipt;
- termination and example-copy counts.

### EVENT, denominator 16 per state

- `event_content_correct`: all five bound fields match the actual
  executed receipt;
- `event_strict`: raw bytes are exactly one canonical line plus LF;
- per-field correctness for ID, source, port, destination, and evidence;
- latest-receipt versus distractor selection; and
- missing/not-called/length/parse/source-rejection counts.

### LINK, denominator 8 per state

- `link_content_correct`: source/target/shared node/evidence are supported by
  accepted child EVENTs;
- `link_strict`: correct canonical lines, cardinality, and order with no extra
  bytes;
- precision over every proposed LINK, including extras and malformed lines;
- missing/not-called/source-rejection counts.

Do not strip fences or repair JSON/typed lines for strict scoring. A separately
declared diagnostic parser may remove exactly one enclosing Markdown fence and
score semantic fields, but its result never enters the compiler or lineage.

## 7. Noncompensatory gates and result labels

### 7.1 Technical availability

For every state require:

- action content and actual execution `>=15/16`;
- strict action form `>=14/16`;
- no copied syntax-example action; and
- no more than one action loss relative to OFF.

If any perception state fails this, use `FBR_ACTION_INTERFACE_FAIL`; do not
interpret its missing records as a perception deficit. If OFF and all three
perception states fail, the shared interface is invalid.

### 7.2 Formation availability

For each state report, without compensation:

- EVENT content `>=14/16` and strict `>=12/16` as the usable DEV screen;
- LINK content `>=7/8`, strict `>=6/8`, and precision `>=.80`; and
- whether either root independently achieved the PCFL formation requirement
  of exact `8/8 EVENT + 4/4 LINK`.

The relaxed pooled screen thresholds localize a usable direction; only the
root-exact conjunction qualifies that state for the existing PCFL formation
gate.

### 7.3 Level-1 transfer candidate

Let `C_s` be EVENT+LINK content correctness over the 24 opportunities for
perception learner seed `s`, and `C_OFF` the same fixed OFF vector. Label
`FBR_L1_TRANSFER_CANDIDATE` only if all three independent fitted seeds satisfy:

```text
C_s - C_OFF >= 3/24
EVENT_s - EVENT_OFF >= 2/16
LINK_s >= LINK_OFF
executed_action_s >= executed_action_OFF - 1
```

and the gain includes at least one latest-receipt/distractor correction rather
than only fence/whitespace removal. Strict output may improve or remain flat,
but content must move. Report all three paired win/loss vectors; do not pool
the 72 adapter opportunities as iid.

Result branches:

- `FBR_FORMAT_ONLY`: strict improves but content does not.
- `FBR_HEADROOM_ABSENT`: OFF is `24/24` content; formation is available, but
  this panel cannot identify a Level-1 contribution.
- `FBR_L1_TRANSFER_NOT_DETECTED`: technical gates pass but the three-seed
  content conjunction does not.
- `FBR_EVENT_CONTENT_FAIL`: action executes but EVENT content misses its gate.
- `FBR_LINK_CONTENT_FAIL`: EVENT passes but LINK misses its gate.
- `FBR_NONREPORTABLE`: custody, source, process, or reducer integrity fails.
- `FBR_RESOURCE_CAP`: the fixed execution budget is exhausted.

These labels do not select a seed for later use.

## 8. Exact execution and resource budget

Per child state and root, maximum model calls are:

```text
8 action + 8 EVENT + 3 LINK = 19
```

Across eight cells:

```text
64 action + 64 EVENT + 24 LINK = 152 model calls maximum
0 training calls, 0 fits, 0 optimizer updates
```

Output caps are 96 tokens/action, 160/EVENT, and 256/LINK request, for a hard
maximum of `6,144 + 10,240 + 6,144 = 22,528` generated tokens. A failed action
or prerequisite EVENT reduces actual calls; it never changes denominators or
creates a retry.

Run serially on one A40 with four fresh state engines. The controller hard cap
is **1,800 charged A40-seconds = 0.5 A40-hours**, including model load, calls,
teardown, and release verification; collection gets a separate CPU-only 180
seconds. Do not extend the GPU cap, add a fit, repeat a root, or replace a
failed state. This screen is cheap enough to run beside PCFL, not in front of
it.

## 10. Does PCFL v2 already subsume this?

**It subsumes formation availability, but not the Level-1 causal contrast.**

PCFL v2 already contains the stronger claim-bearing fact that a clean child
must execute public experience and form exact `8/8 EVENT + 4/4 LINK` rows on
each DEV root before any SLEEP. If that gate passes, another experiment is not
needed to show that authentic records exist. Its subsequent two-SLEEP test is
far more important than this screen.

PCFL v2 intentionally mounts no Level-1 birth adapter. It therefore cannot say
that an authored perception fit helped real formation. This screen can answer
that narrow transfer question without changing or contaminating v2.

Operational consequences:

1. Run PCFL CPU materialization and this zero-fit screen in parallel.
2. If clean OFF achieves the exact PCFL formation conjunction, keep PCFL v2
   unchanged regardless of the Level-1 contrast.
3. If all three perception adapters improve content but OFF fails, do **not**
   hot-mount the best one into v2. Preserve v2 as the clean-child test and
   propose a separately versioned born-child PCFL comparison using all seeds.
4. If PCFL v2's own DEV formation passes first, this screen becomes optional
   unless the manuscript needs the Level-1 transfer claim.
5. No result here can release SLEEP, retention, reachout, OLD+NEW reuse,
   parenting, or lifetime language; only PCFL v2 can release those next steps.

## 11. Strongest permitted statement

If `FBR_L1_TRANSFER_CANDIDATE` passes:

> Across three independently fitted adapters on a fixed two-root transfer
> panel, a researcher-authored Level-1 perception procedure improved exact
> source-content formation of EVENT/LINK records from strictly executed public
> actions and outcomes, relative to the frozen model, while preserving the
> action interface. The actions were prescribed and the record grammar was
> supplied; this is a development transfer result, not parenting or autonomous
> learning.

This identifies the complete perception-corpus-plus-fit treatment against OFF.
It does **not** isolate perception semantics from generic effects of a
same-dose authored LoRA, because the smallest screen has no matched wrong-skill
adapter. Add that control only if a later manuscript requires a
skill-specific causal claim; do not silently upgrade this result.

If OFF is at ceiling, say only:

> With a literal action contract, the frozen child and fitted perception
> children could form exact PCFL records from real public executions; this
> panel had no headroom to identify a benefit from Level-1 training.

If only format moves, call it serialization transfer. If actions do not
execute, call it interface failure. Never call any branch self-learning,
perception acquisition from life, SLEEP, or a flywheel.
