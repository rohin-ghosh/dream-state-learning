# Causal-occurrence source clarification v2: shared observed CURRENT

Builder, September13,2026. Supersedes only the selected-EVENT-owner condition
for CONTINUE/GOT in v1 (SHA256
`37398723e197fcba2b24a505f06395c311d3dfcd488e9fc4026d883f6aeb4b07`).
All other source restrictions and science/authority boundaries remain intact.
This corrects an overrestrictive Builder source predicate; no model outcome,
canonical material/null result, curriculum, target or metric is changed.

## Reason

The authentic B-family merge construction permits distinct EVENTs to have the
same GOT. In p21/m1 CLOSED CONTINUE, two already returned EVENT GOT fields equal
the latest observed CURRENT; only one EVENT was selected. The second occurrence
does not reveal an unseen destination: its exact bytes were already returned
and are now explicitly known as current state from the actual WORLD outcome.
Changing/deleting the row or history would corrupt the frozen construction.

V2 section8.2 of the Stage2A binding contract defines latest public CURRENT as
an explicit task-fact identity exception. It does not require all historical
occurrences of that node to belong to the selected EVENT. That owner condition
was added by Builder v1, not required by the underlying visibility contract.

## Exact replacement

For an operand-category CONTINUE occurrence in an authentic returned
`event_got` field, require equality to latest observed CURRENT, an exact
pre-decision service-field receipt, and a well-typed EVENT owner. Do not
require that owner to be the selected EVENT. Preserve the original owner and
service provenance; do not relabel it as a host/current field.

This permits neither a foreign EVENT ID nor its port/recovery query as an
operand. It permits only the already-public node identity in the GOT field.
Wrong/missing CURRENT, missing or ill-typed owner, unobserved/forged fields,
future-ledger entries, full scheduled actions, semantic aliases and registered
routes remain rejected. No new future identifier exemption is added.

Keep the original v1 finding and tests' historical receipt. Add a regression
for authentic shared GOT and retain the negative cases. A clear supplied
projection still proves neither inventory completeness nor native/scientific
readiness. This is not completion or enforcement of the deferred C11 guard.
