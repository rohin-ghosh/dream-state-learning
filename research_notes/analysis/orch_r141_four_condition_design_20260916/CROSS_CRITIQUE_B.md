## 1. Strongest defensible case

A correctly makes the hard comparison **L1 + responsive versus original +
responsive**, gives both arms online LoRA learning, and isolates one skill
family. It measures actual starts, treats a single L1 checkpoint as a conditional
initialization experiment, separates Markdown assistance from parameter retention,
and refuses reflection-plus-SFT as a completed SEAL comparator. Its explicit
resource envelope, private offline reward path, immutable snapshots and
capability uncertainty are substantially more testable than a narrative about
richness. Negative outcomes can be informative without expanding levels 2/3.

The plausible claim is narrow: under one specified task stream and teaching
policy, a particular Level-1 initialization improves subsequent file-free skill
acquisition relative to the original initialization, with measured preparation
cost and separately bounded capability loss. Neither A nor B yet supplies a
fully feasible, faithfully implemented four-condition experiment.

### CB-01 — Finite partition is not closed (blocking; evaluation)

**Evidence:** B §4 allocates 32 acquisition + 8 interference + 48 sealed tasks
under semantic-class disjointness. Main's enumeration gives only 97 classes:
`32 + 8 + 48 = 88`, leaving **9 for all remaining disjoint offline preparation,
development and calibration classes**. Online allocation fits; a credible full
allocation has not been supplied. Nine classes do not mathematically prove
SEAL training impossible, but neither volume of repeated prompts nor a nominal
task count demonstrates an adequate independent offline/development split.

A §§2/4 instead proposes constrained expression **repair**, including filtering
and aggregation, with 16 calibration + 64 outer-training + 16 development +
64 online + 64 sealed tasks: **224 nominal skill tasks**, excluding capability
items and separate reward queries. This is not B's enumerated grammar. We must
not claim Main's 97 directly describes A's unenumerated grammar. Conversely,
A's broader examples cannot silently become a repair for B's shortage.

If A's counts were interpreted as one distinct semantic class per task in B's
grammar, they would exceed it; even 64 online + 64 sealed would require 128.
Repeated tasks within a partition may reduce the number of classes required,
but then task count is not independent class count. A must state which unit is
disjoint: target function, bug class, program shape, support examples, or all
of them. Different buggy expressions with the same repaired function can be
different repair tasks without being different held-out target functions.

**Required resolution:** choose one explicit task regime; produce a finite
partition ledger with counts of semantic classes, templates, tasks, support and
reward queries, and allocation across all seeds. Record whether seeds reuse the
same classes or sample disjoint ones. Audit admissibility after equivalence
deduplication and demonstration-identifiability filtering, not before. L1's
historical material also needs overlap auditing; it need not consume an invented
fixed quota of these classes. Any allocation change must be explicit; any grammar
change is a new proposal delta requiring renewed binding. **No grammar expansion
is authorized or implemented by this critique.**

Affected: A-T1, A-T2, A-T6, A-T9; B-T02, B-T03, B-T05, B-T10; A-D1, B-D07.

### CB-02 — Initialization contrast does not isolate richness (material; scientific)

**Evidence:** A §2 appropriately calls A–B an initialization-package effect.
Retain that wording. The L1 arm has extra preparation, distinct initial
competence and possibly a different behavioral prior. Subtracting start scores
does not eliminate ceiling/floor effects or identify richness as mediator.
The same adaptive teacher policy can deliver different interventions; that is
a component of the responsive-system effect, not an uncontrolled failure by
itself. It also means the contrast is not a learner-only intrinsic learning-rate
effect under identical received instruction.

**Required resolution:** make the conditional package estimand primary, add
predeclared development-derived difficulty strata and absolute start/end/gain
tables, and explicitly prohibit richness-specific or teacher-independent causal
language. Parent configuration must be frozen and arm identity hidden from its
metadata; semantic behavior may still reveal the initialization. Match legal
opportunities, not exact parent wording. Historical unparented/frozen and adapter
OFF probes are explanatory controls, **not substitutes for original+responsive**.
The four arms do not establish H2's consolidation-dependent autonomous slope.
Do not secretly add a fifth preparation-matched arm to rescue a stronger claim.

Affected: A-T2, A-T5, A-T9; B-T04, B-T10, B-T12; A-D2, B-D01, B-D02.

### CB-03 — Match the replication unit and freeze the primary statistic (material; statistics)

**Evidence:** A uses one L1 checkpoint with three online seeds, but three
independently trained SEAL policies. That is a legitimate deployment-system
comparison if declared; it does not give equal preparation-level replication.
A makes endpoint near-transfer acquisition change primary and curve area
supporting; B makes baseline-adjusted curve area primary. These cannot remain
interchangeable after results arrive. A's curve mixes checkpoints spaced
0/16/32/64; B's proposed boundaries differ and include interference.

**Required resolution:** ratify one primary contrast, checkpoint grid, integration
rule and normalization, practical effect margin, missing-checkpoint handling,
and analysis population. Report separate uncertainty for task variation and
online/preparation randomness; do not pool checkpoint repeats as new independent
runs. Three seeds permit a small conditional study, not precise population claims.
If only online order changes across seeds, say so. Claims against SEAL remain
conditional on its declared training procedure and unequal preparation design.
Use one primary endpoint plus explicitly secondary contrasts, not the most
favorable of endpoint, AUC, near transfer and composition.

Affected: A-T9; B-T10, B-T12; A-D2, A-D4.

### CB-05 — Full-loop intent does not certify faithful SEAL (blocking; scientific)

**Evidence:** A §5 explicitly proposes a constrained reimplementation, not the
published-result reproduction. Its generated-data action space, rank-8 mapping,
two rounds, two reward queries, positive-edit filter and cumulative eight-task
online block updates need evidence-bound mapping to a selected primary method
regime. A also requires one live adapter starting from the trained policy. It
does not yet establish that the evolving inner-adapted adapter can serve as the
same self-edit policy without departing from that regime. Equalizing A/B/C's
update cadence is not, by itself, a fidelity argument.

Positive rewards on two already-easy queries can produce a policy-update receipt
without demonstrating useful adaptation. This is not a claim that the selected
published method requires improvement-relative reward. It is a request to show
pre/post/no-op diagnostic performance so positive selection is interpretable.
Zero positive edits, empty fitting rows, or ineffective outer updates cannot be
buried behind “two rounds completed.” Three independent policies magnify the
offline costs and need their own selection-lineage receipts.

**Required resolution:** pin official commit and primary regime; map every
component and deviation, specifying policy state versus temporary learner state,
reset/commit behavior, inner objective, outer objective and final online state
machine. Use only offline reward material; preserve rejected/failed candidates.
Bind a toy test proving reward-dependent outer learning and actual inner updates,
plus transparent no-op diagnostics on development material. Adjudicate whether
the constrained implementation satisfies R121's faithful comparator requirement.
If not, label it correctly and leave the four-condition claim incomplete;
ratification cannot make an inaccurately described method faithful.

Affected: A-T4, A-T6, A-T10; B-T05; A-D3, B-D03.

### CB-06 — Markdown memory capacity conflicts with the write envelope (material; evaluation)

**Evidence:** A permits a **1,024-token whole-file replacement** after each task,
but the persistent-write slot permits only **512 generated tokens**. If the
entire replacement must be generated in that slot, its effective capacity is
at most 512, not 1,024. Chunking, carrying forward text, or patch semantics might
resolve this, but none is the declared whole-file replacement protocol. B's
2,048-token file proposal is a different unratified option, not a resolution.

**Required resolution:** choose an attainable file/write specification, with
no hidden extra call. Bind serialization, tokenizer, truncation/failure behavior,
read frequency and file-selection rule. Keep learner-written memory as the
explicit comparator; do not generalize it to the best possible teacher-authored
Markdown guidance. Report file-present application and file-absent retention as
different endpoints. Beating file-absent frozen Markdown alone is structurally
expected and cannot establish superiority to useful external memory. A's
absent-versus-start invariance and leak check should be retained.

Affected: A-T5, A-T7; B-T06, B-T09; A-D7.

### CB-07 — Visibility needs noninterference, not only access checks (blocking; visibility)

**Evidence:** A's default-deny matrix and post-lock scoring are strong. Still,
“scorer/analyst only after all acquisitions and selection are locked” needs an
executable definition: who can inspect intermediate prompts, malformed outputs,
per-task timeouts, status text and cached files? Canary absence proves only the
tested channel, not every indirect leakage route. A parent sees earlier block
events; its local memory must not carry across arms or repetitions. Offline
reward optimization is legal only inside its declared partition, not a hidden
exception permitting final scores into the parent/self-editor.

The small public grammar presents a separate threat: a teacher or synthetic
self-editor can generate candidate programs belonging to held-out semantic
classes without reading sealed files. That is not automatically a visibility
breach, but it can violate a semantic-class-disjoint training claim. Shared
primitive definitions are legal task knowledge; generated worked solutions and
training examples require a declared overlap policy. Hashes of task IDs alone
will not catch equivalent generated examples.

**Required resolution:** post-trajectory readouts or mechanically isolated
embargoed outputs; permission/transport/cache allowlists; quarantine evaluation
generations from all fitting and selection paths. Add a test that perturbs
hidden verdicts and verifies unchanged curriculum, replay admission, checkpoint
choice and scheduling. Audit generated adaptation rows and earlier L1 material
for semantic overlap under the frozen rule. If overlap cannot be ruled out,
narrow the split/transfer claim rather than claim pristine held-out classes.

Affected: A-T2, A-T3, A-T4, A-T7; B-T02, B-T07, B-T08; A-D5, B-D05.

### CB-08 — Generic transfer curves do not isolate forgetting (material; scientific)

**Evidence:** A §6 calls earlier-checkpoint near-transfer performance through
task 64 “skill retention through later acquisition.” This measures performance
while further same-family training occurs, but improvements and losses can
cancel on the aggregate battery. Without tagged earlier-acquired competencies
or a declared interference contrast, it does not isolate forgetting of an
earlier skill. Reload reproducibility is persistence across process resets,
not evidence of resistance to interference or long-term forgetting. B's eight
interference tasks are also only a proposed challenge, not an automatically
validated interference manipulation.

**Required resolution:** label existing A curves as fresh-task skill performance
through acquisition. To claim interference resistance, predeclare the exposure
and readout subsets and identify which earlier competence they measure; preserve
paired per-item changes rather than only an aggregate. Do not add interference
tasks without charging their finite partition and resource costs. Keep source-
free legitimate task specifications/examples in prompts; both A and B are
correct that file-free does not mean an underspecified task.

Affected: A-T7, A-T9; B-T08, B-T10; A-D5.

### CB-09 — Fixed capability panel and margins require reconciliation (blocking for preservation claim; statistics)

**Evidence:** A proposes a new 128-item panel and preserves the historical
32-item panel separately. B calls for the fixed existing capability panel and
requires intake if a canonical version is unavailable. These are different
panel contracts. A's 5-point overall/10-point domain margins also differ from
B's candidate 5-point domain bound. Neither can be selected after outcomes.

With 32 items/domain, one item's correctness is **3.125 percentage points**;
three net losses are 9.375 points and four are 12.5. With 128 pooled items,
one item is 0.78125 points. These are score granularities, not confidence bounds
or a power calculation. Running two prompt variants on the same items does not
double independent capability coverage. Baseline and acquired answers are
paired; multiple domains and two prompt variants need a prebound claim rule.

**Required resolution:** name/hash the mandatory existing panel, any proposed
additional panel, and the primary versus diagnostic prompt modes. Never silently
replace the original panel. Bind margins, sampling population, uncertainty method
and multiplicity interpretation before outcomes. If the fixed battery is a
census diagnostic, distinguish exact finite-panel changes from population
generalization. Require both original-base and arm-start comparisons. Preserve
A's sound adapter-OFF/scaling diagnostics but do not let diagnostic recovery
excuse capability loss at the primary adapter setting. Insufficient precision
means preservation unestablished, not demonstrated by non-significance.

Affected: A-T8, A-T9, A-T10; B-T11, B-T12; A-D6, B-D06.

## 4. Adjudication questions and disconfirmation

Main should resolve, then obtain the required exact-scope human ratification:

1. Which task regime is intended, and what feasible partition closes the
   offline/development/online/final allocation? B's grammar stays unchanged
   unless a new explicit proposal replaces it; A's unenumerated grammar is not
   an already-approved fallback.
2. Is the paper's primary result endpoint gain or gain-AUC, conditional on one
   L1 checkpoint? Which practical effect and capability-loss margins apply?
3. What exact primary-source mapping qualifies C as the requested SEAL baseline,
   and what happens if no effective outer learning occurs within the cap?
4. What attainable Markdown file/write budget and evaluation setting is being
   compared, and which efficiency claims survive unknown preparation costs?
5. Which fixed capability panel is mandatory, what is added rather than replaced,
   and which limited retention/transfer claims do the exposure schedule identify?

The meaningful L1 advantage is disconfirmed in this regime if sufficiently
precise paired gain evidence excludes the prebound practical benefit, or favors
original+responsive. Imprecision is inconclusive. A higher starting level alone,
longer prose, a parser-only gain or a win solely over file-removed Markdown does
not establish retained-acquisition advantage. Loss beyond the capability bound
defeats the combined preservation claim. Unfaithful SEAL or contaminated final
data invalidate the relevant comparison rather than count as a negative result
for the scientific hypothesis. A result can support a conditional online gain
while failing a lifecycle-efficiency or SEAL-superiority claim.

**Final disposition:** retain A's bounded question, essential original+responsive
control, dual Markdown readouts, honest costs and source-free evaluator. Require
explicit rework of finite partitions, primary numerics, SEAL state/fidelity,
Markdown capacity and capability-panel continuity. Original B is preserved with
its 97-class feasibility concern now recorded here for adjudication. Nothing in
this critique authorizes implementation, grammar widening, launches or claims.
