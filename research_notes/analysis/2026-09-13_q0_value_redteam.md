# Q0 value red-team: useful kill gate, not the own-experience result

**Date:** 2026-09-13 UTC

**Role:** fresh independent value/claim audit

**Scope:** analysis only. I changed no builder source, test, threshold, model,
tokenizer, adapter, job, GPU state, or scientific result.

## Verdict

Run **one valid Q0 development root next**. It is the cheapest clean test of
the writer failure that has repeatedly blocked the project: can this exact
rank-8 recipe install opposite input-conditioned native actions without
turning them into a global habit or damaging nearby behavior?

But Q0 is a **writer kill gate, not the paper's causal experiment**. Requiring
all three Q0 roots before even opening a disposable own-experience test is not
the highest-information path toward Dream--LoRA--Think. If the first valid Q0
root passes, freeze it, run the two unchanged Q0 repetitions in parallel, and
immediately start one excluded, one-SLEEP endogenous relay on the same action
surface. The extra Q0 roots buy reliability for a narrow supplied-policy
claim; the endogenous relay buys the first evidence about the actual thesis.

This distinction matters because the executor is still absent
(`gpu/astra_pairwise_q0.py` and `tests/test_astra_pairwise_q0.py` do not
exist), while the estimated GPU cost after implementation is only 15--35
minutes per two-fit root. Q0 is high information per **GPU-hour**, but its
large bespoke objective/canary/reducer implementation makes it less obviously
dominant per engineering day.

## Shortest experiment that really tests own-experience learning

The next causal unit should be a **parent-free, one-SLEEP endogenous relay**,
not the full parenting or two-SLEEP connected-memory study.

1. On a fresh, Q0-disjoint opaque root, the child commits real actions in two
   visible modes and receives later public success/failure outcomes.
2. After the outcome, the child itself emits either `NULL` or one scoped
   conditional action record with citations to those executions. The compiler
   may verify and copy exact child bytes; it may not fill an action, relation,
   or answer.
3. Fit two equal-dose states from the same clean start using the Q0-qualified
   action surface: `AUTH` from the admitted child records and a predeclared
   mode-swapped/binding-swapped control. Keep an adapter-OFF or shadow state.
4. Delete context, ledger, record, and source events. On new objects and held
   wording, require AUTH to follow the lived map, the swapped write to redirect
   to its complementary map, and OFF/shadow not to gain.

One excluded root and two small fits are enough for a kill test. This is the
first minimal edge that satisfies Rohin's vocabulary for **learned**: the
model prepares the material that later changes its weights. It does not yet
test parenting, connected knowledge, a second SLEEP, or a lifetime slope.
Those belong after this edge exists. The existing
`2026-09-12_minimal_decisive_h1_parent_dream_sleep_bridge_protocol.md`
contains the fuller controlled version; removing the parent factor yields the
shortest substrate test rather than weakening its provenance logic.

## Three pre-GPU weaknesses that must be made explicit

### 1. Q0 does not presently qualify the M-core read interface

Q0 trains the first divergent token of `ACT: -mem2reg` versus `ACT: -gvn`.
The candidate-free M-core closure instead requires a goal-blind memory process
to generate `MISS` or one **complete MemoryRow**, with no answer-bearing
candidate available. The closure checklist currently says Q0 must qualify
exact row generation on the same renderer/grammar/runtime. The present Q0
cannot satisfy that sentence.

This is not a defect in Q0's bounded action-writer claim. It is fatal only to
using a Q0 pass as the automatic release of M-core. Either:

- scope Q0 explicitly to action carriage/H1 and add a later generative-row
  carrier gate for M-core; or
- make the downstream endogenous relay use Q0's exact action surface and do
  not claim that M-core's MemoryRow writer was qualified.

### 2. A Q0 pass does not validate the current birth/SLEEP recipe

Q0 uses a `3e-5` pairwise common-prefix loss. The separate birth path uses a
`1e-4` full-response objective. The repository correctly says neither can
compensate for the other, but that also means Q0 is only upstream of the full
architecture if the next endogenous test actually reuses its qualified
writer surface. Otherwise Q0 and birth are two unrelated supervised-policy
assays, and Q0 becomes paper-oriented detour rather than mechanism risk
reduction.

### 3. The archived first root is development, not a fresh confirmation unit

The first material is the old, repeatedly inspected root-1 Q0 surface. It is
appropriate for implementation and DEV classification, but prose saying
“three fresh roots” would be false if it counts this root plus two new ones.
A strong paper claim needs either `DEV + 2 frozen repetitions`, described
exactly that way, or three newly generated opaque confirmation roots after the
DEV recipe freezes. Before those roots exist, pin an output-blind
root/optimizer-seed allocation manifest as the executor-gap audit already
requires.

Also preserve the public model binding now resolved for prospective work:
`Qwen/Qwen2.5-7B-Instruct@a09a35458c702b33eeacc393d103063234e8bc28`
plus the complete local model/tokenizer hash inventory.

## Recommended order

1. Build and validate the closed Q0 executor; do not add another birth/prompt
   repair to it.
2. Run one valid DEV root and classify it failure-inclusively.
3. On a full pass, freeze immediately, launch the two Q0 repetitions, and in
   parallel implement/run the one-root endogenous relay above on the same
   action writer. Do not wait for paper-grade replication to learn whether the
   own-experience edge exists.
4. Only after the endogenous edge passes should connected two-SLEEP M-core,
   parenting, and lifetime branches consume clean lineages.
5. If Q0 fails, follow its registered subtype. Do not convert a recipe-specific
   early miss into a general impossibility claim, and do not spend clean
   children on a writer that failed exact/held/locality.
