# Adversarial review: does the connected relay measure memory or scaffolding?

Date: 2026-09-12 UTC

Status: watcher-side design review only. No source, model, adapter, job, GPU,
claim, or release authority. No builder code or run was touched.

Reviewed current sources include the end-to-end synthesis; the fresh connected-
memory audit; Learned-PCFL V5 `exact_scope.md` at SHA-256
`6bcef58e...823a`; its `REWORK` review; the exact finite-reader source; the
active-text role amendment; and the exact V3 sections V5 still imports.

## Verdict

With a few cheap but non-negotiable repairs, M-E2/E4/E5 can establish a useful
**bounded, compiler-mediated causal relay**:

- a grounded two-atom co-use record carried by a LoRA affects later behavior;
- a goal changes which records a clean actor queries and follows through an
  exact one-hop reader; and
- an old record changes an information-seeking action, whose public outcome is
  committed into a cumulative old-plus-new carrier and later used.

As written, the proposal cannot yet support even that release. Its current
bytes are not bound by the review receipt, the disposition is `REWORK`, the
finite world/endpoint registry is not closed, and two scientific seams can
let the action blueprint or reader provide the claimed connection/signal.

Even after repair, the result is not native graph learning, a learned search
policy, post-outcome child-authored interpretation, persistent online adapter
growth, recurrence, or agentic open-world expansion. The exact reader,
compiler, schema, and clean resolver are declared parts of the system. The
paper must say so.

The compiler is not automatically a confound. Selecting one member of a
precommitted map from a public outcome is a legitimate transactional grounder
if it is total, target-blind, capability-separated, never repairs content, and
missing/false proposals remain adverse. It does mean the result is
**compiler-mediated**. A native self-interpretation claim would need a separate
endpoint in which the child determines the post-outcome interpretation without
an answer-selecting compiler.

## Minimum controls before any M fit

1. **Authorship-before-blueprint.** Move `COUSE_PROPOSE` before every public
   field that reveals the support action's atom arguments. Bind support after
   execution. This changes chronology/schema, not GPU count.
2. **Carrier-origin receipt.** For every positive READ, bind
   `training-row bytes -> published carrier -> raw reader output -> actor-visible
   bytes`. Positive arms may not use a semantic return substitution. Cuts and
   twins may intervene only in explicitly negative/redirection cells.
3. **Oracle air gap.** Run actor and reader in a fresh process that cannot
   import/open the generator, theorem, compiler receipts, hidden truth, scorer,
   oracle policy, or expected trace. Re-run the same exact-text transcript with
   those artifacts absent and require byte-identical visible inputs/returns.
4. **Proxy and address audit.** Finish the exact world algebra, semantic-
   independent opaque IDs, and exhaustive shortcut proof over goal bytes,
   catalog order/type, action menu, query/address incidence, HIT/MISS pattern,
   lengths, and four-read enumeration. Add catalog-order and surface-form
   permutations; semantics-preserving permutations must preserve value, while
   truthful semantic twins must redirect it.
5. **Content-specific exploration.** Add a Phase-C truthful twin, not merely an
   irrelevant sham. Two equally supported old relations must imply different
   unique maximum-EIG actions; the observed query/action/map/outcome row and D
   action must all redirect. This distinguishes using old content from reacting
   to the presence of a salient row.

These are stronger than asking whether the scripted oracle scores 1.0. The
oracle is a positive fixture only; it supplies no evidence about where the
model's behavior came from.

## Information per GPU-hour

Use the following kill order; `K` is the maximum transactional writer
candidates per requested adapter.

1. **Zero M fits:** re-review the current proposal bytes; close the world,
   endpoint, signal-match, and actor-visible-address contracts; run the
   authorship-before-blueprint assay, oracle air-gap, carrier-origin, mutations,
   and exhaustive proxy proofs on CPU.
2. **Inference only:** run exact text on four fixed DEV roots with the new
   catalog permutation and Phase-C semantic twin. Stop if fewer than 2/4 pass
   E2+E4, if the child cannot propose links before the blueprint, or if any

3. **First LoRA kill gate:** on two presealed roots, build only `AUTH_OLD` and
   truthful `LINK_NULL`: `2 roots * 2 builds * K = 4K` candidate fits. Reuse
   the authentic adapters for goal swap, cut/twin, catalog permutations,
   adapter-off, and cyclic wrong-life inference. This is a kill gate, not an
   E2/E4 release.
4. **Only after E2+E4 survive:** add `EDGE_NEW` and `SHAM_NEW` on those roots,
   another `4K` candidate fits. Reuse the old adapter for no-write and execute
   the Phase-C truthful-twin and D redirection/cut controls before widening the
   root count.
5. **Optional stronger expansion:** one incremental old-to-old+new update per
   root adds `2K` fits at the two-root gate. Spend this only if the intended
   sentence is persistent parametric expansion; otherwise keep the narrower
   cumulative-reconstruction claim.
6. Fill `NONLINK_PAD_TARGET`, separately built derangement, spill/interface,
   and the complete frozen deck only after the core survives. At most eight
   unpooled M-DEV roots may estimate feasibility/covariance; fresh confirmation
   remains separately powered by endpoint.

This ordering makes the decisive new controls free or inference-only and uses
already-required builds for the first learned-memory contrasts. E5, the second
write, and any sequential-update claim remain downstream of a demonstrated
connection and goal redirection.

## Claim firewall

If all repaired typed endpoints pass, the strongest accurate sentence is:

> In a finite benchmark, compiler-admitted records grounded in the child's
> public actions and outcomes were carried by a per-root LoRA; a clean actor
> selected exact one-hop reads differently under different goals, and one
> public outcome selected a precommitted new record whose cumulative carrier
> later supported an old-plus-new action.

Use **child-discovered connection** only if proposal precedes the action
blueprint and exceeds the frozen matched-pair chance policy. Use **old memory
selected the experiment** only if the raw mounted-carrier signal and truthful
semantic-twin redirection both pass. Use **persistent expansion** only if a
sequential update retains old content while adding the new row. Otherwise,
`connected carriage`, `typed functional traversal`, and `one-cycle
compiler-mediated cumulative reconstruction` are the defensible endpoint
names.
