The proposed task is a good replacement for SEQ160's brittle NOTE schema. It
scores real choices in a deterministic world and can test process tutoring.
It is not ready to launch verbatim. The fixes are local; there is no need to
redesign the parenting thesis or wait for PCFL composition before Gate 0/1.

## 1. Task headroom and shortcuts

The present six constructor bullets are necessary but not sufficient. They do
not bind the number of devices/probes, posterior sizes, decision-tree depth,
or whether adaptive probing is ever necessary. A family can satisfy “all rows
distinguishable within three probes” while one fixed three-column script solves
every task. That would test table lookup, not deciding which question is worth
asking.

Before material generation, bind one exact task class and exhaustively certify:

1. a fixed candidate count of at least six, a fixed probe count, and a uniform
   hidden-device prior within every balance block;
2. an oracle adaptive decision tree that identifies every device within three
   probes, with at least one genuine depth-three path;
3. no single probe resolves a device, no fixed nonadaptive set of three probes
   resolves every device, and at least two different second probes are required
   on different outcome branches;
4. every valid CHOOSE label is surface-symmetric before evidence, and row,
   column, device, answer, optimal-first-probe, and first-outcome positions are
   exactly balanced;
5. independent matrices for source and apply tasks—not the same table under an
   opaque renaming—and independent matrices again for calibration, localizer,
   canary, and withdrawal-exam banks; and
6. exact scores for fixed row/column rank, first/last probe, repeated probe,
   fixed three-probe sequence, majority outcome, choose-without-evidence, and
   every public ID/order singleton and relevant pairwise projection.

“Homologous” should mean independently generated under the same predeclared
difficulty/process stratum. It must not mean isomorphic table, shared hidden
row, shared outcome code, or shared permutation. Otherwise a source-specific
hint can become an answer hint on apply.

Materialize and hash **all** Gate 0, source, apply, canary, localizer-rule, and
Gate 3 banks before the first Gate 0 output. Gate 0 may stop the version, but it
may not select another candidate count, difficulty stratum, or generated bank.
The present `3/12`--`8/12` child range is a reasonable DEV headroom rule once
the task itself is fixed. The shallow-policy bound is a deterministic
pre-model certificate, not a statistic to infer from twelve child tasks.

## 2. The action loop and call count are currently undefined

The task permits free THINK before actions, while the cost table assumes four
calls total (`3 PROBE + 1 CHOOSE`). Those cannot both be true unless prose and
actions share an unstated parser. This is exactly the kind of interface seam
that made SEQ160 uninformative.

The smallest clean contract is a strict one-line union:

```text
THINK <one nonempty physical line>
PROBE Q_<opaque>
CHOOSE H_<opaque>
```

Give every arm the same maximum of four THINKs, three PROBEs, one CHOOSE, eight
physical generations, 256 tokens per turn, and 2,048 generated tokens per
task. A repeated valid PROBE consumes a probe. An unknown ID, mixed command,
wrong family, malformed output, cap exhaustion, or failure to CHOOSE is a
terminal failure without extraction or repair. THINK is not scored except as
a separately reported diagnostic.

Another exact common controller is acceptable, but it must be frozen before
materialization and the arithmetic must use its real physical-call cap.

## 3. ALIGNED/YOKED is useful but incomplete

The crossed two-task yoke is well motivated. Within a round both arms receive
the same two exact corrections, parent-contact count, and message distribution;
only correction/task pairing changes. Preserve that design with these binding
details:

- A and B parent calls start independently from the byte-identical pre-round
  notebook and receive only their own completed source trajectory;
- the parent sees no apply table, apply ID, apply hidden answer, or future
  task-selection information while writing either correction;
- both source/apply pairs and their A/B assignment are presealed;
- the same correction bytes are mounted once aligned and once crossed, with no
  regeneration, rewriting, semantic “cleanup,” or favorable replacement; and
- identical or generic corrections remain valid observations and normally
  drive the contrast toward zero; they are not regenerated to manufacture
  alignment.

But YOKED can hurt simply by directing attention to the wrong issue. Therefore
`ALIGNED - YOKED >= 4/16` does not by itself establish that aligned teaching
helped. Add one **NO_PARENT** disposable copy on each of the same 16 apply
tasks. It receives no teaching message, the same task/action budgets and paired
decode schedule, and never enters either fit. All three copies receive the same
generic opportunity to state a plan in a THINK turn; the corrected copies may
refer to their supplied lesson, while NO_PARENT is not forced to invent one.

Gate 1 should require both:

```text
success(ALIGNED) - success(YOKED)     >= 4/16
success(ALIGNED) - success(NO_PARENT) >= 4/16
```

Keep the prebound-half and action-quality checks, applying no-worse invalid,
repeat, and outcome-inconsistency requirements against both comparators. This
supports “aligned tutoring helped now.” Without NO_PARENT, narrow the result to
“own-diagnosis correction outperformed a crossed correction.”

Because all children are tensor-identical copies, `OWN_DIAGNOSIS` and
`CROSS_YOKED` are more exact arm names than implying stable distinct child
identities. The experiment tests contingency to a trajectory, not personal
identity.

## 4. Parent and notebook feasibility/leakage

“Strongest reproducibly bound model available at launch” is not an executable
identity. Before Gate 0, bind one exact endpoint/model revision or immutable
local checkpoint, system prompt, decoding, context/output caps, tools, files,
privacy boundary, retry rule, and maximum input/output tokens. A provider model
without a snapshot revision can be timestamped and receipt-bound but must be
described as service-version limited, not exactly reproducible.

The parent sees the source hidden answer, so source/apply independence does
most of the causal safety work: even subtle source-answer leakage cannot name
the independently sampled apply answer. Still enforce the stated direct-answer
rules on correction text. A failed literal or semantic hygiene check invalidates
Gate 1 and prohibits fitting; do not regenerate the message. Count every
independent semantic-review or answer-swap call in the parent budget.

The 8-KiB notebook and 384-output-token “complete replacement” do not compose:
a full legal notebook can exceed the parent's output cap. Retain the 8-KiB
state but use the v5 mechanism already ratified: one bounded schema-validated
**patch**, applied deterministically and atomically. The patch may add/revise
one teaching hypothesis and one recent summary; it may not rewrite arbitrary
history. Bind the patch grammar and rejection behavior in advance.

Notebook model-visible content may contain abstract process errors,
interventions, predicted effects, aggregate outcomes, and evidence references.
It may not contain task/probe/device IDs, tables, answer positions, raw bit
sequences, exact hidden answers, future-bank data, or reusable generator
surface rules. Each round's two correction calls use the old notebook;
promotion occurs only after both applications. Require eight valid/rejected-
but-recorded transitions with no silent fallback. Notebook updates see aligned
application outcomes only, as proposed, so the resulting effect is the
adaptive-parent package—not evidence that notebook adaptation itself helped.

Destroy the DEV notebook after this experiment. Reusing it in a later clean
development or deployment claim would be a declared parent bootstrap and a
new lineage, not continuation of a clean parent.

Twenty-four primary parent calls is correct (`16` diagnoses + `8` patches).
It is not a hard total if semantic leakage review or counterfactual checks use
models. The proposed `0.5` H100/A100-hour and API budget are forecasts until
the exact parent, context lengths, check calls, and serving rate are bound.

## 5. Corpus and mask equivalence

The crossed yoke gives both fits the same parent-message multiset, source/apply
task multiset, and common struggle anchors. That is strong. Correct these
remaining ambiguities before Gate 1, because post-outcome corpus design would
invalidate the later comparison:

- parent corrections, task text, environment outcomes, and memory/notebook
  text are loss-masked **inputs** only;
- public outcomes occur chronologically in the training conversation but are
  not targets;
- only exact accepted child restatements, THINKs, PROBEs, and CHOOSEs are
  supervised targets;
- invalid/uncommitted drafts are not converted into valid targets, and failed
  but valid behavior remains without outcome-based filtering;
- all 16 common struggles and all available P/N application continuations are
  included by a prospectively fixed rule; and
- the exact tokenizer, segmentation, truncation, EOS, mask, and worst-case
  context-fit rule are frozen and CPU-checked before Gate 1.

Loss-masking a parent message does not make it causally absent: the gradient
on the child's response is conditioned on that message. That is lawful here
and matches v5. Gate 3 must therefore be described as testing whether a policy
learned under parent conditioning transfers after withdrawal.

Equal examples/updates are not automatically equal write dose when child
continuations have different token counts. Use one of two prebound choices:

1. a per-child-turn mean loss so every paired continuation has equal total
   loss mass, with loss-masked padding to equalize paired tensor shapes; or
2. the already retention-qualified token-mean objective, plus a prospective
   target-token-ratio tolerance and `DOSE_MISMATCH` stop if P/N fall outside
   it.

The first is cleaner but must itself be included in writer qualification. The
second changes the claim to episode/update-matched rather than “equally dosed.”
Do not post-hoc drop verbose thoughts or repeat favorable rows to equalize
tokens.

## 6. Gate 2 localizer needs one substantive repair

The original child produced every training target. Replaying the exact prefix
with the same child and generation seed can therefore reproduce the target
without learning. The proposed requirement that native exact next-action
recovery “improve on `6/12`” has no stable headroom and should not gate the
writer.

Keep Gate 2 explicitly as a memorization/acquisition assay:

1. Before fitting, predeclare the first eligible accepted action decision in
   each of the first twelve complete apply tasks per arm; do not select easy or
   correct actions after training.
2. For each prefix, enumerate every grammar-valid action available at that
   state. Score the complete exact target action against this fixed candidate
   set by length-normalized teacher-forced log probability.
3. Define `delta` as adapter minus unchanged-child target log-odds under the
   exact training prefix. Require positive delta on `9/12` and median delta at
   least `+0.5` nat, as proposed.
4. Remove native exact regeneration from the gate. If retained, use a new
   presealed decode schedule and report it as a formatting diagnostic only.
5. Repeat the same scoring after replacing the teacher turn with one frozen
   no-parent boundary. Report this withdrawal bridge separately; Gate 3 owns
   the behavioral claim.

Run all twelve without favorable replacement, including wrong but valid
targets. Exact prefixes make this a source acquisition localizer, not evidence
of a good or general policy. N must pass the same acquisition and interface
gates; otherwise P-minus-N remains confounded by unequal writer operation.

## 7. Gate 3 is a withdrawal exam, not delayed retention

Eight parent-free filler tasks with no write followed by complete KV/context
destruction cannot change a stateless adapter. They create wall-clock theater,
not a retention challenge, and the table undercounts them as one call each.
Delete them.

After Gate 2, destroy all actor conversations, KV state, parent state,
notebook, retrieval state, and task-local caches; reload unchanged/P/N states;
then run the presealed 32-task panel. Call it a **parent-withdrawal fresh-task
exam**. A genuine delayed-retention test would require an intervening qualified
unrelated write and belongs in a later version.

The existing Gate 3 P-versus-N and P-versus-unchanged conditions are directionally
sound: P-N isolates the different child material induced by aligned versus
yoked conditioning, while P-base prevents a win created only by N degradation.
Keep exam tasks independently generated and keep the four eight-task blocks
balanced by task strata rather than chronology.

One P/N fit pair is one exploratory lineage. Even if all thresholds pass, the
claim must say “in this predeclared DEV lineage.” General adaptive-parenting or
reliable causal efficacy requires independently grown parent/child lineages,
not 32 tasks or four blocks treated as replications.

## 8. Corrected maximum-call arithmetic

The published `756` child-call hard total assumes no separately callable
THINK and counts eight filler **tasks** as eight calls. Under the concrete
four-THINK controller above and the necessary NO_PARENT apply branch, the
conservative maximum is:

| stage | maximum child/reader invocations | parent invocations | fits |
|---|---:|---:|---:|
| Gate 0: 12 tasks x 8 generations | 96 | 0 | 0 |
| 16 source struggles x 8 | 128 | 16 | 0 |
| 16 apply tasks x 3 arms x 8 | 384 | 0 | 0 |
| eight notebook patches | 0 | 8 | 0 |
| Gate 2 exact/withdrawn scoring plus paired canaries | up to 144 | 0 | 2 |
| Gate 3: 32 tasks x 3 states x 8 | 768 | 0 | 0 |
| **maximum** | **1,520** | **24 + hygiene calls** | **2** |

Teacher-forced localizers may be batched, and most tasks will use fewer than
eight turns, so this is a hard envelope rather than expected usage. But the
current `1.5--2.5` aggregate A40-hour forecast and `4.0` hard cap are not yet
validated for this corrected controller. Benchmark one sealed smoke, then bind
the resource cap before execution; do not infer it from the erroneous 756-call
table.

## 9. Smallest closure that licenses Gate 0/1 now

Gate 0/1 may run before EVENT retention if and only if a short immutable
preparation binds:

1. all task banks and deterministic shortcut certificates;
2. exact THINK/PROBE/CHOOSE controller, caps, reducer, and terminal semantics;
3. independent source/apply construction and the three apply arms
   `OWN_DIAGNOSIS`, `CROSS_YOKED`, and `NO_PARENT`;
4. exact parent endpoint, isolated per-trajectory parent calls, patch notebook,
   hygiene rules, and complete call budget;
5. future corpus extraction/tokenization/masks and a worst-case context-fit
   certificate, although fit dose remains unset;
6. raw custody, no retry, and one frozen Gate 0/1 stopping reducer; and
7. quarantine of every task, output, and parent notebook from PCFL, clean child
   lineages, and later deployment data.

This closure requires no LoRA and no retention result. After it passes, the
GO is only for the no-fit immediate teaching question.

Gate 2 remains blocked until an acquisition-capable, non-destructive writer
objective/dose is prospectively qualified. SEQ188's `0/4` state cannot serve
as that writer. Gate 3 remains blocked until both P and N pass the corrected
Gate 2. Neither branch needs the PCFL READ-to-STEP mechanism.

## Final recommendation

**Do not launch the present memo verbatim. Amend it, then GO for Gate 0/1
only.** The world-task direction and crossed-yoke control are good. The smallest
scientific repairs are an actually adaptive task certificate, a typed thought/
action controller, an unparented apply comparator, an atomic notebook patch,
correct loss accounting, and a probability-based acquisition localizer.

**NO-GO for fits and withdrawal behavior today.** Wait for writer acquisition
and no-harm qualification, then run exactly two fits without reopening the
teaching outcomes. Remove the no-op filler and describe a passing final panel
as parent-withdrawn transfer in one exploratory lineage—not delayed retention,
general parenting, or a paper-level causal result.
