## 0. The one claim and the one lineage

Conditional on one target/topology-disjoint M-COMBINE-selected `BIRTH`
adapter, TSJ-v2 asks whether this exact longitudinal conjunction can occur:

```text
scheduled child action -> public OLD outcome -> exact child EVENT
two independently witnessed indispensable EVENTs -> exact child LINK
same-adapter SLEEP 1, replaying the exact selected BIRTH tape
fresh actor episode, no mounted autobiographical/content store
self-issued one-record READs -> OLD-dependent held STEP
that authentic route opens a fresh, precommitted public observation
child action -> public NEW outcome -> exact child EVENT and crossing LINK
same S1 tensors -> SLEEP 2 with OLD + NEW + exact BIRTH replay
fresh actor episode -> delayed first STEP jointly dependent on OLD and NEW
```

The authentic tensor lineage is exactly:

```text
BIRTH -> S1_AUTH_LINKED -> S2_AUTH_OLD_NEW
```

Fresh optimizers do not create fresh children. The S2 fit starts from the
exact S1 adapter tensors, not BIRTH. THINK is the actor loop, DREAM is the
fixed preparation of admitted experience, and SLEEP is the continued write.

This is a **paired two-world DEV demonstration conditional on one BIRTH
child**. The worlds are intentionally complementary, not independent. Goals,
worlds, cuts, arms, and decodes are not independent n. No reliability,
parenting, lifetime-improvement, strong-baseline-superiority, emergence, or
whole-organism claim is licensed.

## 4. Authentic records and source classes

### 4.1 Scheduled formation, exact child authorship

Each OLD edge is witnessed in a separate cold opportunity. The public source
and one legal port are shown; the child executes it; the world returns the
precommitted outcome. These are **child-executed scheduled formation
actions**, not autonomous goal choice.

The exact scheduled-action system string is:

```text
Execute exactly the one public observation action named by the opportunity. Return only the canonical action line and no explanation.
```

OLD action user bytes are:

```text
FORMATION
CURRENT {SOURCE}
LEGAL_PORT {PORT}
OUTPUT STEP {PORT}
```

The goal-neutral NEW user bytes are:

```text
FRONTIER_OBSERVATION
CURRENT {SOURCE}
LEGAL_PROBE {PORT}
OUTPUT PROBE {PORT}
```

Only the emitted child line is executed. A mismatch is not repaired.

Every admitted EVENT must be an exact child continuation grounded in that
call's receipt:

```text
EVENT <event_id> SOURCE <node> PORT <port> DEST <node> PROVENANCE <handle>
```

Each LINK is made in a separate call after both indispensable EVENTs exist:

```text
LINK <link_id> FIRST <event_id> SECOND <event_id> VIA <node> PROVENANCE <handle>
```

The LINK request supplies accepted EVENT rows in a fixed nonsemantic order,
one source EVENT ID, and one reserved role-blind LINK slot. It does not supply
the matching second EVENT. Admission requires exact syntax, exact slot, both
independently witnessed parents, `FIRST.DEST == SECOND.SOURCE == VIA`, and
valid receipts. Missing, malformed, duplicated, unsupported, or compiler-
completed output stops that world's authentic lineage with zero.

OLD formation is exactly `8 ACT + 8 EVENT + 4 LINK` calls. NEW formation is
exactly `2 PROBE + 2 EVENT + 2 LINK` calls; the primary route is already a
scored S1 rollout and is not double-counted.

### 4.2 Two disjoint corpus laws

`AUTHENTIC_CORPUS` contains only exact admitted child target bytes plus the
meaning-preserving views in Section 6. It may not invent, repair, infer,
rebind, orient, or add an EVENT/LINK. Private provenance resolves every
surface handle to a real action/outcome or two-parent receipt.

`CONTROL_TRANSFORM` is a deterministic checker-authored laboratory
intervention over an authenticated bank. Every transformed/filler unit is
privately typed `SYNTHETIC_CONTROL`, points to a transform receipt rather than
a factual receipt, and is barred from the authentic lineage and from any
claim of child authorship. Its public grammar, row types, identifier lengths,
PROVENANCE field surface, slots, target-token counts, and batches match its
authentic twin. Private provenance type is never a model-visible cue.

No synthetic unit may enter `S1_AUTH_LINKED` or `S2_AUTH_OLD_NEW`.

### 4.3 Donor and filler provenance

There is no foreign authentic donor. Before any model call, a fixed
`CONTROL_FILLER_POOL` is generated in a permanently disjoint, control-only
namespace. It contains role-isomorphic synthetic `2 EVENT + 1 LINK` blocks
for S1 cuts and one synthetic `2 EVENT + 2 LINK` block for S2. It has no TSJ
goal, action, node, or receipt semantics. Each filler has a private transform
receipt and `SYNTHETIC_CONTROL` provenance.

Relevant/irrelevant cuts replace exactly one `2E+1L` block with the same
token-matched filler block. Atom-only replaces all target LINK slots with
fixed token-matched synthetic LINK fillers. Counts never change.

## 5. Exact public interface

### 5.1 Address and slot law

EVENT, LINK, receipt, and provenance handles are opaque equal-token strings
from disjoint alphabets. They are assigned by one presealed role-blind
permutation. At S, the two outgoing EVENTs occupy slots 0/1 under a presealed
coin independent of O/T/N/action/goal/display. Every other reachable node has
one EVENT in slot 0; slot 1 is MISS. Every TSJ EVENT has at most one LINK;
that LINK occupies slot 0 and slot 1 is MISS. Controls retain the same
addresses and slots.

There is no aggregate index and no `EVENTS_AT` or all-links response. Each
READ returns exactly one row or `MISS`.

### 5.2 Actor grammar and prompt bytes

The exact actor system string is:

```text
You navigate an opaque public world. On every turn output exactly one permitted line and nothing else. THINK may reason, READ may recall one local record, STEP changes the public state, and STOP is legal only when CURRENT equals GOAL.
```

The initial user template is exactly:

```text
START {START}
CURRENT {CURRENT}
GOAL {GOAL}
LIMITS THINK=8 READ=10 STEP=3 STOP=1
PERMITTED
THINK <text>
READ EVENT_AT <current_node> SLOT <0-or-1>
READ LINKS_FROM <event_id> SLOT <0-or-1>
READ EVENT <event_id>
STEP <public_port>
STOP
```

After THINK the user returns `CURRENT {CURRENT}`. After STEP it returns
`CURRENT {CURRENT}` or `INVALID`. After READ it returns exactly the one-row
reader response. At CURRENT==GOAL, STOP succeeds; early STOP is failure.

S1 proof: read two start EVENTs (`2`), their two LINKs (`2`), and two tail
EVENTs (`2`) = `6 <= 10`. S2 adds two crossing LINKs and two NEW EVENTs =
`10`. Thus complete two-branch search fits exactly without an aggregate.

### 5.3 Native reader bytes

Reader system string:

```text
You recall one local experienced record. Return exactly one canonical EVENT line, one canonical LINK line, or MISS. Return no explanation.
```

Reader requests are exactly one of:

```text
READ EVENT_AT {CURRENT} SLOT {SLOT}
READ LINKS_FROM {EVENT_ID} SLOT {SLOT}
READ EVENT {EVENT_ID}
```

The response is exactly the addressed canonical row or `MISS`. For
`EVENT_AT`, the host rejects a request whose node is not the actor's current
public node. Duplicate requests return the same bytes and consume budget.
Unsupported address/slot returns MISS. The reader sees only its request and
mounted adapter; it never sees goal, task answer, candidate rows, scorer, or
hidden world. There is no host ranking, repair, retry, or selection.

Cold reader gates query every registered EVENT/LINK address once, both valid
slots at every required node/source, and four fixed MISSes. Exact row
accuracy, exact slot accuracy, and exact MISS accuracy must each be `1.00` for
every native arm; canary minima do not average with them.

### 5.4 Formation templates

EVENT record system:

```text
Write one exact canonical EVENT from the public action and outcome. Copy only observed bytes. Return no explanation.
```

EVENT user template:

```text
EVENT_SLOT {EVENT_ID}
ACTION STEP {PORT}
SOURCE {SOURCE}
PUBLIC_OUTCOME DEST {DEST}
PROVENANCE {HANDLE}
```

For NEW, `ACTION PROBE {PORT}` replaces STEP. LINK system:

```text
Write one exact canonical LINK only when two accepted EVENTs meet at the same public VIA node. Do not invent an event. Return NONE if unsupported.
```

LINK user template:

```text
LINK_SLOT {LINK_ID}
SOURCE_EVENT {SOURCE_EVENT_ID}
ACCEPTED_EVENTS
{EIGHT_OR_TEN_CANONICAL_EVENT_ROWS_IN_PRESEALED_ORDER}
PROVENANCE {HANDLE}
```

The exact expected EVENT/LINK line in Section 4.1 is the only accepted target.

S1 has 12 units, hence `2,400` memory presentations and `600` batch-4 memory

S2 has 16 units, hence `3,200` memory presentations and `800` memory updates.
Its six continuations from corresponding S1 snapshots are:

```text

```

The ancestry map is exact:

```text

S2 ATOM_ONLY              starts S1 ATOM_ONLY
S2 RAW_CHRONOLOGY         starts S1 RAW_CHRONOLOGY
S2 OLD_PLUS_MATCHED_FILLER starts S1 AUTH_LINKED
```

`S2_OLD_PLUS_MATCHED_FILLER` starts from exact `S1_AUTH_LINKED`, receives
exactly the 12 authentic OLD units plus the fixed synthetic `2E+2L` filler,
and shares S2 unit slots, target-token count, padding/FLOPs, optimizer/dropout
RNG, BIRTH replay, and updates with S2 AUTH. It contains no NEW meaning.

Compiled memory presentations are ordered by
`(repeat_ordinal 0..24, view_ordinal 0..7, SHA256(canonical_row))`; consecutive
groups of four are memory batches. The imported BIRTH presentation tape keeps
its own exact batch order. The two batch lists are combined by a deterministic
proportional weave: at combined position `k` (zero based), emit the next BIRTH
batch iff `floor((k+1)*B/(B+M)) > floor(k*B/(B+M))`, otherwise emit the next
memory batch, where B and M are the exact BIRTH and memory batch counts.
Internal order is never permuted. This is the exact sleep batch schedule.

For RAW, the integer solver returns the lexicographically smallest positive
unit-multiplicity vector satisfying presentation, supervised-target-token,
and padded-FLOP equality, then the lexicographically smallest feasible
batch-4 slot assignment. Thus tokenizer output cannot leave a choice to the
implementer.

### 6.3 RAW is feasible and exactly enumerated

RAW contains chronology-only, never isolated compiler-authored claims.

S1 has exactly 12 whole units:

- `R0..R7`: each unit is one original cold formation segment: exact
  loss-masked formation prompt, exact child STEP, exact public outcome, exact
  child EVENT. STEP and EVENT are response targets; prompt/outcome are masked.
- `R8..R11`: each is one original LINK formation call: exact masked LINK
  prompt with its actually available accepted EVENT rows, followed by the
  exact child LINK target.

S2 appends exactly four whole units:

- `R12..R13`: the two goal-neutral frontier formation segments, each exact
  prompt, child PROBE, public outcome, and child EVENT. The primary route goal
  ended before this boundary, so no goal/evaluator/future text is present.
- `R14..R15`: the two exact crossing-LINK formation calls and child targets.

No substring is extracted from a scored goal episode. The primary route only
makes its frontier observation opportunity available; the first N reveal is
inside R12/R13 according to the presealed primary order.

Before fitting, a deterministic integer solver assigns positive whole-unit
repetition counts so RAW exactly equals its compiled twin's supervised target
token total and presentation count (`2,400` S1; `3,200` S2). It then assigns
units to batch-4 slots with exact padded-token/FLOP equality. The solver sees
only tokenizer lengths, never scores. If no solution exists, TSJ-v2 stops
`RAW_UNSAT`, performs no fit, and makes no DREAM-versus-RAW claim. Dropping
RAW after seeing results is forbidden.

## 7. Causal controls

### 7.1 Whole-bank twins

O/T/N transforms coherently swap only the named destination binding and every
entailed LINK endpoint. IDs, row counts, public grammar, token lengths,
provenance-field surfaces, slots, targets/batches, and all other bytes remain
matched. They are privately synthetic under Section 4.2.

ATOM retains EVENTs but replaces target LINKs with matched synthetic fillers.
Relevant and irrelevant cuts replace their respective `2E+1L` blocks with
the same filler block. FOREIGN mounts the authentic other-world adapter with
no identifier overlap. BIRTH_ONLY mounts unchanged BIRTH.

### 7.2 Request-valid same-surface response twins

At the exact prior actor byte prefix, an AUTH actor issues the same legal READ
request. The twin service returns the same requested address, row type,
syntax, line count, token count, provenance-field surface, slot, and every
non-treatment byte. Only the coherent destination/entailed LINK endpoint for
T (S1) or O/N (S2) is changed. The response therefore remains legal and
request-valid; it is privately `CONTROL_TRANSFORM`.

The fork shares exact prior actor bytes and greedy decode. The required first
STEP changes to the precomputed counterfactual action on **each world and each
goal**. An unrelated or malformed return may be logged only as a separate
error-handling diagnostic and cannot license semantic mediation.

### 7.3 Text conditions

`EXACT_SUPPLIED_TEXT_CEILING` supplies exact admitted rows through a perfect
one-row service. `SAME_AUTH_HISTORY_ACTIVE_TEXT_CEILING` supplies the same
authentic child's rows in active text/service form. It is a conditional
carrier ceiling, not an independently living text-memory agent and not a
strong on-policy baseline. That stronger baseline is explicitly deferred.

Both ceilings use the exact actor bytes in Section 5.2. Their service accepts
the same exact one-row READ requests and returns the same canonical one-row or
MISS response as Section 5.3; only the carrier is active supplied text rather
than native adapter recall. No route, candidate ranking, or goal-conditioned
selection is supplied.

## 10. Decode, RNG, stopping, and ITT

Actor/reader/record generations use greedy decoding: `do_sample=false`,
temperature ignored/0, `top_p=1`, top-k disabled, repetition penalty `1`, one
sequence, fixed max tokens, exact EOS/stop IDs from the selected tokenizer,
and no retry, repair, resampling, best-of, or human choice. Fresh processes
are used per rollout/state. Calls run in manifest order: world 0 then world 1;
within world, exact section/arm/goal ordinal. Wall clock and prior calls never
enter prompts.

Malformed output, early STOP, invalid STEP/READ/PROBE, cap exhaustion,
formation failure, rejected canary/controller write, or scientific timeout is
scored zero and retained. There is no replacement world or learner. A
verified infrastructure failure before any model-visible call/side effect may
restart the identical call once from the same bytes; any uncertainty or later
failure marks the whole source version `TSJ_V2_INVALID` and stops it. It never
opens a replacement seed.

Training uses one predeclared writer seed per world. Within a world, causal
twins share exact init tensors, unit slots, target-token positions, dropout,
optimizer, batch order, and padding/FLOP tape. S2 arms start from their named
S1 snapshots; AUTH and OLD+filler both start exact S1 AUTH. No unit sampling
with replacement occurs except the explicit deterministic presentation
multiplicities. Root construction, task order, goals, display order, slots,
and primary frontier are fixed before calls.

Parser acceptance is exact UTF-8 after removal of at most one terminal LF.
Leading/trailing spaces, additional lines, prose around a command, Markdown,
unknown commands, wrong IDs, or multiple commands are malformed. Generation
ends at the first registered EOS/stop token or the per-call token cap; a
truncated line is malformed. No normalization changes scientific output.

No scored goal, H identifier/binding, expected first action, evaluator label,
or future route is ever a response target in formation, DREAM, BIRTH replay,
or an authentic sleep tape. A literal, normalized, role-aware, and tokenizer-
ID scanner must record zero such leakage before each fit.
