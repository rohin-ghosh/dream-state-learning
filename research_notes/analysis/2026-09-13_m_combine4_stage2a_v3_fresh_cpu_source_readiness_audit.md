## Exact blockers

### B1 -- Eight unresolved STEP-mismatch cases are made reached

V3 preserves v2's terminal formula `b mod 2`: 32 cases reached and 32
unresolved. The fixed mismatch pairs are
`p01,p03,p05,p07,p25,p27,p29,p31`; the eight cases at
`p05/{m0,m1}`, `p07/{m0,m1}`, `p29/{m0,m1}`, and `p31/{m0,m1}` are therefore
unresolved. Their fourth target must be `READ INDEX <latest-CURRENT>`.

V3 section 4.1 instead states that every registered birth surprise-corrective
matching row GOT its FOR goal. Section 4.2 sends every STEP-mismatch case
through exactly such a block. All 16 STEP-mismatch corrective STEPs therefore
reach GOAL. For the eight cases above, source has only two choices:

- obey v3's world and emit STOP, yielding reached/unresolved `40/24` and
  target counts `READ 88 / STEP 64 / THINK 64 / STOP 40`; or
- preserve `32/32` and `96/64/64/32`, emit READ while CURRENT equals GOAL,
  and violate the exact STOP/world/oracle contract.

The CPU gate cannot pass either branch. Repair by making a birth corrective
matching row obey the case terminal class: GOT the task goal when reached and
the exact A/B hub when unresolved. The two deep-swap-capable rows must share
that terminal class. Then republish any affected registry, graph, and fixture
hashes.

There is a second inheritance collision in the relation/deep-swap mismatch
pairs. V2 keeps the failed event fixed and applies the FOR swap to the
target-bearing corrective block; relation-pair members share candidate IDs and
all non-FOR fields. V3 puts two mistaken candidates in the failed block and
allocates `surp_m/recovery_m` corrective EVENT/PORT/receipt IDs separately by
member. Either explicitly and materially supersede the inherited causal-pair
identity rule, or restore a common failed event and one shared corrective
candidate set with only the two FOR leaves swapped. Do not leave the checker
to choose which contract “preserved 32 causal pairs” means.

### B2 -- Held first-EVENT positions have two incompatible definitions

V3 section 4.1 says that, except for a relation/deep-swap block, the matching
row is at

```text
(3*j + state_ordinal(z) + skin) mod 4
```

and says the candidate component is the rendered row position. V3 section 4.4
simultaneously preserves v2's held first-EVENT position
`(h + member) mod 4`. Applying both formulas to the 32 chain tasks disagrees
for 20 tasks. The first conflict is `h00/m1`: its right goal is `g12`, so the
generic start-state formula gives row `0`, while the preserved held formula
gives row `1`. `h01/m0` gives `3` versus `1`.

Repair by adding an explicit scored-chain first-hop exception to section 4.1,
stating which rule fills the other three candidate rows and whether the same
exception applies to expected and mismatch worlds. Then bind a 32-row
`world/member/goal/row` table or its hash. The current “all held display pins”
CPU gate cannot determine which of the two binding positions to enforce.

### B3 -- Both graph vectors put CURRENT on the wrong state

Section 7.1 requires the latest CURRENT to carry the CURRENT flag. The
TRAIN_REACHED vector is explicitly path-complete at a reached CONTINUE
decision. Its EVENT/WORLD edges run from start `S0001` to goal-state `S0000`,
but its vertex table flags `S0001` as CURRENT and leaves `S0000` unflagged.

HELD_TWO_STEP has the same reversal. Its two WORLD edges run
`S0002 -> S0001 -> S0000`; at path-complete CONTINUE, latest CURRENT is
`S0000`, but the vector flags start `S0002`. Both corresponding core objects
repeat the error. The CJSON and all printed hashes are internally consistent
with those wrong flags, and CPU gate 7 requires matching them before generated
objects are checked. A checker cannot honor both the golden bytes and the
latest-CURRENT rule.

Repair the flags in full graphs, every affected induced radius, and both core
public graphs, then recompute graph/radius/signature/core hashes. Add one
explicit table of all allowed string values for `phase`, `flow`,
`recovery_subtype`, `family_motif`, `goal_side`, and `terminal_class`;
“uppercase names in v2/v3” does not choose bytes such as hyphen, slash, space,
or underscore for the non-vector phases and recovery subtypes.
