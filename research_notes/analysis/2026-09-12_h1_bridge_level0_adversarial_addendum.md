# H1 bridge adversarial addendum after the level-zero result

**Date:** 2026-09-12
**Scope:** red-team and minimal amendment to
`2026-09-12_minimal_decisive_h1_parent_dream_sleep_bridge_protocol.md`.
This memo changes no builder source and launches nothing.

## Bottom line

The proposed H1 design is still structurally useful, but it must **not launch
yet**. Level zero shows a sharp asymmetry:

- one repeated global response-order habit transfers perfectly across three
  optimizer seeds (`96/96` taught versus `0/96` task-only); but
- arbitrary device--colour facts exposed once are not extractably acquired,
  even on their exact training contexts (the trained models collapse to a
  colour prior).

H1 asks the same writer to carry 32 arbitrary family--mode actions. Replaying
each child action under eight surface forms is a hypothesis, not evidence that
the binding will be learned. A one-update gradient sign canary is necessary
but no longer sufficient.

The one new hard dependency is therefore:

> **Before any H1 parent or child call, the exact H1 writer, action tokens,
> renderer, dose, objective, initialization, and readout must carry an
> oracle-supplied balanced family x mode mapping and its complementary swapped
> mapping on held objects and held wording, across three optimizer seeds,
> without action-prior collapse or spill.**

If that gate fails, do not run STORE/NULL parenting. Repair the conditional
writer or representation first. Level-zero ritual adherence does not qualify
this dependency.

## The one prelaunch writer qualification: W-H1

Run this on disposable development identifiers only. It is not H1 evidence and
no resulting adapter or identifier may enter a clean lineage.

1. Construct the exact H1 surface: 16 new nonce families, two modes, the two
   equal-token action strings, eight frozen SLEEP renderings per family-mode,
   and two unseen readout renderings with new objects. Use the same qualified
   level-1 birth material, rank, modules, objective, optimizer, replay mixture,
   loss mask, and clean-base reconstruction proposed for H1.
2. Replace child artifacts with a mechanically authored oracle table only for
   this qualification. Create AUTH and exact mode-swapped corpora. They must
   have the same target-token sequence and marginal counts, differing only in
   which mode context precedes each target.
3. Fit AUTH and SWAP from identical initialization at optimizer seeds
   `{0,1,2}`. Run the existing one-update opposite-sign gradient canary first,
   but do not call the writer qualified from that canary.
4. Read every state with ordinary strict generation and candidate-normalized
   action log odds on exact training contexts, held objects/wording, unexposed
   families, unsupported modes, native action canaries, and unrelated tasks.
   Every item is stateless and feedback-free.

W-H1 passes only if all three seeds satisfy:

- exact-training balanced accuracy >=`.90` for AUTH and SWAP;
- held balanced accuracy >=`.80` for each write, each mode and action recall
  >=`.75`, and valid single actions >=`.95`;
- own-map redirection `B>=.40` for the paired AUTH/SWAP writes;
- each unsupported/unexposed control family's action-distribution TV from OFF
  <=`.05`, with unrelated/interface performance no worse than OFF by `.05`;
- exact corpus, target-token, initialization, step, reload, and scorer/world
  receipts all pass.

The gate is intentionally stronger than “loss fell” or “the action changed.”
It demands the arbitrary interaction on held surfaces. If the current eight
renderings fail, do not increase repetition inside H1. Any new dose or
objective is a new writer version that must first pass W-H1 and then be frozen.

## Minimal amendments to the H1 protocol

No new scientific arm or root is needed. Keep P/S, OFF/AUTH/SWAP, TEXT, the 16
paired roots, and the original claim boundary. Amend only these points:

1. Replace release dependencies 1--2 with W-H1 plus the independently
   qualified level-1 birth state. The current level-zero result is evidence
   that global habits write; it is not a conditional-writer release gate.
2. Freeze equal-token action strings and random root-local external name
   permutations. Do not reuse the unequal historical action strings.
3. Add schema parity (`P>=.90`, `S>=.90`, absolute gap <=`.05`) before the
   semantic artifact gate. Preserve supported coverage, supported precision,
   NULL accuracy, `q`, `g`, and `B` as separate reported quantities.
4. Bind the scientific answer key to the world manifest, not to admitted
   artifacts. Add the enumerated shortcut audit and stateless shuffled-order
   readout.
5. Tighten the parent/verifier view and byte-source allowlist as specified
   above. Parent adaptation within a child's school remains allowed; parent
   weights and cross-root state remain fixed/reset as before.

These changes do not make the architecture larger. THINK still produces the
real actions and outcomes; DREAM still chooses and authors STORE or NULL;
SLEEP still mechanically replays only grounded child action continuations
into one unified LoRA. They only prove that the writer can carry the kind of
conditional memory H1 asks it to carry, and prevent a global response ritual
from masquerading as that memory.

## Claim after these repairs

Even if H1 passes, the claim remains the original bounded one: this exact
process-parent package increased grounded child-authored two-condition
artifacts, and the qualified LoRA writer selectively carried those artifacts
into parent-free first actions on new instances. It is not broad metacognition,
domain transfer, long-horizon improvement, or a self-learning flywheel.
