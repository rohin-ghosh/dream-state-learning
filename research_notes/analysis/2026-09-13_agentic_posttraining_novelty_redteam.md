# Red-team: agentic post-training novelty and data-design claims

**Date:** 2026-09-13  
**Artifact reviewed:** `2026-09-13_agentic_posttraining_single_policy_survey.md`  
**Scope:** Primary papers and official repositories only; no implementation or GPU work. “Reset” below distinguishes an in-episode context clear from a new deployment episode. “Causal controls” distinguishes ordinary method ablations from interventions on memory content or provenance.

## Bottom line

The survey is right that the broad claim “an agent writes its own experience into parameters and uses it later” is occupied. Its proposed narrower claim is still too broad in one material place: **TMEM already clears both working history and textual memory while preserving a fast LoRA, then samples later actions from the adapted policy in the same episode** ([TMEM, Eq. 6](https://arxiv.org/abs/2606.04536)). Therefore “survives a context reset” and “later use from weights” cannot be presented as open contributions without specifying a **fresh episode/life boundary** and stronger content-causal tests.

[AgeMem](https://arxiv.org/abs/2601.01885) is also a closer curriculum collision than the survey implies. It withholds the formal query during information exposure, resets context while retaining LTM, injects distractors, and later requires retrieval plus multi-step reasoning. The difference is the substrate: AgeMem retains content in an external semantic store, not in the policy parameters. Thus exposure-before-goal, reset, distractors, and autonomous memory operations are precedents, not novelty.

The defensible contribution is the **conjunction** of target-disjoint operator birth, later continuation of the identical adapter on life-specific opaque bindings, fresh-episode use with no external content store, held-out binding composition, and identity-sensitive causal interventions. The paper should disclaim novelty for every ingredient separately.

## Adjudication of the named sources

| Work | What is actually established | Consequence for the proposed claim |
|---|---|---|
| [TMEM](https://arxiv.org/abs/2606.04536) | The agent emits grounded QA supervision from accumulated session context; a context-budget rule triggers online SFT into fast LoRA. Equation 6 sets working history and explicit memory to empty while the updated LoRA persists, and subsequent actions use the adapted policy. The LoRA starts from zero per rollout and can accumulate multiple writes within that rollout. | **Direct collision on own-rollout parametric memory, in-episode reset, and later implicit use.** The trigger and memory-writing prompt are fixed, not learned cue actions. TMEM does not show cross-episode/lifetime retention, a learned explicit address/read action, or a birth-policy adapter later reused as the memory adapter. It has component ablations, but no own/foreign-life, same-ID derangement, content redirection, or adapter-cut localization. Do not say that TMEM “does not cross reset”; say it does not cross a new-episode boundary. |
| [PEAM](https://arxiv.org/abs/2605.27762) | A slow GPT-4o tier explores, verifies, and corrects; selected success and failure–correction trajectories are consolidated with BC plus preference learning into routed, category-isolated Qwen3-VL LoRA skill adapters. Category adapters persist and accumulate across consolidation cycles. Held-out tasks require multi-step planning/execution. A fixed statistical test over failure rates plus a hand-designed, grid-searched worthiness score triggers updates. | **Direct collision on cross-episode experience-to-LoRA skill memory and later multi-step execution.** Do not deny same-adapter accumulation within a category. The remaining distinction is that general deliberation and memory reside in different tiers/modules, and PEAM does not first install a target-disjoint composition operator in an adapter and then continue that identical adapter on exact autobiographical bindings. PEAM has meaningful BC/DPO, routing, trigger, and forgetting ablations; it lacks identity/content swap and cut controls. |
| [AgeMem](https://arxiv.org/abs/2601.01885), [official repo](https://github.com/y1y5/AgeMem) | One policy learns Add/Update/Delete/Retrieve/Summary/Filter actions. Stage 1 exposes information before the query; Stage 2 resets context but preserves LTM and adds distractors; Stage 3 reveals the query and requires retrieval/reasoning. Content stays in an external vector store, and Retrieve returns backend top-k semantic matches. The appendix also performs a scripted retrieval on every Stage-1 step for LTM introspection. | **Direct collision on the temporal curriculum and learned memory management, but not parametric content.** “Autonomous cueing” must be operationalized narrowly: the policy can select memory tools, but some retrieval and all top-k selection are supplied by the wrapper/backend. AgeMem’s ordinary component/reward ablations do not identify whose binding caused the answer. |
| [AgentTuning](https://arxiv.org/abs/2310.12823), [official repo](https://github.com/THUDM/AgentTuning) | Response-only SFT on 1,866 verified GPT-4 trajectories across six tasks, mixed with ShareGPT, produces one multi-task agent policy. | Supports multi-task trajectory SFT and input-token masking. It does not experimentally isolate named “faculties,” memory writing, or later experience acquisition. Held-out absolute gains are scale-sensitive, strongest at 70B. |
| [Agent-FLAN](https://arxiv.org/abs/2403.12881), [official repo](https://github.com/InternLM/Agent-FLAN) | Agent traces are decomposed and rebalanced across format following, reasoning, function-name selection (called retrieval), and argument understanding; narrow tool/no-tool negatives are included. | Supports difficulty-aware mixture tuning and selective tool use. Its “retrieval” is function selection, not evidence or memory retrieval. Its negatives do not by themselves support the full proposed `MISS`/irrelevant/already-solved/no-change set. |
| [FireAct](https://arxiv.org/abs/2310.05915) | SFT on GPT-4-generated CoT, ReAct, and Reflexion mixtures can place several response modes in one policy. Reflection is inserted at fixed rounds in data generation; mixture effects are non-monotonic, and adding Reflexion slightly hurts one reported HotpotQA setting. | Supports trajectory mixtures and warns against assuming additivity. “Reflective pivot” is mainly qualitative behavior, not a strong autonomous-correction result. It does not support parametric memory or the proposed exact curriculum dose. |
| [STeP](https://arxiv.org/abs/2505.20023) | A strong teacher evaluates learner actions and writes first-person reflections/corrections. Only successful final trajectories are retained; erroneous learner tokens remain as masked context while the teacher continuation is supervised. The final policy is retrained from the base model on original plus reflected data. | Supports the masked-error/correct-continuation data format. It is **teacher-authored correction**, not evidence that outcomes alone elicit intrinsic self-correction or autobiographical memory. |
| [ETO](https://arxiv.org/abs/2403.02502), [official repo](https://github.com/Yifan-Song793/ETO) | BC is followed by iterative learner exploration and trajectory-level DPO over higher- versus lower-reward trajectories; the main construction pairs learner failures with expert successes. Task and observation tokens are masked. | Establishes that a learner’s own failure distribution can shape later policy weights. It is target-family training with expert support, not a target-disjoint memory treatment. Prefer “higher- versus lower-reward trajectories” over the categorical “failure versus success” description. |
| [SCoRe](https://arxiv.org/abs/2409.12917) | Two-stage on-policy RL trains intrinsic second-attempt correction, first constraining attempt one and then adding an improvement reward. | Strong evidence that correction data/objectives require care, but no tools, environment observations, or memory are involved. A matched “correct/no-change” example is a reasonable design inference from degradation analysis, not a data recipe SCoRe itself tested. |
| [Search-R1](https://arxiv.org/abs/2503.09516), [official repo](https://github.com/PeterGriffinJin/Search-R1) | One Qwen policy learns repeated search and reasoning with outcome RL on HotpotQA, 2WikiMultiHopQA, MuSiQue, and Bamboogle. Retrieved tokens are masked from policy/KL losses. A wrapper supplies an explicit retry sentence after malformed actions. | **Direct precedent for autonomous external retrieval plus multi-hop composition.** It supports masking environment text, not parametric memory. Do not attribute every repair to the policy. |
| [ReTool](https://arxiv.org/abs/2504.11536) | Validated code-integrated cold-start SFT is followed by PPO with a live interpreter and final-answer reward; interpreter output is masked. | Supports staged tool-use training. “Emergent repair” should be labeled qualitative/case-study evidence rather than a causal recovery result. The 32B math result is not direct support for SFT sufficiency at 7B. |

Two vocabulary traps account for most possible overclaiming:

1. **Deployment memory versus learning from rollouts.** TMEM and PEAM explicitly parameterize memory/skills. ETO, SCoRe, Search-R1, and ReTool also let self-generated rollouts affect future weights, but optimize a reusable policy rather than claiming retention of a particular life event. A novelty sentence that merely says “own experience changes weights” collides with all of them.
2. **Multi-step versus binding composition.** PEAM, AgeMem, Search-R1, FireAct, and TMEM all evaluate multi-step or multi-hop behavior. The open test must be defined as a held-out decision that jointly depends on at least two independently acquired opaque bindings, with the eventual target action absent during birth and acquisition. “New multi-hop actions” alone is not differentiating.

## Missing close citations

The survey’s claim boundary should also acknowledge these primary sources:

- [Online Experiential Learning](https://arxiv.org/abs/2603.16856) extracts knowledge from the model’s deployment trajectories and consolidates it into the model with on-policy context distillation across repeated deployment/training cycles. This occupies broad “continuous improvement from own deployment experience in weights,” although it learns transferable game knowledge rather than exact identity-bound autobiographical facts.
- [SEAL](https://arxiv.org/abs/2506.10943) has the model generate self-edits and update directives whose SFT produces persistent weight changes, with downstream performance training the self-edit policy. This occupies generic self-directed content-to-weight adaptation, not grounded action–outcome memory.
- [Doc-to-LoRA](https://arxiv.org/abs/2602.15902), [official repo](https://github.com/SakanaAI/doc-to-lora) maps unseen context to a LoRA adapter and answers later queries without the source context. This is a direct collision on context-free factual content in LoRA, but uses a separate hypernetwork and documents rather than the agent’s verified life events.
- [ParamMem](https://arxiv.org/abs/2602.23320) stores cross-sample reflection patterns in a parametric module and combines it with episodic and cross-sample memory on code, math, and multi-hop QA. It is procedural/reflective memory rather than exact event binding, but rules out generic “first parametric memory for a reasoning agent” language.
- [Auto-Dreamer](https://arxiv.org/abs/2605.20616) learns cross-session offline consolidation of provenance-linked trajectories into a compact external memory bank. It is not parametric, but it is a close collision on learned “dream/offline consolidation” framing and should be cited wherever that protocol is described.

## Exact safer wording

Recommended main claim:

> We test a conjunction not established by the primary systems reviewed here. The identical low-rank adapter is first trained on identifier and relation families disjoint from evaluation to execute a generic closed-loop composition policy, then continued—without mounting a second adapter—on verified, instance-specific action–outcome events from one deployment life. In a fresh episode with the event transcript and every textual/vector memory removed, the policy must select a content-dependent cue and execute a held-out action that composes at least two independently acquired opaque bindings. Matched own-life/foreign-life, within-identifier derangement, memory-cut or binding-redirection, and birth-only controls test whether behavior depends on the identity and availability of those acquired bindings.

Required disclaimer immediately after it:

> We do not claim the first parametric agent memory, the first memory retained after context clearing, the first autonomous memory policy, the first multi-hop agent, or the first system to improve from its own rollouts. TMEM, PEAM, AgeMem, Search-R1, OEL, SEAL, Doc-to-LoRA, and ParamMem establish those ingredients in other combinations.

Use these narrower comparisons:

- **TMEM:** “TMEM demonstrates within-episode QA-to-LoRA memory that remains after working context and explicit memory are cleared. Our test instead asks whether a pre-existing composition adapter can acquire identity-bound events, carry them into a fresh episode, and pass content interventions.”
- **PEAM:** “PEAM demonstrates cross-episode consolidation of embodied trajectories into routed category-specific LoRA skills and later multi-step execution. Our test uses one continued birth adapter, exact opaque event bindings, no slow-tier correction at recall, and identity-level causal controls.”
- **AgeMem:** “AgeMem is the closest non-parametric curriculum control: information precedes the formal query, context is reset while LTM persists, distractors intervene, and one policy later retrieves and reasons. Our distinction is parameter-resident content plus binding-sensitive interventions, not the stage structure.”

## Data-design corrections

- Present the acquisition→reset/interference→use schedule as adapted from AgeMem, not as novel. Make “fresh episode” an executable condition: new conversation/rollout ID, empty KV/context, no text/vector store, and the continued adapter as the only retained life-specific state.
- Separate **cue selection** from **memory availability**. Score whether the policy emits the correct cue before any row is injected; report forced-cue performance separately. A fixed threshold (TMEM), category router (PEAM), wrapper retrieval (AgeMem Stage 1), or malformed-action retry prompt (Search-R1) must not count as autonomous cueing.
- Keep response-only masking. AgentTuning/ETO support input masking, Search-R1/ReTool mask tool feedback, and STeP supports retaining an erroneous attempt as masked context. These papers do not justify the proposed numerical corpus dose.
- Label matched no-change examples, `MISS`, irrelevant reads, and already-solved `STOP` cases as project hypotheses motivated by failure modes—not as recipes directly validated by Agent-FLAN or SCoRe.
- Keep SFT as the cheapest falsifiable birth test, not as a literature-backed expectation of sufficiency. Search-R1, ReTool, SCoRe, AgeMem, and TMEM use on-policy optimization for autonomous decisions; if SFT learns syntax but not cueing/recovery, a later RL/DPO rescue is a separate causal treatment.
- Report ordinary component ablations and binding-causal controls separately. TMEM and PEAM do have real ablations; the accurate gap is the absence of matched provenance/content interventions, not the absence of controls altogether.

**Verdict:** revise the survey before reusing its claim. The project can plausibly claim a previously unreported **controlled conjunction**, but not reset-surviving parametric memory, autonomous memory use, own-experience weight learning, or multi-hop behavior individually.
