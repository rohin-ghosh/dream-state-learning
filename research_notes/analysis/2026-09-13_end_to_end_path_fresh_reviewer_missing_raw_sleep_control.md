# Fresh ICLR review: the missing raw-SLEEP comparator

**Date:** 2026-09-13 UTC  
**Role:** fresh skeptical ICLR reviewer  
**Evidence cut:** `a699a464c3fa` plus the clean worktree inspected for this memo  
**Scope:** analysis only; no source, fixture, model, tokenizer, adapter, job,
GPU, threshold, result, or paper claim changed

## Verdict

**Do not delay the bounded PCFL v2.2 DEV vertical. REWORK the transition from
DEV to the expensive lifetime campaign.**

The most likely unclosed reviewer objection is not another leakage edge or a
missing memory ceiling. It is the absence of a **same-child, same-history,
raw-chronological LoRA comparator**. The present causal family compares:

- compiled AUTH versus compiled ATOMS/TWIN/PERMUTE;
- compiled DLT versus no mounted write;
- compiled DLT versus external text/graph memories; and
- periodic compiled fitting versus optional terminal compiled fitting.

Every comparison either keeps the addressed EVENT/LINK compiler on both
sides, removes learning entirely, changes the carrier, or changes timing. None
asks whether the compiler adds value beyond ordinary response-masked SFT on
the exact child chronology it received.

Consequently, even a completely positive path could still be summarized by a
reviewer as:

> The child was prompted to serialize a tiny graph, then repeatedly fine-tuned
> on task-specific memory requests. The paper never shows that DREAM's
> compilation is better than replaying the child's transcript into the same
> LoRA.

That objection is especially serious because the repository's own prior
contract already named raw-trajectory LoRA as the compiler ablation, and the
related-work audit identifies raw LoRA as necessary when attributing gains to
dreaming rather than to the training recipe. The present successor silently
dropped that comparison.

This is a **compiler-attribution gap**, not a reason to reopen THINK, parenting,
PCFL topology, rank, heat, replay, or the strong text baseline.

## Why the existing controls do not answer it

| Existing condition | What it isolates | Why it does not test compiler increment |
|---|---|---|
| `S1_ATOMS` | value of explicit LINK organization over EVENT atoms | both sides are addressed, wrapped, replayed compiler products |
| `EVENT_TWIN` / `LINK_PERMUTE` | dependence on authentic semantic bindings | both sides retain the compiler surface and dose |
| `SLEEP_FROZEN` | effect of the whole promoted learner on policy | removes all weight updates, so task-format practice and experiential semantics move together |
| `NONE` / wrong-root / adapter-off | whether the mounted state is root-specific and causally active | does not show whether raw chronological fitting would produce the same useful state |
| `ACTIVE_LINKED_TEXT` / `RAW_RAG` / exact graph | carrier and access comparisons | changes persistence substrate and reader, not just compilation |
| terminal batch controls | periodic timing and history quality | use the same compiled training multiset |
| zero-fit predictive reuse | whether a successful final adapter reuses structure | downstream diagnostic; it cannot tell whether DREAM was needed to obtain that adapter |

The v2.2 semantic controls remain necessary. The raw comparator answers a
different question: whether arranging exact lived bytes into addressed,
replayed memory supervision contributes anything beyond ordinary experiential
post-training.

## Cheapest decisive repair: four DEV fits, no new life

Freeze one additional quarantined condition now:

```text
RAW_CHRONOLOGICAL_S1
RAW_CHRONOLOGICAL_S2_R0
RAW_CHRONOLOGICAL_S2_R1
```

For the minimum two-root DEV, only four fits are necessary for the first
decision: one S1 raw fit per root and the one prospectively designated native
S2 continuation per root. The unused R twin needs no raw fit unless the first
four cells make a compiler claim plausible. These are disposable same-history
fits, not longitudinal branches; they never write back into an authentic
lineage.

### Raw corpus rule

For each root and frontier, take the exact causally visible native chronology
already sealed for AUTH:

- child thought/action continuations;
- public tool/world outcomes as loss-masked context;
- the child's exact post-outcome continuation, including an EVENT or LINK only
  where the child actually emitted it in the life; and
- no generated question, QA row, address request, paraphrase, canonical repair,
  inferred edge, compiler summary, or additional semantic target.

Train only on exact child assistant spans in chronological order. Preserve
conversation boundaries. The compiler may tokenize, pack, repeat complete
chronological blocks, and response-mask; it may not rewrite them. This is raw
experiential replay, not full-sequence loss on world text and not a weaker
handwritten strawman.

Start from the byte-identical clean child used by the paired compiled fit. Use
the selected v2.2 rank, learning rate, optimizer, final-checkpoint rule,
numerical checks, generic canary, PCFL task-retention panel, and target-token
upper bound. Match optimizer updates to AUTH. Report exact supervised target
tokens and presentations; do not invent padding prose or partially mask a
semantic continuation merely to force token equality. Couple fit and inference
seeds wherever meaningful.

### Readout rule

Compare on **native organism endpoints only**:

- S1 old-route action;
- relevant reachout choice;
- S2 delayed OLD+NEW action;
- legality, formation ability, generic canary, and PCFL task retention.

Do not require raw replay to answer `READ EVENT` or `READ LINKS_FROM`; those
requests are the compiled representation's private API and would make the
control circular. Local/service memory scores remain AUTH diagnostics, not a
fair raw-replay endpoint.

The raw adapter is always quarantined. It cannot generate experience, parent a
child, seed the lifetime campaign, or contribute rows to another condition.

## Prospective interpretation

Use the two roots only as a development decision, not a confidence interval:

1. **Compiled succeeds, raw fails, and the existing authentic-versus-semantic-
   control gates pass:** the compiler has earned a plausible incremental
   mechanism; proceed to lifetime without redesign.
2. **Compiled and raw are similar:** experiential parametric learning may
   still be real, but DREAM compiler advantage is unshown. Proceed only with a
   whole-system claim that does not attribute the gain to compilation, or
   simplify the mechanism before confirmation.
3. **Raw exceeds compiled:** the addressed compiler is harming the native
   learner. Do not spend the full lifetime budget merely because compiled
   local reads are good.
4. **Neither succeeds while exact text/graph succeeds:** the parametric writer
   remains the bottleneck; strong-memory and predictive-reuse claims do not
   rescue it.

No DEV numerical margin should be invented from these two roots. Preserve all
raw results and use direction, native endpoint conjunction, and absence of
retention harm only to select the next claim family.

## When each repair is essential

### Before PCFL v2.2 DEV

Essential only:

- preserve the exact raw causal chronology and masks;
- predeclare the raw-corpus construction above before any DEV outcome is
  opened; and
- keep the existing ATOMS/TWIN/PERMUTE, locality, retention, and rollback
  gates unchanged.

Do **not** make raw fitting a prerequisite to starting or completing the
stage-gated DEV vertical. DEV first answers whether the proposed mechanism can
work at all.

### Before PCFL-STREAM lifetime

Run the four raw DEV fits and open the decision table above. This is essential
before committing roughly `22.2` A40-hours to scale qualification plus at
least `142.4` A40-hours to an initial N=16 lifetime campaign, because it can
show cheaply that the proposed compiler is unnecessary or harmful.

Also freeze which statement the lifetime is intended to support:

- **whole recurrent experiential learner:** no extra raw longitudinal branch
  is required;
- **DREAM compilation improves learning:** the raw comparison must be carried
  into confirmation as described below.

Parenting receptivity is orthogonal. Do not insert parent prose into either
corpus and do not make a Level-1 parenting result gate this comparison.

### Only before paper-grade confirmation

If the paper claims an incremental benefit from DREAM compilation, confirm it
on independent lineages. The cheapest confirmatory form is one
same-DLT-history raw fit at the registered terminal cut per powered lineage,
with a root-paired native-utility interval. Because the proposed writer
rebuilds every checkpoint from the same clean child and cumulative data, this
terminal comparison requires no raw on-policy life.

That supports only a **terminal compiler increment**. If the abstract claims
that compilation improves the full lifetime AUC or changes later experience
collection, raw fits are required at every claimed cut or a raw on-policy
branch is required, respectively. Do not infer either from a terminal fit.

If the paper makes no compiler-superiority claim, report the four DEV raw
cells as an ablation and retain the whole-system DLT-versus-frozen and
DLT-versus-active-text estimands. The strong active-memory certificate and
zero-fit predictive-reuse assay remain downstream and unchanged.

## Claim boundary after repair

The maximum incremental sentence, only after independent confirmation, is:

> Holding child history, base checkpoint, adapter capacity, update count, and
> native action interface fixed, replay through the provenance-bound DREAM
> representation improved terminal action utility over chronological replay
> of the same lived interaction.

Do not say that DREAM is necessary, generally optimal, biologically realistic,
or physically compressive. A raw tie removes this sentence but does not erase
a valid own-experience, connected-memory, lifetime, or strong-carrier result.
