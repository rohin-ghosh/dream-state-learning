# PCFL-GOAL-BRAID-v1 after addendum: adversarial source-authoring audit

**Date:** 2026-09-13 PT  
**Scope:** documentation and existing-source inspection only. No runtime,
fixture, checker, model/tokenizer, training, GPU, or remote action occurred.

## Decision

**The graph geometry is sound; the source contract is not closed yet.** Give
source authoring a **conditional GO after a small written amendment**, not an
unqualified GO from the present memo.

The delayed two-goal task has the intended information structure. If raw
identifiers, row order, address order, and chronology are neutralized, the
correct first `STEP` cannot be selected from the current node, destination
degree, direct-goal status, one-hop LINK count, path length, or any radius-0
through radius-3 rooted topology. It depends on the goal mark at radius four
and the life-specific OLD port binding. The addendum also correctly retracts
the stronger two-sided reachout claim: the authentic two-card reachout needs
only the destination suffix, not the source prefix.

However, the current document still leaves four source-critical ambiguities:

1. semantic EVENT/LINK roles conflict with chronological address allocation
   when either branch may be selected first;
2. the inherited singular `e0`/`e8` cut scheme is not a valid cut for two
   start events and two NEW bridges;
3. the promised memory-service comparison cannot run under the stated action
   grammar because that grammar has no `READ`; and
4. “followed remembered connections” is stronger than final behavior alone
   can identify unless surface/chronology projections and a deep-content
   intervention are bound.

These are local contract repairs. They do not require another topology.

## 1. Independent topology and ceiling check

After both NEW bridges exist, the graph contains two disjoint five-edge paths:

```text
S -> U0 -> F0 -> R0 -> K0 -> G0
S -> U1 -> F1 -> R1 -> K1 -> G1
```

For a fixed root and `GOAL G0`, the exact route depends on two independent
bits:

- `O`, which assigns `a0/a1` to the `S -> U0` edge; and
- `N0`, which assigns `q0/q1` to the `F0 -> R0` edge.

`N1` is irrelevant. Hence the eight cells contain four exact routes twice
each. The same proof holds for `G1` using `O` and `N1`. Therefore:

```text
prompt-only known-label exact-route ceiling: 2/8 per root-goal = 1/4
four roots x two goals:                       16/64
first STEP without O:                         1/2
bridge STEP without the relevant N bit:       1/2
goal-blind policy on paired goals:             1/2
full graph oracle:                             64/64
```

State feedback does not improve the exact-route ceiling. A wrong first edge
is irreversible and reaches the wrong terminal corridor. Conditional on the
correct first guess, an unknown bridge label still costs another independent
one-half. The addendum is right that `1/4` is a known-label information ceiling,
not a prediction that the physical OFF model can emit unseen opaque ports.

Each goal has exactly one simple successful route. Reusing the same bridge
port label at `F0` and `F1` when `N0=N1` causes no ambiguity because action
validity is conditioned on `CURRENT`. There is no route-length or dead-end
asymmetry in the proposed complete graph.

## 2. Does the first STEP truly require nonlocal goal-conditioned memory?

### At the task-information level: yes, conditionally

Root the two candidate continuations at `U0/U1`. With opaque labels quotiented
by type, both have one outgoing transition at radii 0, 1, 2, and 3. The target
mark first appears at radius 4 (`G0` versus `G1`). Thus a topology-only policy
bounded to radius three ties. `O` independently swaps the two ports at `S`, so
even a fixed goal-to-port rule ties over the complete cube.

The source checker should calculate the Bayes-best label accuracy for
canonical radius-0, radius-1, radius-2, and radius-3 neighborhood projections,
not only `LOCAL_1_DEGREE`. All four must be exactly one-half on the first-step
decision. A radius-4 goal-path controller is the intended constructive solver.

### At the model-mechanism level: not from success alone

A correct final route proves that the mounted condition contained enough
information to act. It does not by itself prove that the model internally
performed graph search. It could have compiled a direct goal-to-first-port
association from chronology, row position, address allocation, or correlated
training order. The safe claim without another intervention is:

> With start and learned memory fixed, changing the distant goal redirected
> the first irreversible action on a task whose valid solution depends on
> distributed life-specific relations beyond radius three.

Do not claim an observed hidden search algorithm or literal traversal of LINK
objects from output behavior alone.

If “followed remembered connections” is claim-critical, add the smallest
deep-content redirection control: hold `S`, both first edges, both prefixes,
both bridges, all IDs, row positions, and the visible goal fixed while
coherently swapping the two terminal goal destinations in the memory and
world. The correct first STEP must flip. A supplied-text version is zero-fit;
a native-LoRA version requires a separately trained, dose-matched coherent
tail-swap sibling. A tail *cut* only demonstrates missing information; it does
not demonstrate directional use.

The full `(O,N0,N1)` cube need not be doubled merely to obtain this optional
control. A prospectively selected paired subset is sufficient if its role is
mechanistic redirection rather than a powered outcome cohort.

## 3. Surface and order leakage that topology symmetry does not prevent

Opaque, equal-length identifiers are necessary but insufficient. A source
implementation must prevent each of these policies from decoding branch role:

- lexical/ordinal rank of the two first ports;
- lexical/ordinal rank of `U`, `F`, `R`, `K`, goal, EVENT, LINK, and PROBE IDs;
- “first S EVENT belongs to the first displayed goal”;
- contiguous row blocks for branch 0 versus branch 1;
- chronological EVENT or LINK address (`e0`, `e8`, `l4`, and so on) as a
  semantic branch label;
- order in which OLD sources, tails, and NEW bridges were experienced;
- selected-first versus scheduled-second NEW bridge;
- probe-card position and reachout goal side;
- training-row order, repeated batch slot, or compiler view order; and
- any combination of goal-ID rank with one of the above.

Do not hash semantic slot indices directly into public IDs and call the result
balanced. Allocate an independent opaque pool, then assign it to roles through
a prospectively fixed block permutation. Independently permute:

1. semantic role to identifier;
2. role to child address;
3. public row serialization;
4. OLD formation order, subject to valid receipts;
5. which goal/branch is selected first during authentic reachout; and
6. batch/view order in SLEEP.

The permutations must be balanced across roots/cells by construction, not by
regenerating until a shortcut score happens to pass. Because four DEV roots
are small, report exact projection collisions rather than relying on character
frequency or a tokenizer-level “looks random” test.

The shortcut certificate should include every singleton and relevant pairwise
projection of visible goal/current IDs, port-ID rank, node-ID rank, event/link
address rank, row position, chronology position, probe-card position, and
training position. For each projection report support, number of labels, and
Bayes-best first-step and whole-route accuracy. Any deterministic key or
radius-0--3 policy above one-half blocks the prospective interpretation.

## 4. Authentic chronology is feasible, but not as presently implied

The existing PCFL machinery has nine EVENTs, six LINKs, one NEW probe, and one
NEW EVENT. The braid needs ten EVENTs, eight LINKs, two valid probes, and two
NEW EVENTs. Reuse is plausible, but the following semantics must be explicit
before authoring.

### OLD formation

The host must visit `S` twice and each of `U0,U1,R0,K0,R1,K1` once. Those are
scaffolded source opportunities, not one continuous walk from `S`; call them
that. Both S ports must ultimately be executed, but the first child choice
cannot determine which semantic EVENT address permanently means “branch 0.”

Use branch-bound opaque addresses supplied after the actual receipt, or define
semantic role from the admitted source/destination fields and keep child
addresses independent of role. Required banks and cuts must compare semantic
fields as sets. They must not require a specific child execution order merely
to make `e0/e2` or `l0/l1` line up with a private diagram.

### NEW formation

A `PROBE` result is not automatically an executed EVENT under the current
schema. The present admission path requires an `EXPLORE` receipt and rejects a
probe receipt as EVENT evidence. For both selected and scheduled bridges, bind
one of two honest choices:

1. PROBE reveals the port, then the child executes that port at the frontier,
   receives the ordinary transition receipt, and authors the EVENT; or
2. prospectively redefine PROBE as the witnessed transition action and change
   the public EVENT/provenance contract everywhere.

The first option is smaller and preserves the existing EVENT meaning.

Whichever probe is chosen first, the other branch must receive the same
sequence shape: public probe result, child-executed frontier action, ordinary
receipt, EVENT commitment, and two exact crossing LINK commitments. The four
crossing LINKs are a required semantic set; LINK address assignment cannot
depend on which pair the child happened to write first.

The current NEW session becomes terminal after some probe choices and only
allocates `e8,l4,l5`. It cannot simply be reused. Separate “selection task
terminal” from “authentic lineage terminal,” allow both symmetric probes, and
allocate both branch-specific bridge records without silently manufacturing
child rows.

### Selection failures and the scheduled complement

Predeclare the adverse path. A wrong but valid probe still returns its real
bridge and is scored wrong for that goal; the scheduled complement can then
supply the other branch. An invalid/malformed probe cannot be quietly repaired
or replaced with a favorable child choice. Either the lineage fails the
reachout/formation gate, or both bridges are subsequently supplied under a
plainly non-autonomous scheduled condition and that root loses the reachout
claim. Do not select only lives whose first probe was correct.

The scheduled complement is legitimate only if its model-visible EVENT/LINK
rows are indistinguishable in schema and provenance wording from the first
bridge. Private receipts may record which was scheduled. Neither scheduled/
selected labels nor the reachout goal, card position, PROBE transcript, or
selection judgment may appear in any supervised **or loss-masked input** of
the S2 writer. Loss masking a goal-bearing prompt does not prevent the target
gradient from learning a goal-conditioned shortcut.

Only grounded EVENT/LINK spans and their target-blind compiler views should
enter this bounded S2 comparison. This is stricter than the eventual whole-life
dreamer, but necessary here because the same two goal IDs are used at delayed
evaluation.

### Cell isolation

Every `(root,O,N0,N1)` cell is a different authentic lineage and S2 adapter.
Never pool cells that share a root: they contain contradictory first-port and
bridge bindings for the same opaque IDs. The two goals alone fork from one
byte-identical, non-writing S2 snapshot. No goal fork writes back.

There is no information-theoretic impossibility in child EVENT/LINK formation.
There is a real behavioral risk that a 7B child cannot recall the OLD event
addresses well enough to author four cross-sleep LINKs. That is a formation
result. Do not backfill failed LINKs with ideal rows or show it the required
pair in an answer-bearing prompt. The ideal row bank is valid only for the
separate supplied-memory ceiling.

## 5. Cuts need a new grouped definition

The current PCFL implementation's `OLD` and `NEW` cuts are singular carriers
(`e0` and `e8`). That cannot be inherited unchanged.

For the braid, the information-removal projections must be:

- **OLD-start binding cut:** remove or mask both `S -> U0` and `S -> U1`
  EVENT blocks and every incident LINK block. The resulting visible bytes must
  collide across `O=0/1` while required first actions differ.
- **NEW-bridge binding cut:** remove or mask both `F0 -> R0` and `F1 -> R1`
  EVENT blocks and every incident LINK block. The resulting bytes must collide
  across the relevant `N` bit while required bridge actions differ.
- **tail cuts:** remove the goal-relevant final suffix relation and all
  incident LINKs, separately and symmetrically for each goal.
- **coherent opposite-cell mount:** mount a complete internally coherent
  memory from the opposite `O` or relevant-`N` cell while keeping the task
  world fixed; the registered first or bridge STEP must redirect and fail in
  the true world.

A cut which deletes only one candidate can reveal the other by absence. A cut
which leaves an incident LINK can leak the removed EVENT identity. Every cut
must have exact byte-collision groups with multiple correct labels, not merely
a lower graph-oracle score. The addendum's statement that the old cuts survive
unchanged should therefore not govern source authoring.

## 6. The action grammar and memory-service condition conflict

The proposed static grammar admits only `THINK`, `STEP`, and `PROBE`. Yet the
comparison roster later includes a memory service, and the current
`ACTIVE_LINKED_TEXT` service requires child-issued `READ EVENT`,
`READ EVENTS_AT`, or `READ LINKS_FROM` operations. Both statements cannot be
implemented simultaneously.

Choose and bind one of these designs:

1. **Passive supplied-memory comparison:** full graph, exact EVENT/LINK text,
   EVENT atoms, raw receipts, native LoRA, OFF, and wrong-root all use the
   common `THINK/STEP/PROBE` grammar. Remove “memory-service” and
   `ACTIVE_LINKED_TEXT` from this comparison.
2. **Active-reader comparison:** add the exact common `READ` union and a fixed
   cumulative READ budget to every compared actor. Define target-blind service
   semantics for text and LoRA-reader arms and exact `MISS` semantics for
   controls. The service must never choose the first read, rank by goal,
   enumerate legal ports, or return only the correct branch.

Do not compare a service arm whose decoder can request concrete information
against a native arm under a different grammar and call it a substrate effect.
`ACTIVE_STRUCTURED_TEXT` in section 8 is also not the current registered name
(`ACTIVE_LINKED_TEXT`); the source contract must use one exact condition name.

## 7. Supplied-memory ceilings and later LoRA results

The staged comparison is scientifically interpretable if the ceilings are
kept in their correct role:

- `EXACT_WITNESSED_GRAPH` establishes that the actor/interface can execute the
  topology when all semantic edges are supplied.
- Exact authentic-shaped EVENT/LINK text establishes that the actor can parse
  the same row language the writer later trains.
- EVENT-only text establishes that LINK rows are not information-necessary.
- Active target-blind text, if retained under a valid READ contract, measures
  cueing/search separately from storage.
- Native LoRA versus OFF/wrong-root/cuts/cross-mounts tests whether personal
  parametric content changes action.

The graph ceiling is not an equal-access baseline for LoRA: the graph prints
every port, while mounted LoRA must both recover and use it. Treat it as a
constructive ceiling, not evidence that native failure is “only storage.” If
exact EVENT/LINK text also fails, no native-LoRA action result is interpretable
as a composition test.

If the cold 7B ceiling fails and a composition bootstrap is introduced, the
bootstrap must be frozen on target-disjoint, non-isomorphic graph families and
mounted identically in every memory condition. Re-run every supplied-memory
ceiling and OFF control with that exact inherited child. Preserve the cold
failure; do not call the bootstrap a SLEEP repair or evidence the child learned
composition from personal experience.

Requiring an overt `THINK` in the ceiling is an interface/compliance endpoint,
not proof of internal reasoning. Report strict goal reach and accepted THINK
separately. If the architecture requires THINK-before-STEP, make that public
rule identical across all arms and keep the joint gate, but do not describe a
failure to emit THINK as inability to follow the supplied graph.

## 8. LINK-added value remains empirical and resource-sensitive

The memo correctly says exact EVENT endpoints already determine every LINK.
AUTH over ATOMS can therefore show that an explicit connected representation
improves acquisition/access/use, not that LINK contains additional world
information.

A claim needs all of:

- identical authentic EVENT rows;
- matched initialization, optimizer/update tape, presentation count, target
  token count, and interface;
- a non-inert equal-work comparator, not parser-disjoint PAD presented as
  gradient-neutral;
- EVENT read fidelity matched before behavior is compared;
- an internally coherent LINK intervention whose changed content redirects a
  predeclared action; and
- no target-aware retrieval or row ordering.

If EVENT-only succeeds, report connected read-time composition. If AUTH and
ATOMS tie, report no observed LINK-added value. If AUTH wins but the work or
fidelity gates differ, the mechanism remains confounded.

## 9. Minimum amendment before source authoring

Source authoring may begin once one short amendment binds these points:

1. independent, prospectively balanced permutations for role-to-ID,
   role-to-address, row order, formation order, reachout order, and sleep
   order, plus an exhaustive
   radius-0--3 plus surface-projection shortcut certificate;
2. branch-semantic EVENT/LINK membership independent of child chronology;
3. the exact selected-probe and scheduled-complement action/receipt/EVENT/LINK
   sequence, including adverse behavior for wrong and malformed selections;
4. strict exclusion of reachout-goal, selection-order, card, judgment, and
   scheduled/selected bytes from every S2 training input and target;
5. one isolated S2 lineage per cube cell and sterile paired-goal forks only;
6. grouped OLD/NEW/tail cuts and coherent opposite-cell mounts, all with exact
   collision/redirection certificates;
7. passive-memory versus active-READ interface choice and one exact condition
   registry;
8. graph, exact EVENT/LINK text, and EVENT-only ceilings before learned-memory
   interpretation; and
9. claim wording limited to goal-conditioned early action from distributed
   personal memory unless the deep tail-redirection control is run.

Then run the two independent deterministic topology/checker implementations
already required by the proposal before any model use. Any surface projection
above one-half, route multiplicity, inability to produce both authenticated
NEW EVENTs, or failure of exact cut collisions returns the design to source
repair—not to prompt or threshold tuning.

## Final ruling

**Conditional source-authoring GO after amendment; execution remains NO-GO.**
The addendum repaired the reachout overclaim and its `1/4` proof is correct.
The delayed braid is a materially better prospective task than the retired
local-degree topology. Its core geometry does force an early goal-conditioned
choice using nonlocal life information, provided the source author blocks
surface and chronology channels.

The smallest next move is not a new benchmark. It is a precise source contract
for chronology, grouped cuts, ordering, and the READ/no-READ interface. Once
those checks pass, supplied-graph/text ceilings can validly qualify the actor;
later LoRA, wrong-root, cut, and coherent cross-mount comparisons can validly
test whether parametric personal memory changes the action. They still cannot,
without the deep redirection control, reveal the model's internal search
algorithm.
