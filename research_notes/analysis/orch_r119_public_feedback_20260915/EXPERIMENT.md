## Hypothesis and reason to change the experiment

R109 yielded no executable interpreter output in 96 attempts. Its instructions
omitted the exact required JSON key and mixed helper-signature placeholder
names with the one permitted input identifier. Descriptive review found some
task-aligned edits, but no usable corrected program. A format-confounded zero
cannot test functional feedback learning fairly.

R119 explicitly supplies the required single-line final JSON schema, the
`values` input identifier, allowed syntax, and every helper's signature and
semantics. These are public interface documentation, not a task solution.
Reasoning before the final line remains permitted, with no mandated headings,
branch count, minimum length, or invented observations. The unchanged original
parser and interpreter remain the evaluator. No permissive rescoring.

## Matched collection and parent-free readout

- Sixteen fresh TRAIN and eight fresh DEV parameter combinations. Reserve
  eight additional CONFIRM combinations but do not query them in collection.
  Check normalized functional specifications against all 64 historical ledger
  tasks and across the new partitions. This is compositional within-family
  freshness, not a claim that the base never learned these operations.
- Four analysis conditions: fixed C2 FULL15332 and frozen BASE, each with
  actual public execution feedback versus matched no-new-feedback opportunities.
  Each model/task produces one draft, shared verbatim into the two forks.
  Identical initial prompts and decoder settings.
  This is a feedback-collection comparison, not a second parenting baseline
  trio and not evidence of a learned effect by itself.
- One draft per model/task and two revision opportunities per fork, at most
  **240 responses** (160 TRAIN, 80 DEV). Continue the assigned opportunities after failure or
  success; preserve all outputs and outcome tags. No success-dependent retries.
- At most 2,048 generated tokens/response, 16,384 context tokens; do not trim
  context or fill a minimum budget. Record actual tokens, truncation, changed
  expressions, executed public probes, and functional versus interface-only
  repairs. A changed expression or a successful parse is not metacognition.
- Public feedback contains only the child's own interpreter observation or
  diagnostic on declared public inputs. No expected answer, hidden test input,
  hidden score, or teacher correction is supplied. DEV transcripts never enter
  candidate rows, parent prompts, or a sleep buffer.
