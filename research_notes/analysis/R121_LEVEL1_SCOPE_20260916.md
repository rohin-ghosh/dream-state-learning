subsequent acquisition of the SAME skill in four conditions:

1. Level-1 child plus responsive teaching.
2. Original frozen-base starting point plus responsive teaching.

preservation measured separately. Levels 2–3, deployment, environment-clone

scope change does not retroactively turn exploratory results into a matched

## What the four-condition experiment still needs

- One declared skill family and disjoint acquisition, development and sealed
  transfer/retention task IDs. Validate the response interface first: the R136
  parser failure pattern would confound a purported semantic skill comparison.
- Pin the original base and selected Level-1 adapter before skill acquisition.
  Preserve their distinct starting measurements. Do not pick an adapter using
  FINAL results or silently transfer optimizer/replay history across conditions.
- Identical task streams/seeds, common teacher policy for the two responsive
  teaching conditions, explicit available feedback, and matched acquisition
  opportunities. Report actual delivered teaching, missing slots, generation
  tokens, optimizer updates/exposures, latency and total compute; equal sleep
  counts alone are not equal doses.
- Fresh-process, empty-context evaluation of each acquisition state at the
  same declared boundaries. No parents, Markdown files, acquisition lesson/source
  tables, prior solutions or acquisition histories may enter the retention
  prompt; the novel task's legitimate input data must still be supplied. No
  evaluation-generated material enters subsequent training. Keep acquisition
  feedback separate from hidden evaluator verdicts. Add fresh transfer tasks and the fixed
  code/math/tool/concise-answer capability panel.
- Report starting level AND acquisition change, learning curves at matched
  budgets, paired task/seed contrasts and uncertainty. Richness/persistence/
  functional metacognitive-control measures explain behaviour; verbosity or
  branch counts alone do not establish a skill-acquisition advantage.

These are design requirements, not a claim that the new benchmark is ratified
at the implementation-byte level. Before changing the benchmark/claim system,
bind the scoped intake and required deliberation under the repository contract.
No Level-2/3 architecture work is needed to answer these questions.

## SEAL baseline: missing components and fidelity

Primary source checked September 16, 2026: Zweiger et al., *Self-Adapting
Language Models*, arXiv:2506.10943v2; official repository
`Continual-Intelligence/SEAL`.

SEAL generates self-edits (adaptation data and/or update directives), adapts
weights in an inner loop, and learns its self-edit policy in an outer
reinforcement-learning loop using post-adaptation performance as reward.
A single generated reflection followed by SFT is NOT a faithful SEAL baseline.

Needed: pin the official implementation/version and chosen task regime; map it
to the project's frozen Qwen2.5-7B plus LoRA constraint; implement or reuse its
self-edit generation, inner adaptation and reward-trained outer policy; isolate
outer-policy training tasks from final acquisition/retention tasks; preserve
checkpoint/optimizer lineage; and account separately for offline policy-training
cost and online acquisition cost. Do not reuse sealed test scores as reward.
Any omitted outer-loop training, changed update mechanism or model constraint
must be named explicitly (e.g. "SEAL-inspired self-edit ablation"), not reported
as reproducing the published method. No SEAL baseline is currently verified in
this repository by this audit.

## Markdown baseline: missing components and interpretation

Needed: an original-model wrapper with an explicit file creation/edit policy,
bounded file size/context and the same legal acquisition feedback; versioned
file snapshots, append/edit provenance and a fixed read policy; and no adapter
or optimizer updates in this condition. Declare whether edits are learner-written
or teacher-written and count the associated teaching/model calls.

Report two distinct evaluations: (a) memory-assisted acquisition/application
with the file present, and (b) the mandated empty-context retention test with
the file absent. A frozen model with its only memory removed has no intended
parameter-learning channel; file-free performance is a no-retention reference,
not an equal-mechanism adaptation baseline. Do not claim a discovery from
beating that reference alone. Responsive teaching on the original model is
the essential control for whether Level-1 initialization helps learning.
