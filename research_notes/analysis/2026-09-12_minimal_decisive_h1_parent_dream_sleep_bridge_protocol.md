# Minimal decisive H1 bridge: parent -> child DREAM -> SLEEP -> parent-free action

**Date:** 2026-09-12
**Status:** design memo only; no implementation, model call, training, or GPU
launch was performed by this memo.
**Purpose:** specify the smallest paper-worthy experiment that closes the
currently missing causal link without expanding into H2 or the full PCFL
programme.

## Decision in plain language

Use one tiny arbitrary-action world. In each source block the child sees two
visible modes, chooses real actions, and receives real success/failure
outcomes. It then decides, in its own output, either to write one scoped
two-mode action rule with evidence citations or to write nothing. A strong
parent teaches this process across blocks; an equally present sham parent does
not. The parent never sees the later test or any hidden action mapping.

SLEEP admits only supported child-written rules, mechanically replays their
exact child-written action lines, and writes one unified rank-8 LoRA. Then all
parent messages, classroom state, artifacts, ledgers, and retrieval are
removed. On new objects and new wording, the child must take the right first
action from weights alone.

The decisive comparison is not merely parented versus unparented. Each
child's sleep is also copied into a **mode-swapped** control with the same
tokens, targets, dose, and optimizer seed. If the writer is genuinely using
the child's conditional rule, the authentic adapter must follow the lived
mapping and the swapped adapter must follow the opposite mapping. A global
`ACT:` habit, generic action preference, or formatting improvement cannot
pass this test.

This is one bounded H1 bridge:

```text
strong process parent (versus active sham)
  -> child acts and observes outcomes
  -> child chooses STORE or NULL and authors the rule
  -> factual/provenance gate only
  -> authentic versus mode-swapped SLEEP write
  -> parent/context-free first action on held instances
```

It does not attempt recurrence, long-horizon improvement, knowledge-graph
traversal, or the H2 deployment interaction.

## Why this is the next bridge

The current evidence isolates exactly this missing composition:

- The level-0 teaching fit installs one repeated prediction-before-action
  sequence on 32/32 held operand pairs, but its one-exposure nonce bank reads
  as one constant colour (4/16), so a global habit is not evidence of
  conditional memory.
- Synthetic and supplied material can move LoRA outputs, but the historical
  writer shows spill, interference, and interface damage. The opposite-action
  sign canary and level-1 conditional qualification therefore remain hard
  dependencies rather than assumed machinery.
- The child has occasionally produced grounded source records after worked
  examples, while the citation and RuleGame paths have not yet carried a
  qualified child record through write, clean reload, and use. Prompting the
  form and writing the form are not the missing end-to-end result.
- Existing parenting observations are lexical or transient and no clean test
  has connected a parent intervention to a grounded child-selected memory and
  then to parent-free action.

This protocol joins those edges once. It does not reopen the full paper
ladder.

## 1. Exact question and claim unit

The question is:

> Does a bounded process-teaching package cause a clean child to author more
> useful grounded conditional artifacts from its own actions and outcomes,
> such that a selective SLEEP write of those artifacts causes better first
> actions on held instances after every temporary teaching channel is gone?

The **independent unit is one clean root block**, containing one process-
parented child and one active-sham child born from byte-identical state. Task
items, prompt forms, generations, modes, and optimizer steps are nested
measurements, not independent samples.

The experiment is a case study of one taught competency:

> After a completed evidence block, distinguish observation from guess;
> connect the two observed modes into a scoped conditional action rule; cite
> the executions supporting it; and choose no write when the observations do
> not support a reusable rule.

This is narrower than “learn to think.” It is the smallest version of the
paper's observed missing skill: failure/outcome -> grounded diagnosis ->
reusable lesson -> later action.

## 2. Release dependencies

Do not spend a clean child until all of the following are terminal:

1. The four-update, two-input/opposite-action sign canary passes on the exact
   native `ACT: a0` / `ACT: a1` strings, tokenizer, chat prefix, scoring path,
   loss mask, LoRA modules, optimizer family, and clean reload used here.
2. The level-1 teaching corpus passes its registered open-loop acquisition and
   held-form readout, including at least one complementary conditional mapping
   with an equal-marginal wrong-binding control, and selects one fixed
   plasticity recipe without opening its sealed confirmation set. A pass of
   only the current level-0 addition/global-ritual scout is insufficient.
3. The chosen level-1 birth adapter and corpus have clean, task-naive lineage,
   pass interface/no-harm checks, and contain none of this experiment's family,
   mode, object, parent, source, or evaluation identifiers.
4. A CPU end-to-end fixture proves real action -> immutable outcome receipt ->
   child artifact -> exact evidence join -> child-only loss target -> adapter
   identity -> fresh-process readout. Forged, orphaned, reordered, duplicated,
   parent-copied, and evaluation-derived artifacts must fail.

If level 1 does not qualify, do not silently start this experiment from a
different checkpoint. A base-only H1 test would be a separately frozen study.

## 3. Starting child and unified adapter

All roots start from the same frozen Qwen2.5-7B-Instruct base and the same
qualified level-1 birth state. There is still only **one adapter**.

- The no-personal-write condition is the sealed birth adapter.
- An authentic or swapped personal SLEEP reconstructs one rank-8 adapter from
  the frozen base using the identical frozen birth corpus plus the new child
  corpus.
- No adapter stacking, separate memory adapter, base-weight update, optimizer
  continuation, or task-exposed ancestor is allowed.
- Birth material receives exactly the fixed replay share selected before H1;
  it is byte-identical in every personal write. Only the child corpus differs.

Every experimental child is disposable after this study. None may become an
ancestor of the CompilerGym deployment experiment.

## 4. The micro-world

### 4.1 Informative families

Each root has 16 opaque family identifiers, two opaque modes `m0` and `m1`,
two legal actions `a0` and `a1`, and fresh opaque object identifiers. The
family mapping is:

```text
correct_action(family, mode) = a[orientation(family) XOR mode]
```

Exactly eight families have each orientation. This makes constant-action,
mode-only, object-only, and first-position strategies score 0.50. The mapping
is arbitrary; it cannot be recovered from pretraining semantics.

For each family the child completes one source block:

1. It receives a new object in `m0`, emits exactly one `ACT: a0` or
   `ACT: a1`, and receives the real deterministic `SUCCESS` or `FAILURE`.
2. It receives a different object in `m1`, acts once, and receives the real
   outcome.
3. The public contract says exactly one of the two actions succeeds for a
   given family-mode pair. Therefore either success or failure identifies the
   supported future action; the harness does not state that action.
4. The child receives one neutral DREAM opportunity and writes either
   `DREAM: NULL` or a child-generated record containing the family, both
   mode-conditioned `ACT:` lines, and evidence IDs.

The child is not forced to explore a preferred action, repaired after an
invalid output, or given a hidden answer. Missing/invalid actions and missing
artifacts remain failures.

### 4.2 Null families

Four additional families return the truthful public result `UNAVAILABLE` for
both source actions. They have no scored downstream mapping. Their correct
DREAM decision is `NULL`. They prevent “store every block” from counting as
discretionary memory.

### 4.3 Task separation

- Parenting/source objects, held readout objects, canary items, and unrelated
  interface items are identifier-disjoint.
- The held readout reuses the learned family and mode cues because this is a
  memory test, but uses new objects and two unseen ordinary task renderings.
- Call this **held-instance and held-rendering transfer within a registered
  world family**, not unseen-task-family or domain generalization.
- Family identities and orientation maps are disjoint across root blocks.

Before any model call, freeze and hash every identity, mapping, template,
order, generation seed, scorer, parser, threshold, and exposure-registry
result. Reject any identifier with prior model exposure.

## 5. Parenting treatment

The parent is the strongest available model at protocol freeze. “Pinned” means
its exact model/version, teaching core, starting prompt, tools, and decode
policy are fixed; it **does not** mean the parent is stateless. Within one
child's school, the parent retains its own prior teaching dialogue and may
improve its explanations from context. Parent weights never train. Parent
state is reset between root blocks and may never read another child.

There are five interventions per child, after source blocks 1, 5, 9, 13, and
17. Block 1 and blocks 18--20 are informative. Put one null block in each of
the four intervals 2--5, 6--9, 10--13, and 14--17, rotating its within-interval
position across roots. After each intervention the child writes one short
process note in its own words; this is the only compact classroom state carried
into the next blocks.
That temporary note is DREAM/context management, not SLEEP material.

Two randomized childhood conditions share the same world tape and opportunity
budget:

- **P — process parent.** It teaches the single competency in section 1,
  choosing its correction adaptively from the child's actual process failure.
- **S — active sham.** The same parent model gives warm, equally timed
  acknowledgment and asks for a chronological recap, but may not teach
  evidence use, scope, conditionality, storage, future action, comparison, or
  credit assignment.

The parent sees only a bounded redacted view of completed blocks: the child's
reasoning, public action/outcome relations, artifact, and categorical verifier
reasons, with every literal family, mode, object, evidence, and action token
replaced by stable role placeholders. It may therefore notice process errors
such as ignoring a failure or collapsing two conditions, but cannot emit a
literal task action. It never sees target identifiers, orientation maps,
future blocks, held items, adapter state, loss, canary score, or evaluation
score. Current-block advice arrives only after that block's artifact, and the
next family has an independent hidden orientation.

Deliver P and S through the same marked field and native-token-pad the visible
message to the same fixed length. Match parent calls, output ceiling, child
restatement calls, schedule, tools, and context capacity. Record actual parent
input/output tokens and latency rather than claiming equal compute from equal
caps. One output only: no regeneration to obtain a nicer lesson or sham.
Parent text is visible to the child during childhood but is never a supervised
target. In this minimal renderer it is absent from SLEEP bytes entirely; any
audit reconstruction of the dialogue must loss-mask every parent token.

Literal task identifiers/actions are absent from the redacted input and any
such string in the output is rejected. An invalid parent turn uses one
presealed neutral
fallback in both arms and stays in the intention-to-treat denominator.

## 6. Child-authored DREAM and factual admission

The common DREAM interface supplies syntax, not an answer:

```text
DREAM: NULL
```

or

```text
DREAM: STORE
FAMILY: <visible family>
WHEN: <visible mode>  ACT: <child-chosen action>  EVIDENCE: <execution id>
WHEN: <visible mode>  ACT: <child-chosen action>  EVIDENCE: <execution id>
```

The child writes every semantic field. The system never completes, repairs,
paraphrases, ranks, or supplies a missing action. The gate only checks:

- the output belongs to the child-generation receipt;
- the cited executions occurred earlier in this block;
- family, modes, actions, outcomes, and ordering match immutable receipts;
- each stated future action follows from `SUCCESS`/`FAILURE` plus the public
  exactly-one-action contract;
- both modes are present exactly once and citations are unique;
- there is no unsupported universal claim or literal parent/evaluation text.

The child's selection score is

```text
Q = 0.5 * (supported STOREs / 16 informative families
           + correct NULLs / 4 unavailable families).
```

All 20 decisions stay in the denominator. Record raw STORE rate, grounding
precision, coverage, exact-parent overlap, rejection family, and the six
registered phase bands (block 1; 2--5; 6--9; 10--13; 14--17; 18--20). No post
hoc threshold or semantic judge may rescue an artifact.

## 7. SLEEP: one decision, one mechanical renderer, one write

SLEEP receives only admitted `DREAM: STORE` artifacts and their immutable
receipts. Parent turns, child classroom notes, raw parent-bearing prompts,
verifier prose, hidden maps, scores, and null blocks are absent from every
training byte.

For every accepted artifact, each of its two exact child-written `ACT:` lines
is replayed under eight predeclared held-evaluation-disjoint situation
renderings. The situation text may reorder the exact family/mode/object fields;
it may not introduce a new relation, diagnosis, or action. Context is
loss-masked. The supervised target is the exact `ACT: a0` or `ACT: a1` byte
span authored by the child. Thus the compiler changes exposure and surface
form but never decides what to remember or what action is correct.

Create two equal-dose personal writes from each child's accepted artifacts:

- **AUTH:** the actual family-mode binding.
- **SWAP:** swap `m0` and `m1` in every rendered context while leaving the
  child's target action spans and all other bytes in place. This is a coherent
  complementary control mapping because the two modes require opposite
  actions. It preserves row count, target-token multiset, action marginal,
  family exposure, supervised positions, batch composition, optimizer steps,
  initialization, and writer seed.

The mode swap is a quarantined laboratory control, not claimed lived
experience. Its receipt must prove `map_SWAP(f,m) = map_AUTH(f,1-m)` for every
admitted family and exact native-token parity after collation.

If a child admits no artifact, its real SLEEP performs no personal write and
its behavioral result equals its OFF birth state. Do not exclude the root,
borrow the other child's artifacts, add more episodes, or top up with harness
text. Corpus amount is a treatment mediator; AUTH/SWAP within that child still
have exactly matched dose.

Use the rank, learning rate, epochs, replay ratio, target modules, and canary
chosen before H1 by the qualified level-1 experiment. No rank/LR/dose search is
allowed on H1 output. Each AUTH/SWAP pair starts from byte-identical LoRA
initialization and reconstructs the common birth plus personal corpus from the
same frozen base.

## 8. Arms and parent-free readout

Each root contains these states:

| Childhood | Persistent state at readout | Purpose |
|---|---|---|
| P | OFF = common birth only | no-personal-write cut |
| P | AUTH personal SLEEP | complete proposed path |
| P | SWAP personal SLEEP | equal-dose binding redirection |
| S | OFF = common birth only | duplicated identity/randomness check |
| S | AUTH personal SLEEP | active-sham path |
| S | SWAP personal SLEEP | sham binding redirection |
| P or S | TEXT | common birth, no personal LoRA; frozen retrieval of that child's admitted artifact |

OFF needs no new fit. P-OFF and S-OFF should be byte-identical after complete
state removal; run both as a technical identity check, but do not count them as
two learners.

Before readout, preserve all evidence in the audit namespace but give the
evaluation process no read path to the parent process or outputs, child
classroom note, source prompts, raw outcomes, DREAM artifacts, corpus, ledger,
retrieval index, caches, or prior KV state. Reload each adapter in a fresh
process whose mounted inputs are enumerated and hashed. The scientific readout
contains only ordinary task instructions, one held object, family, mode, and
the two legal action forms. No feedback is shown before the scored first
action.

For each of the 16 informative families, score both modes under two unseen
task renderings: 64 strict first-action items per state. An item earns one only
for exactly one valid `ACT: a0` or `ACT: a1` matching the registered map;
missing, extra, late, or invalid actions score zero. Also record normalized
two-action log probabilities.

TEXT is a strong diagnostic memory baseline: a frozen candidate-blind exact
family/mode retriever supplies the smallest admitted child artifact within a
fixed 256-token context to the common birth model. Tie-break, truncation, and
empty behavior are frozen before results. TEXT is reported, not a prerequisite
that weights must beat at this rung. For the localization table only, “TEXT
works” means balanced accuracy at least `.75`, at least `.70` within each mode,
and at least 95% valid single actions.

Read additionally:

- 16 unexposed-family prompts;
- 16 missing/unsupported-mode prompts;
- 16 native-interface copy/action canaries; and
- 16 unrelated ordinary instructions.

Report each control family's action-distribution TV from OFF, strict validity,
multiple-action rate, and exact-copy/non-harm score. Do not average spill away
across families.

## 9. Estimands and success gate

Let `BA_z^M` be balanced first-action accuracy for state `z` scored against
mapping `M`. For childhood arm `a` in root `r`, define conditional carriage:

```text
B[a,r] = 0.5 * ((BA_AUTH^AUTH - BA_AUTH^SWAP)
                + (BA_SWAP^SWAP - BA_SWAP^AUTH)).
```

This is positive only when both equal-dose adapters prefer the mapping in
their own corpus. Formatting and constant-action shifts cancel.

The three predeclared root-level quantities are:

```text
artifact effect:   q[r]     = Q[P,r] - Q[S,r]
action gain:       g[r]     = BA[P,AUTH]^AUTH - BA[OFF]^AUTH
parented binding:  theta[r] = B[P,r] - B[S,r]
```

The H1 bridge passes only if all of the following hold on the 16 untouched
confirmation roots:

1. The two-sided 95% root-level paired interval for mean `q` is above zero and
   the mean is at least `+0.10`. Aggregate P supported-STORE coverage is at
   least `.70`, its coverage advantage over S is at least `+.10`, P's correct
   NULL rate is at least `.75`, and it is no worse than S by more than `.05`.
2. The two-sided 95% root-level paired interval for mean `g` is above zero and
   the mean is at least `+0.10`; aggregate P-AUTH balanced accuracy is at least
   `.75`, at least `.70` within each mode, and OFF is at most `.625`.
3. The two-sided 95% root-level paired interval for mean `theta` is above zero
   and the mean is at least `+0.10`. P's mean `B` is at least `.20`, P-AUTH and
   P-SWAP each have positive own-map gain over OFF, and at least 12/16 roots
   have `q>0`, `g>0`, and `B[P]>0`.
4. P-AUTH produces valid single actions on at least 95% of held items; native
   interface/unrelated-task score is no worse than OFF by `.05`; and each
   spill family's mean two-action TV from OFF is at most `.05`. Report worst
   root/family even though the gate uses the root-balanced mean.
5. Every fitted candidate has finite loss, expected target counts/steps, exact
   clean reload, and immutable corpus/adapter receipts. A technical commit
   canary may roll a candidate back to OFF, but that named condition remains
   in the intention-to-treat analysis and is scored from its actual OFF
   fallback outputs. Never replace it or manually impute a successful write.

The primary interval is the ordinary two-sided paired-`t` 95% interval over
the 16 root differences. Also report the exact 65,536-assignment paired
sign-flip test as a sensitivity analysis. The three endpoints are
noncompensatory components of one intersection claim: every one must pass;
failure of one cannot be offset by another. Never use 64 prompts, two modes,
templates, optimizer steps, or repeated OFF calls as the inferential `n`.

Interpretation by failure location is fixed:

- `q` fails: this parenting package did not improve grounded discretionary
  artifact formation.
- `q` passes but P-TEXT fails: artifacts are not usable even as explicit
  memory; repair formation/task access, not the writer.
- P-TEXT works but `g/B` fail after a qualified writer: the child material or
  personal rendering does not survive this SLEEP path.
- `g` rises but SWAP does not redirect or spill fails: broad habit, not
  selective experiential memory.
- P and S both work equally: child-authored SLEEP works under the common
  interface, but causal parenting is not established.
- P passes all gates: the bounded H1 bridge is closed; proceed to H2 only under
  a separately frozen deployment protocol.

## 10. Roots, staging, and GPU budget

### Excluded executor sentinel

Run one root first. It is permanently excluded from confirmation. It may check
only call counts, target blindness, grounding joins, token/collation equality,
adapter reconstruction, state deletion, fresh reload, and measured throughput.
Do not change scientific prompts, parent competency, maps, thresholds, dose,
or panels from its behavioral direction. A genuine infrastructure repair gets
a new version and reruns the sentinel before confirmation.

### Confirmation

Run exactly 16 new independent root blocks with predeclared root, child,
world, parent, fit, and read seeds. Randomize P/S labels and GPU/launch order
within roots. Seal readout outputs until all states in a root are terminal;
open aggregate results only after all 16 roots or their predeclared terminal
failures are closed.

This sample size is deliberately for a large bridge, not a subtle population
effect. Under the planning value `SD=0.20` for paired root effects, 16 roots
give about 80% power for a `+0.15` mean effect at two-sided .05 (normal
approximation). The registered `+0.10` practical margins remain binding. If
the root variance is larger and the intervals cross zero, call the result
inconclusive; do not promote nested prompt counts or add roots after unblinding.

Per-root maxima:

- 2 childhoods x 20 source families x (2 action calls + 1 DREAM call) = 120
  child calls;
- 10 parent calls and 10 child process-note calls;
- at most four personal fits, each at most 256 child-derived rows and 128
  optimizer steps. The exact optimizer, epoch, and batch recipe is inherited
  unchanged from qualified level 1; if it exceeds either hard cap, do not
  launch this version;
- 64 held items x 8 named states (OFF identity once, P/S AUTH, P/S SWAP, and
  P/S TEXT, plus one repeated OFF identity check) = 512 short action calls;
- four 16-item control families x 5 unique parametric states (OFF plus P/S
  AUTH and P/S SWAP) = 320 additional short calls; each of the two TEXT states
  receives the native-interface and unrelated-task controls, another 64 calls;
- no more than **6 reserved A40-hours per root**, including loads, fits,
  readout, cleanup, and failed scientific candidates.

The confirmation cap is therefore 96 A40-hours; the excluded sentinel adds at
most 6, for **102 aggregate A40-hours**. Parent service use is at most 170 calls
(10 x 17 roots), each with a 256-token output ceiling. Before launch, one
result-blind profile must replace the illustrative fit/runtime forecast with
measured counts while staying under these ceilings. If the exact protocol does
not fit, stop and re-freeze; do not silently reduce roots or controls.

With 16 free A40s this is approximately one root per GPU and should fit in one
working day if the measured per-root cap holds. Sequential stages of one root
may not overlap; independent roots may.

Scientific failure, artifact shortage, invalid child action, rejected adapter,
and sham success are terminal data, never rerun. A pre-model-load or other
clearly infrastructure-only abort may repeat the identical root plan in a new
directory; preserve both attempts and never replace a root based on outcome.

## 11. Information visibility

| Principal | May see | Must never see |
|---|---|---|
| Child during source | current family/mode/object, its own action and public outcome, current temporary process note | hidden mapping, held objects/forms, another child/root, report scores |
| Adaptive parent | its own prior teaching context; bounded redacted child reasoning, public action/outcome relations, and categorical artifact defects | literal family/mode/object/action/evidence IDs, future/source maps, held panel, sleep corpus, adapters, losses or scores |
| DREAM child | its current family's two immutable public execution receipts and temporary process note | hidden answer, evaluator map, held items, other roots |
| Grounding gate | child output and immutable public action/outcome receipts | authority to repair, paraphrase, rank, or invent a lesson |
| SLEEP renderer | admitted artifact, exact cited receipts, frozen birth corpus, predeclared renderings | parent/classroom text, hidden map, evaluator outputs, rejected/null artifacts |
| Writer | frozen rendered corpus and recipe | parent, live child context, report output, alternative-arm results |
| Scientific readout | ordinary current task only; TEXT gets its frozen retrieved artifact | parent, source transcript, DREAM prompt, ledger, previous item, feedback before first action |
| Analyst | sealed manifests and blinded completeness status until terminal | partial treatment direction used to stop, extend, select, or repair |

All source, parent, artifact, corpus, adapter, state-deletion, and readout
identities receive immutable hashes. The semantic exposure registry is a
mandatory nonempty input; a missing/default registry is preparation failure.

## 12. Stop rules

Stop before model execution on prior-exposure collision, nonidentical P/S
world tape, target token in parent input, invalid sham semantics, task token in
parent output, birth contamination, parser/scorer ambiguity, token/collation
mismatch, target truncation, non-child target token, or inability to make all
temporary state unreadable at readout.

Stop a root, preserving it, on source/corpus/adapter mutation, wrong model or
checkpoint, nonfinite training, unexpected step count, stale cache, parent
cross-root state, task-order drift, result exposure before paired completion,
failed teardown, or missing generation/execution receipt. Do not regenerate a
parent message, child artifact, source episode, or eval item to improve a
scientific outcome.

The whole H1 experiment stops without confirmation if the exact writer sign
canary or conditional level-1 qualification fails. After the excluded sentinel
passes operations, confirmation does not use outcome-adaptive early efficacy
stopping. The complete 16-root analysis is required for a paper claim.

## 13. Claim boundary

If every gate passes, the maximum claim is:

> Across 16 predeclared clean root blocks in an arbitrary two-action world, a
> strong adaptive process parent increased the child's production of grounded
> two-condition action artifacts relative to an active sham. A single LoRA
> reconstructed from the common birth corpus plus only those verified
> child-authored action continuations selectively changed first actions on new
> objects and new task wording after the parent and all temporary childhood
> state were removed; equal-dose mode-swapped writes redirected the behavior.

This establishes one-cycle, parent-caused, child-authored experiential
compilation and parent-free held-instance action use under the frozen recipe.
It does **not** establish:

- broad metacognition or general parenting efficacy;
- domain/task-family transfer;
- multi-sleep retention, continued improvement, H2, or a flywheel;
- connected knowledge beyond one two-branch conditional artifact;
- goal-conditioned graph traversal or active knowledge expansion;
- physical or semantic compression;
- superiority to the evolving active-text baseline (TEXT is diagnostic here);
- a sentience or alignment claim.

If the bridge passes, the exact adult lineage still cannot be reused for the
final CompilerGym test; it licenses the frozen parenting/SLEEP recipe to be
used on new clean children in the H2 2x2. If it fails, its localization table
determines whether the next work is parenting, artifact formation, rendering,
or writer repair rather than another unstructured lifetime.
