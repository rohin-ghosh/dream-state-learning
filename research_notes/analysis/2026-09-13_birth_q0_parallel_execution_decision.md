# Birth and selective-writer execution decision

**Date:** 2026-09-13 UTC / 2026-09-12 PT  
**Scope:** watcher-side execution advice. This changes no builder source, model,
adapter, job, GPU process, threshold, or scientific result.

## Decision in plain language

Run two small tracks in parallel.

1. **Engineering birth:** finish and run the already prepared authored birth
   fit once. It asks whether the current corpus can install the intended
   conditional routines while preserving addition and copy behavior.
2. **Claim-bearing writer:** implement and run the already closed complementary
   Q0 test without using any engineering-birth outcome. It asks whether the
   writer can make the intended local action change without changing unrelated
   behavior.

This is not two competing architectures. Q0 is the selective-write gate for
the conditional part of birth. Parallel execution buys calendar time because
the prepared birth runner and the new Q0 executor are different engineering
paths and the available compute is not the limiting resource.

The separation is strict:

- label the current 1e-4 full-response birth EXPLORATORY_PRE_Q0;
- do not use its weights, losses, outputs, errors, templates, root, seed, or
  downstream behavior to alter Q0 bytes or interpret Q0;
- do not use that adapter as the scientific Level-2 child;
- if Q0 qualifies a writer, create the claim-bearing birth from a fresh
  root under the frozen selected writer;
- if Q0 does not qualify, preserve the engineering birth result as a direct
  installed-routine diagnostic and do not call it selective writing or
  learning-to-learn.

The small duplication is deliberate. It prevents a day of serial waiting while
also preventing an exploratory result from becoming a post-hoc recipe search.

## What the engineering birth must measure

Do not change the pending corpus, rank, learning rate, epoch count, batch
composition, or held-development panel before its first result. The corpus
already has the most relevant known data ingredients:

- multiple renderings (4 for PROSPECT and 2 for REVISE);
- explicit visible keys and native use-shaped targets;
- fully crossed counterconditions;
- distinct-source interleaving; and
- truthful addition and copy anchors.

Add one readout only: a deterministic exact-training-form conditional panel.
Use one rendering for each 16 PROSPECT and 32 REVISE semantic sources in each
of OFF, AUTH and DERANGED: 48 x 3 = 144 extra greedy calls. It diagnoses:

    exact low, held low       -> acquisition failed
    exact high, held low      -> stored but not extractable
    exact high, held high,
    locality failed           -> extractable but unscoped
    exact high, held high,
    locality passed           -> direct supplied-policy component passed

The last line remains an installed finite routine. It is not evidence that the
child learns better from later experience.

Allen-Zhu and Li (arXiv:2309.14316) motivate the separation of exact storage
from held-form extraction, varied renderings, and early use-shaped data. Their
actual experiments concern scratch-pretrained biography models, not repeated
LoRA sleep, so they are a design prior rather than direct evidence for our
rank, rate, dose, or architecture.

## What can proceed to Level 2

Only a fresh birth produced after the selective writer is frozen can enter the
claim-bearing Level-2 sample. The engineering adapter may still be used to
exercise and debug the role-routing bridge, but that is plumbing and carries
no learning claim.

The first Level-2 causal sample should remove adaptive-teacher variation:

- create a new opaque task mapping only after births are sealed;
- give authentic birth, a non-harmful active control birth, and OFF the same
  task opportunities, public evidence, teaching bytes, order, and budgets;
- let child-authored records differ, because that is the proposed mediator;
- fork each birth into PROMOTE (write the new records) and SHADOW (collect the
  same phase but reload the unchanged birth);
- read all branches after teacher/context deletion on fresh task cases;
- test at zero evidence and after two small evidence/write blocks.

The primary question is not whether AUTH emits more reflection words. It is
whether its promoted-minus-shadow task-learning slope exceeds both controls.
External task actions are primary; record quality, selective use/omission,
interface preservation, and cost are mediators.

Adaptive strongest-model parenting follows this controlled slice. It is the
system we ultimately want, but transcript-conditioned lessons make it a
different causal treatment and should not be used to decide whether birth
itself changed absorption.

## Deadline split

- The three-root Q0 terminal is the only new experiment required by the narrow
  deadline paper.
- The engineering birth and one Level-2 root are the highest-value research
  probes for the intended Experience Models paper.
- Run them in parallel; do not make either wait for optional replay,
  compression, larger memory banks, or classroom-scale work.
