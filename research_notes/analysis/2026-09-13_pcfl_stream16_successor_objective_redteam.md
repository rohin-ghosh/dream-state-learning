## Verdict: REWORK before paper-grade execution

The successor is a strong skeleton, and its exogenous lifetime clock is a real
repair. It is not yet safe to execute as the paper-grade O1--O10 campaign.
Four gaps can still turn a clean-looking result into the wrong claim:

1. It is explicitly bound to DEV **v2.1**, while the current prospective
   writer repair is **v2.2**. The lifetime campaign must inherit the exact
   qualified v2.2 writer without reopening heat, replay, batching, wrappers,
   rank, or checkpoints.
2. `ACTIVE_LINKED_TEXT` can pass its certificate without demonstrating that
   its access budget is saturated, and the fixed-history carrier contrast is
   sampled at only three cuts. That is insufficient for either a carrier AUC
   or a plateau claim.
3. `FINAL_BATCH` inherits the periodically learned DLT history. It controls
   the timing of fitting on that history, but not the effect of periodic
   writes on which later experience was generated. It therefore cannot by
   itself attribute the recurrent THINK--SLEEP flywheel.
4. Sixteen roots are a rational blinded starting cohort, not a guaranteed
   paper sample. The eight-root ATOMS sentinel and vaguely "positive paired
   direction" do not support the connected-memory claim at the same strength
   as the lifetime claims.

These are prospective design repairs. They do **not** justify delaying the
bounded v2.2 two-root DEV vertical. The highest-information next action per
GPU-hour remains: qualify the v2.2 writer on the disposable authentic root,
then run the stage-gated v2.2 DEV and stop at the first failed seam.

## 2. Shortcut audit

### 2.1 Writer inheritance is presently wrong

The successor repeatedly says "v2.1 passes unchanged" and freezes the v2.1
recipe. That is no longer the intended causal object. v2.1's trainable
`padvoid` targets gave ATOMS and OLD_REPLAY more synthetic-dialect gradients
than their paired treatments. The v2.2 delta removes them, replaces them with
truthful child-row replay, enforces source-diverse batches, and selects LOW
versus HIGH heat once on an excluded authentic root using semantic carriage,
locality, and canary gates.

Required edit: make a v2.2 DEV pass the sole release dependency. Bind the
selected writer's exact corpus-construction algorithm, replay allocation,
batch schedule, masks, heat, rank, wrappers, target dose, canary, and final
checkpoint into the lifetime manifest. A different lifetime corpus size may
require more total updates, but that scaling law must be fixed from corpus
size before confirmatory outputs; it cannot silently revert to "five epochs"
if that changes per-row presentation with age.

### 2.2 Authors are not independent units

The memo correctly declares one lineage triple as the unit. It must be equally
strict about semantic authorship. A row is child-authored only when:

```text
committed child action span
  -> public receipt span
  -> later exact child EVENT/LINK span
  -> compiler inclusion receipt
```

All spans need immutable hashes and chronology. Deterministic wrappers,
replays, packing, and byte copying are compiler work and may not be described
as additional child observations. A compiler-produced inference, repaired
identifier, filled outcome, or inferred LINK invalidates O1 for that row. A
later actor using a child-authored memory does not make a researcher-supplied
route scaffold autonomous; action choice and row authorship must be reported
separately.

### 2.3 Fresh opaque modules may make O8 impossible rather than rigorous

The proposed stream grows primarily by adding unrelated opaque modules while
keeping task path length fixed. That is excellent for testing finite keyed
memory capacity and retention. It provides no stated cross-module law for the
LoRA to amortize. A lossless indexed text graph should be the statistically
favored carrier of hundreds of independent exact bindings.

Therefore a DLT failure to beat ACTIVE_LINKED_TEXT would not falsify the broad
idea that parametric experience can exploit recurring structure; it would
show that LoRA did not beat an exact store on independent bindings. Conversely,
engineering the text baseline to miss those bindings would be a benchmark
shortcut.

Decision before execution: either (a) keep this world and bound O8 to
"carrier comparison on opaque exact bindings," accepting that text may win,
or (b) prospectively add a separately scored, public recurring rule family
whose instances remain locally opaque but whose cross-module structure can be
learned. Do not introduce hidden compressibility after seeing the opaque-world
result.

## 3. Lifetime clock: PASS with two required clarifications

`m_sched={15,114,213,312,411}` is the correct primary age coordinate because
it counts scheduled semantic opportunities, including malformed or absent
child attempts. Admitted rows, DREAM derivatives, optimizer steps, replay
presentations, and successful episodes must remain secondary coordinates.
This closes the success-dependent-clock shortcut.

Two details must be sealed:

1. The potential-outcome tape must be action-contingent: for every legal probe
   an arm might choose, its outcome is fixed before the fork. Sharing only the
   RNG seed does not guarantee equal luck once policies diverge.
2. If blinded sample-size re-estimation adds later lineages, root allocation,
   learner seed, infrastructure batch, and run order must be block-randomized.
   Protocol bytes must remain identical. Otherwise the first 16 and later
   cohorts confound N expansion with calendar/hardware changes.

Five cuts can establish a finite novelty-growing lifetime. They cannot
establish asymptotic growth, a learned sleep schedule, or a plateau. The memo
correctly reserves plateau language for a seven-cut extension.

## 4. ACTIVE_LINKED_TEXT fairness and saturation

### What is already right

- The store grows on-policy and remains unlimited.
- It receives only branch-local public events and admitted child-authored
  EVENT/LINK rows, never the hidden graph.
- Query calls and returned tokens are charged.
- Wrong-root, twin, cut, and exact-graph checks can expose fake retrieval.
- On-policy and fixed-DLT-history comparisons separate whole-system and
  carrier questions in principle.

### What must change

1. **Certificate is not saturation.** `15/16` task success on three of four
   excluded roots establishes service competence, not a flat resource curve.
   Report all four roots without dropping failure, and require either the
   predeclared equivalence-to-doubling rule or label the chosen point
   `MAX_TESTED_ACCESS`, not saturated.
2. **The q=8 edge has no initial doubling.** If no lower q saturates, selecting
   `(q=8,B=4096)` is conservative but does not show saturation. The q=16,
   B=8192 sensitivity must exist before any saturation or plateau claim, not
   only after a favorable main result.
3. **Three fixed-history cuts do not identify carrier AUC.** Either evaluate
   DLT and linked text on the identical DLT history at all five cuts and use a
   registered paired AUC, or predeclare one fixed-history cut—preferably
   terminal—as the sole carrier estimand. "Directionally positive" is not a
   claim gate. Require its root-level lower interval above zero for parametric
   carrier superiority; otherwise claim only total-system advantage.
4. **Equal information, not identical prose.** On-policy branches may author
   different rows; that is legitimate for total-system comparison. At fixed
   history, ACTIVE_LINKED_TEXT must receive every exact eligible DLT public
   and child-authored row at the same frontier, including rejected-row status,
   but no DLT-only DREAM inferences. That comparison isolates carrier plus
   access rather than life quality.
5. **Access accounting must include prompt cost and calls.** Returned tokens,
   actor-written query tokens, query-generation calls, retrieval computation,
   and final inference tokens should be reported. DLT's adapter bytes and
   SLEEP compute must be reported alongside them, even when they are not
   forced equal.

## 5. Recurrence attribution

The current design supports two distinct claims:

- `DLT_PERIODIC - SLEEP_FROZEN` on policy: effect of the whole periodic
  learner, including how earlier writes change later experience collection.
- periodic DLT versus `FINAL_BATCH` on the exact terminal DLT history: whether
  spaced writes outperform one final fit **conditional on the periodic
  learner's data**.

It does not support the stronger statement that recurrence is necessary. The
terminal batch inherits a history created by recurrent writes. If it catches
up, recurrence may have mattered only for collecting that history; if it does
not, fit cadence and exact exposure allocation may differ.

Minimum repair:

1. Define an exact per-row exposure ledger. "Same cumulative target-token
   presentations" must reproduce how many times each old and new target was
   supervised across periodic fits, not merely match the grand token total.
   Final shuffling is the deliberate timing intervention.
2. Report the two estimands above separately and avoid "recurrence caused"
   unless both support it.
3. If O10 is headline-critical, add a terminal `FROZEN_HISTORY_BATCH` arm:
   start at the clean child and fit once on the SLEEP_FROZEN branch's exact
   accumulated corpus with the same per-row exposure ledger. Together with
   DLT-history FINAL_BATCH, this locates whether the gain came from data
   collection, fit timing, or both. This adds one fit per lineage but is more
   informative than another weak memory baseline.

## 6. Can 16 roots carry the claims?

Only conditionally. The memo's blinded sample-size re-estimation is the right
idea, but N=16 is not automatically adequate.

For a one-sided alpha `.05`, power `.80`, SESOI `.05` paired test, the normal
approximation requires approximately:

```text
N ~= 6.18 * (paired_SD / .05)^2.
```

Thus N=16 is adequate only around paired SD `.080` or lower; N=24 around
`.099`, N=32 around `.114`, and N=48 around `.139` (exact small-sample t
thresholds are slightly stricter). Prior CompilerGym lineages included a full
motor collapse, so low variance cannot be assumed.

The blinded re-estimation must specify exactly how labels are masked, which
two covariance estimates are used, who/what opens them, and that no mean,
sign, arm-specific variance, gate rate, or qualitative transcript is visible.
Choose N once at the middle cut; do not re-estimate again.

Mechanism reliability needs its own gate. Add:

- at least `14/16` fully valid first-cut two-SLEEP roots before scaling the
  lifetime claim, with every invalid/unsafe lineage counted as failure;
- exact binomial interval, not only `14/16`; and
- ATOMS on all 16 initial roots, not eight, unless the eight-root sentinel has
  a prospectively powered magnitude test and root-level lower interval.

Running ATOMS on all 16 costs eight additional fits—small relative to the 120
already planned—and removes the weakest O3 inference in the campaign.

## 7. Compression and authorship claim boundaries

The semantic-schema sidecar is acceptably narrow if it remains quarantined.
It can show that a child chose a shorter exact code from a supplied language
and that the code remained accessible after LoRA writing. It cannot show:

- that the 80.8 MB LoRA physically compressed the life;
- that DREAM invented the schema family;
- that the whole organism is smaller than a normalized text/codec store; or
- that the main lifetime benefit was mediated by compression.

For the paper record, model-generated design/code/prose and human decisions
must remain in the AI-use ledger, with named human review of each claim-bearing
source path, sampled raw artifact, statistical reduction, and final claim.
That is a submission/authorship obligation, not a scientific arm and not a
reason to weaken or inflate the claims.

## 9. Decisive paper-grade gate

Release a paper-grade experiential-learning headline only if all of the
following pass prospectively:

1. v2.2 DEV passes unchanged on both roots, including causal LINK added value,
   not merely EVENT composition.
2. At least 14/16 initial independent confirmation roots complete the full
   authentic two-SLEEP seam; all failures remain in intention-to-treat.
3. The adaptively selected final N is adequately powered and DLT exceeds
   SLEEP_FROZEN by at least `.05` on the registered lifetime endpoint with a
   one-sided 95% lower bound above zero, positive absolute growth, retained
   OLD upper-loss bound below `.05`, and no rising formation/interface harm.
4. Certified ACTIVE_LINKED_TEXT is compared on-policy and on identical DLT
   histories. DLT exceeds it by `.05` with lower 95% above zero for the total
   system; carrier superiority is stated only if its separately registered
   fixed-history interval also clears zero.
5. Any recurrence claim uses exact per-row exposure matching and states
   separately the on-policy learning effect and fixed-history timing effect;
   a strong necessity claim requires the frozen-history batch control.
6. Plateau is used only after seven novelty-growing cuts and pre-run doubled
   text access satisfy simultaneous equivalence intervals. Compression is
   used only for a passing quarantined schema sidecar and only in its semantic,
   supplied-language sense.

If (1)--(3) pass but (4) does not, the honest paper is a bounded recurrent
experiential parametric-memory result, not superiority over strong textual
memory. If O3 fails, the result is EVENT carriage/composition, not connected
memory. If only v2.2 DEV passes, report a mechanism result and do not imply a
lifetime flywheel.
