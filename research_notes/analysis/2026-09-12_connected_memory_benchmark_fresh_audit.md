# Fresh-context audit: connected/compressed experiential-memory benchmark

Date: 2026-09-12

Role: Codex subagent, read-only design audit

Scope: M-E2/M-E4/M-E5 and successors; no implementation or scientific execution

## Bottom line

The connected-memory benchmark is a **well-motivated, still-unimplemented
proposal**. No M-E2, M-E4, or M-E5 model result exists. The latest proposal is
explicitly `REWORK`; no corresponding source, test, or result directory exists.
Historical Alchemy/RML results prove useful components under strong scaffolding,
not learned connected carriage, goal-conditioned traversal, prospective
expansion, or compression.

If its remaining contract defects are repaired, the proposed typed four-read
assay can validly establish a bounded causal relay:

- M-E2 can show that an authentic, child-proposed connection carried in a LoRA
  changes behavior beyond its two atoms.
- M-E4 can show that a public goal changes which stored path the actor reads and
  follows.
- M-E5 can show one controlled cycle in which old memory changes an experiment,
  a public outcome selects a precommitted new record, and a cumulative adapter
  later uses old and new records together.

It cannot by itself establish a latent graph geometry inside the weights,
native free-form planning, recurrent self-improvement, LoRA superiority to a
strong external-memory system, or compression.

## Does the proposed benchmark measure the intended properties?

### M-E2: connected carriage — conditionally yes, narrowly

The decisive contrast is `LINK_AUTH` versus a truthful `LINK_NULL`, together
with a same-build read-time permutation. The authentic link row exposes only
opaque atom IDs; it does not contain the goal, path, action, or value. The
world must certify that both atoms are necessary for the downstream action.
Adapter-off, cyclic wrong-life, spill, and interface controls test whether the
effect is really carried by the correct adapter/read.

If exact text passes the same semantics and LoRA passes those contrasts, the
valid claim is: **the adapter transported an action-derived connection record
whose semantic content was necessary for bounded downstream use**. It does not
show that weights spontaneously acquired graph geometry, that the model can
search an arbitrary graph, or that atoms alone were unavailable; the assay
deliberately gives the actor an explicit exact one-hop read API.

The current review correctly requires renaming gradient-bearing `ATOMS_PAD` to
`NONLINK_PAD_TARGET` and keeping bridge cut/twin interventions in E4, not E2.

### M-E4: goal-conditioned traversal — conditionally yes, at the actor/API level

Two incompatible goals share the same non-goal public start and carrier.
`GOAL_SWAP` changes only the goal bytes. A valid pass requires the goal to alter
the first relevant query, complete path, and action; a necessary bridge cut
must remove value and a truthful twin must redirect the trace.

That is a strong causal test of **functional, goal-conditioned selection and
following of stored paths**. It is not evidence that a hidden graph was
traversed internally within one transformer forward pass. The public read
trace is the mechanism. The typed endpoint is appropriately described as a
mechanistic ceiling; the separate native-policy endpoint is required before
using “agentic.”

### M-E5: prospective expansion — conditionally yes, for one controlled cycle

The strongest part of V5 is chronology. Before seeing the outcome, the child
must declare its gap, two hypotheses, chosen separating experiment, and a
complete outcome-to-row map. Only the public outcome may select one of those
precommitted rows. After a sterile reset, a cumulative old+new adapter must
retain the old record and solve a delayed goal requiring exactly one old plus
the new relation.

No-write, matched sham-write, old-cut, reachout-off, adapter-off, wrong-life,
and `OUTCOME_VALUE_TWIN` redirection make that a credible **one-cycle expansion
relay**. A separate `ACTION_OUTCOME_BINDING_SHUFFLE` is required for the
stronger statement that the particular action--outcome binding caused the
write. This remains strongly scaffolded: the schema, two-hypothesis form,
experiment grammar, outcome branches, compiler, and four-read ceiling are
fixed. It is not autonomous open-world discovery, recurrence, or a flywheel.

### Compression — no

No current result measures compression. A small LoRA rank, shorter dream, or
successful relay is not a rate result. The adjudication calculates that the
actual rank-8 adapter is about **80.8 MB** (fp32 save), so an expanded equivalent
must exceed about **161.6 MB** even to demonstrate a physical rate below 0.5,
and an eligible raw baseline must exceed about **230.8 MB** for a rate below
0.35. Current small fixtures are orders of magnitude below those thresholds.

The smallest credible compression follow-up is therefore semantic text
rate--distortion after connected utility succeeds: expanded same-denotation
records versus normalized connected records versus schema+residual, with exact
round-trip, task utility, false-memory count, and total serialized bytes. LoRA
transport and physical compression should remain separate endpoints.

## Memory baselines and claim limits

The exact same-semantics text carrier is an excellent causal ceiling because it
holds payload semantics fixed. It is **not** a strong external-memory agent.
The proposed `ACTIVE_TEXT_NATIVE` system would be the strong opponent, but its
full updater/retriever/query/budget contract and implementation do not yet
exist. Historical RAG and static-brief results are on different tasks and do
not substitute for it. Existing matched CompilerGym evidence is near zero:
brief-vs-adapter was approximately `+0.0046` on the report panel and `-0.0041`
on the disjoint panel; a nine-life 2x2 estimated adapter `-0.0146` and text
`+0.0041`. None establishes superiority.

Therefore:

- M-E2/E4/E5 may support carrier-specific causal claims without LoRA beating
  text.
- LoRA-over-text superiority requires a separately powered direct-system
  comparison against a validated `ACTIVE_TEXT_NATIVE`.
- Failure to validate that strong baseline must block superiority language,
  not erase an otherwise valid carrier-specific M result.

## Two critical pre-source defects

1. **The review receipt does not bind the current proposal bytes.**
   `review_synthesis.md` says it reviewed `exact_scope.md` SHA-256
   `d36c58f7...aa4c`; the current committed file hashes to
   `6bcef58e...823a`. No review artifact found in this audit binds the current
   bytes. Re-review or restore the reviewed bytes before any source-authoring
   grant.
2. **Baseline precedence is internally inconsistent.** V5 section 8 says
   `BASELINE_INVALID` blocks full E5 release. The independent benchmark audit,
   `research_notes/2026-09-11_pcfl_decisive_benchmark_independent_audit.md`,
   says a failed strong-baseline integration blocks superiority only and does
   not erase valid E2/E4/E5 carrier evidence. Adopt the latter rule explicitly:
   keep exact-text fidelity as the M assay gate; keep `ACTIVE_TEXT_NATIVE` as a
   separately validated comparison and paper-claim gate.

The standing `REWORK` disposition also must be honored: finite world algebra,
opaque IDs independent of semantics, primitive endpoint equations, exact deck,
phase state table, root generation, call/token/training limits, E0, and source
boundaries are not frozen enough for implementation.

## Smallest high-information experiment after writer qualification

Do **not** start with E5 or the full six-build deck.

1. First run CPU M0 plus scripted positive/mutation fixtures, then an exact-text
   E2+E4 canary on four fixed DEV roots. Extend to eight only if at least 2/4
   core roots pass. This verifies that the world, controls, and reader admit the
   intended theorem before consuming LoRA fits.
2. With the frozen qualified writer, run a **two-root LoRA E2+E4 kill-gate**.
   Per root build only `LINK_AUTH` and truthful `LINK_NULL`; use the same-build
   read permutation, adapter-off, cyclic wrong-life donor, and the two-goal
   goal-swap/cut/twin traces. E4 reuses the old adapter, so it adds high causal
   information without another write.
3. If transactional qualification evaluates `K` candidates per requested
   adapter, this first LoRA gate costs `2 roots × 2 builds × K = 4K` candidate
   fits, versus `12K` for the full six-build two-root deck.
4. Stop if authentic link cannot beat truthful-null/permutation/off/wrong-life,
   or if goal bytes do not redirect query, path, and action. A pass is a DEV
   kill-gate, not the full M claim: fill `NONLINK_PAD_TARGET`, independent
   derangement, spill/interface, full shortcut, and remaining E2/E4 controls
   before release.
5. Only after E2+E4 survive should one `EDGE_NEW`/`SHAM_NEW` E5 transaction be
   added. It introduces a second write, chronology, reset, and action--outcome
   attribution and is therefore the wrong first debugging surface.

This sequence maximizes information per fit: it tests semantic carriage and
goal-dependent use of the same adapter before paying for online expansion. Run
compression only after connected utility, and validate the strong active-text
opponent in parallel for superiority claims rather than making it a blocker for
the carrier assay.

## Claim firewall

Until the above runs exist, the defensible record remains:

> Historical component ceilings show that structured verified memories can be
> transported and used under resolved reads. Learned connected carriage,
> goal-conditioned traversal, one-cycle prospective expansion, compression,
> and superiority over strong external memory remain unshown.
