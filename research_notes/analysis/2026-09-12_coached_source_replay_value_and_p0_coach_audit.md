## Exact recommendation

**NO-GO** on the proposed 512-request replay -> first-64 extraction -> two
rank-8 fits -> parent-free record probe as a priority experiment for the full
Dream--LoRA--Think objective. **GO only for one 28-request paired interface
canary if the builder still needs to certify that the NOTE_AFTER surface can
be made reliable. Do not fit its outputs.** Put the scientific budget into the
32-block, no-write `P0-COACH` below.

The replay proposal is careful about source custody. It binds historical ACTs,
feedback, prompts, seeds and output bytes; preserves the original roots; uses
no new world execution; leaves teacher/coach text out of targets; and gives the
new consumer its own schema. Those are good engineering properties.

But the proposed intervention supplies the exact submitted action and score,
then explicitly asks the child to quote them in a judge-approved first-person
form. A success therefore establishes transcription/interface compliance. It
does not require failure diagnosis, selection of a thinking move, a changed
decision, a fresh outcome, or an adaptive parent. Both historical arms receive
the same fixed coach, while their old q14 lesson/sham histories retain the
203-versus-158-token confound. Training the first 64 passing copies and probing
the same record form can learn a global NOTE habit. The current writer is also
not selectively qualified. Thus a replay-fit result cannot close Link B, H1,
H2, or even show that the copied record improved reasoning.

This is especially low-value after the terminal formation result: 1,903 and
1,627 measured ACTs survive in the lesson and sham ledgers, while both arms
produced zero strict records. SLEEP can mechanically preserve the authoritative
action--outcome joins; child reflection can be optional grounded enrichment.
The intelligence claim should not depend on one brittle first-person NOTE
predicate.

## Smallest source-replay scope worth running

If a real-model NOTE interface check is still useful, replace the 512-call
proposal with `NOTE-IFACE-14`:

1. Select exactly 14 historical sources before generation: the first measured
   ACT in physical order for each of the seven train families in each original
   arm. Missing cells remain missing; there is no replacement.
2. For every source issue two requests from the exact stored prompt: unchanged
   and with Astra's fixed coach inserted immediately before the exact outcome
   suffix. Use the same recorded model, renderer, temperature, 100-token cap
   and source-request seed; randomize request order. Explicit seeding is logged,
   not called byte-deterministic pairing.
3. Preserve all 28 outputs. Re-run the unchanged source join, `judge_record`,
   echo/leak check and action/score agreement. The source event, not a request,
   is the unit. No retry, prompt variant, wake trajectory, corpus or adapter.

Call the interface `READY` only if at least 12/14 coached outputs are eligible,
coaching improves eligibility on at least 10/14 paired sources, and there are
zero wrong-action, wrong-score, reference-answer, teacher-echo, or source-binding
acceptances. Otherwise call it `NOT_READY` and park the prompt path. This is a
one-draw engineering gate, not parenting or learning evidence. A pass does not
authorize the proposed fits; a later fit would still require a qualified W0
writer and an action endpoint different from the record judge.

## Actual `P0-COACH`: adaptive process selection before SLEEP

### Question

Given one persisted child failure, can a stronger parent choose an answer-free
process move that causes a better child-authored plan and a better authoritative
action on a fresh homologous problem than a dose-matched but failure-mismatched
move? This isolates diagnosis, uptake and thought-to-action before asking LoRA
to retain anything.

### Frozen material and pre-treatment eligibility

- Frozen Qwen2.5-7B-Instruct child, no adapter, no training, no store and an
  interface-only bootstrap: task, `ACT:` contract, verifier meaning and equal
  generous action/token budget. Remove metacognitive recipes from both arms.
- Four partial-feedback train families: `countdown`, `mini_sudoku`,
  `futoshiki`, and `arc_1d`. Prebind 12 source/apply pairs per family. Source
  and apply seeds are disjoint and outside existing gate/exam and previously
  consumed ranges. All 96 item IDs are consumed by this DEV scout.
- Run one source tape per candidate: the child gets exactly two action
  opportunities. Persist prompts, raw thoughts, parsed ACTs and public scores
  once. A source qualifies if it has at least one measured valid ACT and no
  accepted attempt. Select the first eight qualifying pairs per family in
  prebound order. If any family has fewer than eight, emit
  `P0_SOURCE_HEADROOM_FAIL` and stop before parent calls.

This yields 32 independent blocks. Every treatment continuation begins from
the same immutable source tape; separately generated childhoods are forbidden.
Use the existing 400-token child action ceiling at temperature 0.7, a 128-token
child-plan ceiling at the same temperature, and greedy parent selection capped
at 128 tokens. Prebind every request seed. The hard envelope is 640 child calls
and 32 parent calls, at most 242,688 newly generated tokens; no retry or
outcome-conditioned call is allowed. Preparation must replace this conservative
token envelope with measured prompt/prefill tokens and a caller timeout before
launch.

### Fixed answer-free card bank

Freeze six short cards, all with the same child-token count and common wrapper:

| ID | Process move |
|---|---|
| `FORM_CHECK` | Derive the required output form and reject a candidate that violates it before submitting. |
| `CONSTRAINT_LEDGER` | Externalize the live constraints and require the next candidate to satisfy each one. |
| `LOCAL_REVISION` | After partial credit, preserve the supported part and change one uncertain component. |
| `DISCRIMINATE` | Contrast two hypotheses and choose an action whose possible outcomes distinguish them. |
| `RESET_ASSUMPTION` | After repeated zero, identify an assumption shared by the failed attempts and replace it. |
| `COMPOSE_VERIFY` | Solve subparts, recombine them, then check the whole against the original conditions. |

The cards contain no worked example, task fact, answer, NOTE syntax, required
thought wording, or claim about which card is correct.

### Parent and active sham

For each block, one exact pinned stronger parent sees only the source question,
the child's raw source tape, executed ACTs and public feedback. It sees neither
the reference answer nor either apply item. It returns a validated `card_id`
and an audit-only rationale. No free parent prose reaches the child. The parent
is stateless across blocks in P0; “adaptive” here means that its process-card
choice is conditioned on the actual failure, not that the parent learns across
children.

Freeze all 32 parent choices before any continuation outcome. Construct a
same-family, same source-best-score-bin, no-fixed-point sham permutation whose
donor card ID differs from the targeted card ID. If a complete different-card
matching does not exist, emit `P0_SELECTOR_VARIATION_FAIL`; do not relax the
matching. The targeted and sham arms receive the same wrapper, token count,
timing, output budget and number of calls. Only the card content differs.

### One block after assignment

1. Fork targeted and sham continuations from the identical persisted source
   tape and deliver their fixed cards.
2. Ask each child once for a concise plan in its own words, with the same cap.
   Preserve raw bytes; do not rewrite, template-score or admit/exclude the plan
   for sounding like the card.
3. **Direct manipulation check:** on the source task, keep that arm's card and
   plan visible for three fixed ACT opportunities.
4. **Primary relay:** start a fresh process on the prebound same-family apply
   item. Supply only that arm's child-authored plan. The parent/card, source
   question/tape/scores, hidden answer, store, cache and prior process state are
   absent. Give three fixed ACT opportunities.
5. **Sterile anchor:** run the same apply item from the frozen child with no
   card and no plan. It detects state leakage and estimates ordinary headroom;
   it is not another learned child.

All continuations, order and device positions are prebound/randomized before
outcomes. Missing or invalid ACTs score zero. Generation seeds are recorded but
do not create fake byte-level pairing. There are no NOTE_AFTER generations,
record predicates, corpora, optimizer steps, adapters, lineage heads or
CompilerGym exposures.

### Endpoints and analysis

For each three-attempt action sequence, let `best@k` be the best authoritative
score through attempt `k`, carrying zero through missing/invalid attempts, and
define:

```text
action_AUC = (best@1 + best@2 + best@3) / 3
DELTA_RELAY = mean_block(AUC_targeted_plan - AUC_yoked_sham_plan)
DELTA_DIRECT = mean_block(AUC_targeted_direct - AUC_yoked_sham_direct)
ABS_TARGET = mean_block(AUC_targeted_plan - AUC_sterile)
```

The primary is `DELTA_RELAY`. Use the 32 blocks, never actions or decodes, as
`n`; report every block, a family-stratified randomization test over the frozen
sham assignment, and a paired interval. Secondary outcomes are `DELTA_DIRECT`,
`ABS_TARGET`, score revision after attempt one, valid/missing ACT rate, family
effects, card distribution, plan length and card-copy diagnostics. Lexical
agreement, eloquence, longer thought and parent ratings are never success.

## P0 gates and decisions

Pre-execution validity requires exact source/apply split proofs, immutable
common source tapes, equal-token cards, a complete different-card sham match,
all parent decisions frozen before outcomes, structural answer withholding,
and a fresh relay process containing only the child plan. Any answer/apply-task
exposure to the parent or parent/card/source text in the relay invalidates the
run. More than two block-level infrastructure failures is
`P0_EXECUTION_INVALID`; otherwise retain failed actions as zero.

Call `P0_COACH_GO` only if all are true:

1. `DELTA_RELAY >= 0.05` and the predeclared family-stratified one-sided
   randomization test gives `p <= 0.05`;
2. `ABS_TARGET >= 0.03`, so the contrast is not created only by a harmful sham;
3. `DELTA_DIRECT > 0` and at least three of four family relay means are positive;
4. targeted valid-ACT rate is no more than 0.05 below sham, and no family has a
   targeted-minus-sham relay mean below `-0.10`; and
5. the sterile mean is below `0.85`; otherwise label `P0_PROBE_SATURATED`.

If direct benefit is positive but relay fails, label `CONTEXT_ONLY` and repair
the child-plan/DREAM carrier, not LoRA heat. If targeted and sham both improve
over sterile without directional separation, label `GENERIC_SCAFFOLDING`:
adaptive selection is not established. If direct benefit fails, repair the
parent observations/card bank on fresh DEV blocks. If action validity falls,
fail the intervention. Do not answer any of these outcomes with the coached
NOTE replay-to-fit path.

A P0 pass supports only this statement: on these disposable blocks, the pinned
parent selected fixed process cards whose effect survived deletion of the card
through a child-authored contextual plan and improved fresh same-family action.
It does not show weight learning, SLEEP, durable parenting, far transfer, parent
improvement, H1 or H2. Freeze the P0 tapes/choices only as prospective P1
development material. P1 remains ineligible until W0 establishes selective
writer carriage; it must then delete the child plan and all context so the only
treatment carrier is the child LoRA.
