## Bottom line

The reduced Stage2A screen is deliberately a **narrow learned controller
test**. By itself it does not test free-form planning or thought over
autobiographical memory. Its job is to qualify one target-disjoint child that
can perform four coupled operations—SEEK, PROSPECT, CHECK, and CONTINUE—on
held two-step tasks without losing its typed action channel.

The authentic two-SLEEP junction is materially stronger. If all its bound
gates pass, the same continued adapter will have:

```text
executed public actions -> authored grounded EVENT/LINK records -> slept
  -> self-issued single-record READs after a clean reset
  -> traversed OLD records under a goal -> acted
  -> acquired NEW experience -> slept again
  -> traversed OLD+NEW records -> acted while retaining OLD
```

That is a valid **minimal autobiographical memory-use loop**, not merely a
syntax test. It uses the instruction-tuned base as the planner and the learned
controller as the interface habit. However, the initial 2,880-call AUTH
tranche does **not** by itself prove that free-form CoT mediated success or
that a particular recovered content field caused the action. Those are
different estimands. Preserve the existing claim order: AUTH first; content
attribution only on an AUTH positive.

No broader prerequisite ladder is needed. Add one zero-call thought-trace
sidecar to the already retained rollouts, and retain the already specified
same-adapter response forks/ATOM controls for attribution after AUTH passes.

## Why this is more than a typed interface—but still narrow

Stage2A chain success is not parser compliance alone. A successful held chain
must select relevant records from 24- and four-row returns, make two correct
world actions, issue the correct KEEP/REVISE after the actual public outcome,
recover after a contradiction, arrive at the goal, and stop immediately. The
causal-twin and D1-minus-BASE gates prevent a pure formatting pass.

Nevertheless, it is a lab-taught finite controller. Its grammar disallows
ordinary free thought, and its deterministic schema can be solved without a
general theory of planning. The correct description is therefore:

> Stage2A qualifies the interface policy needed to expose the memory
> construct; it is not itself evidence of CoT over memory.

TSJ crosses the construct boundary because the recalled rows are generated
from the same child's own adapter, arrive one at a time, must be combined in
the actor's fresh context, and determine a later physical route. The clean
resets, foreign-life control, birth/no-write controls, retained OLD test, and
second write make this substantially different from following an inline
answer. It is still a deliberately tiny, explicit graph, which is appropriate
for a first causal junction.

## Zero-call thought/headroom piggyback

Before model execution, prospectively register one **descriptive, non-gating**
`THOUGHT_TRACE_V1` reduction over raw calls that the current plans already
retain. It needs no new fit, arm, actor call, token, or GPU work.

For every existing Stage2A chain and TSJ P10/P30/P50/P70 rollout, record:

1. total THINK calls and generated THINK tokens/bytes;
2. maximum consecutive THINK calls;
3. whether any THINK occurred before the first READ;
4. whether any THINK occurred after at least one returned memory row and
   before the first STEP;
5. whether any THINK occurred after at least two distinct returned rows and
   before the first STEP (`multi_record_deliberation_opportunity_used`);
6. whether any THINK occurred after the first public outcome and before the
   next READ/STEP;
7. success split descriptively into zero-THINK versus at-least-one-THINK
   rollouts.

Stage2A's KEEP/REVISE commands must be counted separately as
`typed_outcome_check`, never as free THINK. Its pre-first-STEP count therefore
does not become a CoT result. For TSJ, retain the exact raw THINK bytes for a
later blinded qualitative appendix, but do not add a post-hoc semantic score
or make lexical mentions of IDs into a reasoning claim.

Two already planned outcomes supply functional headroom without another arm:

- Stage2A reports the paired BASE and D1 chain counts and requires D1 gain;
- TSJ P10/P50 `SAME_AUTH_HISTORY_ACTIVE_TEXT_CEILING` requires the selected
  BIRTH child to self-read and solve when the exact memory is externally
  available.

The latter is a **BIRTH-child functional ceiling**, not a pure-base ablation.
Do not say it isolates pretrained CoT. A new pure-base TSJ arm would cost calls
and does not improve the immediate go/no-go enough to gate AUTH.

Interpretation is fixed in advance:

- AUTH success with zero free THINK still proves self-issued memory use and
  action utility, but **not CoT over memory**;
- observed post-read THINK shows that the permitted workspace was used, but
  not that it caused success;
- only a later thought intervention/ablation could establish CoT mediation,
  and that is not a prerequisite for this paper's first junction.

the narrow TSJ-v4 maximum wording about content interventions redirecting

trace, not an identified mediator.
